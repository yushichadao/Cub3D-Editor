# 立方 · 3Dデザインワークショップ —— 使用説明書

## ゼロから習熟までの啓発型教材（Web 版・PC 版・Android 版 共通）

> 本書は冷たい機能リストではなく、**一緒に学び、一緒に作り、一緒に考えられる**教材です。
> あなたが 3 次元デザインに触れたことがなく、専門ソフトを使ったこともないことを前提にします。あなたのそばに座る先生のように、
> 「3 次元とは何か」から始め、問いで考えを導き、比喩で直観を築き、練習で手触りを固め、
> 最終的に「ボタンの押し方」から「独りで創れる力」へと至ります。

> 📦 **一冊で 4 つの形態に対応**：本ツールには Web 版・PC デスクトップ版・Android 版の 3 つの配布版があり、
> さらに Web 版は端末に応じて**マウスモード**と**タッチモード**に自動で切り替わります。
> 本書は**この 4 形態すべてを同時にカバー**します。操作が異なる箇所では「形態バッジ」で各端末のやり方を明示します。

### 0.3 最大の違い：指には「右クリック」も「ホイール」も無い

4 形態のうち、本当に身体の慣れを変える必要があるのは **入力方式** だけです。

マウスは 3 つの独立した信号（左・右・ホイール）を持ちますが、指は 1 つ（押す→動かす→離す）しかありません。そこでタッチでは**指の本数**で意図を区別します：

| やりたいこと | 🖥️💻 マウス（Web·マウス／PC） | 📱🤖 タッチ（Web·タッチ／Android） |
| --- | --- | --- |
| オブジェクトを選択 | 左クリック | 1 本指タップ |
| 図形を配置 | 地面を左クリック | 地面を 1 本指タップ |
| 視点を回転 | **右**ドラッグ | 空白を**1 本指**ドラッグ |
| 視点を平行移動 | **中**ドラッグ／`Shift`+右ドラッグ | **2 本指**ドラッグ |
| 視点をズーム | **ホイール**回転 | **2 本指**ピンチ／広げる |
| 複数選択 | `Shift` + 左クリック | 「すべて選択」、または「ボックス選択」 |
| 範囲選択 | そのまま左ドラッグで矩形 | 先に「ボックス選択」ボタン → 1 本指ドラッグ |

💡 **一言で覚える**：**マウスは「どのボタンか」、指は「何本か」。**

### 0.4 タッチ形態だけの 2 つのボタン

キーボードが無いため、タッチ形態（📱 Web·タッチ と 🤖 Android）では下部バーに 2 つのボタンが追加され、`Ctrl+A` とドラッグ範囲選択を代替します：

- **「すべて選択」**：マウス版の `Ctrl + A` に相当。シーン内の全オブジェクトを一括選択；
- **「ボックス選択」**：一度タップすると範囲選択モードに入り（ボタンが青くなる）、1 本指で矩形をドラッグして中のオブジェクトをまとめて選択。
  ⚠️ **注意**：範囲選択は**1 回使うと自動的に解除**されます（ボタンの色が戻る）。もう一度使うには**再度タップ**してください。誤操作防止の設計です。

### 0.5 PC 版だけの強み：「本物のソフト」として使う

PC 版は単なる「web をガワで包んだもの」ではなく、デスクトップソフトならではの機能を備えます：

- **ウィンドウ操作**：右上の自前描画の最小化／最大化／閉じる、上部バーの `☰` ネイティブメニュー；
- **ドラッグ＆ドロップ読込**：`.json` プロジェクトファイルを**ウィンドウに放り込むだけ**で開けます；
- **最近開いたファイル**：メニューに履歴が残り、ワンクリックで再開；
- **クラッシュ復元と自動保存**：不意に落ちても、再起動時に前回の続きを復元するか尋ねてくれます；
- **付箋の独立ウィンドウ化**：付箋をメインウィンドウの外に出し、**常に最前面**の小窓にできます。別の資料を見ながらメモを表示し続けられます；
- **拡張センター**：プラグイン・ランタイム・言語パックを導入でき、複数のプログラミング言語で拡張を書けます。

### 0.6 Android 版だけの注意：戻るキーと終了保護

Android 版で最も注意すべきは**システムの戻るキー**の挙動で、階層的になっています：

> 戻るキー → 付箋が開いていれば 1 つずつ閉じる（未保存の内容があれば先に確認）→ 目次を閉じる → 説明書を閉じる → 最後にアプリ終了を確認。

終了時の確認ダイアログには 3 つの選択肢があります：**保存して終了／保存せず終了／キャンセル**。苦労して作ったシーンが誤操作 1 回で消えないための仕組みです。

💡 Android 版に**「全画面」ボタンはありません**——アプリ自体が全画面で動作しているためです。

### 0.7 ネット接続とデータの安全について

| | ネット必要？ | データはどこに？ |
| --- | --- | --- |
| 🖥️📱 Web 版 | 必要（ページ読込時） | 計算はすべて端末内。**作品データは一切アップロードされません** |
| 💻 PC 版 | **不要** | すべてローカル |
| 🤖 Android 版 | **不要** | すべて端末内 |

3 つの版とも、作品をサーバーへ送信することはありません。Web 版がネットを使うのはページを取得するときだけで、開いた後の制作はすべて自分の端末内で完結します。

# 第 1 篇 スタート篇（ゼロから入門）

## 第 1 章 もう一度「3 次元」を知る：ある写真から

### 1.1 2 次元と 3 次元、違いはどこか

スマホで机の写真を撮ってみてください。写真は**2 次元**です。幅も高さもありますが、指で触れても平ら——つまり「立体に見える」だけなのです。

次に机の横に回ってもう一度見てください。本物の机は**3 次元**です。幅も高さもあり、さらに**奥行き**（机の脚が前に伸びている分）があります。あなたが動くと見える形が変わりますが、写真はいつまでもその瞬間のままです。

💡 **一言で覚える**：2 次元は「絵」、3 次元は「その中を歩き回れる本当の空間」。

### 1.2 このツールがくれるのは「3 次元ステージ」

エディタを開くと、中央のキャンバスが 3 次元ステージになります。左から図形を選び、その「地面」の上をクリックすると、それは本当にステージの中に「落ちて」きます——後ろに回って見ることも、持ち上げることも、上から見下ろすこともできます。

❓ **考えてみよう**：友達に「青い箱の左に赤い球がある」と説明するとき、2 次元の写真と 3 次元のシーン、どちらが誤解されにくいでしょうか。なぜでしょう。

### 1.3 なぜ「軽量な 3 版構成」なのか

Blender や Maya といった従来の 3D ソフトは強力ですが、インストールファイルが数百 MB もあり、画面もぎっしり詰まっています。本ツールは中核機能だけを軽量エンジンにまとめ、3 つの版として提供します。

- 🖥️📱 **Web 版**：URL を開けばすぐ使え、閉じれば終わり、ディスクを圧迫しない；
- 💻 **PC 版**：一度入れれば以降は**完全オフライン**。ドラッグ＆ドロップやプラグインも使える；
- 🤖 **Android 版**：スマホに入れて、通勤中でもモデリング。

3 つに共通する利点：

- すべての計算はあなたの端末ローカルで完結し、**いかなるデータもアップロードしません**；
- 出力は一般的な JSON ファイルと PNG 画像で、保存と共有が簡単；
- **プロジェクトファイルは 3 版共通**——スマホで書き出した `.json` を PC 版で開いて続きを編集できます。

💡 ここが重要：**同じ作品を端末間でリレーできます**。スマホで下書きし、帰宅後に PC 版で仕上げる、といった使い方が可能です。

✏️ **やってみよう**：自分の形態を確認し（第 0 章）、ツールを開いて、中央のキャンバスと周囲のパネルが見えることを確認しましょう。まだ操作しなくていいので、ただ「環境に馴染む」だけで OK です。

## 第 4 章 座標系：画面上の X / Y / Z という 3 本の線

これは本書で最も重要な章です。多くの 3D ソフトが「座標軸が読めない」ところで挫折します。ゆっくりいきましょう。

### 4.1 まず「数学の座標軸」の荷物を降ろす

数学の授業で 3 本の軸を見て「右手の法則」を暗記したかもしれません。まずそれを忘れてください。本ツールでは、**座標軸とは色と文字ラベルが付いた 3 本の矢印**です。「この物は空間のどの位置にあって、どちらを向いているか」という問いに答えるためのものです。

### 4.2 画面上で実際に見るラベル

「座標軸」表示をオンにします（上部バーの 📐 ボタン）。3 本の矢印が見え、先端に **X・Y・Z** と書かれ、それぞれ色が違います。

> ⚠️ **重要**：本書および本ツールの**画面に書かれている X/Y/Z は「web 上のラベル」**であり、ソフトの内部実装で使っている軸と完全には一致しません。一般的な読者は**画面のラベルだけを見れば十分**です。以下の対応が、あなたが画面で本当に見ているものです。

| web ラベル | 矢印の色 | 表す方向 | 身近な例え |
| --- | --- | --- | --- |
| **X** | 🔵 青 | **前後**（奥行き） | あなたが「前に進む / 後ろに下がる」 |
| **Y** | 🔴 赤 | **左右** | あなたが「左へ / 右へ」 |
| **Z** | 🟢 緑 | **上下**（高さ） | あなたが「つま先立ち / しゃがむ」 |

つまり、この web では：**Z 軸が上を向く 1 本（緑）、X が前後（青）、Y が左右（赤）** です。

💡 一言のコツ：**「青＝前後、赤＝左右、緑＝上下（Z が天を突く）。」**

### 4.3 なぜ「高さ」が Z なのか、Y ではなく

多くの 3D ソフトでは高さは Y です。しかし本ツールの**画面ラベル**では高さを Z（緑の 1 本）としています。あなたが勘違いしたのではなく、**この web はそうラベルしている**のです。本書は最初から最後まで「画面ラベル」に従って説明するので、画面の色と文字をしっかり見ていれば迷いません。

❓ **考えてみよう**：もしあなたが設計し直すとしたら、「高さ」をどの文字にしますか。文字そのものはただの名前です。大切なのは「名前と色と方向」の 3 つが一致することです。

### 4.4 地面と「高さ = 0」

ステージの底には**グリッド地面**があります。地面は「高さがゼロ」の基準です。何かを地面に置くと、その Z（高さ）は 0 になります。持ち上げると Z が大きくなります。

web ラベルでは、地面は **X（前後）と Y（左右）** が張る水平面で、式では「Z = 0」と書きます。式を覚える必要はなく、ただ **地面は「足の踏み場」、上（緑軸 Z）へが上昇** と理解してください。

### 4.5 体で 3 本の軸を感じる

立って、3 つの動作をしてください。

- 一歩前へ、一歩後ろへ → あなたは **X（青）** に沿って動く；
- 左へ横へ、右へ横へ → あなたは **Y（赤）** に沿って動く；
- つま先立ち、しゃがむ → あなたは **Z（緑）** に沿って動く。

これを筋肉に刻めば、以降のすべての「オブジェクト移動」操作に基準ができます。

✏️ **やってみよう**：座標軸を表示し、「上面図」と「正面図」を切り替えて（下部バーボタン）、3 本の矢印の向きが体の感覚と一致するか観察しましょう。上面図では X–Y 平面が見え、正面図では X–Z 平面が見えます。

## 第 5 章 さっそく作る：あなたの最初の 3D 作品

見るだけでは駄目です。この章では、本当にスクリーンショットを撮ってシェアできる小作品を作ります：**色付きの立方体が地面に立っている** ものです。

### 5.1 ステップ 1：図形を選ぶ

1. 左パネルの「3D 図形」区画を探す（📱🤖 タッチ形態でパネルが畳まれている場合は、端のボタンで開く）；
2. 1 番目の「立方体」（またはお好みの立体）をクリック；
3. 「配置モード」に入りました：
   - 🖥️💻 マウス形態：カーソルがキャンバスに入ると**プレビューが追従**します；
   - 📱🤖 タッチ形態：指には「ホバー」が無いため**追従プレビューはありません**。タップした場所に置かれます。

### 5.2 ステップ 2：置く

中央の地面を**クリック**します（📱🤖 タッチ形態では**1 本指タップ**）。立方体が「パン」とグリッドに落ちます。おめでとう、あなたの最初の 3D オブジェクトの誕生です。

💡 落ちた場所が見えなくても焦らない——次章で「選択」を学べばいつでも動かせます。

### 5.3 ステップ 3：それを選ぶ

左パネルの「選択 / 変換」ツールをクリックし、その立方体を**シングルクリック**します（📱🤖 タッチ形態では**1 本指タップ**）。周りに矢印や枠が現れ、「選択された」ことを示します。このとき右パネルが点灯します。

### 5.4 ステップ 4：色をつける

右パネルの「色」区画で：

- 直接**プリセット色**（例えば明るいオレンジ）をクリックすれば、立方体は即座に変色；
- より個性的にしたければ、カスタム色の「選択ツール（ピッカー）」を使う。

⚠️ **注意**：「無色」を選んだり不透明度を 0.1 にしたりすると、物体は透明になり「見えなく」なりますが、消えたわけではありません。元に戻せば OK です。

### 5.5 ステップ 5：少し動かし、回す

選択を維持し、矢印をドラッグして移動（青＝前後 / 赤＝左右 / 緑＝上昇）、リングをドラッグして回転。第 4 章で学んだ 3 本の軸を感じましょう。

### 5.6 ステップ 6：成果を保存

上部バーの「スクリーンショット」（または `Ctrl+P`）で PNG を得ます。あるいは「エクスポート」で JSON を残し、次回「インポート」で続きを編集できます。

✏️ **やってみよう**：以上の手順を繰り返し、「青い立方体が赤い球の左にある」小シーンを作り、スクリーンショットで保存しましょう。あなたは体の動作（前/後・左/右・上/下）で各物体の位置を友達に説明できますか。

## 第 6 章 保存と共有：スクリーンショット・エクスポート・バックアップ

作ったものはもちろん残して、見せたいものです。この章では 4 つの「保存」方法とその使い分けを説明します。

### 6.1 なぜ「こまめな保存」が良い習慣か

ページを閉じたり更新したり、戻るキーを誤って押したりすると、エクスポートしていないシーンは消えてしまいます。「一段落したら JSON をエクスポート」の習慣をつければ、何度も救われます。

💻 **PC 版は例外**：**自動保存とクラッシュ復元**があり、不意に終了しても再起動時に前回の続きを復元できます。ただしこれは保険であり、**意識的なエクスポートの代わりにはなりません**。

### 6.2 スクリーンショット：作品の写真を撮る（Ctrl + P）

「スクリーンショット」は現在の画面を **PNG 画像** として保存します。

- 向いている：SNS への投稿・挿絵・他人に「見た目」を見せる；
- 提案：スクリーンショット前に上部バーで**座標軸・グリッド面を非表示**にすると画面がきれい；
- 出力サイズは現在のキャンバスのピクセル通り。

**画像はどこに保存される？ 形態ごとに異なります：**

| 形態 | 保存のされ方 |
| --- | --- |
| 🖥️📱 Web 版 | ブラウザの**ダウンロード**として「ダウンロード」フォルダへ（スマホのブラウザでは「画像を保存」の確認が出ることも） |
| 💻 PC 版 | **システムの保存ダイアログ**が開き、フォルダとファイル名を自分で指定できる |
| 🤖 Android 版 | アプリのストレージに保存され、**システムの共有**シートから他アプリへ直接送信可能 |

💡 スクリーンショットは「見た目」だけを保存し、再編集可能なデータは含みません。後で編集したいなら、以下の「エクスポート」を使ってください。

### 6.3 シーンのエクスポート：編集可能な「プロジェクト」を残す（Ctrl + S）

「エクスポート」は **JSON ファイル** を生成します。各オブジェクトの位置・色・パラメータ……が記録されており、次回「インポート」すればそのまま復元されます。

- 向いている：未完成品・磨きをかけたい作品；
- ファイル名は通常タイムスタンプ付きなので、意味のある名前（例：`house_v1.json`）に変えることを提案。

保存のされ方はスクリーンショットと同じです：🖥️📱 Web 版はブラウザのダウンロード；💻 PC 版はシステムの保存ダイアログ（フォルダを選択可）；🤖 Android 版はアプリのストレージに保存して共有可能。

> ✅ **重要**：この `.json` は**3 版共通**です。スマホで書き出したプロジェクトを PC 版でインポートして編集を続けられますし、その逆も可能です。

### 6.4 インポート：プロジェクトを読み戻す（Ctrl + O）

以前エクスポートした `.json` を選ぶとシーンが再構築されます。⚠️ インポートは**現在のシーンを置き換え**ます。手元の作業は先に保存してください。

形態ごとのファイルの選び方：

- 🖥️📱 **Web 版**：「インポート」をクリックし、ブラウザのファイル選択画面から選ぶ；
- 💻 **PC 版**：「インポート」のほか、**`.json` をウィンドウに直接ドラッグ**しても開けます。メニューには「最近開いたファイル」もあり、ワンクリックで再開；
- 🤖 **Android 版**：「インポート」をタップし、システムのファイル選択画面で `.json` を探します。

### 6.5 新規：最初から（Ctrl + N）

「新規」はシーン全体をクリアします。危険な操作ですが、「先にエクスポートでバックアップ」しておけば安全です。

### 6.6 🤖 Android 版だけ：戻るキーで作業が無駄にならない

Android 版で戻るキーを押してアプリを終了しようとすると、確認ダイアログに 3 つの選択肢が出ます：

- **保存して終了**：現在のシーンをエクスポートしてから終了（推奨）；
- **保存せず終了**：慎重に；
- **キャンセル**：編集を続ける。

💡 Android で戻るキーを誤って押しても怖くありません——ただし節目ごとのエクスポートの習慣はやはりおすすめします。

### 6.7 頼れるバックアップのリズム

> 手を付ける前に一度エクスポート → 重要な節目でさらにエクスポート（別ファイル名で）→ いつでも取り消しで戻る。
> （🖥️💻 マウス形態は `Ctrl+Z`；📱🤖 タッチ形態は上部バーの「取り消し」ボタン。）

✏️ **やってみよう**：第 5 章で作った「赤い立方体と青い球」シーンを、「スクリーンショット」と「エクスポート」でそれぞれ 1 つずつ保存し、さらに「インポート」で読み戻して内容が一致するか確認しましょう。
応用：スマホと PC の両方がある人は、**片方でエクスポートし、もう片方でインポート**してみて、プロジェクトファイルが 3 版共通であることを体感してみてください。

## 第 7 章 オブジェクトを選ぶ技術：単一選択・複数選択・囲み選択

3 次元の世界では、**「先に選んで、それから操作する」**が鉄則です。この章では「選ぶ」という小さな動作をとことん解説します。

### 7.1 なぜまず選ばなければならないか

右パネルのパラメータや変換矢印は、すべて「現在選択しているオブジェクト」を対象にします。選んでいないと、ツールは「誰を変更したいのか」が分かりません。これは、クラス全員に「名前が 1 つだけ書かれた賞状」を同時に配れないのと同じ——まずは点呼（名前を呼ぶ）が必要なのです。

### 7.2 単一選択：一度タップ

「選択 / 変換」ツールで、オブジェクトをタップします。それがハイライトしてコントロールが現れ、「選ばれた」ことを示します。

- 🖥️💻 **マウス形態**：**左クリック**；
- 📱🤖 **タッチ形態**：**1 本指タップ**（タップして離す。ドラッグしない）。

### 7.3 複数選択：2 つ目、3 つ目を追加する

| 形態 | 複数選択の方法 |
| --- | --- |
| 🖥️💻 Web·マウス／PC | `Shift` を押しながら他のオブジェクトをクリックで**加算**選択。選択済みをもう一度クリックすると**解除** |
| 📱🤖 Web·タッチ／Android | `Shift` キーが無いので、下部バーの「**ボックス選択**」で囲むか、「**すべて選択**」で一括選択 |

💡 複数選択してから変換すると、すべてのオブジェクトが 1 つの塊として一緒に動き、基準はそれらの「グループの中心」になります。

### 7.4 囲み選択：矩形をドラッグ

「一度にまとめてつかまえたい」ときに便利ですが、両形態で始め方がまったく異なります。ここは最も混同しやすい箇所です：

**🖥️💻 マウス形態（Web·マウス／PC）**

**空白の場所で左ボタンを押したまま矩形をドラッグ**すると、枠内のオブジェクトがすべて選択されます。モード切替は不要で、いつでも使えます。

⚠️ 囲み選択は「空白」から手を付けます。オブジェクトの上から手を付けてドラッグすると、**そのオブジェクトを動かす**動作になります。

**📱🤖 タッチ形態（Web·タッチ／Android）**

指でのドラッグは既定で「視点回転」なので、先に「今は範囲選択をしたい」と伝える必要があります：

1. 下部バーの「**ボックス選択**」ボタンをタップ。ボタンが青くなれば範囲選択モードです；
2. **1 本指で矩形をドラッグ**して、選びたいオブジェクトを囲みます；
3. 指を離すと選択完了——**このとき範囲選択モードは自動的に解除**され、ボタンの色が戻ります。

⚠️ **重要**：タッチ形態の範囲選択は**1 回限り**です。続けてもう一度囲むには、**再度「ボックス選択」ボタンをタップ**してください。視点を回したいときの誤操作を防ぐためです。

### 7.5 全選択

シーン内のすべてのオブジェクトを一括選択します。「全削除」や全体変換と組み合わせると便利です。

- 🖥️💻 **マウス形態**：`Ctrl + A` を押す；
- 📱🤖 **タッチ形態**：下部バーの「**すべて選択**」ボタンをタップ。

### 7.6 選択の解除

- **4 形態共通**：キャンバスの空白をタップ；
- 🖥️💻 **マウス形態はさらに**：`Esc` を押す。

### 7.7 選択できない？まずこれを確認

1. まだ「配置モード」にいないか。先に「選択 / 変換」ツールに戻る；
2. 選びたい物体が別の物体に隠されていないか。視点（下部バー）を変えて正面から回り込む；
3. 透明になっていないか（不透明度 0）。先に戻す；
4. 2D 筆跡ではないか。一部のペンオブジェクトは消しゴムや専用ロジックが必要で、普通のクリックでは選べない場合がある。

❓ **考えてみよう**：複数選択と囲み選択、どちらが「隣り合わない 3 つを正確に選ぶ」に向き、どちらが「1 列まるごと選ぶ」に向く？

✏️ **やってみよう**：5 つの異なる図形を置き、①そのうち 1 つを単一選択 ②Shift で 3 つまで加選 ③まとめて囲み選択 ④Ctrl+A で全選択 ⑤Esc で解除、を練習しましょう。

## 第 8 章 変換 3 点セット：移動・回転・スケール

「変換」は 3 次元制作で最も頻繁な動作です。本質は 3 つ：**位置を動かす、向きを回す、大きさを変える**。

### 8.1 3 つの変換とは

| 変換 | 身近な例え | 画面のコントロール |
| --- | --- | --- |
| 移動（平移） | コップを机の左から右へ運ぶ | 3 本の色付き矢印 |
| 回転 | コップの口をあなたに向ける | 円/弧のハンドル |
| スケール | コップを大きく/小さく | 四角いハンドル |

### 8.2 移動：3 本の軸に沿ってドラッグ

オブジェクトを選ぶと、赤・緑・青（web ラベルでは Y 赤＝左右、Z 緑＝高さ、X 青＝前後）の矢印が現れます。

- **赤い矢印**をドラッグ → Y（左右）に移動；
- **緑の矢印**をドラッグ → Z（高さ）に上昇/下降；
- **青い矢印**をドラッグ → X（前後）に移動。

💡 1 本の矢印だけをドラッグすれば、その 1 方向にしか動かず、それ以外には流されません。斜めに自由に動かしたいときは、矢印の間の「平面ブロック」をドラッグします。

### 8.3 回転：軸を中心に回す

「回転」モードに切り替えると、オブジェクトがリングに囲まれます。

- リングをドラッグ → 対応する軸の周りを回転。例えば「正面」を前から左に向けるのは、Z（高さ・緑軸）の周りを回すこと。

⚠️ **注意**：回転は「どの軸の周りか」です。コツを覚えましょう。緑軸（Z）の周り＝その場で方向転換；青軸（X・前後）の周り＝うなずくように；赤軸（Y・左右）の周り＝首をかしげるように。

### 8.4 スケール：大きさを変える

「スケール」に切り替えてハンドルをドラッグし拡大縮小。既定は**均等**（ロックについては第 9 章で後述）。

### 8.5 正確にしたい？右の数値を使う

ドラッグは感覚任せ、パラメータは入力任せ。右パネルには各変換に数値枠があります。

- 位置：X / Y / Z の 3 数（web ラベル下では前後 / 左右 / 高さ）；
- 回転：3 つの角度；
- スケール：倍率。

💡 「ぴったり揃えた」レイアウトを作るときは、同じ数値を入力する方が、目分量のドラッグよりずっと正確です。

✏️ **やってみよう**：立方体を置き、まず矢印をドラッグして右上方へ移動。次に右の数値枠で X・Y・Z を整数（例：2, 0, 3）に変え、正確な落点を観察しましょう。

## 第 9 章 変換モードと均等スケールロック

前章は動作を、本章は「モードの切り替え方」と「比率のロック」を説明します。

### 9.1 3 モードの切り替え場所

右パネル下部（オブジェクト選択後）に「移動 / 回転 / スケール」の 3 ボタンがあり、ショートカットでも切り替え可能（効率篇で詳述）。切り替えると、オブジェクトのコントロールが対応する見た目になります。

### 9.2 均等スケールロックとは

スケール時に「均等スケールロック」スイッチがあります。

- **オン**：どの方向でも同期して拡大縮小し、形は**変形しません**（球は球のまま、箱は箱のまま）；
- **オフ**：**単軸ストレッチ**可。例えば球を潰して楕円に、箱を伸ばして棒に。

⚠️ **注意**：均等スケール欄は「単一選択かつ均等スケールオン」のときだけ表示されます。複数選択時は無効（変換コントロールで全体スケール）。

### 9.3 いつロックを外すか

「潰したワッシャ」「伸ばした柱」「平らな楕円レンズ」を作るときは、ロックを外して単軸ドラッグ。これが「標準体」から「個性体」へ進む鍵です。

❓ **考えてみよう**：なぜ「潰した球」と「標準の球」は 3 次元で異なる視覚言語なのでしょう。それぞれ何を表すのに向いていますか。

✏️ **やってみよう**：球体を置き、均等ロックを外し、Z（高さ・緑軸）だけを 0.3 まで潰すと「UFO / 平らな円盤」ができます。単軸スケールを体感しましょう。

## 第 10 章 取り消しと履歴：失敗を恐れず試せる底力

初心者最大の心理的壁は「間違えるのが怖い」ことです。この章で安心感をお渡しします。

### 10.1 取り消しとやり直し

- `Ctrl + Z`：1 ステップ取り消し；
- `Ctrl + Y`（または `Ctrl + Shift + Z`）：やり直し。

連続で何ステップも戻れ、また前に redo もできます。

### 10.2 「履歴スタック」とは

ソフト内部には**操作リスト**（ブラウザの戻る履歴のようなもの）が記録されています。重要な操作をするたびに 1 件プッシュされ、取り消しは最後の 1 件をポップします。

⚠️ **注意**：履歴には**ステップ数の上限**があります。古い操作はリストから「追い出され」、戻れなくなることがあります——だから重要な節目では JSON バックアップをエクスポートしてください（第 6 章）。

### 10.3 何が履歴に入り、何が入らないか

- **履歴に入る**：オブジェクトの増減・色変更・変換・テクスチャなど「作品内容への変更」；
- **履歴に入らない**：単なる視点回転や観察用ズーム（これらは「見方」であり、作品そのものを変えない）。

だから安心してぐるぐる回して観察しても、視点の変動が山のように取り消しステップに記録される心配はありません。

### 10.4 失敗を恐れず試す心構え

> すべての操作が取り消し可能 ＋ 重要な節目にバックアップ ＝ 本当の「やらかし」はない。

この言葉を心に貼れば、怖がらずにあちこちクリックできるようになります。

✏️ **やってみよう**：5 つの異なる操作（オブジェクト追加・色変更・移動・スケール・1 つ削除）を連続で行い、その後 `Ctrl+Z` を連打して一歩ずつ巻き戻し、さらに `Ctrl+Y` で再生し、「タイムマシン」を体感しましょう。

# 第 3 篇 図形の宇宙篇

3 次元制作とは結局、「正しい位置に、正しい形状を置く」ことです。本篇ではまず全 **40 種の図形** をすべて広げて見せ、その上で 3D と 2D の根本的な違いを説明します。

## 第 11 章 3D 図形総覧（20 種をどう分類するか）

### 11.1 「3D 図形」とは

3D 図形には**体積**があります——光で陰影がつき、後ろの物を遮り、ぐるりと見回せます。本ツールは立方体から奇妙なトーラス・ノットまで 20 種の立体形状を提供します。

### 11.2 20 種のリスト早見

| 番号 | キー名 | 日本語名 | 一目でわかる特徴 |
| --- | --- | --- | --- |
| 1 | box | 立方体 | 6 面が真四角 |
| 2 | sphere | 球体 | 丸く膨らむ |
| 3 | cylinder | 円柱 | 上下が円、筒がまっすぐ |
| 4 | cone | 円錐 | 尖った頂、円い底 |
| 5 | torus | トーラス | ドーナツ |
| 6 | knot | 結び目 | 編み紐の輪 |
| 7 | icosa | 正二十面体 | 20 の三角面 |
| 8 | octa | 正八面体 | 上下が尖り、中央が膨らむ |
| 9 | dodeca | 正十二面体 | 12 の五角面 |
| 10 | capsule | カプセル体 | 丸い頭の柱 |
| 11 | pyramid | 正四角錐 | 四角い底に尖った頂 |
| 12 | prism | 三角柱 | 三角の柱 |
| 13 | tube | 曲線管 | 曲がったパイプ |
| 14 | lathe | 回転体 | 花瓶/コマ状 |
| 15 | tetra | 四面体 | 4 面のピラミッド |
| 16 | barrel | 樽 | 少し膨らむ円柱 |
| 17 | dome | 半球（ドーム） | 半分の卵/丸い屋根 |
| 18 | helix | 螺旋環 | 3/4 回転させた輪 |
| 19 | octaPrism | 八角柱 | 8 辺のまっすぐな柱 |
| 20 | star3d | 立体五角星 | 厚みのある星 |

### 11.3 3 つの分類法（20 種から素早く探す）

- **日常での馴染み度で**：箱(box)・球(sphere)・円柱(cylinder)・円錐(cone) は生活物に最も似ており、初心者におすすめ；
- **「幾何感」の強弱で**：プラトン立体（icosa/octa/dodeca/tetra）はとても「数学的」；knot/helix/tube はとても「流動的」；
- **用途で**：建築には box/cylinder/prism/pyramid/dome；装飾には torus/star3d/heart（2D）/lightning（2D）；有機的な造形には sphere/capsule/lathe/barrel。

### 11.4 最初に何を選ぶか

どれにするか迷ったら、まず **box** で感覚を練り、**sphere** で「曲面の陰影」を体感し、最後に **torus** で「中を突き抜けられる」立体の面白さを味わってください。

❓ **考えてみよう**：立方体・球・円錐、どれが「最も少ない材料で最も多く入る」でしょう。これは実は本当の世界の問題です（コンテナや貯槽はこれに基づいて設計されています）。

### 12.1 2D とは

2D 図形は**厚みがなく**、切り絵のように**地面に平らに寝て**います（XY 平面、Z=0）。記号・目印・装飾文様に向いています。

### 12.2 20 種を一つずつ紹介

| triangle | 三角形 | 警告、山の頂 |
| star | 星形 | 評価、装飾 |
| hexagon | 六角形 | ハチの巣、ナット、テクノロジー感 |
| heart | ハート | 愛、いいね |
| pentagon | 五角形 | 家の平面、バッジ |

| ellipse | 楕円 | レンズ、軌道 |
| parallelogram | 平行四辺形 | 斜め引っ張り、透視ブロック |
| trapezoid | 台形 | 台体、屋根の側面 |
| diamond | 菱形 | ダイヤ、指し示し |
| rightTri | 直角三角形 | スロープ、直角マーク |

| crescent | 三日月 | 月、鉤 |

💡 このうち **heart / arrow / crescent / cross / lightning** の 2D 図形は**独立した形状パラメータを持ちません**（fields が空）。大きさを変えるには全体スケールか変換コントロールしか使えません。

### 12.3 「シール思考」

2D は地面に貼ったシールのように考えてください。いつも「ぺたん」と寝ていて、立ち上がることはありません。利点——上面図ではそれははっきりした記号図になり、テクスチャと色を組み合わせれば、地面の案内線・会社のロゴ地貼り・チェック柄などが作れます。

### 12.4 隠れに注意

2D は地面に貼っているので、3D 物体が上から押さえると隠れます。ある角度からは薄い 2D が「線」に消えて見えなくなります。目立たせたいときは、少し持ち上げる（Z 緑軸方向）か、開けた場所に置きます。

✏️ **やってみよう**：square2・heart・arrow・star をそれぞれ 1 つ置き、「上面図」で最もはっきり見える姿を見てください。次に「透視図」で、彼らがどう「寝ている」かを見ましょう。

## 第 13 章 各 3D 図形のパラメータ詳解（上）：基本形体

> この節では最もよく使う 10 種の立体を一つずつ説明します。すべて「外観 / 例え / 用途 / ヒント」の 4 段で、直感を作りやすくします。

### 13.1 立方体 box
- **外観**：縦横高さが等しい 6 面体。
- **例え**：宅配ダンボール、サイコロ、レンガ。
- **用途**：建築の壁、土台、あらゆる「四角い」もの。
- **ヒント**：最も安定する「土台」形状。低い壁を作りたければ Z（緑/高さ）方向に潰す（均等ロックを外す）。

### 13.2 球体 sphere
- **外観**：完璧な丸い球。
- **例え**：バスケットボール、星、バブル。
- **用途**：頭部、天体、装飾球。
- **ヒント**：球面にテクスチャ/画像を貼ると最も「広げやすく」、アイコン付きの球に向いています。

### 13.3 円柱 cylinder
- **外観**：上下が等しい円、側面がまっすぐ。
- **例え**：缶、柱、蝋燭。
- **用途**：梁柱、筒身、塔身。
- **ヒント**：上面半径を小さく（パラメータかスケール使用）すると「上狭下広」の擂鉢（すりばち）感が出ます。

### 13.4 円錐 cone
- **外観**：円い底、尖った頂。
- **例え**：アイスクリームコーン、誘導コーン、テントの頂。
- **用途**：尖った屋根、表示灯、クリスマスツリーの各層。
- **ヒント**：複数の cone を積み重ねて縮めれば「層状の塔」が組めます。

### 13.5 トーラス torus
- **外観**：ドーナツ、真ん中に穴。
- **例え**：フラフープ、タイヤ、指輪。
- **用途**：輪の装飾、パイプのエルボ、光輪。
- **ヒント**：穴に「突き抜けられる」のは、本当の立体かを確かめる良い例です。

### 13.6 環面結び目 knot
- **外観**：三つ編みのように巻いた輪。
- **例え**：ロープの結び目、エネルギー記号。
- **用途**：テクノロジー感の装飾、ロゴの主体。
- **ヒント**：造形が複雑なので、単色かシンプルなテクスチャにし、テクスチャの乱れを避けてください。

### 13.7 正二十面体 icosa
- **外観**：20 の正三角形で組んだ、球に近い多面体。
- **例え**：サッカーボール（古典的 32 面版の親戚）、鉱石の結晶。
- **用途**：宝石、サイコロ、ローポリ風の球。
- **ヒント**：「ローポリゴン（low-poly）」美学の代表。純色と合わせると非常に高見えします。

### 13.8 正八面体 octa
- **外観**：上下 2 つの尖り、中央が 8 面に膨らむ。
- **例え**：ダイヤモンドカット、双円錐。
- **用途**：水晶、宝石、抽象彫刻。
- **ヒント**：回転させると光と影の変化が豊かで、「焦点の装飾」に向いています。

### 13.9 正十二面体 dodeca
- **外観**：12 の正五角面を持つ球感の多面体。
- **例え**：魔法石、サイコロ（D12）。
- **用途**：神秘的な記号、置物。
- **ヒント**：面数が多いので、テクスチャを貼ると各面に 1 枚ずつ表示されます。複雑なテクスチャは控えめに。

### 13.10 カプセル体 capsule
- **外観**：円柱の両端に半球。
- **例え**：カプセル薬、トラック、ボウリングのピン。
- **用途**：人体胴体の簡略化、ホース、丸みのある柱。
- **ヒント**：純粋な円柱より「柔らか」で、キャラクターや生物を作るときによく使います。

✏️ **やってみよう**：box + cylinder + cone で「街灯」を組んでみましょう。円柱で竿、box で灯具、cone で頂カバー。基本形体の組み合わせの力を体感してください。

## 第 14 章 各 3D 図形のパラメータ詳解（下）：特殊形状

### 14.1 正四角錐 pyramid
- **外観**：正方形の底面 + 1 つの尖った頂。
- **例え**：エジプトのピラミッド、屋根。
- **用途**：塔、尖った屋根の建築、記念碑。
- **ヒント**：cone と違い、「斜面」は平らな 4 つの三角で、より「人造建築」の感じがします。

### 14.2 三角柱 prism
- **外観**：三角形断面のまっすぐな柱。
- **例え**：三稜鏡、路上の障害物、屋根の梁。
- **用途**：三角梁、くさび、テクノロジー構件。
- **ヒント**：横向きに置けば「スロープブロック」になり、他の体と組み合わせて斜面を作れます。

### 14.3 曲線管 tube
- **外観**：曲がった経路に沿って走る丸い管。
- **例え**：曲がったストロー、水管、リボン。
- **用途**：流れる線、パイプ、装飾のリボン。
- **ヒント**：造形は内部曲線で決まり、現在は 1 つの S 字。、「動き」の要素に向いています。

### 14.4 回転体 lathe
- **外観**：輪郭を中心軸の周りに回して生まれる体（花瓶/コマ状）。
- **例え**：花瓶、電球、コマ、ワイングラス。
- **用途**：対称な容器、器、彫刻。
- **ヒント**：この種の形状は生まれながらに「対称の美」があり、単色か縦方向のグラデーションテクスチャが最も映えます。

### 14.5 四面体 tetra
- **外観**：4 つの三角面を持つ最小の多面体。
- **例え**：三角錐、結晶の欠片。
- **用途**：小石、ローポリ装飾、鋭い記号。
- **ヒント**：面が少なく稜が硬いので、「ハード/テクノロジー」風に最適です。

### 14.6 樽 barrel
- **外観**：中央が少し膨らむ円柱（わずかなテーパ付き）。
- **例え**：木樽、酒樽、ロケットの中段。
- **用途**：容器、機体、貯水槽。
- **ヒント**：まっすぐな円柱より「肚（はら）」があり、生物や容器をより生き生きさせます。

### 14.7 半球 dome
- **外観**：半球（上半）。
- **例え**：ゲル（パオ）の天井、天文台、鐘形のカバー。
- **用途**：屋根、カバー、プラネタリウム。
- **ヒント**：box と組めば「屋根付きの小屋」に；ひっくり返せば（回転）「碗」になります。

### 14.8 螺旋環 helix
- **外観**：約 3/4 回転させた輪（torus の 1 区間）。
- **例え**：バネの区間、渦、DNA の断片。
- **用途**：動的な装飾、渦の記号、エネルギー輪。
- **ヒント**：造形に「未完成感」が強く、「回転/流動」を表すのに向いています。

### 14.9 八角柱 octaPrism
- **外観**：8 つの縦辺を持つまっすぐな柱。
- **例え**：八角形の立柱、灯台、縦穴の壁。
- **用途**：整った立柱、塔身、基座。
- **ヒント**：円柱より「角があり」、box より「丸みがあり」、折衷感が良いです。

### 14.10 立体五角星 star3d
- **外観**：五角星を厚みのある立体に押し出したもの。
- **例え**：メダル、星のチャーム、勲章。
- **用途**：褒賞記号、装飾の主体、ロゴ。
- **ヒント**：厚みがあるから「立つ」し、2D の star よりずっしりします。

❓ **考えてみよう**：3D 図形を 4 つ以下で「ロボット」を組むとしたら、どの 4 つを選びますか。それぞれ何の部位になりますか。

## 第 15 章 「立つ」と「寝る」：3D と 2D の本質的な違い

### 15.1 体積 vs 面積

- **3D は体積を持つ**：空間を占め、影を落とし、互いに隠し合う。地面に「立ち」、高さ（Z 緑軸）がある。
- **2D は面積だけ**：一枚に平らに広がり、厚みはゼロ。地面に「寝て」いる（Z=0）。

これを理解すれば、なぜ 3D は「おしくらまんじゅう」ができ、2D は「床を敷く」しかできないかがわかります。

### 15.2 なぜ一方は立ち、一方は寝るか

コード上、3D は `seatOnGround` で底面を y=0（web ラベル Z=0）に落とし、2D は `shape2D` で XZ 平面（地面）に回転して貼り付けます。だから：

- box を置けば、自然に地面に「座る」；
- heart を置けば、自然に地面に「貼る」。

### 15.3 混用のコツ

- 2D を「立たせたい」？それを赤軸（Y）の周りに 90° 回転させれば、「寝る」から「立つ」に——立て札や看板にできます；
- 3D を「寝かせたい」？回転で横倒しにし、「倒れた木」「もたれかかる板」に；
- 地面記号（矢印で道案内）+ 立体建築は、シーンで最も一般的な組み合わせです。

✏️ **やってみよう**：arrow（2D）を置き、選択して Y（赤/左右）の周りに 90° 回転させ、それが「寝た矢印」から「立った案内板」に変わるのを観察しましょう。これが「立つと寝る」の自由な切り替えです。

# 第 4 篇 色とマテリアル篇

色は作品の「感情」です。この章は「光とは何か」から始め、27 種のプリセット、カスタム取色、12 種のテクスチャへと進み、最後に画像テクスチャと不透明度を説明します。

## 第 16 章 色入門：人間の目と光のゲーム

### 16.1 色は物体が「元々持っている」ものではない

暗闇の中の赤いりんごは黒です——あなたが赤を見えるのは、光が当たり「反射」して目に入るからです。つまり **色 = 物体 + 光**。本ツールは `MeshStandardMaterial`（受光マテリアル）を用い、シーンに環境光（強度 1.0）と指向性光（強度 2.6）があり、物体に陰影が生まれます。

💡 だからこそ同じ色でも、光の当たらない面は「暗く」なるのです——色が変わったのではなく、光が減ったのです。

### 16.2 RGB：画面は三原色の混合

ディスプレイは **赤(R)・緑(G)・青(B)** の 3 つの光を混ぜてすべての色を作ります。本ツールのプリセット色の `0xff0000` は「満赤、緑青なし = 純赤」を意味します。

### 16.3 HSV：人間の脳が色を選ぶ直感

RGB よりも、人は **色相(H、どんな色か)・彩度(S、派手か)・明度(V、明るいか)** で選ぶ方が馴染みがあります。取色器をドラッグするとき、実は HSV を調整しています。

- 色相 = 赤橙黄緑青藍紫を一周；
- 彩度が低い → 灰がかる；高い → 鮮やか；
- 明度が低い → 暗い；高い → 明るい（白っぽくさえなる）。

### 16.4 マテリアルの 2 つの隠れたパラメータ

物体表面には `roughness`（粗さ/0.6、大きいほどつや消し）と `metalness`（金属感/0.0、大きいほど金属らしい）があります。現在の既定は「つや消しのプラスチック」寄りです。あなたが変えるのは色で、この 2 つは通常そのままですが、彼らが存在することを知っていれば、「なぜ鏡面反射しないのか」が理解できます。

### 16.5 不透明度：光を通す

色の他に「透けるか」もあります。詳しくは後半の第 20 章で述べますが、ここでは覚えておいてください。不透明度 1 = 中身が詰まる、0 = 不可視。

❓ **考えてみよう**：なぜ病院の壁や手術着は「低彩度の浅い青/浅い緑」が多いのでしょう。色の彩度の高低は、どう人間の感情に影響するか。

✏️ **やってみよう**：白い球を置き、色々な視点に切り替え、光の当たらない面が暗くなるか観察しましょう。これが「光が色を作る」の直感的な証拠です。

## 第 18 章 カスタム色：HEX・HSV とスクリーンカラーピッカー

### 18.1 HEX とは

HEX は `#` の後に 6 桁の 16 進数が続き、2 桁ずつ R・G・B を表します。例えばブランドカラー `#1e90ff`（ドッジブルー）。特定の色を正確に再現したいときは、HEX を直接入力するのが最も確実です。

### 18.2 取色器のドラッグの仕方

右パネルの「選択ツール（ピッカー）」ボタンを開くと、取色ウィンドウが出てきます。中身は「大きな色ブロック + 色相バー + HEX/RGB 入力枠」です。

- 大きな色ブロック内でクリック/ドラッグ → **彩度 + 明度** を選ぶ（左右が濃淡、上下が明暗）；
- 下の**色相バー**をドラッグ → **色相** を調整（赤橙黄緑青藍紫を一周）；
- 絶対に正確にしたいなら、HEX または R/G/B 枠に数字を入力するのが最も安定。

💡 「同系色の濃淡」を探すときは、色相バーを**固定したまま**、大きな色ブロック内だけ上下にドラッグ（明度を変える）すると、最も調和の取れた配色になります。

### 18.3 スクリーンカラーピッカー（スポイト）

一部のバージョンでは「画面から色を取る」機能があります。スポイトをクリックし、画面の任意の場所（他の物体の色や背景も含む）をクリックすると、その色が採取されます。「現実から採取した」配色を作るのに極めて便利です。

### 18.4 「無色」（NO_COLOR）とは

ソースコードには `NO_COLOR = -1` という特殊マークがあります。これを選ぶと、物体は**純色の着色を適用しません**（画像テクスチャや特殊マテリアルと組み合わせて「下地なし」の効果を出すことが多い）。

⚠️ **注意**：誤って「無色」を選ぶと物体が「着色されていない/暗い」ように見えますが、壊れたわけではありません。普通の色を選び直せば OK です。

✏️ **やってみよう**：HEX でお好みの色（例：`#ff6b6b`）を入力して立方体に塗り、さらにスポイトでページ内のどこかから色を採取し、両者を比べましょう。

## 第 19 章 12 種のテクスチャ：表面に物語を

純色は平板すぎ、テクスチャが物体に「内容」を与えます。本ツールには **12 種のテクスチャ**（`PATTERNS`）が内蔵されています。

| テクスチャ | 何に似ている / 用途 |
| --- | --- |
| ソリッド | 模様なし、最も clean |
| グリッド子（チェック） | チェス盤、テーブルクロス、タイル |
| ストライプ | シマウマ、警告、布 |
| ドット | 水玉スカート、キャンディ |
| グラデーション | 空、金属の遷移 |
| レンガ | 壁、建築 |
| 斜線 | 速度感、テクノロジー |
| 波形 | 水の波、シルク |
| 点陣 | ピクセル、テクノロジーパネル |
| クロス | 網目布、包帯 |
| メッシュ | 方眼紙、工学 |
| 螺旋 | 渦、螺旋管 |

💡 テクスチャは通常「主色 + 模様色」の 2 層から成り、右パネルで別々に調整でき、千変万化する表面が作れます。

⚠️ **注意**：複雑なテクスチャ（レンガ、メッシュなど）を面数の少ない球に貼ると「伸びて歪む」のは正常です。整った見た目にしたいなら、box/cylinder のように平面の多い体に優先して貼ってください。

✏️ **やってみよう**：box を置き、「レンガ」「格子」「ストライプ」を順に試し、テクスチャがいかに「それが何に見えるか」（壁 vs 布 vs 警告標識）を一瞬で変えるかを体感しましょう。

## 第 20 章 画像テクスチャのアップロードと不透明度・ワイヤーフレーム

### 20.1 画像のアップロード：写真を表面に貼る

プリセットテクスチャ以外に、自分の画像（PNG/JPG）を**表面テクスチャとしてアップロード**できます——会社のロゴ、写真、手描きなど何でも可。貼ると、物体表面にその図が「印刷」されます。

- 向いている：実写写真付きの展示板、ロゴを印刷したメダル、地図を貼った地面；
- ヒント：画像は正方形で、鮮明なものが良く、box の正面に貼ると最もはっきり。

### 20.2 不透明度（opacity）

右パネルで「不透明度」を調整できます。

- 1 = 完全に中身が詰まる；
- 0.1 = ほとんど見えない；
- 中間値 = 半透明（ガラス、ゴースト、水感）。

💡 「ガラスカバー」「氷」「幻影」はすべてこれにかかっています。半透明にすると、後ろの物体が透けて見え、階層感が一瞬で豊かになります。

### 20.3 ワイヤーフレーム

「ワイヤーフレーム」をオンにすると、物体は骨組み線（三角メッシュ）だけになり、実面は見えなくなります。向いているのは：

- 構造を見る（教育、説明）；
- 「ワイヤーフレームテクノロジー風」の装飾を作る；
- 形状が望み通りかを確認する。

### 20.4 コンビネーション

- テクスチャ + 半透明 = かすかなヴェール；
- 画像 + ワイヤーフレーム = インフォグラフィック風；
- 純色 + 高透明 = ガラスブロック。

❓ **考えてみよう**：もし「一片の氷」を表現するなら、色・不透明度・テクスチャをどう組み合わせますか。もし「半透明のレンガ壁」を表現するなら、それはどんな効果のためでしょう。

✏️ **やってみよう**：手元の画像を 1 枚アップロードし、平らな box に貼りましょう。次にその box の不透明度を 0.5 にして「画像が半透明になる」効果を観察。最後にワイヤーフレームをオンにして骨組みを見てみてください。

# 第 5 篇 テキストと画像篇

シーンには形状の他に、情報を伝えるための「文字」と「写真」も必要です。この篇ではテキストと画像という 2 つの「内容型」オブジェクトを説明します。

## 第 21 章 テキストを追加：シーンに話させる

### 21.1 テキストは「話す薄板」

看板、名称、ヒント、標語……文字が 3 次元シーンに意味を持たせます。テキストオブジェクトは本質的に「字を貼った薄い平面」で、普通のオブジェクトと同様に選択・移動・回転・スケール・着色ができます。

### 21.2 3 ステップでテキストを追加

1. 左パネルの「ツール」から「テキストを追加」を選ぶ；
2. 中央の地面をクリックすると、**入力枠**がポップアップ（プレースホルダは「入力テキスト······」）；
3. 文字を入力し、**Enter** で確定、文字が地面に落ちる。

💡 プレースホルダ「入力テキスト······」は単に「ここに打ってください」という注意書きで、内容自体ではありません。最終作品には出てきません。

### 21.3 内容を変える：ダブルクリック

置いた後で字を変えたい？テキストオブジェクトを**ダブルクリック**すれば入力枠が再び出て、変えて Enter するだけ。消して作り直す必要はありません。

### 21.4 テキストも完全なオブジェクト

テキストはすべての通常操作をサポートします。選択、移動（青前後/赤左右/緑上昇）、回転、スケール、色変更、不透明度調整。 「発光文字」「半透明文字」も作れます。

✏️ **やってみよう**：「ようこそ」の 1 行を追加し、シーン入り口へ移動。さらにダブルクリックで「ようこそ」から「いらっしゃいませ」に変え、即時編集の楽さを体感しましょう。

---

## 第 22 章 フォント・文字サイズ・太さ・縦書き横書き

テキストを選ぶと、右パネルにテキスト専用のコントロールが現れます。本ツールは **8 種のフォント** といくつかのレイアウトスイッチを提供します。

### 22.1 8 種のフォントの選び方

| フォント | 雰囲気 / 用途 |
| --- | --- |
| 雅黒（YaHei） | モダン、クリア、中文の既定第一選択 |
| 宋体（SimSun） | フォーマル、書巻気 |
| 楷体（KaiTi） | 手書き感、伝統、扁額 |
| 黒体（SimHei） | 重厚、目を引くタイトル |
| 仿宋（FangSong） | 公用文、繊細 |
| Arial | 西文モダンサンセリフ |
| Times | 西文セリフ、フォーマル |
| Courier | 西文等幅、コード/タイプライター感 |

💡 中文コンテンツは最初の 5 つを優先。純英文は後ろの 3 つで異なる雰囲気を出せます。

### 22.2 文字サイズ（既定 80）

文字サイズの既定は **80** で、右パネルで調整できます。大きすぎるとシーンの比率を「突き破り」、小さすぎると見えません。

⚠️ **注意**：文字サイズはシーン単位に対する相対値なので、図形の大きさと組み合わせる必要があります——1.2 単位の立方体に 500 の字を合わせると、字は物体よりずっと大きくなります。

### 22.3 太さ（太字スイッチ）

ワンクリックで太字にでき、タイトルがより目立ちます。黒体/楷体と組み合わせると「扁額感」が非常に映えます。

### 22.4 横書き / 縦書き

- **横書き**：普通の 1 行、左から右へ；
- **縦書き**：上から下へ並び、中式扁額、書名、標識に向く。

💡 組み合わせ提案：縦書き + 楷体 + 大文字サイズ = 伝統的扁額；横書き + 黒体 + 中文字サイズ = モダン標識。

⚠️ **注意**：テキストが長すぎると薄板の幅を超えることがあるので、文字サイズを適宜小さくするか改行で対応してください。

✏️ **やってみよう**：「茶館」の縦書き扁額（楷体、縦書き、大文字サイズ、木目色）を作り、フォント組み合わせの「性格」を体感しましょう。

## 第 23 章 画像オブジェクト：写真を 3 次元世界へ

### 23.1 画像オブジェクトの追加

左パネルの「ツール」で「画像を追加」→ ローカルの画像ファイルを選ぶ → 地面をクリックすると、画像が**平面スプライス**として現れます（立てられた写真のようなもの）。

### 23.2 普通のオブジェクトのように操作

選択すれば移動・回転・スケールができます。壁にもたせかけ、地面装飾として平らに敷き、持ち上げて看板にすることもできます。

### 23.3 画像も「テクスチャ」にできる

第 20 章で述べたように、画像は任意の 3D オブジェクト表面に「貼り付け」（表面マテリアルとして）できます。だから同じ画像に 2 つの使い方があります。

- **独立したスプライスとして**：シーン内の 1 枚の「写真」として；
- **表面テクスチャとして**：box / cylinder などの物体表面に印刷。

### 23.4 画像 vs 2D 図形

| | 画像オブジェクト | 2D 図形 |
| --- | --- | --- |
| 内容 | あなたの写真 / ロゴ | ソフトが生成する形状 |
| 色変更 | 通常はテクスチャとして全体調整 | 純色 / テクスチャ可変 |
| 典型用途 | 実写写真、本物のロゴ | 記号、目印、装飾 |

両者とも「薄く」、立てられも寝かせられもするので、必要に応じて選びます。

✏️ **やってみよう**：あなたの写真を 1 枚インポートし、シーン内に「平面スプライス」として立てましょう。さらに同じ画像をテクスチャとして box の正面に貼り、2 つの使い方の違いを比べてください。

# 第 6 篇 ペンと消しゴム篇

前 2 篇は「標準形状」、この篇は「手描き」についてです——ペンを使えばシーン内でまるで筆を持つように線を描き、消しゴムでそれらを消せます。

## 第 24 章 2D ペン：地面に線を描く

### 24.1 2D ペンとは

2D ペンは**地面（XZ 平面）** 上に**平面の線**を描き、紙にペンで描くようなものです。地貼り文様、経路、落書き、地面案内の描画に向いています。

### 24.2 使い方

1. 左パネルの「ツール」で「2D ペン」を選ぶ；
2. 中央の地面で**左ボタンを押しながらドラッグ**、離せば 1 画に；
3. 複数の画を連続で描ける。

### 24.3 Shift を押して直線に制約

ドラッグ中に **Shift** を押すと、線は**直線（2 点間）に制約**されます。「まっすぐな道」「きちんとした辺」を描くのに便利です。

> 方向の固定：直線制約に入ると、**この一筆（左ボタンを押したまま描く）が終わるまで、方向は最初に決まった水平 / 垂直 / 45° に固定され**、途中でカーソルがそれても変わりません。方向を変えたいときは、ボタンを離して新しい一筆を始めてください。

### 24.4 ペンの 4 つの属性

右パネル（ペン活性時）で設定できます。

| 属性 | 役割 |
| --- | --- |
| 色 | 線の色 |
| 太さ | 線の幅 |
| 不透明度 | 線が詰まっているか |
| 最小間隔 | サンプル点間の最小距離。小さいほど滑らかで点が密 |

💡 「最小間隔」が小さいほど線は繊細になるが頂点も多く、大きいほど省けるが折れ線感が強くなります。精細な曲線は小さく、ラフなスケッチは大きく調整してください。

### 24.5 ペン vs 2D 図形

- 2D 図形は「標準形状」（円、ハート…）で、色もテクスチャも変えられる；
- 2D ペンは「あなたが手描きした任意の線」、自由だが不規則。

標準記号には図形を、手描きの落書きにはペンを。

✏️ **やってみよう**：2D ペンで地面に「∞」記号を描き、さらに Shift を押してそれを貫く直線を描き、自由線 vs 制約線を体感しましょう。

---

## 第 25 章 3D ペンと参照平面

### 25.1 3D ペンとは

3D ペンは**空間に立体のパイプを描く**——地面に貼るのではなく、空中に浮かぶ「管の線」です。これで「空の中に絵を描く」ことができます。

### 25.2 参照平面：最初の 1 画が「どの層に描くか」を決める

3D ペンの最初のクリックで、半透明の**「参照平面」**が 1 枚決まります。その後のドラッグはこの平面を参照し、線はその近くに落ちます。

💡 **水平な線**を描きたい？まず「上面図」に切り替え、クリックして水平参照面を決めます。**垂直な線**を描きたい？「正面図 / 側面図」に切り替えてから垂直面を決めます。参照面の向きが、あなたが描く「次元」を決めます。

### 25.3 平面上に描画、Ctrl で直線に制約

- 参照平面上でドラッグすれば自由に描画；
- **Ctrl** を押しながらドラッグすると直線に制約（2D ペンの Shift に似ているが、空間パイプに作用）。

> 方向の固定：上と同様、Ctrl で直線に制約すると一画の途中では方向は固定され変化しません。変更するにはボタンを離して新しい一画を始めてください。

### 25.4 球帽キャップ

各画の両端には自動的に**球帽キャップ**が付き、線の始終が丸く切れ目なく、本物のパイプに端キャップを付けたようになります。

### 25.5 用途

- 手軽にリボン、連結線、エネルギービームを彫刻；
- シーンに「動的な線」を描く（標準体を置くより有機的）；
- 抽象芸術、回路の示意。

❓ **考えてみよう**：3D ペンの「参照平面」という概念は、画家が「先に紙を装丁する」のと同じでしょうか。なぜ 3 次元ではこの「仮想の紙」が特に必要なのでしょう。

✏️ **やってみよう**：「上面図」に切り替え、3D ペンで水平参照面を決めて波線を 1 本描きましょう。次に「正面図」に切り替えて別の縦線を描き、空間線の次元の違いを感じてください。

## 第 26 章 消しゴム：全体消去と部分消去

描き間違えたら消せます。本ツールの消しゴムには 2 つのモードがあり、挙動が異なるので必ず見分けてください。

### 26.1 2 つのモードの切り替え場所

右パネルの消しゴム属性に「消しゴムモード」があります：**全体消去 / 部分消去**。

### 26.2 全体消去（既定）

消しゴムの輪をドラッグすると、当たったものを**オブジェクト全体（1 本のペン、1 つの図形まるごと）削除**します。これは「豪快な」掃除です。

💡 1 本の 3D 筆跡や 1 つの図形をさっと消したいなら、全体モードで輪に囲めば即削除。

### 26.3 部分消去

「2D 筆跡の部分消去」をオンにすると：

- **2D 筆跡**：消しゴムの輪と**交差したその 1 区間だけ**を消し、残りは残る（精密な線修正）；
- **その他のオブジェクト**：やはり**最も近い 1 つ**（全体削除）を削除。

⚠️ **注意**：部分モードが「2D 手描き線」に対してのみ区間ごとに消すのに対し、標準図形や 3D 筆跡はやはりオブジェクト全体を削除します。部分モードで「立方体の一角をかじる」ことは期待しないでください。

### 26.4 消しゴムの大きさ

「消しゴムサイズ」スライダーで輪の半径を調整し、細部の精密修正も大範囲の掃除もこれにかかります。輪が小さすぎると何度も消す必要があり、大きすぎると隣を誤削除しやすくなります。

### 26.5 消し間違えても戻る

消しゴムで削除したオブジェクトも、他の操作と同様に履歴に入り——`Ctrl+Z` で戻せます。だから思い切り消してください。

✏️ **やってみよう**：2D ペンで長い曲線を 1 本描き、まず「部分消去」でその中の 1 小区間を消し（残りは残る）、次に「全体消去」で別の筆跡を輪に囲み、それが根ごと削除されるのを見て、2 つのモードを比べましょう。

# 第 7 篇 視点と観察篇

「角度を変えて見る」と、たいていはっきりします。この篇では、観察角度の見方と固定の仕方を説明します。

## 第 27 章 7 つのプリセット視点：角度を変えて世界を見る

### 27.1 なぜ視点を切り替えるか

人間の目は 1 つの角度しか持たず、「前後左右、どちらが高いか」を誤判断しやすいです。ワンクリックで視点を変えるのは、作品の周りを一回りするのと同じです。下部バーには **7 つの視点ボタン** があります。

### 27.2 7 つの視点を一つずつ

| 視点 | あなたは… | 見える主平面（web ラベル） |
| --- | --- | --- |
| 透視図 | 普通に立って見る | 近大遠小、最も自然 |
| 上面図 | 真上から見下ろす | X（青/前後）× Y（赤/左右）平面 |
| 底面図 | 真下から見上げる | 上面図と同じだが裏返し |
| 正面図 | 真正面から平視 | X（青/前後）× Z（緑/高さ）平面 |
| 背面図 | 真後ろから平視 | 正面図と同じだが方向反対 |
| 左面図 | 真左から平視 | Y（赤/左右）× Z（緑/高さ）平面 |
| 右面図 | 真右から平視 | 左面図と同じだが方向反対 |

💡 web ラベルを覚えてください：**X 青＝前後、Y 赤＝左右、Z 緑＝高さ**。上面図で見えるのは「前後 × 左右」（地面）、正面図で見えるのは「前後 × 高さ」（立面）です。

### 27.3 いつどれを使うか

- **透視図**：全体観察、スクリーンショット展示；
- **上面図**：正確な配置、1 列の整列（地面の見下ろし図が最も正確）；
- **正面図 / 左面図 / 右面図**：「まっすぐか」「揃っているか」の確認、対称構図；
- **底面図 / 背面図**：稀だが「裏面/底面」が予期通りかを検証できる。

❓ **考えてみよう**：なぜ建築家は「平面図、立面図、側面図」を描くのでしょう。この 7 つの視点のうち、どれがこの 3 つの工学図に対応しますか。

✏️ **やってみよう**：3 つの異なる図形を置き、上面図・正面図・右面図をそれぞれクリックし、同じシーンが視点によってどう「見え方」が変わるか観察しましょう。

## 第 29 章 なぜショートカットを覚えるか：効率の複利

### 29.1 見くびられがちな一事実

小さな実験をしてください。シーンに立方体を 1 つ置き、マウスで右パネルの「均等スケール」スライダーを往復 10 回引っ張り、次にキーボードの `+` / `-` キーを 10 回押してください。

あなたはほぼ間違いなく気づくはずです：**キーボードの方が速く、正確で、疲れない**。

理由は 3 つあります。

1. **手をキーボードの中核領域から離す必要がない**——目は画面に、指は文字キーの上に。脳は「画面を見る→パネルを探す→マウスを動かす→スライダーを引く」の往復を繰り返さなくて済む。
2. **固定ステップがある**——方向キーを 1 回押すと、物体は正確に「0.1 グリッド」動き、10 回押せばちょうど 1 グリッド。スライダーを 10 回引っ張っても、どれだけ動いたか覚えられません。
3. **重ねられ、取り消しもできる**——各キーボード操作は履歴スタックに入り（第 32 章参照）、間違えたら `Ctrl+Z` で一発戻る。スライダーのドラッグは連続した変化なので、取り消し時に「跳ねる」ことが多い。

💡 **心構え一言**：マウスは「選ぶ」「描く」を、キーボードは「変える」「調整する」を担当。役割分担で効率倍増。

### 29.2 ショートカットにも「場面」がある

本ツールのショートカットは「グローバルで一意」ではなく、**現在オブジェクトが選択されているかどうか**で意味が変わります。

| 現在の状態 | 方向キー / A D W S は何をするか |
|---|---|
| **何も選択していない** | 動くのは**カメラ**（シーンの周りを見ている） |
| **オブジェクトを選択した** | 動くのは**そのオブジェクト**（物体がシーン内で動く/回る） |

同じ `↑` キーでも、何も選んでいない時は「レンズが前に押す」、何かを選んでいる時は「物体が前に進む」。この違いはショートカット体系全体の核心です。まず脳に刻み込み、後で混乱しないようにしてください。

❓ **考えてみよう**：なぜ「選択なし時にカメラを動かす」のは合理的な設計でしょう。——このときあなたはたいてい「角度を探し、全体像を見ている」からです。キーボードで視点を直接平行移動/回転させる方が、空白をドラッグするより正確です（空白のドラッグは連続で、ステップがありません）。

### 29.3 まず「座標軸言語」を復習

本篇の「X / Y / Z 軸に沿って」というすべての表現は、**画面ラベル**に従って覚えます（これは画面で見る軸ラベルと一致します）。

- **X 軸（青）= 前後方向**（青≈「depth/奥行き」）
- **Y 軸（赤）= 左右方向**（赤≈「左右」）
- **Z 軸（緑）= 高さ方向、上が正**（緑≈「高さ」）

> ⚠️ 注意：これは「画面ラベル軸」です。コード内部では別の組（X 赤 Y 緑 Z 青、Y が上）を使っていますが、あなたが画面・説明書・ヘルプパネルで見るのはいつでも上のラベルです。ラベル軸だけ覚えれば十分、内部実装に惑わされないでください。

この表を覚えれば、後の各章はこれを使って「文章を作る」だけです。

## 第 31 章 単キー操作と Shift コンボ

キーボードショートカットには一つの核心ルールがあります：**今オブジェクトを選択しているかどうかを見る**。以下の 2 つの表は、アプリ内「設定 → ショートカット操作」の「単キー操作」「Shift コンボ」と**完全に一致**しています。

### 31.1 単キー操作

> 選択時: 0.1グリッド (0.15単位) 移動 / 5°回転{br}非選択時: 視点を0.1グリッド移動 / 5°回転

| キー | 選択時 | 非選択時 |
|---|---|---|
| `↓` / `↑` | X+/−方向に移動 | 視点を前/後ろに移動 |
| `→` / `←` | Y+/−方向に移動 | 視点を右/左に移動 |
| `PgUp` / `PgDn` | Z+/−方向に移動 | 視点を上/下に移動 |
| `A` / `D` | Z軸 CW/CCW回転 | 左/右に回転 |
| `W` / `S` | Y軸 CW/CCW回転 | 上/下に回転 |
| `E` / `Q` | X軸 CW/CCW回転 | — |
| `+` / `-` | 5%拡大/縮小 | — |
| `Esc` | 操作をキャンセル | コントロールを閉じる |
| `F11` | 全画面 / 全画面終了 | （同上） |
| `Del` / `Backspace` | 選択オブジェクトを削除 | — |

✏️ **やってみよう**：立方体を置く → 選択して `↑` で「前に進む」；選択を解除（空白をクリック）してから `↑` を押すと、今度は視点が前に進みます。同じキー、2 つの顔。

### 31.2 Shift コンボ

> 選択時: 1グリッド (1.5単位) 移動 / 90°回転{br}非選択時: 視点を1グリッド移動 / 90°回転

| `Shift` + キー | 選択時 | 非選択時 |
|---|---|---|
| `↓` / `↑`、`→` / `←`、`PgUp` / `PgDn` | 1グリッド移動 | 1グリッド移動 |
| `A` / `D`、`W` / `S`、`E` / `Q` | 90°回転 | 90°回転 |
| `+` / `-` | スケール×2 / ×0.5 | — |
| 左クリック | 選択に追加（タップ選択） | （同上） |

💡 コツ：**通常キーで近づけ、Shift で到着**。まず方向キーでだいたい合わせ、最後に `Shift`+方向キーで 1 グリッドの大ジャンプで整列；回転も同様、まず `A` で 5° 回して感覚を掴み、次に `Shift+A` で一気に 90° まで補って正します。

## 第 33 章 初めての変換コントロール：3 つの「つかむ道具」

### 33.1 いつ現れるか

**オブジェクトを 1 つ選択する**と（クリックし、選択枠が出る）、物体の中心にハンドルの組が浮かびます。これが変換コントロールです。

これには 3 つの「スキン」があり、3 つの操作に対応し、右パネルの「変換モード」区（⇔ ↻ ⤢ の 3 つの四角ボタンがある小区画）で切り替えます。

| モード | ボタンアイコン | ハンドルの姿 | 何に使う |
|---|---|---|---|
| **移動** | ⇔ | 3 本の**矢印** | 物体を運ぶ |
| **回転** | ↻ | 3 つの**リング** | 物体を回す |
| **スケール** | ⤢ | 3 つの**四角**（角の小さな立方体） | 物体を拡大縮小 |

既定で入るのは**移動**モード。モードを変えたいなら対応ボタンをクリック。切り替え時、下部にヒント文字（「移動/回転/スケール」）が一瞬出ます。

💡 小知識：変換コントロールとキーボードショートカットは**同じことの 2 つの入り口**——キーボードは「精密ステップ」、コントロールは「自由ドラッグ」。両方混用可：まずコントロールでだいたい引っ張り、次にキーボード `↑` で数グリッド微調整して整列。第 36 章で両者の連携を専門に説明します。

### 33.2 あらかじめ言っておくべき「色の罠」

⚠️ **全篇で最も重要な注意、必ずこの段落を読んでください。**

画面の中の 3 本の**座標軸ラベル**は「画面ラベルの色」を使っています。

- **X = 青 = 前後**
- **Y = 赤 = 左右**
- **Z = 緑 = 高さ**

しかし変換コントロールのハンドルの着色は、**three.js のコード軸慣習**（赤=X、緑=Y、青=Z）に従い、上の組と**色が一致しません**！だからあなたが見るハンドルの色は、次のように翻訳する必要があります。

| ハンドルの色 | 実際に表すコード軸 | 対応する画面ラベル軸 | 画面で意味するもの |
|---|---|---|---|
| 🔴 赤ハンドル | コード X | 画面 **Y** | **左右**移動 / 左右軸の周り |
| 🟢 緑ハンドル | コード Y | 画面 **Z** | **高さ**（上下）移動 / 高さ軸の周り |
| 🔵 青ハンドル | コード Z | 画面 **X** | **前後**移動 / 前後軸の周り |

> 覚えられなくても大丈夫、一言覚えて：**ハンドル赤＝左右、ハンドル緑＝上下、ハンドル青＝前後**（画面ラベルで理解）。表面の赤緑青に騙されて「シーン軸ラベルの色」を当てはめないでください。

✏️ **やってみよう（検証用）**：立方体を選択し、移動モードへ。まず**赤い矢印**をドラッグし、物体が「左右」に滑るか「前後」に滑るか——左右のはず。次に**青い矢印**をドラッグし、「前後」に滑るか。この実験で上の表を脳に刻めば、後のすべての回転/スケールの軸も乱れません。

### 33.3 ハンドルをドラッグ中、視点は動かせるか

動かせます。しかもそれが本ツールのとても快適な設計です。

- **左ボタンドラッグ ハンドル** = 物体を操作；
- **右ボタンドラッグ** = 視点回転（カメラ回転）；
- **中ボタンドラッグ** = 視点平行移動；
- **ホイール** = 視点ズーム。

つまり、左手で右ボタンを押して角度を変え物体の側面を見ながら、右手（または同じ手でキー替え）でハンドルを引き続けられる——視点と変換は**互いに邪魔しません**。もう「一旦変換を抜け、視点回転し、また入る」という手間は不要です。

---

## 第 34 章 移動モード：矢印で物体を「つかんで」動かす

### 34.1 3 つの引っ張り方

移動モードでは、3 本の軸矢印の他に、コントロールは**2 つの平面ブロック**（2 本の軸が張る平面上）を提供します。そこで 3 つのつかみ方があります。

1. **単本の矢印をつかむ**（赤/緑/青）→ その 1 本の軸にしか直行できず、最も正確で、それ以外へ流れない；
2. **平面ブロックをつかむ**（例：赤緑矢印にはさまれた面）→ その平面内で自由に滑り、同時に 2 本の軸に制約；
3. 完全に自由に「地面にくっつけてぐちゃぐちゃ引っ張る」？対応平面に切り替えてから引っ張れば可。

💡 経験：正確な整列をするなら、常に**単本の矢印をつかみ**、平面はつかむな——平面は物体を望まない方向へ容易に流します。

### 34.2 平面の見分け方（色の罠と合わせて）

移動モードの平面は「隣り合う 2 本の矢印ではさまれた三角/四角領域」です。第 33.2 節の翻訳に従えば：

- 赤矢印（左右）+ 緑矢印（上下）ではさまれた平面 = **左右×高さ** 平面（物体の「側面」）；
- 緑矢印（上下）+ 青矢印（前後）ではさまれた平面 = **高さ×前後** 平面（物体の「正面/背面」）；
- 赤矢印（左右）+ 青矢印（前後）ではさまれた平面 = **左右×前後** 平面 = **地面**（物体が「踏んでいる」平面）。

✏️ **やってみよう**：物体を地面に置き、「赤+青」ではさまれた平面ブロックを引っ張ってドラッグ——地面にぴったり貼って滑り、昇りも沈みもしない？これが「地面に沿って移動」の最も安定した姿勢です。

### 34.3 キーボード移動と見比べて学ぶ

| やりたい動作 | コントロール | キーボード（第 32 章） |
|---|---|---|
| 前後に正確に 0.1 グリッド動かす | **青矢印**をつかんで引く | `↑`/`↓` |
| 左右に正確に 0.1 グリッド動かす | **赤矢印**をつかんで引く | `←`/`→` |
| 高さに正確に昇/降 | **緑矢印**をつかんで引く | `PgUp`/`PgDn` |
| 大股に 1 グリッド動かす | コントロールで矢印を硬く引く | `Shift`+方向キー |

💡 コツ：**コントロールは「手触り」、キーボードは「精度」**。まずコントロールでだいたい引っ張り、次にキーボード `↑`/`←`/`PgUp` で数グリッド微調整してグリッド線に貼り付け。

## 第 35 章 回転モード：リングが「どの軸の周りか」を決める

### 35.1 3 つのリング = 3 本の軸の回転

回転モード（↻）に切り替えると、物体上が 3 つの色付きリングになり、各リングは「その軸の周りを回す」を表します。

| リングの色 | コード軸 | 画面ラベル軸 | 観感（第 32 章の例えを思い出す） |
|---|---|---|---|
| 🔴 赤リング | コード X | 画面 **Y**（左右軸） | **前のめり/のけ反り**の宙返り |
| 🟢 緑リング | コード Y | 画面 **Z**（高さ軸） | **ターンテーブル/コマ**のその場回転 |
| 🔵 青リング | コード Z | 画面 **X**（前後軸） | **左へ倒れる/右へ倒れる**の横転 |

⚠️ リングの色と「どの軸の周りか」の対応も、第 33.2 節の翻訳表を当てはめる必要があります——**赤リングは左右軸、緑リングは高さ軸（最も常用、正す用）、青リングは前後軸**。

### 35.2 リングをつかんで回すのは、キーボード A/D/W/S/E/Q と同義

第 32 章でキーボードで物体を回しました。そこでは：
- `A`/`D` は**高さ軸**（画面 Z、垂直軸）の周り；
- `W`/`S` は**左右軸**（画面 Y）の周り；
- `E`/`Q` は**前後軸**（画面 X）の周り。

コントロールのリングに対応させると：
- キーボード `A`/`D` ↔ **緑リング**をドラッグ（高さ軸）；
- キーボード `W`/`S` ↔ **赤リング**をドラッグ（左右軸）；
- キーボード `E`/`Q` ↔ **青リング**をドラッグ（前後軸）。

✏️ **やってみよう**：「正面」のある物体を選択し、`Shift + A` で正しく 90° 回転（正す）させ、次に回転モードへ切り替え**緑リング**をドラッグ——手で引っ張るのも同じ垂直軸の周りを回り、しかも任意の角度に停められる（キーボードは 5°/90° 跳びしかできず、コントロールは中間値に停められる）ことがわかります。これがまさに補完です。

### 35.3 自由回転 vs 精密回転

- コントロールのリング：**[任意の角度]**に停められ、「見た目が良くなるまで回す」に向く；
- キーボード `Shift`+文字：**[90°]** だけ整跳び、「必ず正す、必ず直角」に向く；
- キーボード通常文字：**[5°]** ステップだけ、「数度微調整」に向く。

💡 実戦：まずコントロールでだいたいの角度へ → 次に `Shift+A`（緑軸）で正 90°/180° まで補う。立体文字、建築立面のように「正さ」が要る仕事に最も常用です。

## 第 36 章 スケールモード：四角ハンドルと「均等」スイッチ

### 36.1 四角ハンドル：1 本の軸を引くか、全体を膨らませるか

スケールモード（⤢）に切り替えると、物体の角に小さな立方体ハンドルが現れます。単体の四角をドラッグ＝**その 1 本の軸だけ伸ばす/潰す**（例：球を楕球に、柱を高細く）；中心の四角をドラッグ＝全体スケール。

| ハンドルの色 | 画面ラベル軸 | 引っ張った効果 |
|---|---|---|
| 🔴 赤四角 | 左右（Y） | 幅広 / 幅狭 |
| 🟢 緑四角 | 高さ（Z） | 高 / 低 |
| 🔵 青四角 | 前後（X） | 深 / 浅 |

### 36.2 「均等スケール」ロック：初心者が最もオンにすべきスイッチ

右パネルの変換モード区の下にチェックボックス **「均等スケール」**（既定でチェック済）があります。チェック時、どの四角を引っ張っても物体は**全体等比**で拡大縮小し、引き伸ばし変形しません——これがたいていあなたの望む姿です。

⚠️ チェックを外し、単体の四角を引っ張ると、物体は「単軸ストレッチ」で変形します。これには創造的用途（潰したワッシャ、伸ばした梁）がありますが、初心者は誤って外し「なぜ歪んだ」と悩みやすいです。迷ったらチェックを維持してください。

### 36.3 キーボードスケールと見比べ、および「複数選択禁縮」

| やりたいこと | コントロール | キーボード（第 32 章） |
|---|---|---|
| 全体 5% 拡大 | 中心四角をドラッグ（均等チェック） | `+` |
| 全体 5% 縮小 | 中心四角をドラッグ | `-` |
| 倍 / 半分 | 中心四角を硬く引く | `Shift`+`+` / `Shift`+`-` |
| 単軸潰し | 均等を外し単四角をドラッグ | キーボード非対応 |

⚠️ **重要な制限**：**一度に複数オブジェクトを選択**したとき、スケールモードは**自動的に無効**（ボタンが灰色になり、そのときスケールモードなら自動的に移動へ戻る）。理由はキーボード `+`/`-` の複数選択禁縮と同じ——サイズの異なる複数物体を強制一緒にスケールすると奇妙になるからです。

💡 では複数選択時にどうやって統一して大きさを調整するか。2 つの道：① まず `Ctrl + A` してからコントロール/キーボードで個別処理；② 「均等スケール」以外の方法——例えばあらかじめグループを作り、スケールではなく移動で配置。

### 36.4 変換コントロールが「使わせてくれない」とき

複数選択禁縮の他に、変換モードボタンが灰色になりクリックできない場合がいくつかあります。

- あなたが**ペン / テキスト / 消しゴム**ツールモードにいるとき（これらのツールはクリックを自ら引き受け、変換コントロールは譲る）；
- **テキスト編集中**（インライン入力枠が出ているとき）、変換ボタンは一時無効、入力終わりで復帰；
- 一部の**特殊オブジェクト**（画像、ペン筆跡など）はそもそもスケール非対応で、選択するとスケール関連コントロールを自動非表示にしスケールモードを無効化、移動へ戻る。

⚠️ 3 つのモードボタンが動かず灰色なら、まず確認：どこかのツールに留まって抜けていないか？ `Esc` を押すか上部の「選択」系ボタンをクリックしてツールを抜ければ、変換コントロールは復活します。

### 36.5 コントロールと数値枠：双方向同期

右の「変換」区には対応する**数値スライダー/入力枠**（位置、回転角度、スケール値）もあります。これらとコントロールは**双方向同期**：

- コントロールを引っ張ると、数値枠がリアルタイムで追従；
- 数値枠に直接正確な値を入力（例：回転に `45`、スケールに `2.5`）すれば、物体も即座に変わる。

💡 「絶対に正確」（例：回転は正しく 30°、スケールは正しく 1.5 倍）が必要な時は、**数値枠への直接入力**がコントロールよりずっと確実です。コントロールは「感覚を探す」に、数値枠は「数値を嵌める」に向いています。

---

✏️ **本篇まとめ**：変換コントロールはキーボードの「自由ドラッグ版」。3 つを覚えてください——① 移動/回転/スケールの 3 スキンがあり、矢印/リング/四角に対応；② **ハンドル赤＝左右、緑＝上下、青＝前後**（常に画面ラベルで翻訳、表面の色に騙されるな）；③ 左ボタンドラッグで物体、右/中/ホイールで視点、三者は邪魔し合わない。次の篇では「組み合わせとグループ化、整列と分布」を説明し、「単一物体を動かせる」から「一大群を配置できる」へ進みます。

# 第 10 篇 群像篇：一度に「一群」の物体を管理

> 前篇の終わりで「組み合わせとグループ化、整列と分布」を説明すると予告しました。ここでまず白状します：**本ツールには独立した「グループ化」ボタンも、「ワンクリック整列/分布」ボタンもありません**——それより軽量で、より柔軟なルートを通ります：**複数選択 ＋ 一緒に変換 ＋ 複製アレイ**。
>
> この篇では「どうやって一大群の物体を効率よく管理するか」を教えます。銀の弾丸はありませんが、十分な「土着の方法」があり、並べても同じように整然とします。

## 第 37 章 一度に一群を選ぶ：「選択セット」を知る

### 37.1 なぜ複数選択か

これまで「1 つクリック、1 つ変更」でした。しかし真の制作はたいてい一堆の物：一列の木、一列の灯、地面いっぱいの小石。100 個を 1 つずつ調整していたら、人が先に狂います。

解決法：まずそれらを**一度に「選択セット」に選び入れ**、統一操作すること。これが複数選択の意味です。

### 37.2 複数選択三法

| 方法 | 操作 | 向く場面 |
|---|---|---|
| **全選択** | `Ctrl + A`、またはタッチ画面で下部「全選択」ボタン | シーン内すべてのオブジェクトを選びたい |
| **加選 / 減選** | `Shift` を押しながらオブジェクトをクリック：選択されていないものをクリック＝加える；選択済みをクリック＝追い出す | 特定のいくつかを選ぶ（例：「この 2 つの灯 ＋ あの木」） |
| **囲み選択** | 空白で**押しながらドラッグ**、点線枠を引き、枠内のオブジェクトが一度に選択 | 密集した一群、1 つずつクリックするのが面倒 |

✏️ **やってみよう**：5 つの形状を散らばして置きます。まず `Ctrl + A` で全部光るか → 空白をクリックして解除 → `Shift` を押しながらそのうち 2 つをクリック（灰色に）→ もう一度空白で枠をドラッグし、残り 3 つを囲みます。「選択セット」が付箋の山のように、自由に増減するのを感じてください。

💡 囲み選択の小細工：マウスで空白をドラッグすると枠が出る。タッチ画面は「空白をドラッグ」の概念がないので、専用の「囲み選択」ボタンを作り、オンにすると 1 本指ドラッグで囲み選択（オン時下部に「囲み選択モード」と表示）。囲みで何も当たらなくても「囲み選択は対象に命中しませんでした」と優しく知らせ、silent に失敗しません。

### 37.3 選択の「境界事例」

- 空白をクリック（ドラッグなし）＝ 全選択解除；
- 囲み選択で枠が**完全に空**なら、選択セットがクリア（「逆選択して無し」と同等）；
- **テキスト編集中**や**ペン/消しゴム**ツール中は、選択ロジックはツールに譲り、複数選択は一時不可。

❓ **考えてみよう**：なぜ「Shift+クリック」は加えも減らしもできるのでしょう。——選択セットは「オン/オフ」の二元ではなく、1 つの**集合**だからです。存在する要素をクリックすれば除去、存在しないものをクリックすれば加入。この「切り替え」ロジックは、その後ファイルマネージャやメールボックスでも至る所で出会います。

## 第 38 章 一群を一緒に動かす：複数選択変換の「マスターピボット」

### 38.1 見えない「マスターピボット」

**複数**のオブジェクトを選択すると、ツールはコントロールを特定の物体に掛けません（誰に掛けても不公平なので）、その代わりこの一群の**正中心**に**見えない代理点**（コードでは `multiTransformProxy`）を 1 つ置きます。

あなたが見る変換コントロール（矢印/リング）は、実はこの「マスターピボット」に掛かっています。それを引っ張ると、アルゴリズムはマスターピボットの移動/回転の**増分**を計算し、さらに**各選択オブジェクトに同期配信**します。

> 人語に訳す：**見えない「総スイッチ」を 1 つ引っ張ると、選択されたすべての物が一緒に動き、しかも互いの相対位置は変わらない。**

### 38.2 複数選択でできること

| 操作 | 複数選択時可用？ | 説明 |
|---|---|---|
| 一緒に**移動**（矢印/平面を引く） | ✅ 可用 | 群全体が某軸に沿って移動 |
| 一緒に**中心の周りを回転**（リングを引く） | ✅ 可用 | 群全体が群体中心の周りを回る、盤上の駒を弾くように |
| 一緒に**スケール** | ❌ 無効 | 複数選択時スケールモードボタンが灰色、自動で移動へ戻る |

✏️ **やってみよう**：バラバラの 3 オブジェクトを選択 → 回転モードへ → **緑リング**（高さ軸）を引く → 彼らが「一つの手で同時にねじ回される」ように、共同中心の周りを回り、互いの間隔は変わらないか。これが「群回転」の快感です。

### 38.3 なぜ複数選択は一緒にスケールできないか

⚠️ これは**意図的な制限**であり、バグではありません。

- サイズや形状の異なる複数物体を一緒に均等スケールすると、結果はたいてい変（大きいものが巨大に、小さいものがゴマになる）；
- だからツールは複数選択時に**直接スケールモードを無効**にし、「個別に縮めるか、先に複製してから調整せよ」と迫ります。

💡 代替案：
1. 一群を「同じ大きさにしたい」——まず `Ctrl + D` で同じものを一列複製、彼らはもとよりサイズ一致なので、後は個別微調整；
2. 本当に一群を全体スケールしたい——**先に全選択、JSON をエクスポート、数値を変えてからインポート**？それは面倒。より実際的なのは：彼らを「仮のグループ」と見なし、**個体スケール ＋ 統一オフセット**で配置すること。

### 38.4 複数選択 + Shift 大股、やはり便利

第 32 章で学んだ `Shift` 大股（1 グリッド / 90°）は複数選択に**同様に効きます**。一群を選択して `Shift` を押しながら方向キーをドラッグすると、群全体が一度に 1 グリッド跳び、アレイの配置に超便利（次章で使います）。

## 第 39 章 量産：コピー・複製・「アレイ」

反復物を作るとき、2 つ目、3 つ目を手描きしてはいけません——「コピー/複製」でコンピュータに生ませましょう。

### 39.1 三つの「副本を生む」方法

| キー | 名前 | 特徴 |
|---|---|---|
| `Ctrl + C` | コピー | 選択オブジェクトを**クリップボードへ格納**（すぐには現れない） |
| `Ctrl + V` | 貼り付け | クリップボードから**取り出し**、元位置の近くへ貼る |
| `Ctrl + D` | **複製** | ワンステップ：その場でコピーし**自動的に少しオフセット** |

💡 **最も常用なのは `Ctrl + D`**。これは「コピー→貼り付け」より 1 ステップ少なく、しかも複製された副本は自動的に少しずれるので、即座に見え、即座に再配置できる——アレイの定番です。

✏️ **やってみよう**：立方体を 1 つ置く → `Ctrl + D` で、1 つ増え、しかも少しずれる？→ 新しい方を選択 → `→` で次の枠へ → また `Ctrl + D` → また `→`……数回で一列埋まる。マウスパネルに一切触れず。

### 39.2 「複製 + キーボード」で整ったアレイを並べる

「整列/分布」ボタンがない？大丈夫、手動で**グリッドステップ**を使って並べれば、同じく整います。

1. 物体を選び、`Ctrl + D` で複製；
2. 方向キーで**ちょうど 1 グリッド**の場所へ動かす（既定ステップ 0.1 グリッド、10 回押す；または `Shift`+方向キーで 1 回 1 グリッド）；
3. `Ctrl + D` ＋ 方向キーを繰り返せば、一列が出る；
4. 一列終わったら、その列を `Ctrl + A` で全選択、`Shift`+方向キーで「列全体」を大股に次の行へ動かし、さらに複製——二次元アレイ（方陣）もできます。

💡 **円を並べる技**：1 つ複製 → 中心から固定半径の場所へ動かす → 群全体を中心の周りに回転（第 38 章）→ ある角度回るごとに 1 回複製。数回回せば「環状アレイ」が出ます。これが手動版「分布」です。

### 39.3 コピー貼り付けの境界

⚠️ 2 つの足を踏みやすい注意（ツールが小文字で知らせます）：
- **「変換中のため、コピー/複製できません」**：コントロールを引っ張っている（変換活性）とき、コピー/複製ボタンは一時無効。手を離し（ドラッグ終了）てから押せば OK。
- **「先にオブジェクトを選択してからコピーしてください」**：何も選択せず `Ctrl + C` を押すと、先に選べと知らせます。クリップボードが空のとき `Ctrl + V` も「クリップボードが空です」と表示。

❓ **考えてみよう**：複製とコピー貼り付け、底の違いはどこか。——複製は「その場でオフセット副本を生成」し、いかなる中間保存にも依存しない；コピー貼り付けは「先にクリップボードへ格納、次に取り出す」なので、A シーンをコピーし、B シーンへ切り替えて貼り付けできる（本ツールのクリップボードはメモリ級、同ページ内で通用）。これを理解すれば、なぜ時々 `Ctrl + V` が反応しないか——おそらくクリップボードが空だとわかります。

## 第 40 章 保存と共有：作品を画面の外へ

苦労して組んだシーン、web を閉じたら消える？いいえ——本ツールは**エクスポート**でファイルに、**インポート**で戻し、**スクリーンショット**で画像にできます。

### 40.1 三つの「保存/取得」キー

| キー | 作用 | 産物 |
|---|---|---|
| `Ctrl + S` | シーン書出 | 1 つの **JSON ファイル**（シーンの完全記述） |
| `Ctrl + O` | シーン読込 | 以前エクスポートした JSON を読み戻す |
| `Ctrl + P` | 画像書出 | 1 枚の **PNG 画像**（現在の画面の写真） |

💡 ワークフロー：**一段組む → `Ctrl + S` で保存 → 翌日 `Ctrl + O` で読み戻して続き**。JSON はあなたの「プロジェクトファイル」、PNG はあなたの「成果写真」、両者は役割分担。

### 40.2 JSON に一体何が入っているか

エクスポートされた JSON は画像ではなく、1 通の**オブジェクトリスト**で、おおよそ記録します。

- 各オブジェクトの**タイプ/形状**（球か字か、縦横高さパラメータ）；
- 各オブジェクトの**変換**（位置、回転、スケール——つまりどこにあり、歪んでいるか、どれだけ大きいか）；
- 各オブジェクトの**外観**（色、テクスチャ、透明度、テクスチャ貼り）；
- シーンの**環境設定**（座標軸、グリッド面の表示/非表示など）。

⚠️ 保存されるのは「パラメータ」であり「ピクセル」ではないので、インポート後も**編集を続けられる**——これは死んだ図ではなく、生きたプロジェクトです。これも、なぜ前のすべての操作が「履歴スタック」に入り取り消し可能かを説明します。彼らは本質的にこのパラメータを変更しているのです。

### 40.3 共有と協働の提案

- **同僚に効果を見せる**：PNG（`Ctrl + P`）を送るのが最速；
- **同僚に続きを直させる**：JSON（`Ctrl + S`）を送り、相手が `Ctrl + O` で開けば編集可；
- **デバイス間**：JSON をクラウド/WeChat に送り、別の PC で web を開きインポートすれば——シーンは持ち歩き。
- ⚠️ `Ctrl + Del` は**シーン全体をクリア**し確認なしを見落とさないで。クリア前に先に `Ctrl + S` でバックアップし、心血をワンクリックで蒸発させないでください。

### 40.4 手動の「整列と分布」：ボタンがなくても揃えられる

篇頭の約束に戻る——ワンクリック整列/分布がないので、ここで三招の**純手動**整え方を、これまでの学びと組み合わせて示します。

1. **グリッドに頼る**：既定移動ステップ 0.1 グリッド（＝0.15 単位）、整数回押す＝正確に格線に落下。`Shift`+方向キーは 1 回 1 グリッド、最も「グリッド線への貼り付け」に向く。
2. **複製に頼る**：第 39 章のように、複製 ＋ 固定ステップ ＝ 等間隔アレイ（これが「分布」）。
3. **視点に頼る**：まず下部「正面図/上面図」で物体を標準機位へ正し、次に単一軸に沿ってキーボードで動かし、「斜めに並べる」を避ける。

✏️ **総合やってみよう（本篇の卒業作）**：「立方体 + `Ctrl + D` 複製 + `Shift`+方向キー」で 5×3 の方陣を並べ、`Ctrl + A` で全選択後 `PgUp` で全体を地面から 1 グリッド昇らせ、`Ctrl + S` で保存。あなたはすでに「量産 ＋ 整列配置 ＋ 成果保存」ができています。

---

✏️ **本篇まとめ**：本ツールは「グループ化/整列」ボタンに頼らず、**複数選択 ＋ 代理マスターピボット ＋ 複製アレイ**で群像管理を実現します。覚えて——複数選択三法（全選択/Shift 加選/囲み選択）、複数選択は移動回転可だがスケール不可、複製 `Ctrl + D` はアレイ神器、JSON はあなたの生きたプロジェクトファイル。次の篇では**総合実戦**：ゼロから完全な小シーン（小さな家 / 小さな庭）を組み、前十篇の腕前を 1 つの線に繋ぎ、「入門から習熟まで」の最後の一里を体験します。

## 第 41 章 プロジェクト 1：小さな家を建てる

### 41.1 まず成品を見て、次に分解を考える

作るものは質素です：屋根・ドア・窓のついた小さな家が、芝生の上に立っている。

まだ図形を引っ張らないでください。10 秒で 1 つの問いを考えてください。

❓ **考えてみよう**：1 つの家を、もし「立方体、円錐、正四角錐、円柱、平面」という基本形状だけで組むとすれば、どう分解しますか。

これは 3 次元制作で最も核心的な思考——**複雑な物体を単純な幾何体の組み合わせに分解する**。専門用語で「体塊分析」ですが、要するに「積み木」です。

参考分解：

| 部品 | どの図形を使う | なぜ |
|---|---|---|
| 壁体（主体） | `box` 立方体 | 家の本質は箱 |
| 屋根 | `pyramid` 正四角錐 | 四角底に尖った頂、ちょうど四角い壁に被さる |
| ドア | `box` を潰した薄板 | 壁面に貼り、2D 図形より置きやすい |
| 窓 | `box` のさらに小さい薄板 | 同上、半透明にしてガラス可 |
| 煙突 | `cylinder` 円柱 | 細く高く、屋根から飛び出す |
| 地面芝生 | `square2` 正方形 | 2D が地面に平らに寝て、芝生に |

💡 **心法**：どんな造形もまず「それはいくつの体塊から成るか」を問う。車を作ろうとロボットを作ろうと、思考は全く同じです。

### 41.2 ステップ 1：地固め（芝生）

1. 左パネルを **2D 図形** に切り替え、`square2` **正方形**をシーン中央へドラッグ；
2. 選択し、右パネルで**緑系**の色；
3. テクスチャは **格子（チェック）**——遠目に刈り込んだ芝生の模様に；
4. **均等スケール**（右パネルスライダーか `Shift + +`）で、家より明らかに一回り大きくなるまで拡大。

⚠️ **失敗点**：2D 図形は「地面に平らに寝ている（Z=0）」シールです。もし「立ち上がった」ように見えたら、たいてい回転コントロールで回してしまった——`Ctrl + Z` で戻し、無理にねじらないでください。

✏️ ついで練：下部「**上面図**」ボタンを押し、真上から芝生の範囲が十分か一瞥；次に「透視図」で通常視点へ戻る。この「視点を変えて確認」の習慣は、本篇の後每一步で提案します。

### 41.3 ステップ 2：壁体を立てる

1. **3D 図形** に切り替え、`box` **立方体**を芝生中央へドラッグ；
2. 選択し、`PgUp` で**ちょうど地面に座る**まで持ち上げ（底面が地面に付き、浮かず埋まらず）；
3. 右パネルを**ベージュ / 薄黄**（壁色）へ；
4. テクスチャは **レンガ**——一瞬で「1 つのブロック」が「一面の家」に。

💡 **「地面に付く」を見極めるコツ**：下部「**正面図**」ボタンをクリックし、真正面から平視すると、物体が浮いているか地中に埋まっているか一目でわかります。透視図では見誤りやすく、正面図は嘘をつきません。

⚠️ **失敗点**：多くの初心者は透視図で高さを調整し、どう調整しても「なんか変」と思います。正面図に切り替え、2 秒で解決。

### 41.4 ステップ 3：屋根を被せる

1. `pyramid` **正四角錐**を 1 つ引っ張る；
2. `PgUp` で**壁体の真上**まで昇らせ、錐底がちょうど壁頂に押さえる；
3. 左右前後の位置が合わない？ `↑↓←→` で微調整（0.1 グリッドステップ）；大きく合わないなら `Shift +` 方向キーで 1 グリッド跳び；
4. 色を**赤茶 / 濃灰**（瓦色）へ。

❓ **考えてみよう**：なぜ屋根に「正四角錐」ではなく「円錐」を使うのか。——壁が四角だからです。四角い頂に四角い壁、縁がぴったり；円錐を四角い壁に被せると、四隅が出てきます。**形状の一致が「見た目が正しいか」の鍵**です。

✏️ **やってみよう**：わざと `cone` 円錐に変えて 1 回試し、正面図と上面図で各 1 眼、 「隅が出る」違和を感じてください。そして `Ctrl + Z` で戻します。

### 41.5 ステップ 4：ドアと窓を開ける

ドアと窓の作り方は「**潰した薄板を壁面に貼る**」です。

1. `box` を 1 つ引っ張り、まず**「均等スケール」のチェックを外し**（第 36.2 節）、**薄い一片**に引き伸ばす；
2. 均等スケールを再度チェック（後で誤って引き伸ばすのを防ぐ）；
3. 方向キーで**壁の正面**へ貼り——少し壁から「飛び出す」ように注意、さもないと壁と「ケンカ」します（下の失敗点）；
4. 色は**濃棕（こんちゅう）**（木のドア）。

窓も同様、少し小さい薄板 2 枚を作り、色は**薄青**、**不透明度を 0.5 前後に**——ガラス感がすぐ出ます（第 20.2 節）。

⚠️ **重要な失敗点：Z-fighting（ちらつきケンカ）**
ドア板と壁面が**完全に同じ平面に重なる**と、彼らがちらつき、互いに貫通します——これはバグではなく、2 つの面が同じ深さで「位置を奪い合う」ためです。
**解決法**：方向キーでドアを外へ 1～2 小ステップ（0.1 グリッドで十分）動かし、壁の前面に明確に「浮かぶ」ようにします。

💡 2 枚目の窓を描き直すな——1 枚目を選択し、`Ctrl + D` で複製、さらに `←` か `→` で反対側へ。これが第 39 章の複製アレイの実戦初登場です。

### 41.6 ステップ 5：煙突を加え、仕上げ

1. `cylinder` **円柱**を引っ張り、均等スケールで細く、`PgUp` で屋根斜面まで昇らせ、少し飛び出させる；
2. 色は**濃灰**；
3. もっと生活感が欲しい？ `sphere` 球体をいくつか複製し、煙突口に積んで「煙」にし、不透明度を 0.3 に。

**最終チェックリスト**（各プロジェクトで通すべき）：

| チェック項目 | どう確認 |
|---|---|
| 浮いている / 埋まっているはないか | 「正面図」で平視 |
| 前後の位置に貫通はないか | 「左面図」か「右面図」で |
| 全体配置は中央か | 「上面図」で俯瞰 |
| 成品は見栄えが良いか | 「透視図」で通常視点へ戻る |

疑いなければ：`Ctrl + S` で JSON をエクスポートしてプロジェクト保存、`Ctrl + P` で PNG を 1 枚撮って提出。

### 41.7 上級チャレンジ

1. **テラスハウスを一列に**：家全体を全選択（`Ctrl + A`）→ `Ctrl + D` 複製 → `Shift +` 方向キーで全体を 1 グリッド離して動かす → 3 回繰り返す。複数選択複製では整組の相対位置が変わらないことに注意（第 38 章の「マスターピボット」メカニズム）。
2. **季節替え**：芝生テクスチャを「ドット」に、色を白に → 雪地に；壁不透明度を 0.4 に → 氷小屋に。
3. **表札を加える**：第 21 章のテキストツールで、ドアの上に「1 号」の 1 行を追加、フォントは**黒体**、文字サイズを家に比例するよう小さく。

⚠️ 注意：テキスト既定文字サイズは **80** ですが、家の体塊は通常 1～2 単位しかない——そのまま字を加えると「家より大きい巨大文字」になります。文字サイズを小さく（またはテキスト全体を縮小）しないと調和しません。これは初心者が標識を作るとき最もよくある挫折点、慌てず、文字サイズを変えれば OK です。

## 第 42 章 プロジェクト 2：立体的な文字の標語を作る

### 42.1 目標と方針

シーンに立つ**標語看板**を 1 つ作る：背板 ＋ 文字 ＋ 装飾、例えば「いらっしゃいませ」「開業大吉」やお好みの言葉。

⚠️ 誤解しやすい点を先に明確に：本ツールのテキストは「**字を貼った薄板**」（第 21.1 節）であり、本当に厚みのある立体押し出し字ではありません。だから私たちの望む「立体感」は、**背板 ＋ 文字 ＋ 階層配置**というコンボで作り、文字そのものの厚みには頼りません。

これを理解すれば、方針は明確です。

| 階層 | 何を使う | 役割 |
|---|---|---|
| 背板 | `box` を潰した薄板 | 文字に「依拠面」を |
| 主文字 | テキストオブジェクト | 内容の主体 |
| 影文字 | テキストオブジェクト（濃色、後ろへ少しずらす） | 厚みの錯覚を作る |
| 支柱 | 2 本の `cylinder` | 看板を地面に「立たせる」 |

### 42.2 ステップ 1：背板を作る

1. `box` を 1 つ引っ張り、「均等スケール」のチェックを外し、**垂直の薄板**（幅 ＞ 高さ ＞ 厚み）に潰す；
2. 均等スケールを再度チェック；
3. `PgUp` で目の高さ（地面から一段離して、貼り付けない）まで持ち上げ；
4. 色は**濃色**（濃紺 / 濃緑 / 木色どれでも）——濃底に浅字が最もクリア。

💡 **配色原則**：文字と背板には必ず**明度差**が必要。濃底浅字、浅底濃字、どちらかを選ぶ。同明度の組み合わせ（例：中灰底 ＋ 中緑字）は遠目で一团に糊となる、これはデザインで最も基本かつ最も見落とされる規則です。

### 42.3 ステップ 2：文字を打つ

1. 左パネル「ツール」→「**テキストを追加**」；
2. シーン内をクリックし、入力枠がポップアップ（プレースホルダ「入力テキスト······」）；
3. 標語を入力し、**Enter** で確定；
4. 選択し、右パネルで調整：
   - **フォント**：モダンなら「黒体」、伝統なら「楷体」；
   - **文字サイズ**：既定 80、通常は体塊に合わせ**小さく**する必要（41.7 の注意参照）；
   - **太字**：標語類はオンを提案、遠目で目立つ；
   - **色**：背板と対比の強い浅色。

5. 方向キーで文字を背板の**真正面**へ動かし、外へ少し飛び出させる（Z-fighting 防止、41.5 節同様）。

✏️ **やってみよう**：字を打った後**ダブルクリック**（第 21.3 節）し、内容を別の言葉に変える。 「消して作り直す」不要の楽さを体感——文案を繰り返し推敲するとき非常に省けます。

### 42.4 ステップ 3：「影文字」で厚みを作る

これが本章の核心技巧、簡単だが効果抜群です。

1. 主文字を選択、`Ctrl + D` で**複製** 1 部；
2. 複製した方を**濃色**（背板より少し濃い、または純黒）へ；
3. 方向キーで**後ろへ、下へ各 1～2 小ステップ**（0.1 グリッドステップで十分）動かす；
4. それが主文字を覆ったら、前後関係が逆——主文字をもう 1 歩前へ動かせば OK。

これで透視図から見ると：濃色字が後ろ、明色字が前、**視覚的に「浮かぶ」**。これは平面デザインの「投影法」で、3 次元でも同様に効きます。

❓ **考えてみよう**：なぜ「後ろ ＋ 下」のずらしが「後ろだけ」より効果的か。——現実では光は通常**上**から当たり、影は自然に物体の**下やや後ろ**に落ちるから。日常の光の経験に合うずらしだから、脳はそれを「本物」と認めます。

💡 より強い立体感が欲しい？影文字を**さらに 2～3 部複製**し、各々を順に後ろへずらし、色を徐々に濃く——「多層押し出し」の偽厚み効果に。層が多いほど重厚だが、糊になりやすく、3 層前後が最も粋です。

### 42.5 ステップ 4：支柱を加え、看板を立たせる

1. `cylinder` **円柱**を 2 本引っ張り、均等スケールで細く長く；
2. `PgUp` / 方向キーで背板の**下両側**に差し込み、上端を背板に少し入れる（ここで**故意の交差**は正しく、継ぎ目を隠せる）；
3. 色は**濃灰 / 木色**。

💡 2 本目の柱を引き直すな——1 本目を選択し `Ctrl + D` 複製、さらに `←` / `→` で反対側へ。**対称な物はすべて複製を使え、手配置より永遠に正確。**

### 42.6 ステップ 5：横書き vs 縦書き

同じ言葉でも、レイアウトを変えると気質が全く違います。

| 組み合わせ | 気質 | 向く |
|---|---|---|
| 横書き + 黒体 + 太字 | モダン、商業 | 店招、イベント横断幕 |
| 縦書き + 楷体 + 大文字サイズ | 伝統、荘重 | 扁額、書院、茶館 |
| 横書き + Times + 太字なし | 西式、正式 | 英文標識、説明札 |
| 横書き + Courier | 技術、レトロ | テクノロジー感、タイプライター風 |

✏️ **やってみよう（対比実験）**：同じ「茶」の字を 2 版作る——1 版は横書き黒体、1 版は縦書き楷体大文字サイズ ＋ 木色背板。シーンに並べ、「正面図」から 1 眼。直感できるでしょう：**フォントとレイアウト自体が話している**、内容はまだ変わらないのに気質は天と地の差。

### 42.7 よくある失敗点まとめ

| 現象 | 原因 | 解決 |
|---|---|---|
| 字が法外に大きく、シーンを覆う | 文字サイズ既定 80、体塊尺度と不一致 | 文字サイズを小さく、またはテキスト全体を縮小 |
| 字と背板がちらつき貫通 | 両者共面（Z-fighting） | 方向キーで字を外へ 1～2 ステップ |
| 遠目で一团に糊 | 字と背板の明度差不足 | 明暗対比を強め、または字に太字 |
| 文字が背板端を超える | 文案が長すぎ | 文字サイズを小さく、または背板を広く |
| 文字サイズが変えられない / 方向キー効かない | カーソルが数値入力枠に残っている | まず画面空白をクリック（第 32.5 節） |

### 42.8 上級チャレンジ

1. **両面看板を作る**：組（背板 ＋ 字 ＋ 影）を全選択後複製、`Shift + A` で 180° 回転、背面へ配置し、両面見える立式看板に。
2. **発光文字効果**：主文字色を明るい黄に、背板を濃黒に、さらに字の後ろに半透明（不透明度 0.3）の浅黄薄板を「光輪」として置く。
3. **プロジェクト 1 と連動**：この看板を第 41 章の小さな家の前に配置、`Ctrl + S` で 1 つの完成シーンに保存。あなたは「家 ＋ 看板」の完全な小景を持っています。

## 第 43 章 プロジェクト 3：ロゴ / アイコンをデザインする

### 43.1 なぜロゴが「最高の練習」か

前 2 プロジェクトは「3 次元の物」を作っていました。これは逆——**平面デザインのように見える**ロゴを作りますが、3 次元手段で実現します。

それは極めて良い練習です、なぜなら：
- **2D 図形**（第 12 章の 20 種）だけで完成し、形状の負担が小さい；
- **整列、階層、配色**という本当のデザイン問題を考えさせられる；
- 成品を「**上面図**」でスクリーンショットすれば、そのまま clean なアイコンになり、アバター / Logo として直接使える。

❓ **考えてみよう**：あなたが見たロゴ（車のマーク、校章、App アイコン）は、たいてい数要素から成る？——通常 3～4 層を超えない：底形 ＋ 主図形 ＋ 点綴 ＋ 文字。**少ないことは精緻、これがロゴデザインの鉄則**。

### 43.2 重要な前提：上面図で作業

⚠️ 本プロジェクトは**全程「上面図」視点で操作**（下部視点ボタン）。

理由：ロゴは「正面を見る」平面構成であり、2D 図形はすべて地面に平らに寝ている（Z=0）。真上から俯瞰すると、あなたが見るのは成品の姿；透視図では近大遠小の歪みがあり、整列は当てずっぽうになります。

💡 これは一般的経験：**何を作るか、その視点で見る。** 地面レイアウトには上面図、高さ調整には正面図、全体効果には透視図。1 つの視点で全程を無理やり支えないで。

### 43.3 ステップ 1：底形（最外層）

1. 左パネルを **2D 図形** に切り替え、底として 1 つ選ぶ：
   - `circle2` 円 → 円形バッジ、最も汎用；
   - `hexagon` 六角形 → テクノロジー、工業感；
   - `octagon` 八角形 → 重厚、標識感；
   - `pentagon` 五角形 → 盾、学院感。
2. シーン**正中央**へ；
3. 均等拡大で適切なサイズに；
4. 色は**濃色**（濃紺 / 濃緑 / ワインレッドどれも映える）。

### 43.4 ステップ 2：内層と主図形（階層を作る）

ロゴの精緻感は八割が「**同心の階層**」から。

1. 底形を選択、`Ctrl + D` で**複製** 1 部；
2. 複製品を**均等縮小**（`-` キー数回、または `Shift + -` で半分）；
3. **肝心なのは**：`PgUp` で**小さく 1 ステップ持ち上げ**——底形の上に少し浮かぶ；
4. **浅色**（白 / クリーム / 明金）に変える。

これで「濃色外輪 ＋ 浅色内芯」の同心構造ができます。

⚠️ **必ず踏む罠**：2 つの 2D 図形が両方 Z=0 だと、狂ったようにちらつき貫通（また Z-fighting、第 41.5 節）。**2D 図形を重ねる時、各層は必ず `PgUp` で小さく 1 ステップ持ち上げ**、高さで分ける必要があります。これが本章で最も重要な操作規律です。

💡 コツを覚えて：**重ねる層ごとに、1 ステップ持ち上げ。** 3 層の図形 ＝ 3 つの異なる高さ。

次に主図形（ロゴの「主役」）を置きます。

| 表現したいもの | どの 2D 図形 |
|---|---|
| 栄誉、評価 | `star` 星形 |
| 愛、公益 | `heart` ハート |
| エネルギー、速さ | `lightning` 稲妻 |
| 医療、救助 | `cross` 十字 |
| 方向、物流 | `arrow` 矢印 |
| 自然、水 | `teardrop` 涙滴 |
| 夜、静けさ | `crescent` 三日月 |
| テクノロジー、接続 | `hexagon` 六角形 |

置き、1 ステップ持ち上げ、対比色に変え、中央に整列。

⚠️ `heart / arrow / crescent / cross / lightning` は**独立した形状パラメータを持たない**ことに注意（第 12.2 節）、大きさを変えるには**均等スケール**か変換コントロールしか使えません。これは故障ではなく、彼ら自身に調整可能なパラメータがないだけです。

### 43.5 ステップ 3：どうやって正中に整列するか

本ツールには**「ワンクリックで中央へ」ボタンがない**（第 10 篇で既述）が、ロゴはまさに整列が肝心。三招の手動整列法：

1. **グリッドに頼る**：上面図下では、地面のグリッド線が物差し。各層の中心を**同じグリッド交点**に合わせ、方向キー（0.1 グリッド）で微調整。
2. **複製に頼る**：複製された副本は**均等スケールだけ行い、平行移動しない**ので、中心はそのまま元の場所——天然に同心。これが最も楽な一招、強く推奨。
3. **数値枠に頼る**：右パネルの位置数値枠（第 36.5 節）に直接数値入力。各層の水平位置を**同じ組の数字**にすれば、絶対に正確な中央。

💡 **ベストプラクティス**：第 2 招 ＋ 第 3 招の組み合わせ。まず複製で同心を保証し、最後に数値枠で数字の一致を再確認。マウスを引っ張るより百倍信頼できる。

### 43.6 ステップ 4：文字環 / 下部文字を加える

1. 「テキストを追加」、ブランド名か年を入力；
2. 文字サイズを**小さく**（ロゴ内の字は通常とても小さい）；
3. フォント：モダン感は「黒体」、学院感は「Times」、伝統感は「宋体」；
4. **最上層**（すべての図形より 1 ステップ高く）へ持ち上げ；
5. ロゴの下や中央の空白へ配置。

⚠️ 本ツールのテキストは**円弧に沿って並べられない**（「環状文字」は不可能）。似た効果が欲しいなら、文字を 1 字ずつ分解し、複製して回転配置するしかない——非常に手間。初心者は**横書き文字を下部に置く**を直接提案、同じくプロフェッショナル。

### 43.7 ステップ 5：図を出す

1. 「**上面図**」をクリックし、ロゴを画面中央に正す；
2. 必要に応じ `F11` で全画面、画面を大きくきれいに；
3. 邪魔を除きたい？座標軸、グリッド面を非表示に（第 28 章）——このステップは肝心、さもないとスクリーンショットにグリッド線が入る；
4. `Ctrl + P` でスクリーンショット PNG 書出；
5. `Ctrl + S` で JSON プロジェクトを 1 部保存、後で配色を変えやすく。

💡 **図を出す三点セット**：上面図 ＋ 補助非表示 ＋ 全画面。 「きれいな成品図」が必要な場面はすべてこれでやりなさい。

### 43.8 配色速査（そのまま使って）

| スタイル | 底色 | 内層 | 主図形 | 文字 |
|---|---|---|---|---|
| 商務重厚 | 濃紺 | 白 | 濃紺 | 白 |
| 自然環境 | 濃緑 | クリーム白 | 緑 | クリーム白 |
| 活力運動 | 明るい橙 | 白 | 濃灰 | 白 |
| 高級奢華 | 純黒 | 金 | 金 | 金 |
| 医療健康 | 白 | 薄青 | 赤十字 | 濃紺 |

⚠️ 初心者が最もよくする配色ミスは**色が多すぎる**こと。ロゴは **2～3 色**以内に抑えれば、すぐにプロフェッショナルに見えます。階層を豊かにしたいなら、**同じ色相の濃淡変化**に頼り（第 18.2 節：色相バーを固定し、大きな色ブロック内だけ上下にドラッグ）、色を増やすのではありません。

### 43.9 上級チャレンジ

1. **一揃のシリーズアイコンを作る**：ロゴを全選択複製 3 部、主図形だけ変え（星 / ハート / 稲妻）、残りは一切動かさず。スタイル統一のアイコン揃いが得られる——これが本当のブランドデザインのやり方。
2. **浮雕感（レリーフ感）を加える**：主図形を 1 部濃色に複製し、片側へ少しずらし、その下の層に置く（つまり 42.4 節の「影文字」技巧を図形に用いる）。
3. **徽章実体を作る**：ロゴ全体の下に `cylinder` の平たい円柱を 1 枚敷き、透視図へ切り戻す——平面ロゴが一瞬に「手に取れる金属徽章」になる。

## 第 44 章 プロジェクト 4：総合シーン《我が家の小さな庭》

### 44.1 この章は「卒業設計」

前 3 プロジェクトは各々一路の腕前を練りました：**体塊組立**（家）、**文字レイアウト**（標語）、**平面構成**（ロゴ）。この章は彼らを**すべて一つのシーンに合わせ**、さらにペン、画像、半透明などの残り技能を加え、一つの完成作品を作ります。

目標：庭付きの小屋——家、塀、小道、木、池、表札、空の雰囲気、すべて揃う。

⚠️ これは本書で最も長い練習、**、数回に分けて** 作ることを提案、每段階終わるごとに `Ctrl + S` で保存。 「段階的保存」の習慣をつけることは、どんな技巧より値打ちがあります。

### 44.2 創作フロー：先大後小、先定後飾

プロのフローと初心者の最大の差は、手速ではなく**順序**。厳密にこの順序で行ってください。

| 段階 | 何をする | なぜこの順序 |
|---|---|---|
| ① 地面を定める | 芝生を敷き、庭の範囲を定める | まず「舞台」を区画、後で参照ができる |
| ② 主体を配置 | 家を置く（プロジェクト 1 の成果） | 最大の物体を先に定位、それが全体比率を決める |
| ③ 区画を分ける | ペンで小道の向きを描く | 空き地で機能区を計画 |
| ④ 中間物を加える | 木、池、塀 | 中程度の体量を埋め、階層を豊かに |
| ⑤ 小物を加える | 小石、花、表札 | 細部は最後に加え、早期の判断妨害を避ける |
| ⑥ 雰囲気を調整 | 色、不透明度、視点 | 調性を統一、仕上げて図を出す |

❓ **考えてみよう**：なぜ「細部は最後に加える」か。——細部は**全体に対するあなたの判断を妨害**するから。小石の山がそこにあると、家の位置が正しいか見極めにくい。まず大関係を死に定め、細部に意味が出る。これは絵画で「全体から局部へ」と言い、3 次元でも同様。

### 44.3 ① 地面を敷く

1. 2D 図形で `square2` 正方形を 1 つ引っ張り、庭の地面まで拡大；
2. 緑 ＋ 「格子（チェック）」テクスチャ ＝ 芝生；
3. 「**上面図**」へ切り替え、範囲が十分か確認——**大きめの方が良い**、後で物が増えるほど、狭いと直しにくい。

💡 最外輪により大きな浅色底板を 1 枚敷くことを提案（「`PgDn`」で芝生より**1 ステップ低く**し、共面ちらつきを避ける）、「庭の外の空き地」とし、画面に境界感が出ます。

### 44.4 ② 家を配置

第 41 章の成果を直接再利用：

- プロジェクトを保存していれば、`Ctrl + O` でインポート；
- 保存していなくても構わず、41.2～41.6 で再度組む（今回はずっと速い）。

配置提案：**真ん中に置かないで**。家を庭の**やや後ろ、やや片側**に置き、前方に大きな空き地を残す——こうすると構図が自然になり、小道や池の場所もできる。

💡 **構図の小知識**：主体を画面正中に置くと、間が抜ける；少し中心から外すと、かえって生き生き。写真で「三分割法」と言い、地面のグリッド線で位置を推測できます。

### 44.5 ③ ペンで小道を描く

これはペンツール（第 24 章）の実戦での古典的用法：

1. 左パネル「ツール」→ **2D ペン**；
2. 色（土黄 / 薄灰）と線幅（道らしく少し太く）を調整；
3. 庭の入り口から家の門前まで、**わずかに曲がった**線を 1 本；
4. 描き終わったらペンツールを抜ける（`Esc` を押すか選択へ切り戻す）。

⚠️ **ペンの二つの規律**：
1. ペン筆跡は描き終わるとそこに「定まり」、**図形のように細かく形を調整できない**——歪んだら `Ctrl + Z` で取り消し描き直し、直そうとしない；
2. ペン筆跡は**スケール非対応**（第 36.4 節）、選択するとスケールモードが無効化され自動で移動へ戻る。

💡 なぜ小道は「わずかに曲がる」而非直線か。——直線は図面のよう、曲線は生活のよう。この小細工でシーンが一瞬「人間味」を持ちます。

✏️ **やってみよう**：まず直線の道を 1 本描き、一瞥；`Ctrl + Z` で取り消し、曲がった道をもう 1 本描き、対比感受。この「二版対比」の方法は、審美を上げる最速の道です。

### 44.6 ④ 木、池、塀を加える

**木**（二段式）：
1. `cylinder` 円柱を細く長く → 幹、濃棕（こんちゅう）；
2. `sphere` 球体 → 樹冠、緑、`PgUp` で幹頂へ；
3. 幹と樹冠を選択（`Shift` 加選、両方選択）→ `Ctrl + D` で木全体を複製 → 別の場所へ。

💡 ここで第 38 章の肝心のメカニズムを使用：**複数選択複製時、二つの部品の相対位置は保たれる**ので、複製されるのは「一整本の完全な木」、バラバラにならない。一列の木を植えるには「複製 ＋ `Shift +` 方向キー」を繰り返すだけ。

⚠️ すべての木を全く同じ大きさにするな——複製後すぐ `+` / `-` で各木に 5% 前後の大きさ差を与え、自然感がすぐ出る。**規則の中に少しのランダム、それがシーンを本物らしく見せる秘訣。**

**池**：
1. 2D 図形 `ellipse` 楕円または `circle2` 円、地面に平らに；
2. `PgUp` で**小さく 1 ステップ持ち上げ**（芝生と共面しない）；
3. 色は薄青、テクスチャは「**波形**」；
4. **不透明度を 0.6 に** —— 半透明の水感が出る（第 20.2 節）。

**塀**（複製アレイの教科書的用法）：
1. `box` を潰して細長い垂直板 1 本 → 1 本の柵；
2. `Ctrl + D` 複製 → `Shift +` 方向キーで 1 グリッド動かす → さらに `Ctrl + D` → さらに動かす……
3. 一辺が埋まるまで繰り返す；
4. その辺が終わったら、`Shift` で整列全体を全選択 → `Ctrl + D` で整列複製 → `Shift + A` で **90°** 回転 → 庭の反対側へ動かす。

💡 第 4 ステップは本書前十篇の集大成：**複数選択 ＋ 複製 ＋ 整組回転 90°**、三技能を一度に使用。このステップを終えれば、あなたは基本的に「卒業」と言えます。

### 44.7 ⑤ 細部小物を加える

- **小石**：`sphere` または `dodeca` 十二面体を縮小、いくつか複製して小道両側に散らし、色は灰系だが**濃淡各々**；
- **花**：`star` 星形（2D）または小球、明色、芝生に点綴；
- **表札**：第 42 章の標語看板の縮小版、門口に掛け、表札番号を書く；
- **写真壁**：「画像を追加」で自分の図を 1 枚（第 23 章）、庭の展示板に。

⚠️ 細部は**克制（控えめ）**に。 「豊かだが乱れない」ところで手を止める。判断基準：上面図へ切り替え俯瞰し、一目で主従が見えなければ、加えすぎ、いくつか削除。

### 44.8 ⑥ 雰囲気を調整し図を出す

**色調を統一**（質感を最も上げるステップ）：

| 望む雰囲気 | どう調整 |
|---|---|
| 朝 | 全体やや浅く、やや冷たく（薄青、クリーム白）、不透明度やや高め |
| 夕暮れ | 全体やや暖かく（橙、褐、金）、影側の色を濃く |
| 童話 | 高彩度（粉、青、明黄）、テクスチャは「ドット」 |
| 極簡 | 黒白灰のみ ＋ 1 つのアクセント色 |

💡 第 18.2 節の技巧で色調統一：**色相バーを固定し、明度と彩度だけ変える**と、全体の色が自動的に「調和」。これが配色で最も省力かつ最も効果的。

**図を出すフロー**（43.7 同様）：
1. 下部で 7 視点すべて試し、一番良いのを選ぶ（通常は「透視図」やや俯角）；
2. 座標軸とグリッド面を非表示（第 28 章）、画面が即きれい；
3. `F11` 全画面；
4. `Ctrl + P` スクリーンショット；
5. `Ctrl + S` でプロジェクト保存。

✏️ **最後の練習**：同じシーンで**三視点の図**を 1 枚ずつ——上面図（平面レイアウト図）、正面図（立面図）、透視図（効果図）。これがまさに建築家が設計案を納品する標準三点セット。あなたはもう作れます。

### 44.9 詰まった時の自己チェックリスト

大シーンを作るとき最も「作るほど乱れる」。詰まったらこの表で自查：

| 症状 | たいていの原因 | どう救う |
|---|---|---|
| 加えるほど乱れ、何をすべきかわからない | 「先大後小」順序を守ってない | 手を止め、上面図で全体を見て、まず大物の位置を死に定める |
| 物が互いに貫通ちらつく | 共面（Z-fighting） | `PgUp`/`PgDn` で階層を分ける |
| 比率が狂い、某物が特別大きい | 参照物がない | 既知の大きさの物体を 1 つ「物差し」として置き、残りはそれに合わせ |
| 色が乱れ、安っぽい | 色の種類が多すぎ | 3 色以内に切り、濃淡で階層 |
| 望む物体が選択できない | 別の物体に隠されている | 視点を変えて再度クリック、またはまず遮蔽物を動かす |
| 方向キーが突然物体を動かさない | 未選択 / カーソルが入力枠 | 第 32.5 節の排錯三連参照 |
| うっかり全部消えた | 誤って `Ctrl + Del` でクリア | `Ctrl + Z` で取り消し；次回は先に保存 |

### 44.10 結課の言葉：『使える』から『作れる』へ

振り返ってあなたのこの道：

- 第 1 篇ではまだ「3 次元とは」と問い；
- 第 5 篇でシーンに話させることを学び；
- 第 8 篇で手をマウスから離し；
- 第 10 篇で一度に一群の物体を指揮；
- 今、あなたは独立して庭付きの小屋を完成させた。

ツールのボタンは有限（20 種 3D ＋ 20 種 2D ＋ 12 種テクスチャ ＋ 8 種フォント）だが、**組み合わせは無限**。作品の高さを真に決めるのは、決してあなたがどれだけボタンを知っているかではなく、次の 3 つです。

1. **分解能力**——複雑な物体を単純な幾何体の組み合わせとして見る；
2. **順序の意識**——先大後小、先定後飾；
3. **審美の判断**——いつ手を止めるべきかを知る。

この 3 つは、本篇の 4 プロジェクトすべてで繰り返し訓練されています。残りは、練習に任せます。

💡 **あなたへの次の提案**：お好みの写真（部屋、街角、玩具）を 1 枚探し、本ツールで「複製」してみてください。似せられなくて構いません——**「似せられない」ところで、あなた独自の問題に出会い、それが進歩の始まり**です。

## 第 45 章 よくある問題のトラブルシューティング

下表は「あなたが見る現象 → たいていの原因 → どう救う」で並べます。大多数の問題は根拠があり、バグだと疑う前に。

| 番号 | 現象 | たいていの原因 | 解決法 |
|---|---|---|---|
| 1 | 方向キー、`+`/`-` が物体に反応しない | オブジェクト未選択、またはカーソルが右パネル数値入力枠にある | まず画面空白をクリック、物体が選択され、入力枠が失焦していることを確認（第 32.5 節） |
| 2 | 2 面がちらつき、互いに貫通 | 2 片が共面（**Z-fighting**） | `PgUp`/`PgDn` でそのうち 1 片を 1 ステップ持ち上げ/下げて分ける（第 41.5、43.4 節） |
| 3 | 文字が法外に大きくシーンを覆う | テキスト既定文字サイズ **80**、体塊尺度をはるかに超える | 文字サイズを小さく、またはテキスト全体を縮小（第 21、41.7、42.3 節） |
| 4 | 文字サイズを変えたのに方向キー効かない | カーソルがまだ数値入力枠に残っている | まず画面空白をクリックし入力枠を失焦（第 32.5 節） |
| 5 | `Ctrl+C`/`Ctrl+D`/`Ctrl+V` に反応なし | 変換コントロールが活性中、または未選択 | まず `Esc` で変換コントロールを抜け、選択後に操作（第 33、39 章） |
| 6 | 複数選択時に `+`/`-` が拒否 | 複数選択時**全体スケール禁止**（「NoScaleMulti」表示） | 複数選択を解除し個別スケール、または変換コントロールでハンドルを引く（第 36.4 節） |
| 7 | ペン筆跡を選択後スケールが無効 | ペン筆跡は**スケール非対応**、自動で移動へ戻る | 大きさを変えるには描き直しのみ（第 24、36.4 節） |
| 8 | ペン/図形が歪み形を変えたい | ペン筆跡は描き終わり即定型、図形のよう细調不可 | `Ctrl+Z` で取消描き直し（第 24、44.5 節） |
| 9 | 中央へとしたいが「中央」ボタンがない | 本ツール**ワンクリック中央なし** | 三招：グリッド、複製同心、数値枠（第 43.5 節） |
| 10 | テキストを円弧に並べ（環状文字）できない | 本ツール**環状文字非対応** | 横書き文字を下部に置くか、1 字ずつ分解して回転配置（第 43.6 節） |
| 11 | 一部の 2D 図形（ハート/矢印/三日月/十字/稲妻）に「形状パラメータ」スライダーがない | 彼ら**自身に独立調整パラメータなし** | 均等スケールか変換コントロールで大きさのみ変更可（第 12.2、43.4 節） |
| 12 | シーン全体や重要な物を誤削除 | `Delete` の手滑り、またはシーンクリア | 即 `Ctrl+Z` で取り消し；段階的 `Ctrl+S` の習慣を（第 44.1 節） |
| 13 | JSON 読込で「読み込み失敗」 | ファイル破損、または本ツール出力形式ではない | 本ツールの `Ctrl+S` で出力した `.json` を確認（第 6 章） |
| 14 | 視点ボタンが光らず、カメラ回転後消える | 自由回転後「透視図」ボタンが消える（正常現象） | ある視点ボタンをクリックし再整列即可（第 28 章） |
| 15 | 📱🤖 タッチでドラッグしても視点が回るだけで矩形が出ない | タッチ形態は先に**範囲選択モードを有効化**する必要がある | 下部バーの「ボックス選択」をタップ（青くなる）してから 1 本指ドラッグ。**1 回で自動解除**されるので、続けるには再タップ（7.4 節） |
| 16 | 全体色を変えたのに某物が変わらない | その物に**独立色上書き**がある、または「無色」状態 | 選択して個別に色変更（第 18 章） |
| 17 | スクリーンカラーが使えない | 先に取色器ツールを活性していない | 色調整区の取色器ボタンをクリックしてから吸う（第 18 章） |
| 18 | スクリーンショットにグリッド線/座標軸 | 補助要素を非表示にしていない | 座標軸とグリッド面を非表示にしてから `Ctrl+P`（第 28、43.7 節） |
| 19 | 複製した物体が「バラバラ」 | 複数選択複製前に一群を全部選択していない | `Shift` で全体組をすべて選んでから `Ctrl+D`（第 38 章） |
| 20 | 視点/物体の回転方向が逆 | 軸を混同：`A/D` は Y、`W/S` は X、`Q/E` は Z の周り | 第 47 章早見表を見て押す、または `Shift`+方向キーで大角度試（第 32、34 章） |

💡 **排查の第一性原理**：90% の「おかしい」はただ三つの根因——**未選択**、**カーソルが入力枠**、**2 片が共面**。まずこの三句を唱え、次に表で対症、半分の時間を節約。

### 45.2 形態別の問題

上の表はほとんどが 4 形態共通です。以下は特定の形態でのみ発生します：

**🖥️📱 Web 版**

| 現象 | 原因 | 解決法 |
|---|---|---|
| 開いても真っ白 | リソースが読み込めていない、またはブラウザが古い | 再読込；`F12` でコンソールの赤いエラーを確認；新しい Chrome / Edge を試す |

**💻 PC 版**

|---|---|---|

| 前回異常終了して進捗を失った | — | PC 版には**クラッシュ復元**があるので、再起動時の復元確認に注意 |
| ファイルをドラッグしても反応しない | `.json` プロジェクトファイルではない | 本ツールが書き出した `.json` のみ対応 |

**🤖 Android 版**

| 現象 | 原因 | 解決法 |
|---|---|---|
| apk をインストールできない | 「提供元不明」が未許可 | 設定 → セキュリティ → 該当アプリに不明なアプリのインストールを許可 |
| 「全画面」ボタンが無い | Android 版は元々全画面 | 仕様どおりなので探す必要はありません |
| 書き出したファイルが見つからない | アプリのストレージ内にある | 書き出し直後の**共有**シートから送るか、ファイルマネージャでアプリのディレクトリを確認 |
| 戻るキーで作品を失うのが不安 | — | 終了確認が出るので「**保存して終了**」を選ぶ |

### 48.6 色の使用提案

本ツールに固定の「色番号表」はなく、色は**プリセット色板 ＋ カスタム取色 ＋ スクリーンカラー**で取得（第 18 章）：

- 色選びは優先的に**プリセット色板**（色相別グループ、色相バー固定で最も調和色を作りやすい）；
- 正確な色が欲しいなら**カスタム取色**（色値入力）；
- 「画面内のある色」が欲しいなら**スクリーンカラー**で吸う；
- 配色鉄則：**2～3 色以内**に抑え、同じ色相の濃淡で階層を引く方が、色を増やすよりずっとプロフェッショナル（第 43.8 節）。

# 第 13 篇 付箋と多言語

ここまでで「道具の使い方」は身につきました。この篇は「学びを支える」二つの小さな話：読みながら付箋を取ること、と説明書自体が多言語であることです。

## 第 49 章 読みながら付箋：説明書の中の付箋

学習中、ある段落に「印をつけたい」ことがよくあります。説明書なら本文で**文字を選択 → 付箋を追加**できます：

1. 説明書を読みながら任意の文字を選択：
   - 🖥️💻 **マウス形態**：左ボタンを押したまま**ドラッグ選択**；
   - 📱🤖 **タッチ形態**：文字を**長押し**して選択ハンドルを出し、両端をドラッグして範囲を調整；
2. 離すと「付箋を追加」ボタンが出るのでクリック；
3. 選択した文字がハイライトされ、**付箋リスト**に記録される；
4. リストの各項目は個別に**削除**できる——削除前に確認ダイアログが出て、誤削除を防ぐ。

> 💡 付箋は「文字について回る」：選択したその文に紐づくので、後で「当時何を考えていたか」を振り返れる。

## 第 50 章 付箋ウィンドウ：画面に「貼る」

付箋リストをいちいち探すのが面倒なら、付箋を**フローティングウィンドウとして展開**できます：

- 付箋ウィンドウはキャンバス上に浮くドラッグ可能なカードで、操作の邪魔にならない；
- **閲覧**と**編集**の二状態：閲覧は付箋のように、編集は文字を変えられる；
- 不要になったら閉じるボタン（`closeSticky`）をクリック；画面から消えるが、付箋自体はリストに残る。

### 50.1 💻 PC 版だけ：付箋をメインウィンドウの外へ

PC 版では付箋を**本当に独立したシステムウィンドウ**にできます：

- **常に最前面**に表示され、他のどのプログラムよりも上に浮きます；
- サブディスプレイへドラッグして移動できます；
- ブラウザで調べ物をしていても、付箋は見えたままです。

「チュートリアルを見ながら操作する」場面でとても便利です。他の 3 形態では、付箋はアプリの画面内にしか浮かべられません。

### 50.2 付箋を閉じる順番（📱🤖 タッチ形態の注意）

🤖 Android 版で**システムの戻るキー**を押すと、**まず付箋が 1 つずつ閉じ**（未保存の内容があれば先に確認）、次に目次、次に説明書、最後にアプリ終了の確認となります。

> 📌 付箋は「仮のメモ」に向く：例えばあるパラメータの説明を脇に貼り、作業しながら見る。

## 第 51 章 多言語：説明書もあなたの言葉を「話す」

界面も説明書も四言語をサポート：

| 言語 | 界面 | 説明書 |
| --- | --- | --- |
| 簡体中文 | ✅ | ✅ |
| 繁體中文 | ✅ | ✅ |
| English | ✅ | ✅ |
| 日本語 | ✅ | ✅ |

切り替え方：設定で言語を選ぶと、界面の文言と説明書の本文が**同時に**その言語版に切り替わる。説明書の多言語コンテンツは `docs/使用说明书.md`（簡体）、`使用说明书_en.md`、`使用説明書_ja.md`、`使用說明書_zh-TW.md` に分かれている。

✅ **4 言語 × 4 形態を完全網羅**：どの版を使い、どの言語を選んでも、読めるのは同じ「3 版対応済み」の説明書です。💻 PC 版では**拡張センター**から追加の言語パックを導入することもできます。

> ⚠️ 削除確認について：すべての削除（付箋、シーンオブジェクト）はシステム標準ではなく**カスタム確認ダイアログ**を通るので、**フルスクリーン／没入モード**でも確実に表示され、「クリックしても反応しない」ことはない。
