# Cube3D Workshop（立方・3Dグラフィックデザイン工房） — 使用説明書

## ゼロから熟達までの発見的教材（Web版・PC版・Android版 共通）

> 本書は冷たい機能リストではなく、**一緒に学び、一緒に作り、一緒に考えられる**教材である。
> あなたが3Dデザインに触れたことがなく、専門ソフトを使ったこともないと仮定する。私たちはあなたの隣に座る先生のように、
> 「3Dとは何か」から始め、問いかけで思考を導き、類推で直感を作り、練習で手触りを定着させ、
> 最終的に「ボタンの押し方」から「独りで創作できる」へと導く。

> 📦 **一冊で、四つの形態**：本ツールにはWeb版、PCデスクトップ版、Android版の三つのリリースがあり、
> このうちWeb版はさらにデバイスに応じて自動的に**マウスモード**と**タッチモード**に分かれる。
> 本書は**この四つの形態を同時にカバー**し、操作に差異がある箇所はすべて「形態ラベル」で各端末でのやり方を明確にお知らせする。

## 初回起動：サービス利用規約とプライバシーポリシー

どの端末を使うにせよ、本ツールを**初回起動**すると「**サービス利用規約とプライバシーポリシー**」の同意ゲートがポップアップする：

- ページには『サービス利用規約』『免責事項』『プライバシーポリシー』の三つの文書が表示される（リンクをクリックすると全文を確認できる）；
- すべての条項を**先に読み、チェックして同意**してから、「**同意して続行**」をクリックしないとエディタに入れない；
- 「**同意せずに終了**」を選択した場合、プログラムは終了を試み、**本ソフトを利用することはできない**。
  - Web版では、多くのブラウザがユーザーが自ら開いたページをスクリプトで閉じることをブロックする。その場合、**「利用規約への同意が必要です」**という終了失敗パネルが表示され、「**再読する**」をクリックすると同意ゲートに戻って再読・再同意できる。

> ⚠️ これは強制の事前ステップである：同意していない限り、いかなる機能も利用できない。初回起動時にこのポップアップに必ず気をつけ、フリーズしたと誤解しないようお願いする。

## まえがき：3Dに全く触れたことがないあなたへ

このWebページを開いたとき、少し緊張したかもしれない：3D？モデリング？それは長くソフトを学ぶ必要があるのではないか？

まず深く息を吸って吐いてほしい。🙂

あなたの目の前にあるこのツールは、**純Webの3Dエディタ**である——インストール不要、グラフィックドライバ不要、講習への申し込み不要。それは「3Dの世界を創る」ということを、「ポチッと、ドラッグ、数文字入力」という程度に圧縮している。

多くの初心者が最初の一歩でつまずくのは、用語の洪水に怖がるからである：座標軸、変換、グリッド、テクスチャ……。実はこれらはすべて生活に根ざしている：

- **座標軸**は、あなたの部屋にある「前—後、左—右、上—下」の三本の見えない物差しのようなもの；
- **変換**は、「位置を動かす、体の向きを変える、大きさを変える」こと；
- **グリッド**は、床にあるマス目で、大きさや距離を判断する手助けになる；
- **テクスチャ**は、一枚の画像を物体の表面に「貼る」ことで、壁に壁紙を貼るようなもの。

本書はこれらの概念を一つずつ分解し、あなたに分かる言葉で明確に説明する。私たちは「まず定義を暗記してから操作する」という旧来の道を歩まず、**まずあなたにものを作らせ、後からそれがなぜそうなのかを理解させる**。これが「発見的」ということである。

この本を読み終わる頃には、あなたは次のことができるようになっている：

1. 任意の図形を独りで配置し、調整し、色を付けられる；
2. 文字、画像、ペンでシーンを豊かにできる；
3. ショートカットで効率を「流れるように」高められる；
4. 家、標語、徽标までの完全な作品を完成できる。

準備はできたか？まず五分ほどかけて、手元のこのバージョンを確認しよう。

## 第0章 四つの形態と本書の読み方

手を動かす前に、三分ほどかけて確認してほしい：**あなたが今使っているのはどの形態か？** これが後の各章で、どのラベルを見るべきかを決める。

### 0.1 三つのリリース、四つの利用形態

本ツールは**三つのバージョン**をリリースしているが、Web版がデバイスに自動適応するため、実際の利用では合計**四つの形態**になる：

| 形態 | どう手に入れるか | 自分が使っているとどう確認するか |
| --- | --- | --- |
| 🖥️ **Web・マウス** | ブラウザでオンラインアドレスを開く | 画面にマウスポインタがある；「キーボードショートカット」ヘルプ領域は「設定 → 快捷操作」ポップアップに表示される（いずれのパネルにも常駐しない） |
| 📱 **Web・タッチ** | スマホ/タブレットブラウザで同じアドレスを開く | 底部ツールバーに「框选」「全選」ボタンが現れる；「ジェスチャ操作」ヘルプ表がある |
| 💻 **PC 版** | `.exe` をダウンロードしてインストール、または解凍して実行 | ウィンドウ右上に自前描画の「最小化 / 最大化 / 閉じる」がある |
| 🤖 **Android 版** | `.apk` をダウンロードしてインストール | 底部に「框选」「全選」がある；スマホの戻るキーを押すと終了確認が出る |

💡 **Web版は自動判別される**：デバイスが「精密ポインタ（マウス）」か「粗略ポインタ（指）」かを検出し、それに応じて対応モードに自動切り替えるため、**あなたが設定することは何もない**。

⚠️ パソコンのブラウザで**タッチ版**がどう見えるかをプレビューしたい場合（例：授業デモ用）、URLの後ろに `?touch` を付ければよい。例：
[`https://cub3d-editor.cn/Web/index.html?touch`](https://cub3d-editor.cn/Web/index.html?touch)（中国国内）または [`https://yushichadao.github.io/Cub3D-Editor/Web/index.html?touch`](https://yushichadao.github.io/Cub3D-Editor/Web/index.html?touch)（海外）。逆に、Android版はデフォルトで常にタッチレイアウトである。

### 0.3 最も核心的な差異：指には"右クリック"も"ホイール"もない

四つの形態の中で、本当に筋肉記憶を変える必要があるのは、実はただ一つのことである：**入力方式**。

マウスには三つの独立した信号（左ボタン、右ボタン、ホイール）があるが、指には一つ（押下−移動−離す）しかない。だからタッチでは**指の本数**で意図を区別しなければならない：

| やりたいこと | 🖥️💻 マウス（Web・マウス / PC） | 📱🤖 タッチ（Web・タッチ / Android） |
| --- | --- | --- |
| オブジェクトを選択 | 左クリック | 一本指で軽くタップ |
| 図形を配置 | 左クリックで地面 | 一本指で地面を軽くタップ |
| 視点を回転 | **右ボタン**ドラッグ | **一本指**で空白をドラッグ |
| 視点を平行移動 | **中ボタン**ドラッグ | **二本指**で一緒にドラッグ |
| 視点を拡大縮小 | **ホイール**スクロール | **二本指**でピンチ / 広げ |
| 複数選択 | `Shift` + 左クリック | 「全選」を押す、または「框选」を使う |
| 枠選択 | 直接左ドラッグで矩形 | まず「框选」ボタンを押し、それから一本指でドラッグ |

💡 **一言で覚える**：**マウスは「どのキーを押すか」、指は「何本の指を使うか」を見る。**

### 0.4 タッチ端末の二つの専用ボタン

キーボードがないため、タッチ形態（📱 Web・タッチ と 🤖 Android）は底部ツールバーに二つのボタンを追加しており、これらは `Ctrl+A` と「ドラッグ枠選択」を代替する：

- **「全選」**：マウス端の `Ctrl + A` と等価で、ワンタップでシーン内の全オブジェクトを選択；
- **「框选」**：押すと枠選択モードに入り（ボタンが青くなる）、その後一本指で矩形をドラッグすると、枠内のオブジェクトがまとめて選択される。
  ⚠️ **注意**：枠選択は**一度完了すると自動的にそのモードを抜ける**（ボタンは元の色に戻る）。もう一度枠選択したい場合は、**再度「框选」を押す**必要がある。これは誤タップを防ぐための設計である。

> 🤖 **Android版の制限**：「框选」「全選」の二つのボタンは、**選択 / 変換**モードのときのみ利用できる；ペン、テキスト、消しゴムなどのツールモードにあるときは、これらは**灰色で無効**になり「先に「選択/変換」モードへ切り替える必要があります」と表示される。これはツールのクリックロジックとの衝突を避けるためであり、機能欠如ではない。

### 0.5 PC版専用：それを"本物のソフト"として使う

PC版は単なる「殻を被ったWeb」ではなく、デスクトップソフトにしかない能力を追加で提供する：

- **ウィンドウ制御**：右上に自前描画の最小化 / 最大化 / 閉じるボタン；
- **ドラッグ＆ドロップ取り込み**：`.json` プロジェクトファイルを直接ウィンドウに**ドラッグ**するだけで開け、「取り込み」ダイアログを経由しなくてよい；💻 PC版は**画像ファイル**をウィンドウにドラッグすることもサポートしており、ドラッグして放すと画像オブジェクトとして配置される；
- **クラッシュ復旧と自動保存**：予期せず閉じた後で再び開くと、「保存されていないセッションを検出しました」という案内が出て、自動保存された進捗を復旧するか尋ねる（現在のオブジェクト数も表示）；そのまま閉じれば破棄となるが、**それでも能動的にエクスポートすることを勧める**；
- **付箋常時最前面フロート**：付箋を**常に最前面**のフローティングカード（ページ内フロート）として展開でき、他の資料を見ながらメモできる；
- **付箋**：説明書の本文で文字を選択して付箋を追加し、その付箋を常時最前面フロートとして展開できる（詳細は第十三篇を参照）。

### 0.6 Android版専用：戻るキーと終了保護

Android版で最も注意すべきは**スマホの戻るキー**の挙動であり、これは段階的である：

> 戻るキーを押す → 付箋が開いていれば一つずつ閉じる（未保存の内容があれば先に尋ねる）→ 次に目次を閉じる → 次に説明書を終了する → 最後にアプリの終了を尋ねる。

アプリを終了するときは確認ダイアログが出て、三つの選択肢が与えられる：**保存して終了 / 保存せず終了 / キャンセル**。これはせっかく組み立てたシーンが誤タップで消えるのを防ぐためである。

💻 **PC版とWeb版**にも「終了時の保存確認」がある：あなたが**ウィンドウを閉じる / プログラムを終了**するとき、シーンが未保存であれば確認ダイアログが出る——PC版は「シーンに未保存の変更があります / 閉じる前に保存しますか？」を表示し、Web版は「現在のシーンを保存しますか？保存されていない内容は終了後に失われます。」を表示し——三つのオプション（順序は「キャンセル / 保存しない / 保存」）を提供する；保存先を選ばなかった、または保存に失敗した場合は、それでも終了してよいか再度確認する。これはAndroidの「戻るキーによる段階的終了」の発動タイミングとは異なるが、目的は一致している——あなたの作品が誤って失われないよう保護することである。

💡 Android版には**「全屏」ボタンがない**。なぜならもともと全画面で動作するアプリだからである。

### 0.7 "ネット接続"と"データ安全"について

| | ネット接続必要？ | データはどこに？ |
| --- | --- | --- |
| 🖥️📱 Web版 | 必要（ページ読み込み時） | すべての計算はあなたのデバイスのローカルで完了し、**作品データを一切アップロードしない** |
| 💻 PC 版 | **完全に不要** | すべて本機内 |
| 🤖 Android 版 | **完全に不要** | すべて本機内 |

三つのバージョンとも**あなたの作品をいかなるサーバーにも送信しない**。Web版がネットに繋ぐのはページをダウンロードするためだけであり、開いた後のすべての創作はあなた自身のデバイス内で行われる。

❓ **考えてみよう**：ネットのない教室で生徒に授業する場合、どのバージョンを選ぶか？（ヒント：上表の最後の行を見る）

✏️ **やってみよう**：0.2の総表と照らし合わせ、自分のデバイスで探してみよう——「框选」ボタンは見えるか？「キーボードショートカット」領域は見えるか？これで自分が四つの形態のどれを使っているかを確認し、覚えておこう。後の各章で形態ラベルに出会ったとき、どの項目を見るべきか分かるはずだ。

## 第1章 「3D」を再認識する：ある写真から始める

### 1.1 二次元と三次元、何が違う？

スマホで机の写真を一枚撮る。写真は**二次元**である：幅も高さもあるが、指で触れると平らだ——それはただ「見た目に」立体感があるだけである。

今、机の横に回ってもう一度見てみる。本物の机は**三次元**である：幅と高さがあり、さらに**深度**（机の脚が前に突き出している部分）がある。あなたが動くと、見える形が変わる；しかし写真は永遠にその瞬間のままである。

💡 **一言で覚える**：二次元は「絵」、三次元は「その中を動き回れる本当の空間」である。

### 1.2 このWebページがくれるのは"3Dステージ"

エディタを開くと、中央のそのキャンバスが一つの3Dステージである。左側で図形を選び、「地面」の上をポチッとすると、それは本当にステージの中に「落ちて」くる——背後に回り込んで見たり、持ち上げたり、上から見下ろしたりできる。

❓ **考えてみよう**：友人に「青い箱の左にある赤い球」を説明する場合、二次元の写真を用いるのと三次元のシーンを用いるのと、どちらが誤解されにくいか？なぜか？

### 1.3 なぜ"軽量三端"にしたのか？

従来の3Dソフト（Blender、Mayaなど）は強力だが、インストーラーが軽くて数百メガ、インターフェースがびっしり詰まっている。本ツールはコア能力を一つの軽量エンジンにし、三つのバージョンに包んでいる：

- 🖥️📱 **Web版**：URLを開くだけですぐ使え、閉じればすぐ去り、ディスクを占領しない；
- 💻 **PC 版**：一度インストールすれば、以降は**完全オフライン**で、ファイルのドラッグ＆ドロップで開くこともできる；
- 🤖 **Android 版**：スマホに入れれば、通勤中などいつでもどこでも模型を捏ねられる。

三者に共通する利点：

- すべての計算はあなた自身のデバイスのローカルで完了し、**いかなるデータもアップロードしない**；
- エクスポートされるのは通常の JSON ファイルと PNG 画像で、保存と共有に便利；
- **プロジェクトファイルは三端共通**——スマホでエクスポートした `.json` は、PC版でそのまま続きを編集できる。

💡 この点は重要である：**同じ作品を端末を跨いでリレーできる**。スマホでひらめいたらまず下書きを組み、家に帰ってPC版で精修する。

✏️ **やってみよう**：手元の形態を確認し（[第0章](jump:第0章 四つの形態と本書の読み方)参照）、ツールを開き、中央のキャンバスと周囲のパネルが見えればよい。まだ急いで操作しないこと、ただ「環境を認識する」だけだ。

💡 初回起動時はごく短い読み込み（3Dエンジンの初期化）があり、読み込み層が消えればメイン画面に入る。

## 第3章 インターフェース全景：目の前の五つのエリア

インターフェースを五つに分け、それぞれが役割を持つ。読みながら、画面で対応する位置を見つけてほしい。

### 3.1 トップバー（最上部）

横一列のボタンで、三組に分かれる：

- **ファイル組**：新規、取り込み、エクスポート、スクリーンショット；
- **編集組**：元に戻す、やり直す、コピー、貼り付け、クローン、クリア；
- **表示組**：座標軸スイッチ、グリッド面スイッチ、地面スイッチ、設定。

**各端末のトップバーの差異**：

- 🖥️📱 **Web版**：上記ボタンのほか、「全屏」ボタンがあり、ページを画面いっぱいにする。
- 💻 **PC 版**：ウィンドウ右上に自前描画の**最小化 / 最大化 / 閉じる**の三つのウィンドウボタン；**F11** を押すかタイトルバーの「最大化」ボタンをクリックすると切り替わるのは**ウィンドウ最大化 / 元に戻す**（独立した「全屏」ボタンはない）。
- 🤖 **Android 版**：**「全屏」ボタンはない**——アプリ自身が全画面で動作するため、置いておく意味がない。

💡 これらのボタンの多くにはショートカットがある（例：`Ctrl+Z` で元に戻す）。後半の効率篇でまとめて説明する。
⛔ 📱🤖 タッチ形態には物理キーボードがないため、**直接ボタンをタップ**すること；タッチ専用の「全選」「框选」ボタンは3.5を参照。

### 3.2 左面板（素材取得、ツール選択）

左面板は上から下へ四つの区：

1. **3D 図形**：20種の立体形状（立方体、球、円柱……）；
2. **2D 図形**：20種の平面形状（円、ハート、矢印……）、ステッカーのよう；
3. **ツール**：選択/変換、3Dペン、2Dペン、消しゴム、テキスト追加、画像追加；
4. **変換モード**：平行移動、回転、拡大縮小、および等比拡縮。

### 3.3 画布（中央ステージ）

すべての図形はここに表示される。操作方式は形態により異なる：

- 🖥️💻 **マウス端（Web・マウス / PC）**：**右ボタン**ドラッグで視点回転、**ホイール**で拡縮、**左ボタン**で選択または配置。
- 📱🤖 **タッチ端（Web・タッチ / Android）**：**一本指**ドラッグで視点回転、**二本指**ピンチで拡縮・二本指ドラッグで平行移動、**一本指軽タップ**で選択または配置。

💡 完全な対照は [第0章 0.3 节](jump:第0章 四つの形態と本書の読み方) の入力方式表を参照。

### 3.4 右面板（選択後にパラメータ調整）

何らかのオブジェクトを選択して初めて、右面板が「活き」だす：色を変え、模様を貼り、不透明度を調整し、変換数値を設定し、テキストを編集する……。ここは作品を細かく制御する場所である。

### 3.5 底栏（最下部）

一排に7つの視点ボタン：透視、顶視、底視、正視、後視、左視、右視。ワンタップで角度を変えてシーンを見る。

📱🤖 **タッチ端にはさらに二つのボタンが加わる**：

- **「全選」**：ワンタップでシーンの全オブジェクトを選択（マウス端の `Ctrl + A` を代替）；
- **「框选」**：押すと枠選択モードに入り、一本指で矩形をドラッグして一片のオブジェクトを選択。**枠を選び終わると自動退出**し、もう一度枠選択するには再び押す必要がある。

🖥️💻 マウス端はこの二つのボタンを表示しない——なぜなら `Ctrl+A` を直接押せるし、左ドラッグで枠選択も直接できるため、追加ボタンは不要だからである。

### 3.6 快捷操作ヘルプ：「設定 → 快捷操作」で確認

画面にショートカット / ジェスチャの一覧を**常駐表示しない**。マウス端とタッチ端の対応操作説明は、すべて「設定 → 快捷操作」ポップアップにまとまっている：

- 🖥️💻 **マウス端**：ポップアップ内に「**キーボードショートカット**」一覧を表示；
- 📱🤖 **タッチ端**：ポップアップ内に「**ジェスチャ操作**」対照表を表示。

参照したいときは、トップバーの「設定」ボタンを押し、「快捷操作」を選べばよい。

💡 これは意図的なものである：ヘルプを常駐パネルではなくポップアップに収め、創作空間の占有を避けている。

### 3.7 狭い画面の場合どうする

スマホや狭いウィンドウ（幅が約960ピクセル未満）では、左右のパネルが**自動的に畳まれる**。端の小さなボタンを押せば展開できる。設計上「小画面でも使える」ことを保証している。

📱🤖 タッチ端で入ったときは通常すでに畳まれた状態であり、まず左面板を開いて素材を取り、配置が終わったらまた畳むと、最大のキャンバス空間を得られる。

❓ **考えてみよう**：なぜ「パラメータを変える」のは右に、「素材を選ぶ」のは左に置くのか？その裏には、ほとんどのデザインソフトに共通する「左で素材取り、右でパラメータ調整」の習慣がある。あなたは賛成か？

✏️ **やってみよう**：
- 🖥️💻 マウスをトップバーの各ボタンに順にホバーさせ、文字のヒント（tooltip）が出るか見る。
- 📱🤖 トップバーの各ボタンを順に**長押し**し、ヒントを観察；さらに底栏の「全選」「框选」がどこか探してみる。

### 3.8 テーマ：界面に「着替え」を

「設定 → テーマ」には、**12 色のテーマ**があります。クリックするだけで即座に反映され、プレビューもその場で確認でき、再起動は不要です：

| Neon | ネオン紫 | Gray | ミッドナイト灰 |
| Sunset | サンセット橙 | Light | 澄澈青白 |
| Forest | フォレスト緑 | Aurora | 夜紫 |
| Ember | 緋紅 | Bubblegum | 嫣紅 |
| Slate | 金琥珀 | Paper | クリーム |
| Sky | ミント | Blossom | 淡黄 |

💡 選択は**記憶されます**：次回起動時も現在のテーマが続き、システム設定に上書きされることはありません。

## 第4章 座標系：ページに X / Y / Z と書かれた三本の線

これは本書全体で最も重要な章である。多くの3Dソフトが挫折させるのは、「座標軸が読めない」から始まる。ゆっくりいこう。

### 4.1 まず"数学の座標軸"の荷物を下ろす

数学の授業で三本の軸を見たことがあり、「右手の法則」を暗記したかもしれない。それは一旦忘れよう。本ツールでは、**座標軸とは色と文字ラベルのついた三本の矢印**であり、「このものは空間の中のどの位置にあり、どの方向を向いているか」という一つの問いに答えるためにある。

### 4.2 网页上で実際に見るラベル

「座標軸」表示を開こう（トップバーの 📐 ボタン）。三本の矢印が見え、末端にそれぞれ **X、Y、Z** と書かれ、色がそれぞれ異なる。

> ⚠️ **重要**：本書および本ツールの**インターフェースに書かれた X/Y/Z は、网页表記**であり、ソフト内部実装で使う軸とは完全には一致しない。一般読者は**网页表記だけを見ればよく**、以下の対応関係が画面で本当に見えるものである：

| 网页表記 | 矢印の色 | 表す方向 | 生活化した比喩 |
| --- | --- | --- | --- |
| **X** | 🔵 青 | **前後**（深度） | あなたが「前に進む / 後ろに下がる」 |
| **Y** | 🔴 赤 | **左右** | あなたが「左に移る / 右に移る」 |
| **Z** | 🟢 緑 | **上下**（高さ） | あなたが「つま先立ち / しゃがむ」 |

つまり、この网页では：**Z軸が上を向く一本（緑色）であり、Xが前後（青色）、Yが左右（赤色）である。**

💡 一句の口诀を覚えよう：**「青は前後、赤は左右、緑は上下（Zは天を突く）。」**

### 4.3 なぜ"高さ"が Y ではなく Z なのか？

多くの3Dソフトでは高さは Y である。しかし本ツールの**ページ表記**は高さを Z（緑の一本）にしている。あなたが覚え間違いしたのではなく、**この网页はそう表記しているのである**。本書は最初から最後まで「网页表記」に従って説明するので、画面の色と文字を確認すれば、乱れることはない。

❓ **考えてみよう**：もしあなたが再設計するなら、「高さ」をどの文字に表記するか？文字そのものはただの名前であり、肝心なのは「名前と色、方向」の三者が対応することである。

### 4.4 地面と"高さ = 0"

ステージの底には**グリッド地面**がある。地面は「高さがゼロ」の基準である：何かを地面に置けば、その Z（高さ）は 0 になる；それを持ち上げれば、Z は大きくなる。

网页表記の下では、地面は **X（前後）と Y（左右）** が張る水平面であり、式は「Z = 0」と書かれる。式を覚える必要はなく、ただ：**地面は「足を踏む場所」であり、上（緑軸 Z）へが高くなる** と理解すればよい。

### 4.5 体で三本の軸を感じる

立ち上がり、三つの動作をする：
- 一歩前へ、一歩後ろへ → あなたは **X（青）** に沿って動く；
- 左へまたぎ、右へまたぐ → あなたは **Y（赤）** に沿って動く；
- つま先立ち、しゃがむ → あなたは **Z（緑）** に沿って動く。

これを筋肉に刻めば、後のすべての「オブジェクトを移動」操作に照らし合わせができる。

✏️ **練習**：座標軸を表示し、「上面図」と「正面図」（ボトムバーのボタン）をそれぞれ切り替えて、3本の矢印の向きが自分の体の感覚と一致するか観察してみましょう。上面図では X–Y 平面が見え、正面図では X–Z 平面が見えます。

## 第5章 実践：あなたの最初の3D作品

見るだけでなく、実際にやってみましょう。この章では、スクリーンショットを撮ってシェアできる小さな作品を本当に作ります：**地面に立つカラフルな立方体**です。

### 5.1 第一步：図形を選ぶ

1. 左パネルで「3D 図形」エリアを見つけます（📱🤖 タッチ端末でパネルがしまわれている場合は、まず端の小ボタンをタップして展開します）；
2. 最初の「立方体」（またはお好みの立体）をクリックします；
3. 「配置モード」に入ります：
   - 🖥️💻 マウス/デスクトップ端末：カーソルがキャンバスに入ると**プレビューがカーソルに追従**します；
   - 📱🤖 タッチ端末：指には「ホバー」がないため、**追従プレビューはなく**、タップした場所にそのまま配置されます。

### 5.2 第二步：置く

中央の地面を**クリック**します（📱🤖 タッチ端末は**一本指での軽いタップ**）。立方体が「パン」とグリッドの上に落ちます。おめでとう、あなたの最初の3Dオブジェクトが誕生しました。

💡 落ちた位置がよく見えなくても焦らないで——次章で「選択」を学べばいつでも動かせます。

### 5.3 第三步：それを選択する

左パネルの「選択 / 変換」ツールをクリックし、その立方体を**シングルクリック**します（📱🤖 タッチ端末は**一本指での軽いタップ**）。周囲に矢印や枠が表示され、「選択された」ことを示します。このとき右パネルが点灯します。

### 5.4 第四步：色をつける

右パネルの「色」エリアで：

- 直接**プリセットカラー**（例えば明るいオレンジ）をクリックすると、立方体はすぐに色が変わります；
- より個性的にしたい場合は、カスタム色の「選択ツール」機能を使います。
⚠️ **注意**：「色なし」をクリックしたり、不透明度を 0.1 まで下げたりすると、物体は透明になり、やや「見えなく」なりますが、消えたわけではないので、戻せば大丈夫です。

### 5.5 第五步：動かして、回す

選択したまま、矢印をドラッグして移動（青＝前後 / 赤＝左右 / 緑＝上昇）、リングをドラッグして回転させます。第4章で学んだ3本の軸を体感してください。

### 5.6 第六步：成果を保存する

トップバーの「スクリーンショット」（または `Ctrl+P`）をクリックすると、PNG が得られます。また、JSON を「書き出し」して控えを残し、次回「読み込み」で続きを編集することもできます。

✏️ **練習**：上記の手順を繰り返し、「青い球の左に赤い立方体」という小さなシーンを作り、スクリーンショットを撮って保存しましょう。あなたは、身体の動作（前/後、左/右、上/下）を使って、各物体の位置を友達に説明できますか？

## 第6章 保存と共有：スクリーンショット、書き出し、バックアップ

作ったものは、もちろん残して、見せびらかしたいものです。この章では4つの「保存」方法と、それぞれの適した場面について説明します。

### 6.1 なぜ「こまめな保存」が良い習慣なのか

ページを閉じたり、更新したり、戻るキーを誤って触ったりすると、書き出していないシーンは消えてしまいます。「一区切りしたら JSON を書き出す」習慣をつけると、無数の危機を救えます。

💻 **PC 版とウェブ版は例外です**：これらには**自動保存とクラッシュ復元**（デフォルトでは5分ごとに自動保存され、直近10件のスナップショットが保持されます）があり、予期せず閉じた後に再び開くと「未保存のセッションが検出されました」ダイアログが表示され、最後の自動保存の進捗（オブジェクト数を含む）を復元するかどうか尋ねられます。しかしこれはあくまで「安全網」であり、**能動的な書き出しの代わりにはなりません**。

### 6.2 スクリーンショット：作品の写真を撮る（Ctrl + P）

「スクリーンショット」は、現在の画面を **PNG 画像**として保存します。

- 適している場面：SNSへの投稿、挿絵づくり、他人に「効果を見せる」ため；
- おすすめ：スクリーンショット前にトップバーで**座標軸とグリッド面を非表示**にすると、画面がよりすっきりします；
- 出力サイズは **デバイスピクセル比に応じて自動拡大**（最低 **3 倍**）されるため、キャプチャした PNG は画面で見えるよりシャープで高解像度になり、単に現在のキャンバスの表示ピクセルと等しいわけではない。

**画像はどこに保存されるか？端によって異なります：**

| 形態 | 保存先 |
| --- | --- |
| 🖥️📱 ウェブ版 | ブラウザの**ダウンロード**経由で、システムの「ダウンロード」フォルダに落ちます（スマホのブラウザでは最初に「画像を保存」確認が出る場合があります） |
| 💻 PC 版 | **システムの保存ダイアログ**が表示され、フォルダとファイル名を自分で選べます |
| 🤖 Android 版 | アプリのストレージに保存され、**システム共有**パネルから直接 WeChat / フォト / 他のアプリに送れます |

💡 スクリーンショットは「見た目」だけを保存し、再編集可能なデータは含みません。後で編集したい場合は、以下の「書き出し」を使います。

### 6.3 シーンの書き出し：「編集可能なプロジェクト」を保存する（Ctrl + S / `書き出し` ボタン）

「書き出し」は **JSON ファイル**を生成し、各オブジェクトの位置・色・パラメータ……が記録されます。次回「読み込み」すればそのまま復元できます。

- 適している場面：未完成品、さらに磨きをかける必要のある作品；
- ファイル名は通常タイムスタンプが付きますが、意味のある名前（例：`房子_v1.json`）に変更することをおすすめします。

保存先はスクリーンショットと同じです：🖥️📱 ウェブ版はブラウザのダウンロード経由、💻 PC 版はシステムの保存ダイアログ（ディレクトリを選択可）、🤖 Android 版はアプリのストレージに保存され書き出しを共有できます。

> ✅ **重要**：この `.json` は**三端共通**です。スマホで書き出したプロジェクトは、PC 版で直接読み込んで編集を続けられ、その逆も同様です。

💻 **PC 版のファイル保存（ウェブの「書き出し」とは異なる）**：PC デスクトップ端末はシーンを単なる「JSON の書き出し」ではなく、**ローカルファイル**として管理します：
- **`Ctrl + S` = 保存**：現在開いているそのローカルシーンファイルを直接上書き書き込みします（まだ保存したことがなければ、「名前を付けて保存」が出て場所を選べます）；
- **`Ctrl + Shift + S` = 名前を付けて保存**：現在のシーンを**新しい**ローカルファイルとして保存し、元のファイルには影響しません。
> ウェブ・マウス端末／ウェブ・タッチ端末には「現在のファイル」という概念がなく、`Ctrl + S` は 6.3 の「シーンの書き出し」（JSON を1つダウンロード）となり、両者の意味は異なるため、注意して区別してください。

### 6.4 読み込み：プロジェクトを戻す（Ctrl + O）

以前書き出した `.json` を選ぶと、シーンが再構築されます。⚠️ 読み込みは現在のシーンを**置き換え**ます。手元の作業を先に保存しておきましょう。

各端でのファイル取得方法：

- 🖥️📱 **ウェブ版**：「読み込み」をクリックし、ブラウザのファイル選択ボックスでファイルを選びます；
- 💻 **PC 版**と 🖥️ **ウェブ・マウス**端末：「読み込み」をクリックする他に、**`.json` ファイルをウィンドウに直接ドラッグ**することもできます（未対応のファイル種別は「シーンファイルのみ対応」と表示されます）；💻 **PC 版**はさらに**画像ファイル**のウィンドウへのドラッグに対応しており、ドラッグすると画像オブジェクトとして配置されます；
- 🤖 **Android 版**：「読み込み」をクリックし、システムのファイル選択で `.json` の場所を特定します。

### 6.5 新規作成：最初から始める（Ctrl + N）

「新規作成」はシーン全体をクリアします。危険な操作ですが、「先に書き出しでバックアップ」と組み合わせれば安全です。

### 6.6 🤖 Android 専用：戻るキーで「無駄にならない」

Android 版で戻るキーを押してアプリを終了すると、確認ダイアログが表示され、3つの選択肢が出ます：

- **保存して終了**：現在のシーンを先に書き出してから終了します（推奨）；
- **直接終了**：保存せずに終了します。慎重に使用してください；
- **キャンセル**：残って編集を続けます。

💡 そのため、Android で戻るキーを誤って触れても恐れる必要はありません——ただし、やはり段階的な書き出しの習慣をつけることをおすすめします。

### 6.7 一連の安定したバックアップのリズム

> 作業前に1回書き出し → 重要なノードでさらに書き出し（異なるファイル名で）→ いつでも取り消して戻る。
> （🖥️💻 マウス端末は `Ctrl+Z`；📱🤖 タッチ端末はトップバーの「取り消し」ボタンをタップ。）

✏️ **練習**：第5章で作った「赤い立方体 + 青い球」のシーンを、「スクリーンショット」と「書き出し」でそれぞれ1份ずつ保存し、さらに「読み込み」で戻して、内容が一致することを確認しましょう。
発展：スマホとパソコンを両方持っているなら、**一方の端で書き出し、もう一方の端で読み込み**してみて、プロジェクトファイルの端をまたいだ共通性を体感してください。

# 第二篇 操作基礎篇

## 第7章 オブジェクト選択の技術：単選・複数選択・枠選択

3D の世界では、**「まず選び、それから操作する」**が鉄則です。本章では「選ぶ」という小さな動作を隅々まで解説します。

### 7.1 なぜまず選ばなければならないか

右パネルのパラメータや変換用の矢印は、いずれも「現在選択されているオブジェクトに対して」作用します。選択していなければ、ツールは「誰を変更したいのか」が分かりません。これは、クラス全員に同じ名前が一つだけ書かれた賞状を一斉に配ることができないのと同じで——まずは名前を呼ばなければならないのです。

### 7.2 単選：ワンクリック

「選択 / 変換」ツールを使って、オブジェクトを一度クリックします。それがハイライトされ、コントロールが表示されれば「選択された」ことを意味します。

- 🖥️💻 **マウス/デスクトップ**：**左クリック**；
- 📱🤖 **タッチ端末**：**一本指で軽くタップ**（タップしたらすぐに指を離し、ドラッグしないこと）。

### 7.3 複選：2 つ目、3 つ目……を加える

| 形態 | 複数選択の方法 |
| --- | --- |
| 🖥️💻 ウェブ・マウス / PC | `Shift` を押しながら他のオブジェクトをクリックすると**加算**選択される；すでに選択済みのものをもう一度クリックするとそのオブジェクトが**キャンセル**される |
| 📱🤖 ウェブ・タッチ / Android | `Shift` キーはないが、任意のオブジェクトを**一本指で長押し**できる——未選択なら加選、選択済みなら減選（マウス/デスクトップの Shift クリックと同等）；あるいは下部バーの「**矩形選択**」で一片を囲むか、あるいは「**全選**」ですべてを一度に選ぶこともできる |

💡 複数選択してから変換を行うと、すべてのオブジェクトが一つのグループとして一緒に動き、「グループの中心」を基準とします。

### 7.4 矩形選択：四角をドラッグ

矩形選択は「一度にごっそり掴む」のに適していますが、両端の開始方法は全く異なり、これが最も混同しやすい箇所です：

**🖥️💻 マウス/デスクトップ（ウェブ・マウス / PC）**

**空白部分で左ボタンを押したまま四角形をドラッグ**すると、枠内のオブジェクトがすべて選択されます。いつでも使用可能で、モードの切り替えは不要です。

⚠️ 矩形選択は「空白部分」から開始しなければなりません。オブジェクトの上からドラッグを始めると、**そのオブジェクトを移動する**動作になってしまいます。

**📱🤖 タッチ端末（ウェブ・タッチ / Android）**

指のドラッグはデフォルトで「視点回転」なので、まずプログラムに「今から矩形選択する」と伝える必要があります：

1. 下部バーの「**矩形選択**」ボタンをタップすると、ボタンが青くなり矩形選択モードに入ったことを示します；
2. **一本指で**四角形をドラッグし、選びたいオブジェクトを囲みます；
3. 指を離すと選択完了——**この時点で矩形選択モードは自動的に閉じられ**、ボタンは元の色に戻ります。

⚠️ **重要**：タッチ端末での矩形選択は**一度限り**です。2 回目も連続して矩形選択したい場合は、必ず「矩形選択」ボタンを**もう一度タップ**しなければなりません。これは、視点を回転させたい時に誤って矩形選択してしまうのを防ぐためです。

### 7.5 全選

ワンクリックでシーン内のすべてのオブジェクトを選択します。「クリア」や全体変換と組み合わせると便利です。

- 🖥️💻 **マウス/デスクトップ**：`Ctrl + A` を押す；
- 📱🤖 **タッチ端末**：下部バーの「**全選**」ボタンをタップ。

### 7.6 選択のキャンセル

- **4 端共通**：キャンバスの空白部分をクリック；
- 🖥️💻 **マウス/デスクトップではさらに**：`Esc` キーを押す。

### 7.7 選択のヒント：画面が「何を選んだか」を教えてくれる

本リリース以降、選択状態が変化するたびに、キャンバス上部に**軽量なヒントバー**が浮かび上がります（数秒後に自動で消え、操作の邪魔にはなりません）：

| 状況 | ヒント内容 |
| --- | --- |
| 図形を 1 つだけ選択 | `已选中「立方体」`（そのオブジェクトの名前を表示し、角括弧「」で囲む） |
| テキストを 1 つだけ選択 | `已选中「文本：实际内容」`（オブジェクト名 + コロン + テキスト本文） |
| 2 つ以上を選択 | `已选中 5 个对象`（現在の総数を表示） |
| Shift 加選 / 減選 | 毎回クリックするごとに**現在の**数に更新され、例えば 3 → 4 → 3 |
| すべての選択をキャンセル | `已取消选中` |

💡 このヒントが最も実用的な場面は**矩形選択**と **Shift 連続クリック**です：一つずつ数える必要はなく、数字を見るだけで多めに囲ったか、漏らしたかが分かります。

### 7.8 選択状態でツールバーをクリック：自動的に選択を抜ける

オブジェクトを選択した後、左パネルの以下の **5 つのツール**をクリックすると、エディタはまず**現在の選択を自動的にキャンセル**し、それからそのツールに入り、`已退出选中模式` とヒントを表示します：

- テキスト
- 画像
- 3D ブラシ
- 2D ブラシ
- 消しゴム

これら 5 つのツールはいずれも「キャンバスに新たに描き込む」操作であり、古い選択を残したままだと邪魔になるだけです。

⚠️ これ以外のツール（各種 3D / 2D 図形ボタン）は、**選択済みオブジェクトがある状態でクリックしても効果がありません**——これは意図的な保護であり、パラメータを調整したい時に誤って新しい図形を配置してしまうのを防ぐためです。新しい図形を置きたい場合は、まず選択をキャンセルしてください（🖥️💻 `Esc` を押すか空白部分をクリック；📱🤖 キャンバスの空白部分をタップ）。

### 7.9 選べない？まず以下の点を確認

1. まだ「配置モード」のままではないか？まず「選択 / 変換」ツールに戻る；
2. 選びたいオブジェクトが別のものに隠されていないか？視点を変えて（下部バー）正面から回り込む；
3. それは透明になっていないか（不透明度が最低の 0.1 に下げられていないか）？まず戻す；
4. それは 2D ストロークではないか？一部のブラシオブジェクトは消しゴムや専用ロジックが必要で、通常のクリックでは選択できない場合がある。

❓ **考えてみよう**：複選と矩形選択、どちらが「隣り合わない 3 つのオブジェクトを正確に選ぶ」に適しているか？どちらが「一列をまとめて選ぶ」に適しているか？

✏️ **やってみよう**：5 つの異なる図形を配置し、①そのうち 1 つを単選 ②Shift で 3 つまで加選（ヒントバーの数字の変化に注意） ③一片を矩形選択 ④Ctrl+A で全選 ⑤「テキスト」ツールをクリックし、自動的に選択を抜ける様子を観察する、という練習をする。

## 第8章 変換三兄弟：移動・回転・拡縮

「変換」は 3D 制作で最も頻度の高い動作であり、本質はたった三つのことです：**位置を動かす、向きを回す、サイズを変える**。

### 8.1 三つの変換とは

| 変換 | 生活のたとえ | 画面上のコントロール |
| --- | --- | --- |
| 平行移動（移動） | コップを机の左から右へ運ぶ | 三本の色つき矢印 |
| 回転 | コップの口をこちらへ向ける | 円 / 弧のハンドル |
| 拡縮 | コップを大きくしたり小さくしたりする | 四角いハンドル |

### 8.2 平行移動：三本の軸に沿ってドラッグ

オブジェクトを選択すると、赤・緑・青（ウェブでは Y赤=左右、Z緑=高さ、X青=前後 と注記）の矢印が現れます。

- **赤い矢印**をドラッグ → Y（左右）方向に移動；
- **緑の矢印**をドラッグ → Z（高さ）方向に上昇 / 下降；
- **青い矢印**をドラッグ → X（前後）方向に移動。

💡 一本の矢印だけをドラッグすれば、オブジェクトはその一方向だけに動き、それ以外には引っ張られません。自由に斜めへ移動させたい場合は、矢印と矢印の間の「平面の四角」をドラッグすればよいです。

### 8.3 回転：軸を中心に回す

「回転」モードに切り替えると、オブジェクトがリングに囲まれます：

- リングをドラッグ → 対応する軸を中心に回転します。例えば「正面」が前を向いていたのを左を向くようにするのは、Z（高さ・緑軸）を中心に回すことです。

⚠️ **注意**：回転は「どの軸を中心に」です。口诀を覚えましょう：緑軸（Z）を中心に回す = その場で体の向きを変えるよう；青軸（X、前後）を中心に回す = うなずくよう；赤軸（Y、左右）を中心に回す = 横に首をかしげるよう。

### 8.4 拡縮：サイズを変える

「拡縮」に切り替えてハンドルをドラッグすると拡大縮小できます。デフォルトは**等比**（ロックについては後述の第9章で説明）です。

### 8.5 正確にしたい？右側の数値を使う

ドラッグは感覚まかせ、パラメータは入力まかせ。右パネルには各変換に数値ボックスがあります：

- 位置：X / Y / Z の 3 つの数値（ウェブ注記では下から 前後 / 左右 / 高さ）；
- 回転：3 つの角度；
- 拡縮：比率の値。

💡 「ぴったり揃った」配置を作る時は、同じ数値を直接入力する方が、目分量でドラッグするよりずっと正確です。

✏️ **やってみよう**：立方体を 1 つ配置し、まず矢印をドラッグして右上方へ移動させる；次に右側の数値ボックスで X、Y、Z をすべて整数（例 2, 0, 3）に変更し、正確な落下位置を観察する。

## 第9章 変換モードと均等縮尺

前章では動作を説明し、本章では「モードの切り替え方」と「比率のロックのしかた」を説明します。

### 9.1 三つのモードはどこで切り替えるか

右パネルの下部（オブジェクト選択後）に「平行移動 / 回転 / 拡縮」の 3 ボタンがあり、ショートカット（効率編で詳述）も使用できます。切り替えると、オブジェクトのコントロールが対応する見た目に変わります。

### 9.2 等比拡縮とは

拡縮時には「等比拡縮」スイッチがあります：

- **オン**：任意の方向に同期して拡縮され、形状は**変形しない**（球は球のまま、四角は四角のまま）；
- **オフ**：**単軸で伸縮**でき、例えば球を押しつぶして楕円にしたり、四角を棒状に引き伸ばしたりできる。

⚠️ **注意**：等比拡縮欄は「単選かつ等比拡縮がオン」の時だけ表示されます。複数選択時は無効化されます（変換コントロールで全体を拡縮する）。

### 9.3 テキストは等比拡縮に対応しない

**テキストオブジェクト**を選択すると、以下のことが分かります：

- 右パネルの「等比拡縮」スライダーが行ごと**非表示**になる；
- 「等比拡縮」チェックボックスが**非表示**になる；
- モードボタン内の「拡縮」が**灰色でクリック不可**になる（もし拡縮モードにいた場合は、自動的に平行移動に戻ります）。

理由：テキストはフォントサイズ、フォント、太さなどの組版パラメータからリアルタイムに生成される薄い板状のテクスチャであり、直接引き伸ばすと字形がぼやけて歪みます。**テキストのサイズを変えたい場合は、右パネルの「フォントサイズ」パラメータを使ってください**——これは非破壊です。

### 9.4 いつロックを外すか

「押しつぶした座金」「引き伸ばした柱」「平べったい楕円のレンズ」などを作りたい時は、ロックを外して単軸でドラッグします。これは「標準体」から「個性体」への扉です。

❓ **考えてみよう**：なぜ「押しつぶした球」と「標準の球」は 3D において異なる二つの視覚言語なのか？それぞれどんな物体の表現に適しているか？

✏️ **やってみよう**：球体を 1 つ配置し、等比ロックを外して Z（高さ・緑軸）方向だけ 0.3 に押しつぶすと、「UFO / 平べったい円盤」が得られ、単軸拡縮を体感する。

## 第10章 取り消しと履歴：思い切り試せる安心

初心者が抱く最大の心理的障壁は「間違えてクリックするのが怖い」ことです。この章でその不安を解消します。

### 10.1 アンドゥとリドゥ

- `Ctrl + Z`：一つ前のステップをアンドゥ；
- `Ctrl + Y`：リドゥ。

連続で複数ステップを遡ることも、その後リドゥで先へ進めることもできます。

### 10.2 「履歴スタック」とは

ソフト内部には**操作リスト**（ブラウザの戻る履歴のようなもの）が記録されています。重要な操作をするたびに 1 件プッシュされ、アンドゥは最後の 1 件をポップする動作です。

⚠️ **注意**：履歴には**ステップ数の上限**があります。ずっと昔の操作はリストから「押し出されて」しまい、遡れなくなることがあります——だから重要な節目では JSON バックアップをエクスポートしましょう（[第6章](jump:第6章 保存と共有：スクリーンショット、書き出し、バックアップ) を参照）。

### 10.3 何が履歴に入り、何が入らないか

- **履歴に入る**：オブジェクトの追加・削除、色変更、変換、テクスチャ貼りなど「作品内容に対する変更」；
- **履歴に入らない**：単なる視点回転、観察のための拡縮（これらは「見る方法」であり、作品そのものを変えない）。

したがって、安心してあちこち回して観察でき、視点の変動まで山のようにアンドゥステップとして記録される心配はありません。

### 10.4 思い切って試行錯誤する心得

> すべての操作がアンドゥ可能 ＋ 重要な節目にバックアップがある ＝ 本当の意味での「台無し」はない。

この言葉を心に貼っておけば、思う存分クリックできるようになります。

✏️ **やってみよう**：5 つの異なる操作（オブジェクト追加、色変更、移動、拡縮、1 つ削除）を連続で行い、その後 `Ctrl+Z` を連打して一歩ずつ巻き戻る様子を見て、さらに `Ctrl+Y` で順送りし、「タイムマシン」を体感する。

# 第三篇 グラフィック宇宙篇

3D 制作とは、結局のところ「正しい位置に、正しい形状を置く」ことです。本篇ではまず全 **40 種の図形**を丸ごと見せ、その上で 3D と 2D の根本的な違いを明らかにします。

## 第11章 3D図形総覧（20種の分類法）

### 11.1 「3D 図形」とは

3D 図形には**体積**があります——光によって明暗がつき、後ろにあるものを遮り、ぐるりと回して見ることができます。本ツールは立方体から奇妙なトーラス結びまで、20 種の立体形状を提供します。

### 11.2 二十種リスト早見表

| --- | --- | --- | --- | --- |
| 1 | box | 立方体 | 六面が真四角 | 長さ / 幅 / 高さ |
| 2 | sphere | 球体 | 丸く膨らんでいる | 半径 |

### 11.3 三つの分類法（20 種から素早く見つける助けに）

- **日常的な馴染み度で**：箱(box)、球(sphere)、円柱(cylinder)、円錐(cone) は生活の物体に最も似ており、初心者におすすめ；
- **「幾何学的な感じ」の強弱で**：プラトン立体（icosa/octa/dodeca/tetra）はとても「数学的」；knot/helix/tube はとても「流動的」；
- **用途で**：建築には box/cylinder/prism/pyramid/dome；装飾には torus/star3d/heart（2D）/lightning（2D）；有機的な造形には sphere/capsule/lathe/barrel。

### 11.4 最初に何を選ぶか

どれを使えばよいか分からない？まず **box** で感覚を掴み、次に **sphere** で「曲面の明暗」を体感し、最後に **torus** で「真ん中を通り抜けられる」立体のおもしろさを感じてください。

❓ **考えてみよう**：立方体、球、円錐——この中で「最も材料を省いて最も多く入る」のはどれか？これは実は現実の世界の問題です（コンテナ、貯槽はこれに基づいて設計されています）。

## 第12章 2D図形総覧（20種と「ステッカー」思考）

### 12.1 2D とは

2D 図形には**厚みがなく**、折り紙の切り抜きのように**地面に平らに寝ています**（XY 平面、Z=0）。記号、ランドマーク、装飾模様の作成に適しています。

### 12.2 二十種を順に紹介

| キー名 | 日本語 | 何に似ている / 用途 | 固有パラメータ |

| square2 | 正方形 | タイル、標識の台 | 長さ / 幅 |
| circle2 | 円 | ボタン、太陽、点 | 半径 |
| triangle | 等腰三角形 | 警告、山の尖り | 底辺長 / 高さ |
| star | 星形 | 評価、装飾 | 外半径 / 内半径 / 角数 |
| hexagon | 正六角形 | 蜂の巣、ナット、科技感 | 辺長 |
| heart | ハート形 | 愛、いいね | 幅 / 高さ / 心尖凹み度 |
| pentagon | 正五角形 | 家の平面、バッジ | 辺長 |
| octagon | 正八角形 | 駐車場標識、マンホール蓋 | 辺長 |
| ellipse | 楕円 | レンズ、軌道 | 長軸長 / 短軸長 |
| parallelogram | 平行四辺形 | 斜め引っ張り、透視ブロック | 底長 / 高さ / 傾斜度 |
| trapezoid | 台形 | 台体、屋根の側面 | 下底幅 / 上底幅 / 高さ |

| arrow | 矢印 | 指向、フロー | 長さ / 幅 |
| crescent | 三日月 | 月、鉤 | 外半径 / 内半径 / オフセット量 |
| semicircle | 半円 | アーチ、扇型 | 半径 |

💡 **全 20 種の 2D 図形にすべて固有パラメータが揃いました**。かつて heart / arrow / crescent / cross / lightning は全体拡縮しかできませんでしたが、今ではいずれも寸法を正確に指定できるようになっています。

💡 **見落としやすい二つの細かい点**：
- **半円**の直線的な辺は現在**下**を向いており、弧面が上を向いています（平边在下、弧面朝上）；
- **円環（ring2d）**のパラメータ順は「外環半径が先、内環半径が後」で、3D 環面と一致しています；内環半径は常に自動的に外環半径**より小さく**なるよう制限されます。

### 12.3 「ステッカー思考」

2D を、地面に貼られたステッカーだと想像してください：それは常に「伏せ」たままで、立ち上がることはありません。利点は——上空視点では、それがそのまま一枚の明瞭な記号図になります；模様や色と組み合わせれば、地面の誘導線、会社の Logo 地貼り、チェッカーボードなどが作れます。

### 12.4 遮蔽に注意

2D は地面に貼られているため、3D オブジェクトが上から乗るとそれを隠してしまいます；ある角度から見ると、薄い 2D は「一本の線」に消えてしまいます。目立たせたい時は、それを少し持ち上げる（Z 緑軸方向）か、開けた場所に置いてください。

✏️ **やってみよう**：square2、heart、arrow、star をそれぞれ 1 つずつ順に配置し、「頂視」に切り替えて最もくっきり見える姿を見る；さらに「透視」に切り替えて、それらがどう地面に「伏せ」ているかを見る。

## 第13章 各3D図形のパラメータ詳解（前編）：基本立体

> 本節では最もよく使う 10 種の立体を一つずつ解説します。いずれも「外観 / 類比 / 用途 / ヒント」の四段構成で、直観を身につけやすくしています。

### 13.1 立方体 box
- **パラメータ**：`長さ` / `幅` / `高さ`（三者は独立しており、長方体を直接作れるため、わざわざ等比ロックを外して引き伸ばす必要はない）。
- **外観**：六つの矩形面を持つ直角体。
- **類比**：宅配ダンボール、サイコロ、レンガ。
- **用途**：建築の壁、台座、および一切の「真四角な」もの。
- **ヒント**：最も安定した「土台」形状；低い壁を作りたい時は`高さ`を小さくするだけでよく、拡縮より正確。

### 13.2 球体 sphere
- **パラメータ**：`半径`。
- **外観**：完璧な丸球。
- **類比**：バスケットボール、天体、バブル。
- **用途**：頭部、天体、装飾球。
- **ヒント**：球面に模様/画像を貼ると最も「伸び広げられ」、アイコン付きの球を作るのに適している。

### 13.3 円柱 cylinder
- **パラメータ**：`半径` / `高さ`（上下同径で、真の正円柱；上下で異なる径が欲しい場合は**筒状体 barrel** へ）。
- **外観**：上下が等しい円、側壁がまっすぐ。
- **類比**：缶、柱、蝋燭。
- **用途**：梁柱、筒身、塔身。
- **ヒント**：barrel との役割分担をしっかり覚えておくこと——**cylinder は「半径一つ」を担い、barrel は「半径二つ」を担う**。

### 13.4 円錐 cone
- **パラメータ**：`底面半径` / `高さ`。
- **外観**：丸い底、尖った頂。
- **類比**：アイスクリームのコーン、誘導コーン、テントの尖り。
- **用途**：尖った頂、表示灯、クリスマスツリーの各層。
- **ヒント**：複数の cone を`底面半径`を段々小さくして積み重ねると、「層状の塔」が組める。

### 13.5 環面 torus
- **パラメータ**：`外環半径` / `内環半径`（**目に見える二つの輪をそのまま記述**：外側の輪の大きさ、真ん中の穴の大きさ。旧版の「管半径」は廃止）。
- **外観**：ドーナツで、真ん中に穴がある。
- **類比**：フラフープ、タイヤ、指輪。
- **用途**：環状装飾、パイプのエルボ、光輪。
- **ヒント**：`内環半径`は自動的に`外環半径`より小さく制限される；両者が近いほど輪は細くなり、針金の輪のようになる。

### 13.6 結び knot
- **パラメータ**：`半径` / `管太`（`管太`の上限は自動的に`半径`に追随し、半径の約 0.4 倍となり、自己交差して一团になるのを防ぐ）。
- **外観**：三つ編みのように巻かれた輪。
- **類比**：ロープの結び、エネルギーシンボル。
- **用途**：科技感の装飾、エンブレムの主体。
- **ヒント**：形状が複雑なので、単色かシンプルな模様がおすすめで、テクスチャが乱れるのを避ける。

### 13.7 正二十面体 icosa
- **パラメータ**：`辺長`（**半径ではない**——各稜の実際の長さをそのまま与え、幾何学的直観により合う）。
- **外観**：20 の正三角形で組まれた球に近い多面体。
- **類比**：サッカーボール（古典的な 32 面版の親類）、鉱石の結晶。
- **用途**：宝石、サイコロ、ローポリ風の球。
- **ヒント**：「ローポリゴン（low-poly）」審美の代表で、純色と合わせると非常にハイセンス。

### 13.8 正八面体 octa
- **パラメータ**：`辺長`。
- **外観**：上下が二つの尖り、中央が八面に膨らむ。
- **類比**：ダイヤモンドカット、双円錐。
- **用途**：水晶、宝石、抽象彫刻。
- **ヒント**：回転させると光と影の変化が豊かで、「焦点となる装飾」に適している。

### 13.9 正十二面体 dodeca
- **パラメータ**：`辺長`。
- **外観**：12 の正五角面を持つ球感のある多面体。
- **類比**：魔法石、サイコロ（D12）。
- **用途**：神秘的なシンボル、置物。
- **ヒント**：同じ辺長でも、正十二面体は正二十面体より「一回り大きく」見える。なぜなら外接球半径の係数がより高いため。

### 13.10 カプセル capsule
- **パラメータ**：`半径` / `円柱長`（総高 = 円柱長 + 2 × 半径）。
- **外観**：円柱の両端に半球を付けたもの。
- **類比**：カプセル薬、トラック、ボウリングのピン。
- **用途**：人体胴体の簡略化、ホース、丸みのある柱。
- **ヒント**：純粋な円柱より「柔らか」で、キャラクターや生物を作る時にしばしば使われる。

✏️ **やってみよう**：box + cylinder + cone で「街灯」を組んでみよう：cylinder で竿を、box で灯具を、cone で頂の笠を作る。基本体を組み合わせる力を体感する。

## 第14章 各3D図形のパラメータ詳解（後編）：特殊形状

### 14.1 正四角錐 pyramid
- **パラメータ**：`底面辺長` / `高さ`（旧版の「边数」は廃止——もともと**正四**角錐であるべきだった）。
- **外観**：正方形の底面 ＋ 一つの尖った頂。
- **類比**：エジプトのピラミッド、屋根。
- **用途**：塔、尖った頂の建築、記念碑。
- **ヒント**：本リリースで法線を再計算しており、四つの斜面は現在**明瞭な平面の明暗**となり、旧版のような「一团にぼやける」光照はなくなった。

### 14.2 正三角柱 prism
- **パラメータ**：`底面辺長` / `高さ`。
- **外観**：正三角形断面のまっすぐな柱。
- **類比**：三稜鏡、路上的障害物、屋根梁。
- **用途**：三角梁、くさびブロック、科技構件。
- **ヒント**：同様に法線を修復しており、三つの側面は角張っている；横に置けば「斜面ブロック」になる。

### 14.3 パイプ tube
- **パラメータ**：`スパン` / `アーチ高` / `管半径` / `湾曲分割`。
- **外観**：持ち上げられた拱形の丸管で、両端が地面につく。
- **類比**：拱橋、虹、門形の取っ手。
- **用途**：橋梁、アーチ門、装飾リボン。
- **ヒント**：`スパン`は両端点の水平距離、`アーチ高`は中央の持ち上がり高さ——**両者の比が「低い拱」か「高い拱」かを決める**。`管半径`の上限はスパン/アーチ高に応じて自動的に締まり、管が太りすぎて拱の穴を塞いでしまうのを防ぐ。`湾曲分割`は大きいほど滑らか、小さいほど折れ線感が出る。

### 14.4 回転体 lathe
- **パラメータ**：`分割`（≥ 3） / `底面半径` / `中間半径` / `最広半径` / `高さ`。
- **外観**：一条の輪郭線を中軸の周りに回して生じる体（花瓶/コマ状）。
- **類比**：花瓶、電球、コマ、ワイングラス。
- **用途**：対称な容器、器、彫刻。
- **ヒント**：三つの半径はそれぞれ**底部、胴部、最も膨らむ所**を制御する。花瓶を作りたいなら`最広半径` > `中間半径` > `底面半径` に；コマを作りたいなら逆にする。`分割`は円周の精度を制御し、最少 3 分割（この時は三稜台の観感）。

### 14.5 正四面体 tetra
- **パラメータ**：`底面辺長`。
- **外観**：4 つの正三角面を持つ最小の多面体。
- **類比**：三角錐、結晶の破片。
- **用途**：砕石、ローポリ装飾、尖ったシンボル。
- **ヒント**：面が少なく稜が硬いので、「ハード/科技」風に非常に適している。

### 14.6 筒状体 barrel
- **パラメータ**：`頂半径` / `底半径` / `高さ`（旧版の曖昧な「半径」は削除）。
- **外観**：上下の口径が異なってもよい筒。
- **類比**：木桶、植木鉢、紙コップ、ロケットの中段。
- **用途**：容器、胴体、貯水池。
- **ヒント**：**これが最も柔軟な柱状体系**——両径が等しい ＝ 円柱；上小下大 ＝ 植木鉢；上大下小 ＝ 紙コップ；`頂半径`をほぼ 0 にすると円錐が得られる。

### 14.7 半球 dome
- **パラメータ**：`半径`。
- **外観**：半球（上半）。
- **類比**：ゲルの天幕、天文台、鐘形カバー。
- **用途**：屋根、カバー、プラネタリウム。
- **ヒント**：box と組み合わせると「屋根付きの小屋」に；ひっくり返す（回転）と「茶碗」になる。

### 14.8 開口環面 helix
- **パラメータ**：`外環半径` / `内環半径` / `主掃掠角`（旧版の「管半径」は廃止され、環面と一致する内外の二重半径に変更）。
- **外観**：口の欠けた輪——環面から一段の円弧が切り取られたもの。
- **類比**：C 形の留め具、開口ブレスレット、バネの一周。
- **用途**：動的装飾、渦巻きシンボル、エネルギー輪、留め具構造。
- **ヒント**：`主掃掠角`は「この輪が合計で何度回ったか」：360° は完全な環面、270° は古典的な C 形、180° は半環。**この一パラメータを変えるだけで「閉じた」から「開いた」へ滑らかに移行できる**。

### 14.9 正八角柱 octaPrism
- **パラメータ**：`底面辺長` / `高さ`（旧版の「半径」はより直観的な辺長に変更）。
- **外観**：八つの縦辺面を持つまっすぐな柱。
- **類比**：八角形の立柱、灯台、井戸壁。
- **用途**：整った立柱、塔身、基座。
- **ヒント**：円柱より「角張り」、box より「丸み」があり、折衷感が良い。

### 14.10 立体星 star3d
- **パラメータ**：`外半径` / `内半径` / `角数` / `厚み`。
- **外観**：星を押し出して厚みを持たせた立体。
- **類比**：メダル、星のチャーム、勲章、歯車。
- **用途**：報奨シンボル、装飾主体、Logo。
- **ヒント**：`角数`は 5 をはるかに超えてもよい——3 にすると三角星、大きくして「内外半径を近づける」と**歯車**になる。`内半径`は自動的に`外半径`より小さく制限される。

❓ **考えてみよう**：3D 図形を 4 種以内で「ロボット」を組むとしたら、どの 4 種を選ぶ？それぞれ何の部位にする？

## 第15章 「立つ」と「横たわる」：3Dと2Dの本質的差異

### 15.1 体積 vs 面積

- **3D は体積を持つ**：空間を占め、投影でき、互いに遮り合える。それは地面に「立ち」、高さ（Z 緑軸）を持つ。
- **2D は面積だけ**：一枚に広げられ、厚みはゼロ。それは地面に「寝て」（Z=0）いる。

この点を理解すれば、なぜ 3D オブジェクトは「積み重ね」ができて、2D は「床を敷く」ことしかできないかが分かります。

### 15.2 なぜ一方は立ち、一方は寝るか

コード上、3D は `seatOnGround` で底面を y=0（ウェブ注記では Z=0）に落とし；2D は `shape2D` で XZ 平面（地面）に回転して地に貼り付けます。したがって：
（注：前文の「地面 / XY 平面 / Z=0」は**ウェブインターフェース注記**の呼び方；ここでの `y=0` / `XZ 平面` は **Three.js 内部座標系**の呼び方——両者は同じ地面を指しており、単に命名体系が異なるだけ：Three.js 内部では Y 軸で「高さ」を表し、本書 UI 注記の緑軸 Z に対応；内部の X、Z 軸は本書 UI 注記の X（前後）、Y（左右）に対応。）
- box を 1 つ置けば、それは自然に地面に「座る」；
- heart を 1 つ置けば、それは自然に地面に「贴る」。

### 15.3 混用のコツ

- 2D を「立たせ」たい？それを赤軸（Y）で 90° 回転させれば、「寝る」から「立つ」に変わる——立て札、看板にできる；
- 3D を「伏せ」たい？回転させて横倒しにし、「倒れた木」「斜めに寄りかかった板」を作る；
- 地面の記号（矢印で道案内）＋ 立体建築は、シーンで最も一般的な組み合わせ。

✏️ **やってみよう**：arrow（2D）を 1 つ配置し、選択後に Y（赤/左右）で 90° 回転させ、「寝た矢印」が「立ち上がった案内板」に変わる様子を観察する。これが「立つと寝る」の自由な切り替えです。

# 第四篇 色彩とマテリアル篇

色は作品の「感情」である。本篇は「光とは何か」から始め、27 種のプリセット、カスタム色の取得、12 種のパターンへと進み、最後に画像テクスチャと不透明度について解説する。

## 第16章 色入門：人間の目と光の遊び

### 16.1 色は物体が「自ら持っている」ものではない

赤いリンゴも真っ暗闇の中では黒い——あなたが赤を見えるのは、光が当たって「反射」し、あなたの目に入るからである。つまり**色 ＝ 物体 ＋ 光** である。本ツールは `MeshStandardMaterial`（受光マテリアル）を使用しており、シーン内に環境光（強度 1.0）と指向性ライト（強度 2.6）が存在して初めて、物体に明暗が現れる。

💡 これが、同じ色でも背光面に回ると「暗くなる」理由である——色が変わったのではなく、光が減ったのだ。

### 16.2 RGB：画面は三原色を混ぜる

ディスプレイは **赤(R)、緑(G)、青(B)** の三つの光を混ぜてすべての色を作る。本ツールのプリセット色にある `0xff0000` は「赤最大、緑青ゼロ ＝ 純赤」である。

### 16.3 HSV：人間が色を選ぶ直感

RGB よりも、人は **色相(H, どんな色)、彩度(S, 鮮やかさ)、明度(V, 明るさ)** で選ぶ方が馴染みがある。取色器をドラッグしている時、実はあなたは HSV を調整しているのだ。

- 色相 ＝ 赤橙黄緑青藍紫を一周する；
- 彩度が低い → 灰色がかる；彩度が高い → 鮮やか；
- 明度が低い → 暗い；高い → 明るい（白っぽくなることも）。

### 16.4 マテリアルの二つの隠れたパラメータ

物体表面には `roughness`（粗さ/0.6、大きいほどマット）と `metalness`（金属感/0.0、大きいほど金属っぽい）がある。現在のデフォルトはやや「マットなプラスチック」寄り。あなたが変えるのは色であり、この二つは通常変えないが、それらが存在することを知っていれば、「なぜ鏡面反射しないのか」を理解できる。

### 16.5 不透明度：光を通す

色の他に「透けるかどうか」がある。詳しくは後述の第20章で解説するが、ここでは覚えておこう：不透明度 1 ＝ 実体、0 ＝ 透明。

❓ **考えてみよう**：なぜ病院の壁や手術衣には「低彩度の薄い青／薄い緑」が多く使われるのか？色の彩度の高低は、人の感情にどう影響するか？

✏️ **やってみよう**：白い球を置き、異なる視点に切り替えて、背光面が暗くなるかを観察する。これが「光が色を作る」ことの直感的な証拠である。

## 第18章 カスタム色：HEX・HSV・画面スポイト

### 18.1 HEX とは何か

HEX は `#` の後に 6 桁の十六進数が続き、二桁ずつが R、G、B を表す。例えばブランドカラー `#1e90ff`（ドッジブルー）。特定の色を正確に再現したい場合、HEX を直接入力するのが最も正確である。

### 18.2 取色器のドラッグ方法

右パネルの「取色器」ボタンをクリックすると、取色ウィンドウがポップアップし、中には「大きなカラーブロック ＋ 色相バー ＋ HEX/RGB 入力枠」がある：
- 大きなカラーブロック内でクリック／ドラッグ → **彩度 ＋ 明度** を選ぶ（左右が濃淡、上下が明暗）；
- 下の **色相バー** をドラッグ → **色相** を調整（赤橙黄緑青藍紫を一周）；
- 絶対的な正確さを求めるなら、HEX または R/G/B 枠に直接数値を入力するのが最も確実。

💡 「同系色の濃淡」を見つけたい時は、色相バーを **固定したまま**、大きなカラーブロック内で上下にのみドラッグ（明度を変更）すると、最も調和の取れた配色になる。

### 18.3 画面取色器（スポイト）

一部のリリースには「画面から色を取得」機能がある：スポイトをクリックし、さらに画面の任意の場所（他の物体の色や背景も含む）をクリックすると、その色が採取される。現実に即した「実景からの配色」に極めて便利である。

### 18.4 「無色」（NO_COLOR）とは

ソースコードには `NO_COLOR = -1` という特殊なマークが存在する。これを選ぶと、物体には **純色の着色が適用されない**（多くの場合、画像テクスチャや特殊マテリアルと組み合わせて「底色なし」の効果を呈する）。

⚠️ **注意**：誤って「無色」をクリックすると、物体が「着色されていない／暗い」ように見えるが、壊れたわけではない。再度通常の色を選べばよい。

✏️ **やってみよう**：HEX で好きな色（例：`#ff6b6b`）を入力し、立方体に塗る；さらにスポイトでページ上のどこかから色を取得し、両者を比較する。

## 第19章 12種の模様テクスチャ：表面に物語を

純色では平坦すぎる。パターンは物体に「内容」を持たせる。本ツールには **12 種のパターン**（`PATTERNS`）が内蔵されている：

| パターン | 像什么 / 用途 |
| --- | --- |
| 純色 | パターンなし、最も清潔 |
| 方格 | チェス盤、テーブルクロス、タイル |
| 条纹 | 縞馬、警告、布地 |
| 圆点 | 水玉スカート、キャンディ |
| 渐变 | 空、金属のグラデーション |
| 砖墙 | 壁面、建築 |
| 斜纹 | 速度感、テクノロジー |
| 波浪 | 水波、シルク |
| 点阵 | ピクセル、テクノロジーパネル |
| 交叉 | メッシュ布、包帯 |
| 网格 | 方眼紙、プロジェクト |
| 螺纹 | 渦巻き、ねじ管 |

💡 パターンの色は現在の「主色」から自動的に導出される（無色の場合はパターン色が白になる）。右パネルには **独立した「パターン色」コントロールはない** ので、主色を変えれば全体の色が変わる。

⚠️ **注意**：複雑なパターン（例：砖墙、网格）を面数の少ない球に貼ると「引き伸ばされて歪む」が、これは正常である；整った見た目を求めるなら、box/cylinder のように平面の多い物体に貼ることを優先すべきである。

✏️ **やってみよう**：box を一つ置き、「砖墙」「方格」「条纹」を順に試し、パターンがいかに瞬時に「それが何に見えるか」（壁 vs 布 vs 警告標識）を変えるかを体感する。

## 第20章 画像テクスチャのアップロードと不透明度

### 20.1 画像のアップロード：写真を表面に貼る

プリセットパターンに加えて、**自分の画像**（PNG/JPG）を表面テクスチャとしてアップロードできる——会社の Logo、写真、手書きの絵など何でもよい。貼り付けると、物体表面にその画像が「印刷」される。

- 適しているもの：実写写真付きの展示パネル、Logo を印刷したメダル、地図を貼った床面；
- ヒント：画像は正方形で、鮮明なものがよい。box の正面に貼るのが最もくっきりする。

### 20.2 不透明度（opacity）

右パネルで「不透明度」を調整できる：

1 = 完全な実体；
0.1 = ほとんど見えない；
中間値 = 半透明（ガラス、幽霊、水の質感）。

💡 「ガラスケース」「氷」「幻影」はすべてこれにかかっている。半透明にすると、後ろの物体が透けて見え、階層感が一瞬で豊かになる。

### 20.3 コンビネーション

- パターン ＋ 半透明 ＝ ぼんやりしたベール；
- 純色 ＋ 高透明 ＝ ガラスブロック。

❓ **考えてみよう**：「氷のかたまり」を表現するなら、色・不透明度・パターンをどう組み合わせるか？「レンガ壁だが半透明」を表現する場合、どのような効果を狙うのか？

✏️ **やってみよう**：自分の PC 内の画像を一枚アップロードし、平らな box に貼る；さらにその box の不透明度を 0.5 に調整し、「画像が半透明になる」効果を観察する。

# 第五篇 テキストと画像篇

シーンには形状の他に、情報を伝えるための「文字」と「写真」も必要である。本篇ではテキストと画像という二種類の「コンテンツ型」オブジェクトについて解説する。

## 第21章 テキスト追加：シーンに話させる

### 21.1 テキストは「話す薄い板」

標識、名称、ヒント、スローガン……文字によって三次元シーンに意味が生まれる。テキストオブジェクトの本質は「文字を貼った薄い平面」であり、通常のオブジェクトと同様に選択・移動・回転・拡縮・着色ができる。

### 21.2 テキストを加える三ステップ

1. 左パネルの「工具」から「テキストを追加」を選ぶ；
2. 中央の地面をクリックすると、**入力枠**がポップアップする（プレースホルダは「テキストを入力······」）；
3. 文字を入力し、**Enter** で確定すると、文字が地面に落ちる；入力枠内で **Shift + Enter** を押すと改行できる（複数行テキスト）。

💡 プレースホルダ「テキストを入力······」は「ここに文字を打つ」という注意喚起に過ぎず、それ自体が内容ではない；最終作品には現れない。

### 21.3 内容の変更：ダブルクリック

配置後に文字を変えたい場合は、テキストオブジェクトを **ダブルクリック** すると入力枠が再びポップアップし、変更してエンターすればよい。削除して作り直す必要はない。

### 21.4 テキストも完全なオブジェクト

テキストはすべての通常操作に対応：選択、平行移動（青=前後/赤=左右/緑=上昇）、回転、拡縮、色変更、不透明度調整。「発光文字」「半透明文字」も作れる。

✏️ **やってみよう**：「ようこそ」という一行を追加し、シーンの入り口に移動；さらにダブルクリックして「ようこそいらっしゃい」に変更し、即時編集のしやすさを体感する。

---

## 第22章 フォント・サイズ・太さ・縦横配置

テキストを選択すると、右パネルにテキスト専用のコントロールが現れる。本ツールは **複数の内蔵フォントセット**（各言語 5 個、現在の UI 言語で切り替わる）といくつかのレイアウトスイッチを提供する。

### 22.1 フォントの選び方（言語で切り替わる）

フォント一覧は **固定ではない**：現在の UI 言語に応じて変化し、各言語に 5 個の専用内蔵フォントがある。例えば簡体中文はデフォルトで雅黑／宋体／楷体／黑体／仿宋、英語なら Arial／Georgia／Times／Courier／Verdana など。以下は中文 UI での例：

| フォント | 気質 / 用途 |
| --- | --- |
| 雅黑 | モダン、明瞭、中文デフォルトの最優先 |
| 宋体 | フォーマル、書物的な風格 |
| 楷体 | 手書き感、伝統、扁額 |
| 黑体 | 重厚、目を引くタイトル |
| 仿宋 | 公文、清秀 |
| Arial | 西文モダン・サンセリフ |
| Times | 西文セリフ、フォーマル |
| Courier | 西文等幅、コード／タイプライター感 |

💡 中文コンテンツは基本前五つを優先；純英文は後ろ三つで異なる気質を表現できる。UI 言語を切り替えると、フォント dropdown にはその言語専用のフォントが表示される。

### 22.2 フォントサイズ（デフォルト 80）

フォントサイズのデフォルトは **80** で、右パネルで調整できる。大きすぎるとシーンのスケールを「突き破る」ことがあり、小さすぎると見えない。

⚠️ **注意**：フォントサイズはシーンの単位に対する相対値であり、图形の大きさと組み合わせる必要がある——1.2 単位の立方体に 500 の文字を合わせると、文字は物体よりずっと大きくなる。

### 22.3 太さ（太字スイッチ）

ワンクリックで太字にでき、タイトルがより目立つ。黑体/楷体と組み合わせると「扁額感」が非常に際立つ。

### 22.4 横書き / 縦書き

- **横書き**：普通の一行、左から右へ；
- **縦書き**：上から下へ並べ、中式扁額、書名、標識に適している。

💡 組み合わせ提案：縦書き ＋ 楷体 ＋ 大フォントサイズ ＝ 伝統的な扁額；横書き ＋ 黑体 ＋ 中フォントサイズ ＝ モダンな標識。

⚠️ **注意**：テキストが長すぎると薄い板の幅を超えることがある。入力枠内で **Shift + Enter** を押して改行するか、適宜フォントサイズを小さくするとよい。

✏️ **やってみよう**：「茶館」という縦書き扁額（楷体、縦書き、大フォントサイズ、木質色）を作り、フォント組み合わせの「性格」を体感する。

### 22.5 言語をまたぐ読み取り専用：言語を切り替えると見るだけになる

テキストオブジェクトは **作成時の言語（UI テキストの言語）を記憶** する。UI 言語を **別の言語** に切り替えると、そのテキストボックスの専用コントロールが **自動的に読み取り専用／無効** になる：本文入力枠、フォント、太さ、横書き／縦書きの方向は変更できず、見るだけになる。これは、言語の合わないフォントで書き換えて文字化けや崩れを起こすのを防ぐため。このときフォント dropdown にはそのテキストボックス自身のフォントだけが残り、言語全体のフォント一覧は表示されない。

> 📌 編集を続けたい？ テキストボックスを作成した言語に UI 言語を戻せば、すべてのコントロールが復元する。

### 22.6 アラビア語では縦書きを禁止

**アラビア語（ar）** UI に切り替えると、縦書きボタンは **強制無効化され横書きに固定** される（アラビア語自体が右から左へ書かれ、縦書きにすると読む方向が乱れるため）。これはその言語でのハードな禁用であり、22.5 の「言語をまたぐ読み取り専用」とは独立したルールで、矛盾しない。

## 第23章 画像オブジェクト：写真を3D世界へ

### 23.1 画像オブジェクトの追加

左パネルの「工具」から「画像を追加」を選ぶ → ローカルの画像ファイルを選ぶ → 地面をクリックすると、画像が **平面贴片** として現れる（立てかけられた写真のように）。

### 23.2 通常のオブジェクトのように操作する

選択すると移動・回転・拡縮ができる。壁に斜めに立てかけたり、床装飾として平らに敷いたり、高く掲げて看板にしたりできる。

### 23.3 画像も「テクスチャ」になれる

第20章で述べたように、画像は任意の 3D オブジェクトの表面に「貼る」ことができる（表面マテリアルとして）。つまり同じ画像に二つの使い方がある：

- **独立した贴片として**：シーン内の一枚の「写真」として；
- **表面テクスチャとして**：box / cylinder などの物体表面に印刷する。

### 23.4 画像 vs 2D 图形

| | 画像オブジェクト | 2D 图形 |
| --- | --- | --- |
| 内容 | 自分の写真 / Logo | ソフトで生成された形状 |
| 色変更可否 | 通常はテクスチャとして全体で調整 | 純色 / パターンの変更可 |
| 典型的用途 | 写実的な写真、実物 Logo | 記号、ランドマーク、装飾 |

両者とも「薄い」であり、立ても横にもでき、必要に応じて選ぶ。

✏️ **やってみよう**：自分の写真を一枚インポートし、シーン内に立てた「平面贴片」として配置；さらに同じ画像を box の正面のテクスチャとして貼り、二つの使い方の違いを比較する。

# 第六篇 ペンと消しゴム篇

前の二篇は「標準形状」についてだったが、本篇は「手描き」について解説する——ペンを使えばシーン内に線を引くように描け、消しゴムでそれらを消せる。

## 第24章 2Dブラシ：地面に線を描く

### 24.1 2D ペンとは

2D ペンは **地面（XZ 平面）** 上に **平面線** を描く。紙にペンで描くようなものである。地貼り模様、経路、落書き、床の案内などに適している。

### 24.2 使い方

1. 左パネルの「工具」から「2D ペン」を選ぶ；
2. 中央の地面で **左ボタンを押したままドラッグ** し、離すと一本の線になる；
3. 複数本を連続して描ける。

### 24.3 Shift を押しながら直線に拘束

ドラッグ中に **Shift** を押すと、線は **直線（二点間）に拘束** される。「まっすぐな道」「きちんとした辺」を描くのに便利。

> 方向ロック：直線拘束に入ると、**この一本（左ボタンを押して描く）が終わるまで、方向は初回に確定した水平／垂直／45° 方向にロックされ**、途中でマウスが逸れても変わらない。方向を変えたい場合は、左ボタンを離して新たに一本描き始める必要がある。

### 24.4 ペンの四つの属性

右パネル（ペン有効時）で設定できる：

| 属性 | 作用 |
| --- | --- |
| 色 | 線の色 |
| 太さ | 線の幅 |
| 不透明度 | 線が実心かどうか |
| 最小間隔 | サンプリング点間の最小距離、小さいほど滑らかで点が密になる |

💡 「最小間隔」が小さいほど線は繊細だが頂点が多くなり、大きいほど省けるが折れ線感が強くなる。精細な曲線は小さく、スケッチは大きく調整する。

### 24.5 ペン vs 2D 图形

- 2D 图形は「標準形状」（円、ハート…）であり、色やパターンを変更可；
- 2D ペンは「あなたが手描きした任意の線」であり、自由だが不規則。

標準記号には图形を、適当な落書きにはペンを使う。

✏️ **やってみよう**：2D ペンで地面に「∞」記号を描き、さらに Shift を押しながらそれを横切る直線を描き、自由線 vs 拘束線を体感する。

---

## 第25章 3Dブラシと基準面

### 25.1 3D ペンとは

3D ペンは **空間内に立体パイプを描く**——地面に貼るのではなく、空中に浮かぶ「パイプの線」である。これにより「空中に絵を描く」ことができる。

### 25.2 参照平面：第一筆が「どの層に描くか」を決める

3D ペンで最初にクリックした時、半透明の **「参照平面」** が一つ確定する。以降のドラッグはこの平面を参照し、線はその近傍に落ちる。

💡 **水平な線** を描きたい？まず「頂視」に切り替え、クリックして水平参照面を確定する；**垂直な線** を描きたい？「正视 / 左視 / 右視」に切り替えてから垂直面を確定する。参照面の向きが、あなたが描く「次元」を決める。

### 25.3 平面上に描画、Shift で直線拘束

- 参照平面上でドラッグして自由に描く；
- **Shift** を押しながらドラッグすると直線に拘束される（2D ペンの Shift 拘束と同じ、空間パイプに作用する）。

> 方向ロック：同上、Shift で直線拘束した後は **この一本が終わるまで方向ロック** され、途中で変更不可、左ボタンを離して新たに一本描き始めないと方向を変えられない。

### 25.4 球キャップ封止

各筆の両端には自動的に **球キャップ封止** が加わり、線の始端と終端が丸く欠けないようになり、本物のパイプにキャップを付けたようになる。

### 25.5 用途

- ふわっと漂うリボン、連結線、エネルギービームを適当に彫刻する；
- シーンに「動的な線」を描く（標準体を置くより有機的）；
- 抽象芸術、回路図示を作る。

❓ **考えてみよう**：3D ペンの「参照平面」という概念は、画家が「まず紙を装裱する」のと同じことではないか？なぜ三次元ではこの「仮想の紙」が特に必要なのか？

✏️ **やってみよう**：「頂視」に切り替え、3D ペンで水平参照面を確定し、波形線を一本描く；さらに「正视」に切り替えて別の縦線を描き、空間線の次元の違いを感じる。

## 第26章 消しゴム：全体と部分

描き間違えたら消せる必要がある。本ツールの消しゴムには二つのモードがあり、挙動が異なるので必ず区別すること。

### 26.1 二つのモードの切り替え場所

右パネルの消しゴム属性に「消しゴムモード」がある：**全体消去 / 局部消去**。

### 26.2 全体消去（デフォルト）

消しゴム輪をドラッグすると、当たったものは **オブジェクト全体（一本のペン、一つの图形）を削除** される。これは「豪快な」クリーニングである。

💡 一本の 3D 筆跡や一つの图形を素早く消したい場合は全体モードを使い、輪で囲めば削除される。

### 26.3 局部消去

「局部消去」を有効にすると：

- **2D 筆跡**：消しゴム輪と **交差したその一段** だけを消し、残りは保持される（精密な線修正）；
- **3D 筆跡**：同様に消しゴム輪と **交差したその一段** の軌跡点だけを消し、残りは保持される（2D と 3D の筆跡とも段階的な局部消去に対応）；
- **その他のオブジェクト**（標準 3D/2D 图形、テキスト、画像）：やはり **オブジェクト全体** を削除（全体削除）。

⚠️ **注意**：局部モードは「ペンの筆跡（2D と 3D）」に対してのみ段階的に消す；標準图形、テキスト、画像に対してはやはりオブジェクト全体を削除する。「局部モードで立方体の一角を削り取る」ことは期待できない。

### 26.4 消しゴムの大きさ

「消しゴムの大きさ」スライダーで消しゴム輪の半径を調整し、細部の精密修正も大範囲のクリーニングもこれにかかっている。輪が小さすぎると何度も消す必要があり、大きすぎると隣を誤って消しやすい。

### 26.5 消し間違えても復元できる

消しゴムで削除したオブジェクトは、他の操作と同様に履歴に入る——`Ctrl+Z` を押せば戻ってくる。だから気兼ねなく消そう。

✏️ **やってみよう**：2D ペンで長い曲線を一本描き、まず「局部消去」を開けてそのうちの小さな一段を消す（残りは残る）；さらに「全体消去」に切り替えて別の筆跡を輪で囲み、それが一本ごと削除されるのを見る。二つのモードを比較する。

# 第七篇 視点と観察篇

「角度を変えて見る」と、たいていはっきりする。本篇では、あなたの観察角度をどう観察し、固定するかを解説する。

## 第27章 七つのプリセット視点：別の角度から世界を見る

### 27.1 なぜ視点を切り替える必要があるか

人間の目は一つの角度しか持たないため、「前後左右、誰が高いか低いか」を誤判断しやすい。ワンクリックで視点を変えることは、作品の周りを一周することに等しい。底バーには **7 つの視点ボタン** がある。

### 27.2 七つの視点を一つずつ

| 視点 | あなたが…いるような | 見える主平面（ウェブ标注） |
| --- | --- | --- |
| 透視 | 普通に立って見る | 近大遠小、最も自然 |
| 頂視 | 真上から見下ろす | X（青/前後）× Y（赤/左右）平面 |
| 底視 | 真下から見上げる | 頂視と同じだが反転 |
| 正视 | 真正面から平視 | Y（赤/左右）× Z（緑/高度）平面 |
| 後視 | 真後ろから平視 | 正视と同じ、方向反対 |
| 左視 | 真左から平視 | X（青/前後）× Z（緑/高度）平面 |
| 右視 | 真右から平視 | 左視と同じ、方向反対 |

💡 ウェブ标注を覚えよう：**X 青=前後、Y 赤=左右、Z 緑=高度**。頂視で見えるのは「前後 × 左右」（地面）であり、正视で見えるのは「左右 × 高度」（立面）である。

### 27.3 いつどれを使うか

- **透視**：全体観察、スクリーンショット展示；
- **頂視**：正確な配置、オブジェクトの一列整列（地面俯瞰図が最も正確）；
- **正视/左視/右視**：「まっすぐか」「揃っているか」のチェック、対称構図の作成；
- **底視/後視**：稀だが「背面／底面」が予想通りかを検証できる。

❓ **考えてみよう**：なぜ建築家は「平面図、立面図、側立面図」を描くのか？この七つの視点のうち、どれがこの三つの工程図に対応するか？

✏️ **やってみよう**：3 つの異なる图形を配置し、頂視、正视、右視をそれぞれクリックし、同じシーンが異なる視点での「見え方」の違いを観察する。

## 第28章 補助の非表示とフルスクリーン

### 28.1 座標軸とグリッドを隠す

トップバーには「座標軸」「网格面」「地面」の三つのスイッチがある：

- 座標軸を隠す：文字付きの三本の矢印を消す；
- グリッドを隠す：地面の方眼を消す；
- 地面の切り替え：半透明の基準面（物体が着地する参照平面）の表示・非表示を制御する。作品の書き出しや清浄な画面を求める時は、これらをまとめて隠せる。

⚠️ **注意**：スクリーンショット／展示図の書き出し前は、まず **座標軸とグリッドを隠す** ことを推奨する。画面がより清潔で、「完成品感」が増す。それらは単なる補助であり、作品自体には影響しない。

### 28.2 全画面

| 形態 | 全画面の方法 |
| --- | --- |
| 🖥️📱 **ウェブ版** | トップバーの「全画面」ボタンをクリック；🖥️ マウス/デスクトップ端末は **F11** も可。入るのは **ブラウザ全画面** で、ページが画面いっぱいになる |
| 💻 **PC 版** | 「全画面」ボタンなし；**F11** またはタイトルバーの「最大化」ボタンは **ウィンドウ最大化／復元**（真の全画面ではない） |
| 🤖 **Android 版** | **全画面ボタンなし**——アプリ自体が全画面で動作しているため、切り替え不要 |

🖥️ ウェブ・マウス/デスクトップ端末で **Esc** を押しても、閉じるのはコントロール／選択解除のみであり、全画面は **終了しない**；全画面を終了するには、もう一度 **F11** を押すか「全画面」ボタンをもう一度クリックする。💻 **PC 版**で **F11** を押すと最大化/復元であり、もう一度 **F11** を押すとその状態を終了する（PC に「全画面」ボタンはない）。

### 28.3 一つの実用組み合わせ

> 清潔な展示図を出すには：座標軸を隠す ＋ グリッドを隠す ＋ 透視に切り替え ＋ （🖥️📱💻 任意）全画面 ＋ スクリーンショット。

✏️ **やってみよう**：小さなシーンを作り、まず座標軸/グリッドを隠して「清潔な図」を一枚；さらにそれらを表示して「補助線付きの図」を一枚スクリーンショットし、他人への視覚的な印象の違いを比較する。

## 第29章 なぜショートカットを覚えるか：効率の複利

### 29.1 過小評価されがちな一事実

小さな実験をしてみてほしい：シーンに立方体を一つ置き、右側のプロパティパネルの「等比縮放」スライダーをマウスで往復10回引っ張り、次にキーボードの `+` / `-` キーを10回押してみる。

あなたはほぼ間違いなくこう気づくはずだ：**キーボードの方が速く、正確で、疲れない。**

理由は三つある：
1. **手がキーボードの中心領域から離れない**——目は画面を見て、指はアルファベットキーの上にあり、脳は「画面を見る→パネルを探す→マウスを動かす→スライダーを引っ張る」の往復切り替えをしなくて済む。
2. **固定ステップがある**——方向キーを一度押すと、物体は正確に「0.1 グリッド」動き、10回押せばちょうど 1 グリッドだ。スライダーを10回引っ張っても、どれだけ動いたかは到底覚えていられない。
3. **重ねられ、取り消しもできる**——キーボード操作の一歩一歩はすべて履歴スタックに入り（[第32章](jump:第32章 スライダー/入力枠とCtrl組み合わせ)参照）、間違えたら `Ctrl+Z` ですぐに戻る。スライダーのドラッグは連続した変化なので、取り消し時には往々にして「跳ね」が大きい。

💡 **心構え一言**：マウスは「選ぶ」と「描く」を担当し、キーボードは「変える」と「調整する」を担当する。役割分担して協力すれば、効率は倍になる。

### 29.2 ショートカットにも「場面」がある

本ツールのショートカットは「グローバルで一つの意味」ではなく、**現在オブジェクトが選択されているかどうかを見る**：

| 現在の状態 | 方向キー / A D W S は何をしているか |
|---|---|
| **何も選択していない** | 動くのは**カメラ**（シーンの周りを見ている） |
| **オブジェクトを選択した** | 動くのは**そのオブジェクト**（物体がシーン内で移動/回転） |

同じ `↑` キーでも、何も選んでいない時は「レンズが前に押し出される」、何かを選んでいる時は「物体が前に進む」。この違いはショートカット体系全体の核心であり、まず頭に刻み込んでおかないと、後で混乱する。

❓ **考えてみよう**：なぜ「選択していない時にカメラを動かす」のは理にかなった設計なのか？——この時あなたはおそらく「角度を探す、全体を見る」状態にあり、キーボードで直接視点を平行移動/回転させる方が、空白をドラッグするより正確だからだ（空白のドラッグは連続的で、ステップがない）。

### 29.3 まず「座標軸の言葉」をもう一度おさらい

この篇の「X / Y / Z 軸に沿って」というすべての言い方は、**

ページの標注**に従って覚える（これは画面内で見る軸ラベルと一致する）：

- **X 軸（青色）= 前後方向**（青≈「deep/縦深」）
- **Y 軸（赤色）= 左右方向**（赤≈「左右」）
- **Z 軸（緑色）= 高さ方向、上が正**（緑≈「高」）

> ⚠️ 注意：これは「ページ標注軸」だ。コード内部では別の組（X赤Y緑Z青、Y が上向き）を使っているが、あなたが界面上で、説明書で、ヘルプパネルで見るのは、永遠に上記の組の標注だ。標注軸を覚えれば十分で、内部実装に惑わされないように。

この表を覚えておけば、後の各章はすべてこれを使って「文章を作る」だけだ。

## 第31章 単キー操作とShift組み合わせ

キーボードショートカットには核心的なルールがある：**現在オブジェクトが選択されているかどうかを見る**。以下の二つの表は、アプリ内の「設定 → 快捷操作」にある「単キー操作」「Shift 組み合わせキー」と**完全に一致**しているので、そのまま照らして使えばよい。

### 31.1 単キー操作

> オブジェクト選択時：平行移動 0.1 グリッド（0.15 長さ）/ 回転 5°；未選択時：視点平行移動 0.1 グリッド / 回転 5°。

| キー | オブジェクト選択時 | 未選択時 |
|---|---|---|
| `↓` / `↑` | X 軸に沿って +/− 平行移動 | 視点 後 / 前 平行移動 |
| `→` / `←` | Y 軸に沿って +/− 平行移動 | 視点 右 / 左 平行移動 |
| `PgUp` / `PgDn` | Z 軸に沿って +/− 平行移動 | 視点 上 / 下 平行移動 |
| `A` / `D` | Z 軸を中心に 順 / 逆 回転 | 視点 左 / 右 回転 |
| `W` / `S` | Y 軸を中心に 順 / 逆 回転 | 視点 上 / 下 回転 |
| `E` / `Q` | X 軸を中心に 順 / 逆 回転 | — |
| `+` / `-` | 拡大 / 縮小 5% | — |
| `Esc` | 操作取消 | コントロールを閉じる |
| `F11` | 🖥️📱 全画面 / 全画面退出；💻 最大化 / 復元 | （同上） |
| `Del` / `Backspace` | 選択オブジェクトを削除 | — |

✏️ **練習**：立方体を一つ置く → それを選択して `↑` を押し「前に進む」様子を見る；選択を解除（空白をクリック）してからもう一度 `↑` を押すと、今度はレンズが前に押し出される。同じキー、二つの顔だ。

### 31.2 Shift 組み合わせキー

> オブジェクト選択時：平行移動 1 グリッド（1.5 長さ）/ 回転 90°；未選択時：視点平行移動 1 グリッド / 回転 90°。

| `Shift` + キー | オブジェクト選択時 | 未選択時 |
|---|---|---|
| `↓` / `↑`、`→` / `←`、`PgUp` / `PgDn` | 平行移動 1 グリッド | 視点平行移動 1 グリッド |
| `A` / `D`、`W` / `S`、`E` / `Q` | 回転 90° | 視点回転 90° |
| `+` / `-` | 拡大 ×2 / 縮小 ×0.5 | — |
| 左クリック | オブジェクト選択追加（クリック選択） | （同上） |
| 左長押し（ペンツール） | — | ペン直線拘束モード（描画時の筆跡を水平 / 垂直 / 45° に拘束、`Shift` 拘束と同じ効果） |

💡 口诀：**普通キーで寄せ、Shift キーで決める**。まず方向キーで微調整して大体合わせ、その後 `Shift`+方向キーで最後の 1 グリッド大ジャンプで瞬時に整列；回転も同様、まず `A` で 5° 回し、次に `Shift+A` で直接 90° まで補って正す。

| `Y` | やり直し |
| `C` | コピー |
| `V` | 貼り付け |
| `D` | クローン |
| `Del` / `Backspace` | シーンクリア（「シーンをクリアしてよろしいですか？この操作は取り消し可能です。」確認ボックスをポップアップ、確認後にクリア；通常の `Delete`/`Backspace` は `Ctrl` なしの場合、選択済みオブジェクトのみを削除） |

⚠️ `Ctrl + Del` は一度にすべてのオブジェクトを削除するが、**確認ボックスがポップアップ**し、クリア操作は**取り消し可能**（ `Ctrl + Z` で復元）。それでもクリア前にまず `Ctrl + S` でエクスポートしてバックアップすることを勧める。

### 32.3 総合実戦：純キーボードで「小さな灯台」を組む

この篇で学んだことを一つの流れに繋いでみる：

1. パネルから**円柱**を一つシーンへドラッグ（マウスドラッグしかできない、諦めよう）；
2. それを選択し、`Shift + PgUp` を数回押して「高く」ちょうどよい位置まで伸ばす；
3. `Ctrl + D` で一つクローンして「灯室」とし、`PgUp` で柱の頂に移動；
4. `Shift + A` で灯室を 90° 正しく回転（必要なら）；
5. `Ctrl + A` で全選、`Ctrl + S` で保存；
6. 「正面視」ボタンで視点を正し、`Ctrl + P` でスクリーンショットを納品。

第 1 ステップの形状配置以外は、ほとんどマウスパネルに触れていない——これが「效率篇」の終着点：双の手をキーボードに生やすように。

✏️ **この篇のまとめ**：ショートカットの本質は「よく使う動作を、指が最も自然に落ちる位置にマッピングする」ことだ。二つの主線を覚えよう——**選択なし=カメラを動かす、選択あり=物体を動かす**；三つの軸を覚えよう——**X前後、Y左右、Z高度**；一つの加速キーを覚えよう——**Shift 大ステップ**。次の篇では「変換コントロール（直接ドラッグできる矢印）」とキーボードの連携を解説し、あなたの操作をよりスムーズにする。

# 第九篇 変換篇：『話す』矢印

> 第32章ではキーボードで物体をあちこち運んだが、もう十分速い。しかしキーボードには「固定ステップ」がある——それは正確で繰り返しの移動に向くが、「手触りで別の物体にぴったりくっつくまでドラッグする」ような作業には向かない。
>
> この篇の主役は、オブジェクトを選択した後にその上に現れるあの**カラー矢印 / リング / ブロック**の組、専門用語で「変換コントロール（gizmo）」と呼ばれるものだ。これでマウスで直接物体を「掴んで」引っ張れる。

## 第33章 変換ギズモ初め：三つの「掴む道具」

### 33.1 いつ現れるか

**オブジェクトを一つ選択**するだけ（それをクリックし、選択枠が出る）で、物体の中心に一組のハンドルが浮かび上がる。これが変換コントロールだ。

これには三つの「スキン」があり、三つの操作に対応し、右パネルの「変換モード」領域（⇔ ↻ ⤢ の三つの四角ボタンが並ぶ小領域）で切り替える：

| モード | ボタンアイコン | ハンドルの姿 | 何に使うか |
|---|---|---|---|
| **平行移動** | ⇔ | 三本の**矢印** | 物体をあちこち運ぶ |
| **回転** | ↻ | 三つの**リング** | 物体をぐるぐる回す |
| **縮放** | ⤢ | 三つの**ブロック**（角の小さな立方体） | 物体を拡大縮小する |

デフォルトは**平行移動**モードに入る。モードを変えたい時は対応するボタンをクリックすればよい；切り替え時には下部に「平行移動/回転/縮放」というヒント文字も一瞬表示される。

💡 小知識：変換コントロールとキーボードショートカットは**同じことの二つの入口**だ——キーボードは「精密ステップ」、コントロールは「自由ドラッグ」。両方混ぜて使える：まずコントロールで大体ドラッグし、その後キーボードの `↑` で数グリッド微調整して整列。第36章でどう連携するかを専門に解説する。

### 33.2 あらかじめ説明しておかねばならない「色の罠」

⚠️ **全篇で最も重要な注意、この段落を必ず読むこと。**

シーン内の三本の**座標軸ラベル**は「ページ標注色」を使っている：
- **X = 青色 = 前後**
- **Y = 赤色 = 左右**
- **Z = 緑色 = 高度**

しかし変換コントロールのハンドルの着色は、**three.js コード軸慣例**（赤=X、緑=Y、青=Z）に従っており、上記の組とは**色が合わない**！ だからあなたが見るハンドルの色は、こう翻訳しなければならない：

| ハンドル色 | 実際に表すコード軸 | 対応するページ標注軸 | 画面上での意味 |
|---|---|---|---|
| 🔴 赤ハンドル | コード X | ページ **Y** | **左右**移動 / 左右軸を中心に回転 |
| 🟢 緑ハンドル | コード Y | ページ **Z** | **高度**（上下）移動 / 高度軸を中心に回転 |
| 🔵 青ハンドル | コード Z | ページ **X** | **前後**移動 / 前後軸を中心に回転 |

> 覚えられなくても構わない、一句覚えよう：**ハンドル赤=左右、ハンドル緑=上下、ハンドル青=前後**（ページ標注で理解する）。表面の赤緑青に騙されて「シーン軸ラベルの色」を当てはめてはいけない。

✏️ **練習（検証用）**：立方体を一つ選択し、平行移動モードへ切り替える。まず**赤矢印**をドラッグし、物体が「左右」に滑るか「前後」に滑るかを見る？——左右のはずだ。次に**青矢印**をドラッグし、「前後」に滑るか？ この実験で上表を頭に刻み込めば、後ろのすべての回転/縮放の軸も乱れない。

### 33.3 ハンドルをドラッグしている時、視点は動かせるか

動かせる。しかもこれは本ツールのとても快適な設計だ：

- **左ドラッグ ハンドル** = 物体を操作；
- **右ドラッグ** = 視点回転（カメラ回転）；
- **中ドラッグ** = 視点平行移動；
- **ホイール** = 視点ズーム。

つまり、左手で右ボタンを押しながら角度を変えて物体の側面を見ても、右手（あるいは同じ手でキーを替え）はハンドルを引き続きドラッグできる——視点と変換は**互いに干渉しない**。もう「いったん変換を退出、視点回転、また入る」などと手間をかける必要はない。

## 第34章 移動モード：矢印でオブジェクトを「掴んで」動かす

### 34.1 三つの引っ張り方

平行移動モードでは、三本の軸矢印のほか、コントロールは**二つの平面ブロック**（ある二本の軸が張る平面上に貼られている）も提供する。そこで三つの掴み方がある：

1. **一本の矢印を掴む**（赤/緑/青）→ その一本の軸に沿ってまっすぐだけ動き、最も精密で、それることはない；
2. **平面ブロックを掴む**（例えば赤緑矢印に挟まれた面）→ この平面内を自由に滑り、同時に二本の軸に拘束される；
3. 完全に自由に「地面にくっついたまま好き勝手ドラッグ」したい？ まず対応する平面に切り替えてからドラッグすればよい。

💡 経験：正確な整列をするなら、常に**一本の矢印を掴む**こと。平面は掴むな——平面は物体を意図しない方向に連れ去りやすい。

### 34.2 平面の見分け方（色の罠を踏まえて）

平行移動モードの平面は、「隣り合う二本の矢印が挟む三角/ブロック領域」だ。第33.2節の翻訳に従うと：

- 赤矢印（左右）+ 緑矢印（上下）が挟む平面 = **左右×高度** 平面（物体の「側面」）；
- 緑矢印（上下）+ 青矢印（前後）が挟む平面 = **高度×前後** 平面（物体の「正面/背面」）；
- 赤矢印（左右）+ 青矢印（前後）が挟む平面 = **左右×前後** 平面 = **地面**（物体が「踏んでいる」平面）。

✏️ **練習**：物体を地面に置き、「赤+青」が挟む平面ブロックを掴んでドラッグ——それは素直に地面に沿って滑り、上がりも下がりもしないだろう？ これが「地面に沿って平行移動」する最も安定した姿勢だ。

### 34.3 キーボード平行移動と対比して学ぶ

| やりたい動作 | コントロールで | キーボードで（第32章） |
|---|---|---|
| 前後に正確に 0.1 グリッド動かす | **青矢印**を掴んでドラッグ | `↑`/`↓` |
| 左右に正確に 0.1 グリッド動かす | **赤矢印**を掴んでドラッグ | `←`/`→` |
| 高度を正確に上げ/下げる | **緑矢印**を掴んでドラッグ | `PgUp`/`PgDn` |
| 大ステップで 1 グリッド動かす | コントロールで矢印を力づくでドラッグ | `Shift`+方向キー |

💡 口诀：**コントロールは「手触り」、キーボードは「精度」**。まずコントロールで八九不离十（ほぼピッタリ）までドラッグし、その後キーボードの `↑`/`←`/`PgUp` で数グリッド微調整してグリッド線に貼り付ける。

## 第35章 回転モード：リングが「どの軸周りに回すか」を決める

### 35.1 三つのリング = 三本の軸の回転

回転モード（↻）へ切り替えると、物体上が三つのカラーリングになり、各リングは「その軸を中心に回る」を表す：

| リング色 | コード軸 | ページ標注軸 | 観感（第32章の喩えを思い出す） |
|---|---|---|---|
| 🔴 赤リング | コード X | ページ **Y**（左右軸） | **前のめり/後のけ反り**のような宙返り |
| 🟢 緑リング | コード Y | ページ **Z**（高度軸） | **ターンテーブル/コマ**のようなその場回転 |
| 🔵 青リング | コード Z | ページ **X**（前後軸） | **左に倒れる/右に倒れる**ような横転 |

⚠️ リングの色と「どの軸を中心に回るか」の対応も、同様に第33.2節の翻訳表を当てはめなければならない——**赤リングは左右軸、緑リングは高度軸（最もよく使う、正す用）、青リングは前後軸を中心に回る**。

### 35.2 リングを掴んで回すのは、キーボードの A/D/W/S/E/Q と同一事

第32章であなたはキーボードで物体を回したが、そこではこう言った：
- `A`/`D` は**高度軸**（ページ Z、垂直軸）を中心に回る；
- `W`/`S` は**左右軸**（ページ Y）を中心に回る；
- `E`/`Q` は**前後軸**（ページ X）を中心に回る。

コントロールのリングに対応させると：
- キーボード `A`/`D` ↔ **緑リング**をドラッグ（高度軸）；
- キーボード `W`/`S` ↔ **赤リング**をドラッグ（左右軸）；
- キーボード `E`/`Q` ↔ **青リング**をドラッグ（前後軸）。

✏️ **練習**：「正面」のある物体を選択し、`Shift + A` でちょうど 90° 回転（正す）させ、その後回転モードへ切り替えて**緑リング**をドラッグ——手でドラッグするのも同じくその垂直軸を中心に回り、しかも任意の角度に止められる（キーボードは 5°/90° の跳ねしかできず、コントロールは中間値にも止まれる）ことに気づくだろう。これがまさに補い合う。

### 35.3 自由回転 vs 精密回転

- コントロールリング：**

任意の角度**に止められ、「見て気持ちよくなるまで回す」に向く；
- キーボード `Shift`+文字：**

90°**の整数跳ねのみ、**

「必ず正す、必ず直角」**に向く；
- キーボード通常文字：**

5°**ステップのみ、**

「数度微調整」**に向く。

💡 実戦：まずコントロールで大体の角度までドラッグ → その後 `Shift+A`（緑軸）で正 90°/180° まで補う。立体文字、建築立面といった「正さないといけない」作業で最もよく使う。

## 第36章 拡縮モード：立方体ハンドルと「均等」スイッチ

### 36.1 ブロックハンドル：一本の軸を引っ張るか、全体を膨らませるか

縮放モード（⤢）へ切り替えると、物体の角に小さな立方体ハンドルが現れる。単一のブロックをドラッグ = **その一本の軸に沿ってだけ伸ばす/潰す**（例えば球を楕球に潰す、柱を高くthinに伸ばす）；中央ブロックをドラッグ = 全体縮放。

| ハンドル色 | ページ標注軸 | それをドラッグした効果 |
|---|---|---|
| 🔴 赤ブロック | 左右（Y） | 幅が広く / 狭く |
| 🟢 緑ブロック | 高度（Z） | 高く / 低く |
| 🔵 青ブロック | 前後（X） | 深く / 浅く |

### 36.2 「等比縮放」ロック：初心者が最もオンにすべきスイッチ

右パネルの変換モード領域の下に **「等比縮放」** というチェックボックスがある（デフォルトでチェック済み）。チェックしている時は、どのブロックをドラッグしても、物体は**全体等比例**で拡大縮小され、引き伸ばしで変形することはない——これが通常まさにあなたの望むところだ。

⚠️ チェックを外してから単一ブロックをドラッグすると、物体は「単方向ストレッチ」で変形する。これには創造的用途（例えば潰した座金、伸ばした横梁）があるが、初心者は誤ってオフにした後「どうして歪んだ」と首をかしげやすい。迷ったらチェックを維持せよ。

### 36.3 キーボード縮放と対比、および「複数選択禁缩」

| やりたいこと | コントロールで | キーボードで（第32章） |
|---|---|---|
| 全体 5% 拡大 | 中央ブロックをドラッグ（等比チェック） | `+` |
| 全体 5% 縮小 | 中央ブロックをドラッグ | `-` |
| 倍 / 半分 | 中央ブロックを力づくで引っ張る | `Shift`+`+` / `Shift`+`-` |
| 単方向潰し | 等比を解除し単ブロックをドラッグ | キーボード非対応 |

⚠️ **重要な制限**：**

一度に複数のオブジェクトを選択している時**、縮放モードは**自動的に無効**になる（ボタンが灰色になり、かつその時縮放モードなら自動的に平行移動へ戻る）。理由はキーボードの `+`/`-` の複数選択禁缩と同じ——大きさの異なる複数の物体を無理やり一緒に縮放するとおかしくなるからだ。

💡 では複数選択時はどうやって一括でサイズを調整するか？ 二つの道：① まず `Ctrl + A` してからコントロール/キーボードで一つずつ処理；② 「等比縮放」以外の手段——例えば先にグループを編成し、縮放ではなく平行移動で配置すること。

### 36.4 変換コントロールが「使わせてくれない」とき

複数選択禁缩のほかにも、変換モードボタンが灰色になりクリック不可になる場合がいくつかある：

- **ペン / テキスト / 消しゴム**ツールモードにいる時（これらのツールは自身がクリックを引き継ぐので、変換コントロールは一旦譲る）；
- **テキスト編集**中（インライン入力ボックスが出ている時）、変換ボタンは一時無効になり、入力完了で復帰；
- **テキストオブジェクト**自体は等比縮放に対応せず、テキストを選択すると等比縮放関連コントロールが隠され縮放モードが無効になり、自動的に平行移動へ戻る；画像とペン筆跡は正常に縮放できる。

⚠️ 三つのモードボタンが押せず灰色になっているなら、まず確認：まだどこかのツールに留まったまま抜けていないか？ `Esc` を押すか、上部の「選択」系ボタンをクリックしてツールを抜ければ、変換コントロールは復活する。

### 36.5 コントロールと数値ボックス：双方向同期

右の「変換」領域には対応する**数値スライダー/入力ボックス**（位置、回転角度、縮放値）もある。これらはコントロールと**双方向同期**している：
- コントロールをドラッグすると、数値ボックスはリアルタイムで追随；
- 数値ボックスに直接正確な値を入力すれば（例えば回転に `45`、縮放に `2.5` を入力）、物体も即座に変わる。

💡 「絶対的に正確」（例えば回転は必ずちょうど 30°、縮放は必ずちょうど 1.5 倍）が必要な時は、**直接数値ボックスへ入力**する方がコントロールを引っ張るよりずっと確実だ。コントロールは「感覚を探す」に向き、数値ボックスは「数値を決める」に向く。

✏️ **この篇のまとめ**：変換コントロールはキーボードの「自由ドラッグ版」だ。三つのことを覚えよう——① それには平行移動/回転/縮放の三つのスキンがあり、矢印/リング/ブロックに対応；② **ハンドル赤=左右、緑=上下、青=前後**（永遠にページ標注で翻訳し、表面の色に騙されてはならない）；③ 左ドラッグで物体、右/中/ホイールで視点を管り、三者は干渉しない。次の篇では「組み合わせと編成、整列と分布」を解説し、あなたを「単一物体を動かせる」から「一大群の物体を配置できる」へと進化させる。

# 第十篇 群像篇：一度に「一群」の物体を管理する

> 前篇の末尾で「組み合わせ編成、整列と分布を解説する」と予告した。ここであらかじめ打ち明けておく：**本ツールには独立した「編成」ボタンも、「ワンクリック整列/分布」ボタンもない**——それはより軽量で、より柔軟な道を歩む：**複数選択 + 一緒に変換 + クローン配列**。
>
> この篇では「どうやって一大群の物体を効率よく管理するか」を教える。銀の弾丸はないが、足りるだけの『泥臭い方法』があり、並べれば同じように整然となる。

## 第37章 一度に一群を選択：「選択セット」を知る

### 37.1 なぜ複数選択するか

これまで you は「一つクリック、一つ変更」だった。しかし実際の創作はたいてい一団のものだ：一並びの木、一列の灯、一面の小石。100個を一つずつ調整していたら、人間が先に狂う。

解決策：まずそれらを**一度に「選択集」に選び込み**、その後一括操作する。これが複数選択の意味だ。

### 37.2 複数選択三法

| 方法 | どう操作するか | 適した場面 |
|---|---|---|
| **全選** | `Ctrl + A`、またはタッチで下部の「全選」ボタンをクリック | シーン内のすべてのオブジェクトを選択したい時 |
| **選択追加 / 選択解除** | `Shift` を押しながらオブジェクトをクリック：選択されていないものをクリック=加える；選択済みのものをクリック=蹴り出す | 特定のいくつかを選ぶ（例えば「この二つの灯 + あの木」） |
| **枠選** | 空白で**長押しドラッグ**し、点線枠を引く、枠内のオブジェクトが一度に選択される | 一片に密集したオブジェクト、一つずつクリックするのが面倒な時 |

✏️ **練習**：5つの形状をシーンに散らばらせて置く。まず `Ctrl + A` で全部光るか見る → 空白をクリックして解除 → `Shift` を押しながらその中の 2 つをクリック（灰色に）→ その後空白で一つの枠をドラッグし、残りの 3 つを枠に収める。選択集が一沓の付箋のように、自由に増減する感覚を味わえ。

💡 枠選の小細工：マウスで空白をドラッグして初めて枠が出る；タッチは「空白ドラッグ」の概念がないので、専用に「枠選」ボタンを作り、オンにすると一本指ドラッグで枠選となる（オン時は下部に「枠選モード」と提示）。枠選でどのオブジェクトも枠に当たらなかった時も、静かに失敗することはなく、「枠選がオブジェクトに命中しませんでした」と軽く提示される。

### 37.3 選択の「境界事例」

- **空白**をクリック（ドラッグしない）= 全選択解除；
- 枠選時に枠が**完全に空**なら、選択集がクリアされる（「逆選で無に」と等しい）；
- **テキスト編集**中や**ペン/消しゴム**ツールにある時は、選択ロジックはツールに譲り、複数選択は一時使用不可。

❓ **考えてみよう**：なぜ「Shift+クリック」は加えにも減らしにもなるのか？——選択集は「オン/オフ」の二元ではなく、一つの**集合**だからだ。既存の要素をクリックすれば除去すべき、存在しないものをクリックすれば加えるべき。この「切り替え」ロジックは、その後ファイルマネージャーやメールボックスでも至るところで出会うだろう。

## 第38章 一群まとめて動かす：複数選択変換の「マスターポイント」

### 38.1 見えない「マスターポイント」
複数のオブジェクトを選択したとき、ツールはコントロールを特定の物体に取り付けません（どれに付けても不公平だからです）。その代わり、**この一群の物体のちょうど中心**に、**見えないプロキシ点**（コード上では `multiTransformProxy` と呼ばれます）を置きます。

あなたが見ている変換コントロール（矢印/リング）は、実はこの「マスターポイント」に取り付けられています。これをドラッグすると、アルゴリズムがマスターポイントの移動/回転の**差分（インクリメント）**を計算し、それを**選択されたすべてのオブジェクトに同期して配布**します。

> 人間向けに訳すと：**見えない「総スイッチ」を一つ動かすと、選択されたものがすべて一緒に動き、互いの相対位置は変わらない**ということです。

### 38.2 複数選択で何ができるか

| 操作 | 複数選択時に使える？ | 説明 |
|---|---|---|
| 一緒に**平行移動**（矢印/平面をドラッグ） | ✅ 使用可 | 群全体がある軸に沿ってまとめて移動 |
| 一緒に**中心回りの回転**（リングをドラッグ） | ✅ 使用可 | 群全体がグループ中心を軸に回転し、盤上の駒を一斉に回すよう |
| 一緒に**拡縮** | ❌ 無効 | 複数選択時は拡縮モードボタンがグレーアウトし、自動的に平行移動に戻る |

✏️ **やってみよう**：バラバラに置かれた 3 つのオブジェクトを選択 → 回転モードに切り替え → **緑のリング**（高さ軸回り）をドラッグ → 「一つの手で同時にねじ回される」ように共通の中心を軸に回り、互いの間隔が変わらないか確認。これが「グループ回転」の快感です。

### 38.3 なぜ複数選択では一緒に拡縮できないか

⚠️ これは**意図的な制限**であり、バグではありません：

- 大きさや形の異なる複数の物体を一緒に等比拡縮すると、結果は往々にしておかしくなります（大きいものは巨大になり、小さいものはゴマ粒になる）；
- そこでツールは複数選択時に**拡縮モードを直接無効化**し、「個別に縮めるか、先にクローンしてから調整するか」を強制します。

💡 代替案：
1. 一群を「同じ大きさにしたい」——まず `Ctrl + D` で同じものを一列にクローンし、もともとサイズが一致しているのでから、あとは個別に微調整；
2. 本当に一群をまとめて拡縮したい——**先に全部選択、JSON をエクスポート、数値を変えてからインポート**する？ それは面倒すぎます。もっと実践的なのは：それらを「一時的なグループ」とみなし、**個別拡縮 + 統一オフセット**で配置することです。

### 38.4 複数選択＋Shift の大ステップ、やはり便利

第32章で学んだ `Shift` の大ステップ（1 グリッド / 90°）は、複数選択にも**同様に効きます**。一群を選択した状態で `Shift` を押しながら方向キーをドラッグすると、群全体が一度に 1 マス飛び、配列を並べるのに超便利です（次の章で使います）。

## 第39章 量産：コピー・クローン・「配列」

繰り返し物を作るとき、2 個目、3 個目……を手作業で描いてはいけません。「コピー/クローン」を使ってコンピュータに生成させましょう。

### 39.1 複製を「生み出す」3 つの方法

| キー | 名前 | 特徴 |
|---|---|---|
| `Ctrl + C` | コピー | 選択したオブジェクトを**クリップボードに保存**（すぐには出現しない） |
| `Ctrl + V` | 貼り付け | クリップボードから**取り出し**、元の位置の近くに貼る |
| `Ctrl + D` | **クローン** | 一発で完了：その場でコピーし**自動的に少しオフセット** |

💡 **最もよく使うのは `Ctrl + D`** です。これは「コピー→貼り付け」より一手間少なく、しかもクローンされたコピーは自動的に少しずれるので、すぐに見えて、すぐにまた配置できます——配列を作る定番です。

✏️ **やってみよう**：立方体を 1 つ置く → `Ctrl + D` で一つ増える、しかも少しずれる？ → 新しい方を選択 → `→` で次のマスに移動 → また `Ctrl + D` → また `→`……数回で一列に並びます。マウスパネルには一切触れていません。

### 39.2 「クローン＋キーボード」で整った配列を並べる

「整列/分布」ボタンがない？ 気にせず、**グリッド歩長**で手動配置すれば、同じように整います：

1. オブジェクトを一つ選択し、`Ctrl + D` でクローン；
2. 方向キーで**ちょうど 1 マス**の位置に移動（デフォルト歩長 0.1 グリッドなら 10 回押す；あるいは `Shift`+方向キーで一回 1 マス）；
3. `Ctrl + D` + 方向キーを繰り返すと、一列が出来上がる；
4. 一列ができたら、その列を `Ctrl + A` で全選択し、`Shift`+方向キーで「列全体」を大ステップで次の行へ移動、さらにクローンを続ければ——二次元配列（マトリックス）も出来上がります。

💡 **円を並べるコツ**：一つクローン → 中心から一定半径の位置に移動 → 群全体を中心回りに回転（第38章）→ ある角度ごとに一回クローン。何回か回せば、「リング状配列」が出来上がります。これが手動版の「分布」です。

### 39.3 コピー＆貼り付けの境界

⚠️ つまずきやすい 2 つのヒント（ツールが小さく文字で知らせます）：
- **「変換中のため、コピー/クローンできません」**：コントロールをドラッグしている最中（変換がアクティブ）は、コピー/クローンボタンが一時的に無効になります。手を離して（ドラッグを終了）から再度押せば OK です。
- **「先にオブジェクトを選択してからコピーしてください」**：何も選択せずに `Ctrl + C` を押すと、先に選択するよう促されます。クリップボードが空のとき `Ctrl + V` でも「クリップボードが空です」と表示されます。

❓ **考えてみよう**：クローンとコピー＆貼り付け、その底層の違いはどこか？——クローンは「その場でオフセット付きコピーを生成」し、いかなる中間保存にも依存しません；コピー＆貼り付けは「先にクリップボードへ保存、その後取り出して使う」ため、A シーンをコピーし、B シーンに切り替えて貼り付けることができます（本ツールのクリップボードはメモリレベルであり、同一ページ内で共通です）。この点を理解すれば、なぜ時折 `Ctrl + V` が反応しないか——おそらくクリップボードが空だからだと分かります。

## 第40章 保存と共有：作品を画面から離す

苦労して作ったシーンが、ページを閉じたら消えてしまう？ そんなことはありません——本ツールは**エクスポート**でファイル化、**インポート**で戻し、**スクリーンショット**で画像化できます。

### 40.1 3 つの「保存/読取」キー

| キー | 作用 | 成果物 |
|---|---|---|
| `Ctrl + S` | シーンをエクスポート | 1 つの **JSON ファイル**（シーンの完全な記述） |
| `Ctrl + O` | シーンをインポート | 以前エクスポートした JSON を読み戻す |
| `Ctrl + P` | 画像をエクスポート | 1 枚の **PNG 画像**（現在の画面の写真） |

💡 ワークフロー：**一段作る → `Ctrl + S` で保存 → 翌日 `Ctrl + O` で読み戻して続き**。JSON はあなたの「プロジェクトファイル」、PNG はあなたの「成果写真」であり、両者は役割を分担します。

### 40.2 JSON に一体何が保存されているか

エクスポートされる JSON は画像ではなく、一份の**オブジェクトリスト**であり、大体以下を記録します：

- 各オブジェクトの**種類/形状**（球か文字か、長さ幅高さのパラメータ）；
- 各オブジェクトの**変換**（位置、回転、拡縮——つまりどこにあり、傾いているか、どれだけ大きいか）；
- 各オブジェクトの**外観**（色、模様、透明度、テクスチャ）；
- シーンの**環境設定**（座標軸、グリッド面の表示/非表示など）。

⚠️ 「ピクセル」ではなく「パラメータ」を保存しているため、インポート後も**編集を続けられます**——これは一枚の静止画ではなく、生きたプロジェクトです。これもまた、なぜこれまでのすべての操作が「履歴スタック」に入って取り消しできるのかを説明します：それらは本質的にこのパラメータを変更しているのです。

### 40.3 共有と協力の提案

- **同僚に効果を見せる**：PNG（`Ctrl + P`）を送るのが最速；
- **同僚に続きを直してもらう**：JSON（`Ctrl + S`）を送り、相手が `Ctrl + O` で開けば編集可能；
- **デバイス間**：JSON をクラウドストレージ/WeChat に送り、別の PC でページを開いてインポートすればよい——シーンはいつでも持ち運べます。
- ⚠️ `Ctrl + Del` が**シーン全体をクリア**することも忘れずに、確認ボックス「シーンをクリアしますか？」が表示され、クリアは取り消し可能です。クリアする前にまず `Ctrl + S` でバックアップを取り、心血をワンキーで蒸発させないように。

### 40.4 手動の「整列と分布」：ボタンがなくても揃えられる

篇頭の約束に戻ります——ワンクリック整列/分布がない以上、ここでボタンなしの**純手動**整列法を 3 つ挙げます。前述の内容と組み合わせてください：

1. **グリッドに頼る**：デフォルト移動歩長 0.1 グリッド（=0.15 単位）、整数回押す＝正確にグリッド線上に着地。`Shift`+方向キーは一回 1 マスで、「グリッド線にぴったり合わせる」に最適。
2. **クローンに頼る**：第39章のように、クローン＋固定歩長＝等間隔配列（これが「分布」）。
3. **視点に頼る**：まず底部の「正面視/天面視」で物体を標準機位に正しく配置し、その後単一軸に沿ってキーボードで移動し、「斜めに並べる」ことを避ける。

✏️ **総合練習（本篇の卒業課題）**：「立方体 ＋ `Ctrl + D` クローン ＋ `Shift`＋方向キー」で 5×3 のマトリックスを並べる；`Ctrl + A` で全選択後 `PgUp` で全体を地面から 1 マス上げる；`Ctrl + S` で保存。あなたはすでに「量産 ＋ 整列配置 ＋ 成果保存」ができるようになりました。

---

✏️ **本篇まとめ**：本ツールは「グループ化/整列」ボタンに頼るのではなく、**複数選択 ＋ プロキシマスターポイント ＋ クローン配列**によってグループ管理を実現します。覚えておくこと——複数選択の 3 法（全選択/Shift 加選/枠選択）、複数選択では平行移動・回転はできるが拡縮はできない、クローン `Ctrl + D` は配列の神器、JSON はあなたの生きたプロジェクトファイル。次の篇では**総合実戦**を行います：ゼロから一つの完成した小シーン（小さな家 / 小さな庭）を組み立て、これまで十篇の腕前を一本の線に繋ぎ、「入門から精通へ」のラスト一キロを体験します。

## 第41章 プロジェクト1：小さな家を建てる

この章では、これまでに学んだ操作を組み合わせて、実際に「小さな家」を一から作ってみます。完成イメージは、壁・屋根・ドア・窓を持つシンプルな家です。

### 41.1 このプロジェクトの目標

- 基本図形（直方体・三角柱）を使って家の形を作る
- 移動・回転・スケールで各部分を配置する
- 複数選択とグループ化でまとめて扱う
- マスターポイントで全体の位置を調整する
- 書き出し（エクスポート）で成果を保存する

> 💡 初めてのプロジェクトなら、図形一つひとつの操作に慣れてから進めるとスムーズです。

### 41.2 ステップ1：土台（床）を作る

1. ツールバーから「直方体」を選び、地面に一つ配置します。
2. スケールを調整し、横幅 `4`、奥行き `3`、高さ `0.2` 程度の薄い板にします。
3. これを「床」とします。名前欄で `床` とリネームしておくと後で分かりやすくなります。

| 項目 | 値 |
| --- | --- |
| 幅（X） | 4 |
| 奥行き（Y） | 3 |
| 高さ（Z） | 0.2 |

### 41.3 ステップ2：壁を立てる

1. 再び「直方体」を配置し、床の上に乗せます。
2. 高さを `2.5` にスケールします。
3. 前後の壁と左右の壁、合計4枚を複数選択でコピー（`Ctrl+C` / `Ctrl+V`）して並べます。
4. 隙間がないよう、マスターポイントで微調整します。

⚠️ 壁どうしの重なりに注意してください。重なると後で屋根が正しく乗りません。

### 41.4 ステップ3：屋根を作る

1. 「三角柱」を配置します。
2. 家の幅に合わせてスケールし、壁の上に回転させて載せます。
3. 屋根が左右対称になるよう、`0` 度基準で回転を揃えます。

📦 屋根の形状は `.json` テンプレートから読み込んでも構いません。

### 41.5 ステップ4：ドアと窓

1. 壁の一面に小さな直方体を置き、それを「ドア」として色を変えます。
2. 別の壁に穴のような見た目の直方体を置き、「窓」とします。
3. 窓は複数選択で二箇所コピーすると楽です。

✏️ 色や材質はプロパティパネルから設定できます。

### 41.6 ステップ5：グループ化して完成

1. 床・壁・屋根・ドア・窓をすべて複数選択します。
2. 右クリックメニューから「グループ化」を選び、一つの「家」オブジェクトにまとめます。
3. マスターポイントで全体を好きな位置へ移動します。

🖥️📱 デスクトップ版・モバイル版いずれも同じ手順で作成できます。

### 41.7 成果の保存と書き出し

- プロジェクトは `Ctrl+S` で保存します。
- 共有用にはエクスポート機能で `.json` または画像として書き出します。
- 書き出したファイルは他のデバイスへ持ち込めます。

❓ うまく屋根が乗らない場合は、その章の「考えてみよう」で壁の高さと屋根のスケールを再確認してください。

> 🤖 おつかれさまでした。これでプロジェクト1は完了です。
## 第42章 プロジェクト2：3Dテキスト看板を作る

本章では、立方体ベースのアセンブリで「立体字の看板」を作る手順を紹介します。完成すると、壁に飾れるような、またはプリントできるような立体的なテキスト模型が得られます。

### 42.1 このプロジェクトで学ぶこと

- 3Dテキストの配置と整列
- マスターポイントによる複数ブロックの一括移動
- 複数選択とグループ化
- エクスポートによる成果物の取り出し

### 42.2 キャンバスの準備

1. 新しいプロジェクトを作成し、キャンバスを開きます。
2. グリッド表示を ON にし、単位を「ブロック」に設定します。
3. 背景色を `#222222` に変更すると、後続の作業が見やすくなります。

> ヒント：作業前に `Ctrl+S` で保存しておくと、途中でクラッシュしても安心です。

### 42.3 テキストブロックの作成

1. メニューから「挿入」→「3Dテキスト」を選択します。
2. テキスト入力欄に `HELLO` と入力し、フォントサイズを `8` に設定します。
3. 「生成」をクリックすると、各文字がブロックの集まりとしてキャンバスに配置されます。

各文字は独立したブロック群として扱われます。以下の表は、文字ごとのブロック数の目安です。

| 文字 | ブロック数 |
|------|-----------|
| H    | 12        |
| E    | 9         |
| L    | 10        |
| O    | 11        |

### 42.4 整列とマスターポイント

1. 全文字を複数選択します（`Shift` を押しながらクリック）。
2. 「整列」→「底面を揃える」を実行し、すべての文字の高さを統一します。
3. マスターポイントを `HELLO` の先頭ブロックに設定します。
4. マスターポイントをドラッグすると、すべてのブロックが連動して移動します。

```text
マスターポイント設定コマンド（疑似コード）:
set_master_point(target="H_block_0")
move_master(dx=2, dy=0, dz=0)
```

### 42.5 グループ化と調整

1. すべての文字ブロックを複数選択します。
2. 「グループ化」を実行し、1つのオブジェクトとして扱えるようにします。
3. 必要に応じて「回転」ツールで `15` 度傾けます。

> 注意：グループ化を解除するには「グループ解除」を選択してください。誤って解除すると、個別ブロックの位置が崩れることがあります。

### 42.6 素材と色の適用

1. グループ化した看板を選択した状態で、素材パレットから「木目」を適用します。
2. 文字ごとに異なる色を付けたい場合は、グループを一時的に解除してから色を設定します。
3. 色コード `#DDBB88` を使うと、暖かみのある木の色になります。

### 42.7 エクスポート

1. 「ファイル」→「エクスポート」を選択します。
2. 形式として `.obj` または `.stl` を選択します。
3. ファイル名を `hello_sign` として保存します。

エクスポートしたファイルは、3Dプリンタ用スライサーや、他のモデリングソフトで読み込めます。

### 42.8 まとめ

このプロジェクトでは、以下の操作を習得しました：

- 3Dテキストの生成
- マスターポイントによる一括移動
- 複数選択とグループ化

- エクスポートによる成果物の取り出し

## 第43章 プロジェクト3：バッジ/アイコンを設計する

この章では、Cube3D Workshop（立方・3Dグラフィックデザイン工房）を使って、一枚の「バッジ / アイコン」をゼロから設計するプロセスを体験します。バッジやアイコンはサイズが小さく、視認性とシンボルの明快さが求められるため、モデリングの基本操作（押出し、ベベル、ミラー、テクスチャマッピングなど）を総合的に練習するのに最適な題材です。

### 43.1 プロジェクトの目標

本プロジェクトを完了すると、以下の成果を得られます：

- 平面図形から立体のバッジを押出しで作成する方法
- エッジにベベルをかけて、光の反射による「高級感」を出す方法
- 左右対称の形状に対してミラー機能を使う方法
- バッジの表面にロゴやテキストをテクスチャとして貼る方法
- 書き出した `.png` / `.apk` を他アプリで利用する方法

### 43.2 準備：キャンバスと単位

1. 新規プロジェクトを作成し、キャンバスを正方形（例：`512 × 512`）に設定します。
2. グリッド単位を `mm` に設定し、作業しやすいように補助グリッドを表示します。
3. 「マスターポイント（主控点）」をキャンバス中央に配置し、以降の操作の基準とします。

> ヒント：バッジは小さなサイズで使われるため、グリッドを細かくしておくと、後続の細部調整が楽になります。

### 43.3 外形の作成（押出し）

1. 円形または多角形の「外形」を描きます。ここでは正八角形を例にします。
2. 外形を選択し、`押出し（Extrude）` コマンドを実行して厚みを与えます。推奨厚みは `3 mm` 程度です。
3. 顶部の面を少し内側に縮小（インセット）し、段差を作るとデザインに立体感が出ます。

| 操作 | ショートカット | 備考 |
| --- | --- | --- |
| 押出し | `Ctrl+E` | 厚みは数値入力で指定 |
| インセット | `Ctrl+I` | 顶部面を選択して実行 |
| 複数選択 | `Shift+クリック` | 複数の面/辺をまとめて選択 |

### 43.4 エッジのベベル処理

バッジの外縁や段差部分にベベルをかけると、光が当たった際のハイライトが生まれ、製品らしい質感が出ます。

1. ベベルをかけたい辺を「複数選択（多选）」で選びます。
2. `ベベル（Bevel）` コマンドを実行し、幅を `0.5 mm`、セグメント数を `2` に設定します。
3. プレビューで光の反射を確認しながら、値を微調整します。

### 43.5 左右対称デザイン（ミラー）

バッジの意匠によっては、左右対称のモチーフを使うことがあります。

1. 左半分のモチーフを作成します。
2. `ミラー（Mirror）` 機能を使い、右半分に複製します。
3. 両者を結合し、必要に応じて中央の継ぎ目を滑らかにします。

> 注意：ミラー後にそれぞれを別々に編集すると非対称になるため、結合前に左右の形を十分確認してください。

### 43.6 表面へのロゴ・テキスト貼り付け

1. バッジの表面（顶部面）を選択します。
2. `テクスチャマッピング` パネルを開き、用意したロゴ画像（`.png`）を読み込みます。
3. UV を調整して、ロゴが面の中央に収まるよう配置します。
4. 材質の「発光（Emissive）」を少し上げると、ロゴが浮き上がって見えます。

### 43.7 書き出しと利用

1. 完成したバッジを `3D` プレビューで最終確認します。
2. メニューから `書き出し` → `PNG`（透過付き）を選び、アイコン用に保存します。
3. 必要であれば `書き出し` → `.apk` で、Android 用リソースとして書き出します。

| 書き出し形式 | 用途 |
| --- | --- |
| `.png` | Web / UI アイコン |
| `.apk` | Android アプリリソース |

### 43.8 まとめ

このプロジェクトでは、以下の一連のフローを学びました：

- 外形の描画と `押出し` による立体化
- `ベベル` による質感向上
- `ミラー` による対称デザイン
- `テクスチャマッピング` によるロゴ貼り付け
- 各種形式での `書き出し`

次章では、より複雑な造形やアニメーションへの応用について解説します。
## 第44章 プロジェクト4：総合シーン「我が家の小さな庭」

この章では、これまでに学んだ機能を総動員して、一つの小さな庭（「我が家の小さな庭」）をゼロから作り上げる総合プロジェクトに挑戦します。建物、木々、小道、柵、そして照明まで、すべてを自分の手で配置し、一つの完成された3Dシーンを仕上げます。

### 44.1 プロジェクトのゴールと構成要素

このプロジェクトの最終目標は、以下の要素を含む「我が家の小さな庭」シーンを完成させることです：

- **メイン建物**：壁、屋根、ドア、窓を持つ一軒家
- **植栽**：複数の木と低い生垣
- **小道**：建物の入口から庭の外へ続く石畳
- **柵**：庭の境界を示す柵
- **照明**：夜間も見えるようにするための灯具
- **地面**：芝生と土の地面

完成イメージは以下のようなレイアウトになります：

| 領域 | 内容 | 備考 |
| --- | --- | --- |
| 中央 | メイン建物 | 正面を南に向ける |
| 東側 | 木と生垣 | 日陰を演出 |
| 西側 | 小道 | 入口から外へ |
| 外周 | 柵 | 境界を示す |
| 全体 | 照明と地面 | 夜間表示用 |

### 44.2 地面と基本レイアウトの作成

まずは地面を作り、そこに各要素の配置場所を大まかに決めます。

1. **地面の作成**
   - 平面（Plane）を作成し、サイズを `20 x 20` に設定します。
   - マテリアルを「芝生」または「土」に設定します。

2. **グリッドの表示**
   - ビュー設定からグリッドを表示し、配置の目安とします。

3. **仮配置**
   - 建物の中心を `(0, 0, 0)` 付近に、小道を西側に、木を東側に置くよう、大まかな位置を決めます。

> ヒント：この段階では正確な位置決めは不要です。後でマスターポイントを使って微調整します。

### 44.3 メイン建物のモデリング

メイン建物は、壁・屋根・ドア・窓の4つのパーツで構成します。

#### 44.3.1 壁と屋根

- 箱（Box）を使って壁を作り、高さを `3` に設定します。
- 別の箱を使って屋根を作り、傾斜を持たせるか、三角柱（Prism）を使って切妻屋根とします。
- 屋根の色は「茶」系、壁は「白」系にします。

#### 44.3.2 ドアと窓

- 壁の前面に、少し沈み込ませてドア（Box）を配置します。
- 窓は複数配置し、ガラス風の半透明マテリアルを適用します。

#### 44.3.3 建物のグループ化

- 壁・屋根・ドア・窓を複数選択し、グループ化します。
- グループ名を「建物」とします。これで一つのオブジェクトとして動かせます。

### 44.4 植栽（木と生垣）の配置

#### 44.4.1 木の作成

- 幹には円柱（Cylinder）、葉には球（Sphere）または錐（Cone）を使います。
- 幹と葉をグループ化し、「木」という名前を付けます。
- これを複製（Duplicate）して、東側に数本並べます。

#### 44.4.2 生垣

- 細長い箱を複数並べ、あるいは一つの長い箱を使って生垣とします。
- 高さを `1` 程度に抑え、木の手前に配置します。

### 44.5 小道と柵の作成

#### 44.5.1 小道

- 薄い箱を使って石畳を表現します。
- 建物の入口（西側）から庭の外へ、幅 `2` で一直線に伸ばします。
- マテリアルは「石」系にします。

#### 44.5.2 柵

- 柵の柱には細い円柱を、横木には細い箱を使います。
- 庭の外周に沿って配置し、四隅に柱を立てます。
- すべてをグループ化し、「柵」と名付けます。

### 44.6 照明の追加

夜間もシーンが見えるように照明を追加します。

- **環境光**：全体をやわらかく照らす環境光を追加します。
- **灯具**：建物脇と小道沿いに点光源（Point Light）を配置し、灯具オブジェクト（柱＋球）と合わせます。
- **夜間表示**：ビュー設定で「夜」プリセットを試し、照明の具合を確認します。

### 44.7 マスターポイントによる全体調整

すべての要素を配置したら、マスターポイントを使って全体のバランスを整えます。

1. 建物・木・小道・柵を複数選択します。
2. マスターポイントを表示し、それを動かして全体の位置を微調整します。
3. 地面に対する高さ（Y座標）を揃え、物体が地面に埋まらないよう確認します。

> 注意：マスターポイントは選択された複数オブジェクトの基準点です。これを動かすと、選択群全体が連動して動きます。

### 44.8 完成と次のステップ

これで「我が家の小さな庭」は完成です。最後に以下を確認してください：

- [ ] 建物が地面に正しく乗っている
- [ ] 木と生垣が自然に並んでいる
- [ ] 小道が入口から外へ続いている
- [ ] 柵が外周を囲っている
- [ ] 照明で夜間も見える

完成したら、エクスポート機能で `.json` や画像として保存しましょう。さらに発展させたい場合は、アニメーションやカメラワークの章へ進んでください。
## 第45章 よくある問題トラブルシューティング手引き

### 45.1 一般的な問題の切り分け

以下の表は「あなたが見た現象 → おおかたの原因 → どう直すか」の順で並べています。問題の大半は根拠を追えますので、すぐにバグだと疑わないでください。

| 序号 | 现象 | 多半原因 | 解决办法 |
|---|---|---|---|
| 1 | 方向键、`+`/`−` が物体に反応しない | オブジェクトが選択されていないか、カーソルが右パネルの数値入力欄にある | まず画面の空白をクリックし、物体が選択されており、かつ入力欄からフォーカスが外れていることを確認する（第32.1節） |
| 2 | 2つの面がちらつき、互いに貫通する | 2枚が同一平面上（**Z-fighting**） | `PgUp`/`PgDn` で一方を1ステップ持ち上げ／下げて分離する（第41.5、43.4節） |
| 3 | 文字が大きすぎてシーン全体を覆う | テキストの既定フォントサイズは **80** で、立体ブロックの尺度よりずっと大きい | フォントサイズを小さくするか、テキストオブジェクト全体を縮小する（第21、41.7、42.3節） |
| 4 | フォントサイズを変えたら方向キーが効かなくなった | カーソルがまだ数値入力欄から出ていない | まず画面の空白をクリックして入力欄のフォーカスを外す（第32.1節） |
| 5 | `Ctrl+C`/`Ctrl+D`/`Ctrl+V` が反応しない | 変換コントロールが有効化中、またはオブジェクト未選択 | まず `Esc` で変換コントロールを終了し、オブジェクトを選択してから操作する（第33、39章） |
| 6 | 複数選択時に `+`/`−` が拒否される | 複数選択時は**全体縮小を禁止**している（"NoScaleMulti" と表示） | 複数選択を解除して1つずつ縮小するか、変換コントロールのハンドルをドラッグする（第36.4節） |
| 7 | テキストを選択すると縮小モードが無効化される | **テキストは均等縮小に対応しておらず**、自動的に平行移動に戻る | テキストの大きさは「フォントサイズ」パラメータで変更する（第21章）；画像とブラシペン跡はいずれも通常通り縮小可能（第24、36.4節） |
| 8 | ブラシペン／図形を描き間違えて形を直したい | ブラシペンの跡は描き終わると固定され、図形のように細かく調整できない | `Ctrl+Z` で取り消して描き直す（第24、44.5節） |
| 9 | 中央揃えしたいが「中央揃え」ボタンが見つからない | 本ツールには**ワンクリック中央揃えはない** | 3つの方法：グリッドに頼る、同心クローンに頼る、数値ボックスに頼る（第43.5節） |
| 10 | テキストを円弧に並べたい（リングテキスト）が作れない | 本ツールは**リングテキストに対応していない** | 横書きテキストを下部に置くか、1文字ずつ分割して回転させて配置する（第43.6節） |
| 11 | 一部の 2D 図形（ハート／矢印／三日月／十字／稲妻）の形状パラメータの調整方法 | これらは**それぞれ独立した形状パラメータ**を持つ（ハートは `幅/高さ/ハートのくぼみ`、矢印は `長さ/幅`、三日月は `外半径/内半径/オフセット`、十字は `長さ/腕幅`、稲妻は `高さ/幅` など、第12.2節参照） | 右パネルの該当する形状パラメータで直接調整する（第12.2、43.4節） |
| 12 | シーン全体や重要な内容を誤って削除した | 手違いで `Delete` を押したか、シーンをクリアした | すぐに `Ctrl+Z` で取り消す；また `Ctrl+S` で定期的に保存する習慣をつける（第44.1節） |
| 13 | JSON をインポートすると「読み込み失敗」と表示される | ファイルが破損しているか、本ツールが出力した形式ではない | 本ツールの `Ctrl+S` で出力した `.json` であることを確認する（第6章） |
| 14 | 視角ボタンが点灯せず、カメラを回転させると消える | 自由回転後は「透視」ボタンが消灯する（正常な挙動） | いずれかの視角ボタンをクリックして再整列させればよい（第28章） |
| 15 | 📱🤖 タッチ端末でドラッグすると視角が回るだけで矩形選択できない | タッチ端末での矩形選択は**あらかじめ矩形選択モードに入る必要がある** | まず下部バーの「矩形選択」ボタン（青くなる）をタップしてから単指でドラッグする；**選択終了後に自動で終了**するため、再度選択するにはもう一度タップが必要（第7.4節） |
| 16 | 全体色を変えたのに、特定の物体だけ変わらない | その物体に**独立した色の上書き**があるか、「無色」状態になっている | それを選択して個別に色を変更する（第18章） |
| 17 | 画面吸い取り（スクリーンカラーピッカー）が使えない | カラーピッカーツールを先に有効化していない | カラー領域のカラーピッカーボタンをクリックしてから色を吸う（第18章） |
| 18 | スクリーンショットにグリッド線／座標軸が写っている | 補助要素を非表示にしていない | 座標軸とグリッド面を非表示にしてから `Ctrl+P`（第28、43.7節） |
| 19 | クローンした物体が「バラバラ」になった | 複数選択クローンの前に1組をすべて選択していなかった | `Shift` を使ってグループ全体を選択してから `Ctrl+D`（第38章） |
| 20 | 視角／物体の回転方向が逆になった | 軸を取り違えている：`A/D` は Z 軸周り、`W/S` は Y 軸周り、`Q/E` は X 軸周り | 第47章のクイックリファレンス表を見ながら押すか、`Shift`+方向キーで大角度試し（第32、34章） |

💡 **トラブルシューティングの第一原理**：「おかしい」の 90% は根本原因がたった3つ——**選択されていない**、**カーソルが入力欄にある**、**2枚が同一平面上**。まずこの3つを心の中で唱え、それから表で対症療法をすれば、半分の時間が節約できる。

### 45.2 端末別の固有問題

上の表は大半が四端共通です。以下は特定の形態でのみ発生します：

**🖥️📱 ウェブ版**

| 现象 | 原因 | 解决 |
|---|---|---|

- 色選びはまず**プリセットカラーパレット**を優先（色相ごとにグループ化され、固定の色相バーで、最も調和の取れた色が作りやすい）；
- 正確な色が欲しいなら**カスタムカラー選択**（色値を入力）；
- 「画面の中のある色」が欲しいなら**画面カラーピッカー**で吸い取る；
- 配色の鉄則：**2–3色以内に抑え**、同一色相の濃淡で層次を出す方が、色をむやみに増やすよりもずっとプロフェッショナルに見える（第43.8節）。

# 第十三篇 付箋・多言語

ここまで読めば、あなたは「ツールの使い方」を身につけたことになります。この篇では「学びを支える」2つの小さな話——読みながら書く付箋、そして説明書自体の多言語——を扱います。

## 第49章 読みながらメモ：説明書の中の付箋

学習中、ある段落に「印をつけておきたい」ことがよくあります。説明書では本文の中で**テキストを範囲選択 → 付箋を追加**できます：

1. 説明書を読みながら任意のテキストを選択：
   - 🖥️💻 **マウス端末**：左ボタンを押したまま**ドラッグ選択**；
   - 📱 **Web・タッチ**：長押しでカーソル位置の単語が自動選択され、アプリ内の「付箋 / ハイライト / コピー」オーバーレイが表示される（そのままドラッグして選択範囲を調整可）。国産 ROM（MIUI / ColorOS / vivo など）への互換のため「スーパードラッグ」とシステムの長押しメニューを無効化しており、システムのコピー/共有バーは表示されない；
     - 選択範囲が**既存のハイライトと重なる**場合、オーバーレイは「ハイライト解除 / ハイライト拡充」に切り替わる。「ハイライト拡充」でそのハイライトを現在の選択範囲まで広げ、「ハイライト解除」で重なり部分のハイライトを消せる。
   - 🤖 **Android 版**：長押しで選択アンカーと2つのドラッグ可能なハンドルが表示され、それを動かしてテキストを走査選択する。システムのコピー/共有バーは表示されず、代わりにアプリ内の「付箋 / ハイライト / コピー」オーバーレイが引き継ぐ；
2. 離すと「付箋を追加」ボタンが現れるので、クリックする；
3. 選択されたテキストがハイライトされ、**付箋リスト**に記録される；
4. 付箋リストの各項目は個別に**削除**できる——削除前に確認ダイアログが出るため、誤削除を防げる。

> 💡 付箋は「テキストに付いて回る」ものです：選択したその一文に紐づけられるため、後で「その時何を考えていたか」を振り返りやすい。

## 第50章 付箋を画面に「浮かべる」

付箋リストを行ったり来たりするのが面倒なら、1つの付箋を**フローティング付箋ウィンドウとして展開**できます：

- 付箋ウィンドウはドラッグ可能なフローティングカードで、キャンバス上に浮かび、操作の邪魔にならない；
- 付箋ウィンドウには**読み取り専用**と**編集**の2つの状態がある：読み取り専用は付箋紙のように、編集時はテキストを変更できる；
- 不要になったら、付箋の閉じるボタンをクリックすればよい（`closeSticky`）。画面から消えるが、付箋自体はリストに残る。

### 50.1 付箋オーバーレイと操作（四端共通）

付箋を展開すると、それは**ページ内の最前面フローティングカード**（独立したシステムウィンドウではない）になり、四端の挙動は共通：

- それは**常に最前面**にあり、キャンバス上に浮かぶため、チュートリアルを見ながら操作しやすい；
- 位置のドラッグ、ウィンドウのリサイズ、「最前面／最前面解除」の切り替え（`manPin` / `manUnpin`）が可能；
- **最大化／元に戻す**（`manMaximize` / `manRestore`）に対応；
- 付箋の**書き出し／読み込み**（`manExport` / `manImport`）、**全選**と**一括削除**（`manSelectAll` / `manBatchDel`）に対応；
- 「設定 → クイック操作」に列挙されたキーで上記操作を呼び出せる（PC 版はウィンドウ上のボタンをクリックしてもよい）。

> ⚠️ **付箋読み込みの三つの検証ルール**（四端共通）：
> 1. **言語不一致は丸ごとスキップ**：読み込む付箋パッケージの言語ラベルが現在の UI 言語と異なる場合、システムは「言語不一致」と通知して**読み込みを拒否**し、他言語の付箋が混ざるのを防ぐ；
> 2. **旧バージョン通知**：付箋パッケージに現在のソフトより古い（または異なる）バージョン番号が含まれると、読み込み後に「旧バージョンの付箋があります」と通知し、互換性に注意できる；
> 3. **言語ラベルなしの古い付箋**：ごく古い付箋パッケージには言語ラベルがなく、システムは「旧形式・言語なし」と通知するが、現在の言語で読み込み、手動で確認できる。

> 📌 四端の付箋はいずれもページ内オーバーレイであり、アプリウィンドウの外にはドラッグできず、別のプログラムの上にも跨げない。

### 50.2 付箋を閉じる順序（📱🤖 タッチ端末注意）

🤖 Android 版で**戻るキータップ**を押すと、まず**付箋を1つずつ閉じ**（未保存の内容があれば先に確認する）、次に目次を閉じ、次に説明書を終了し、最後にアプリの終了を確認する。

> 📌 付箋は「仮のヒント」に適している：例えばあるパラメータの説明を脇に貼って、作りながら見る、など。

### 50.3 数量上限と一括管理

- **同時に最大5つのフローティング付箋を展開**：超えた場合はシステムが**最も古く開いたものを自動で閉じ**、性能と画面の清潔さを保つ。付箋自体は付箋リストに残り、失われない。
- 付箋リストは**一括削除**に対応：リスト内で複数の付箋を一度にチェックして削除できる（削除前にも同様に確認ダイアログが出る）。1件ずつ操作する必要はない。

## 第51章 多言語：説明書も「あなたの言語」を話す

界面と説明書はいずれも9言語に対応：

| 言語 | 界面 | 説明書 |
| --- | --- | --- |
| 簡体中文 | ✅ | ✅ |
| 繁體中文 | ✅ | ✅ |
| English | ✅ | ✅ |
| 日本語 | ✅ | ✅ |
| 한국어 | ✅ | ✅ |
| Русский | ✅ | ✅ |
| Español | ✅ | ✅ |
| Français | ✅ | ✅ |
| العربية（アラビア語） | ✅ | ✅ |

切り替え方法：設定で言語を選択すると、界面の文言と説明書の本文が**同時に**対応言語版に切り替わる。説明書の多言語コンテンツはそれぞれ `docs/使用说明书.md`（簡体）、`使用说明书_en.md`、`使用説明書_ja.md`、`使用說明書_zh-TW.md`、`사용설명서_ko.md`、`使用说明书_ru.md`、`使用说明书_es.md`、`使用说明书_fr.md`、`使用说明书_ar.md` に格納されている。

💡 **言語はどう選ばれるか**：**初回起動**時は**システムの言語設定から自動判定**される——OS・ブラウザの言語設定に基づき、簡体中文・繁體中文・English・日本語・Español・Français・العربية などの常用言語に自動で一致する。その後、手動で言語を切り替えると、アプリは**その選択を記憶して完全に尊重**し、もうシステム言語に上書きされることはない。つまり、最初はシステムに従い、以降は自分が選んだ言語が使われる。

✅ **9言語 × 4形態すべてが統合済み**：どの端末を使い、どの言語を選んでも、読むのはいずれも三端対応済みの同じ一冊の説明書である。アラビア語などの右から左へ書く（RTL）言語では、説明書内の表と配置が自動的に鏡像される。

> ⚠️ 削除確認について：すべての削除操作（付箋、シーンオブジェクト）は**カスタム確認ダイアログ**を経由し、システムのネイティブダイアログではないため、**全画面／没入モード**でも安定してポップアップし、「クリックしても反応がない」ことはない。
