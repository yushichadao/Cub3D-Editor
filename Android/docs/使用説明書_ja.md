# 立方・3Dデザインワークショップ —— 使用説明書

## ゼロから習熟までの啓発型教材（Web 版・PC 版・Android 版 共通）

> 本書は冷たい機能リストではなく、**一緒に学び、一緒に作り、一緒に考えられる**教材です。
> あなたが 3 次元デザインに触れたことがなく、専門ソフトを使ったこともないことを前提にします。あなたのそばに座る先生のように、
> 「3 次元とは何か」から始め、問いで考えを導き、比喩で直観を築き、練習で手触りを固め、
> 最終的に「ボタンの押し方」から「独りで創れる力」へと至ります。

> 📦 **一冊で 4 つの形態に対応**：本ツールには Web 版・PC デスクトップ版・Android 版の 3 つの配布版があり、さらに Web 版は端末に応じて**マウスモード**と**タッチモード**に自動で切り替わります。本書は**この 4 形態すべてを同時にカバー**します。操作が異なる箇所では「形態バッジ」で各端末のやり方を明示します。

## 前言：3 次元に触れたことのないあなたへ

本ページを開いたとき、少し緊張したかもしれません。3 次元？モデリング？それは重いソフトを長く勉強しなければならないものでは？

まず深く息を吸ってください。🙂

目の前のツールは**純ウェブの 3D エディタ**です。インストールもドライバも講座も不要。3D の世界を作ることを「クリック、ドラッグ、数文字入力」にまで圧縮しました。

多くの初心者は「座標軸、変換、グリッド、テクスチャ…」という専門用語に怯えて、最初の一歩でつまずきます。実はどれもごく日常的です：
- **座標軸**は部屋の目に見えない 3 本の物差し——「前後、左右、上下」；
- **変換**は単に「動かす、回す、大きさを変える」；
- **グリッド**は地面の升目で、大きさと距離を測る目印；
- **テクスチャ**は物体の表面に写真を貼ること、壁に壁紙を貼るようなもの。

本書はこれらの概念を一つずつ、わかる言葉で説明します。「定義を覚えてから操作する」旧来の道ではなく、**まず作らせてから、なぜそうなのかを振り返らせる**——それが「啓発型」の意味です。

本書を読み終わると、あなたは次のことができるようになります：
1. 任意の図形を独りで配置し、調整し、着色できる；
2. テキスト・画像・ペンでシーンを豊かにできる；
3. ショートカットで効率を飛躍させられる；
4. 家、スローガン、ロゴと、完成した作品を作れる。

用意はいいですか？まず 5 分で、手元の版がどれか確認しましょう。

### 0.1 三つの配布版、四つの使用形態

本ツールには**3 つのエディション**がありますが、Web 版は端末に応じて自動で切り替わるため、日常使うのは実質**4 形態**です：

| 形態 | 手に入れ方 | 使っていると確認する方法 |
| --- | --- | --- |
| 🖥️ **Web·マウス** | ブラウザで公開 URL を開く | 画面にマウスポインタがあり、左パネルに「ショートカット」欄がある |
| 📱 **Web·タッチ** | 同じ URL をスマホ／タブレットブラウザで開く | 下部ツールバーに「囲み選択」「全選択」ボタンがあり、「ジェスチャー操作」ヘルプ表が出る |
| 💻 **PC 版** | `.exe` をダウンロードしてインストール／展開して実行 | ウィンドウ右上に独自の「最小化／最大化／閉じる」がある |
| 🤖 **Android 版** | `.apk` をダウンロードしてインストール | 下部に「囲み選択」「全選択」があり、戻るキーで終了確認が出る |

⚠️ デスクトップブラウザでタッチ版の見た目を**プレビュー**したいとき（授業デモなど）は、URL に `?touch` を付けます。例：

### 0.3 最大の違い：指には「右ボタン」も「ホイール」もない

四形態のうち、本当に筋肉記憶を変える必要があるのは一つだけです：**入力方式**。

マウスには 3 つの独立信号（左ボタン・右ボタン・ホイール）があり、指には一つ（押して動かして離す）しかありません。だからタッチは**指の本数**で意図を区別します：

| やりたいこと | 🖥️💻 マウス（Web·マウス／PC） | 📱🤖 指（Web·タッチ／Android） |
| --- | --- | --- |
| オブジェクト選択 | 左クリック | 指一本タップ |
| 図形を配置 | 地面を左クリック | 地面を指一本タップ |
| 視点回転 | **右ボタン**ドラッグ | **指一本**で空白をドラッグ |
| 視点平行移動 | **中ボタン**ドラッグ／`Shift`+右ボタン | **二本指**で一緒にドラッグ |
| 視点ズーム | **ホイール** | **二本指**でつまむ／広げる |
| 複数選択 | `Shift`+左クリック | 「全選択」ボタン、または「囲み選択」 |
| 囲み選択 | 空白で左ドラッグで矩形 | まず「囲み選択」をタップしてから指一本ドラッグ |

💡 **一言で**：**マウスは「どのボタン」を見る、指は「何本の指」を見る。**

### 0.4 タッチ版の二つの専用ボタン

キーボードがないため、タッチ形態（📱 Web·タッチ と 🤖 Android）は下部ツールバーに二つのボタンを加え、`Ctrl+A` と「ドラッグ囲み」を置き換えます：
- **「全選択」**：マウス側の `Ctrl + A` と同等、一度でシーン内全オブジェクトを選択；
- **「囲み選択」**：タップすると囲み選択モードに入り（ボタンが青く）、指一本で矩形をドラッグ、中のオブジェクトをまとめて選択。
  ⚠️ **注意**：一回の囲みが終わると**自動でモードを抜け**（ボタンが元の色に戻ります）。もう一度囲みたいときは、**もう一度「囲み選択」をタップ**してください。誤タッチ防止の設計です。

### 0.5 PC 版専用：それを「本物のソフト」として使う

PC 版は「殻に入れたウェブページ」ではなく、デスクトップソフト独有の能力を加えます：
- **ウィンドウ制御**：右上に自前の最小化／最大化／閉じる、トップバーにネイティブ `☰` メニュー；
- **ドラッグ＆ドロップ取り込み**：`.json` プロジェクトをウィンドウへ**放り込む**だけで開く；
- **最近使ったファイル**：メニューに履歴があり、ワンクリックで開く；
- **クラッシュ復旧＆自動保存**：異常終了後に再開すると、最後の進行を復元する案内；
- **独立浮動付箋ウィンドウ**：メインウィンドウから付箋を「放り出し」、常に最前面のミニ窓にできる；
- **拡張センター**：プラグイン・ランタイム・言語パックを導入。

### 0.6 Android 版専用：戻るキーと終了保護

Android 版で最も注意すべきは**戻るキーの挙動**で、階層になっています：
> 戻るを押す → 付箋が開いていれば順に閉じる（未保存なら確認）→ 次に目次を閉じる → 説明書を閉じる → それからアプリ終了の確認。

アプリ終了時は確認ボックスが出て、三択：**保存して終了／そのまま終了／キャンセル**。誤タップで苦労したシーンが消えるのを防ぎます。

💡 Android 版には**「全画面」ボタンはありません**。もとから全画面アプリだからです。

### 0.7 「通信」と「データ安全」について

| | 通信必要？ | データはどこに |
| --- | --- | --- |
| 🖥️📱 Web 版 | はい（ページ読み込み時） | すべての計算は端末内で、作業データの送信はなし |
| 💻 PC 版 | **まったく不要** | すべてローカル端末 |
| 🤖 Android 版 | **まったく不要** | すべてローカル端末 |

三つのエディションとも、あなたの作品を**どのサーバへも送信しません**。Web 版はページをダウンロードするためだけに通信し、開いたあとはすべて端末内で創作されます。

# 第 1 篇 スタート篇（ゼロから入門）

## 第 1 章 もう一度「3 次元」を知る：ある写真から

### 1.1 2 次元と 3 次元、何が違う？

スマホでテーブルを写真に撮ってみてください。写真は**2 次元**：幅と高さはあるが、指で触ると平ら——つまり「3 次元に見える」だけです。

今度はテーブルの横に回り込んで見てみてください。本物のテーブルは**3 次元**：幅・高さ、そして**奥行き**（脚が前に突き出る分）があります。動くと見え方が変わりますが、写真はずっと凍ったままです。

💡 **一言で**：2 次元は「絵」、3 次元は「入れる本当の空間」。

### 1.2 このウェブページはあなたに「3 次元舞台」をくれる

エディタを開くと、中央のキャンバスが 3 次元舞台です。左から図形を選び、地面を一度クリックすると、それは本当に舞台に「降り立ち」、横から回り込んだり、持ち上げたり、上から見下ろしたりできます。

❓ **考えてみよう**：友達に「青い箱の左にある赤い球」を説明するとき、2 次元の写真と 3 次元のシーン、どちらが誤解されにくい？なぜ？

### 1.3 なぜ「軽量三端」にしたか

従来の 3 次元ソフト（Blender、Maya など）は強力ですが、インストーラが数百 MB で、画面もごちゃごちゃ。本ツールはコア能力を軽量エンジンに凝縮し、3 エディションで届けます：
- 🖥️📱 **Web**：URL を開くだけ、閉じれば去る——ディスクを取らない；
- 💻 **PC**：一度インストールすれば**完全オフライン**、ファイルドラッグやプラグイン導入も可；
- 🤖 **Android**：スマホにインストールし、通勤中にいつでもモデリング。

三つ共通の利点：
- すべての計算は端末内ローカル、**データ送信なし**；
- 書き出しは平易な JSON ファイルと PNG 画像、保存共有が容易；
- **プロジェクトファイルは三エディション間で共通**——スマホで書き出した `.json` は PC 版で続きを編集できる。

💡 これが重要：**同じ作品をエディションをまたいでリレーできる**。ひらめいたらスマホで下書き、家で PC で仕上げる。

✏️ **やってみよう**：形態を確認し（第 0 章）、ツールを開き、中央キャンバスと周囲パネルを認識してください。まだ操作しなくていい——「環境に慣れる」だけで。

## 第 3 章 画面全体図：目の前の 5 つの領域

画面を五ブロックに分け、それぞれ役割があります。読み進めながら画面上の位置を探してください。

### 3.1 トップバー（最上部）

横一列のボタン、三グループ：
- **ファイル系**：新規、取り込み、書き出し、スクリーンショット；
- **編集系**：取り消し、やり直し、コピー、貼り付け、複製、クリア；
- **表示系**：軸切替、グリッド切替、設定。

**エディションごとのトップバー差**：
- 🖥️📱 **Web**：上記ボタンのほか「全画面」ボタンでページ全体を最大化；

## 第 4 章 座標系：画面上の X / Y / Z という 3 本の線

本書で最も重要な章の一つです。多くの人は「座標軸が読めない」で 3 次元ソフトを遠ざけます。ゆっくり行きましょう。

### 4.1 まず「数学の座標軸」の荷物を下ろす

数学の授業で 3 本の軸を見て「右手系」を覚えたかもしれません。まず忘れてください。本ツールでは**軸とはただの色と文字ラベルの矢印**で、「この物は空間でどこにあり、どちらを向くか」に答えるだけです。

### 4.2 画面上で実際に見えるもの

「軸」表示を入れると（トップバーの 📐 ボタン）、3 本の矢印が出て、端に **X, Y, Z** の文字が異なる色で書かれています。

> ⚠️ **重要**：本書やツールの**画面に表示される X/Y/Z は「画面ラベル」**であり、ソフト内部で使う軸とは厳密には同じではありません。普通の読者は**画面ラベルだけを見れば十分**です。以下は画面で本当に見える対応：

| 画面ラベル | 矢印色 | 向き | 日常の比喩 |
| --- | --- | --- | --- |
| **X** | 🔵 青 | **前後**（奥行き） | 「前へ一歩／後ろへ一歩」 |
| **Y** | 🔴 赤 | **左右** | 「左へ／右へ」 |
| **Z** | 🟢 緑 | **上下**（高さ） | 「つま先立ち／しゃがむ」 |

つまり、この画面では：**Z が上向きの緑、X が前後の青、Y が左右の赤。**

💡 語呂合わせ：**「青は前後、赤は左右、緑は上下（Z は空へ）」。**

### 4.3 なぜ「高さ」が Z で Y ではないのか

多くの 3 次元ソフトでは高さは Y です。しかし本ツールの**画面ラベル**では高さを Z（緑）にしています。あなたの勘違いではありません——**この画面はそうラベルしている**だけです。本書は一貫して「画面ラベル」に従います。名前・色・向きの三者がそろえば迷いません。

❓ **考えてみよう**：もしあなたが設計し直すなら、どの文字を「高さ」にしますか？文字はただの名前、肝心は「名前と色と向き」が一致することです。

### 4.4 地面と「高さ = 0」

舞台の底は**升目の地面**です。地面は「高さがゼロ」の基準：地面に置いたものは Z（高さ）= 0、持ち上げると Z が増えます。

画面ラベルでは、地面は **X（前後）と Y（左右）** が広がる水平面で「Z = 0」と書きます。式を覚えなくていい——**地面は「足の付く場所」、上（緑 Z 軸）が上がること**だけ理解すればいいのです。

### 4.5 三本の軸を体で感じる

立って三つの動きを：
- 前へ一歩、後ろへ一歩 → **X（青）** に沿って動く；
- 左へ一歩、右へ一歩 → **Y（赤）** に沿って動く；
- つま先立ち、しゃがむ → **Z（緑）** に沿って動く。

筋肉に刻み込めば、あとの「オブジェクト移動」は全部参照があります。

✏️ **やってみよう**：軸を表示し、「上」と「前」視点（ボトムバーのボタン）を切り替え、三本の矢印が体感と合うか。上視点では X–Y 面、前視点では X–Z 面が見えます。

## 第 5 章 さっそく作る：あなたの最初の 3D 作品

読むだけでなく作らねば偽物の技です。この章では実際に、スクリーンショットして共有できる小作品**「地面に立つ着色した立方体」**を作ります。

### 5.1 ステップ 1：図形を選ぶ

1. 左パネルで「3D 図形」ゾーンを探す（📱🤖 パネルが折りたたまれていたら端ボタンで展開）；
2. 最初の「立方体」をクリック（好きな立体でも可）；
3. 「配置モード」に入ります：
   - 🖥️💻 マウス：カーソルがキャンバスに入ると**プレビューがカーソルに追従**；
   - 📱🤖 タッチ：指には「乗る」がないので**追従プレビューなし**——タップした場所に置きます。

### 5.2 ステップ 2：降ろす

中央の地面を**一度クリック**（📱🤖 は指一本タップ）。立方体が升目に「ポン」と。おめでとう、最初の 3D オブジェクトの誕生です。

💡 降ろす位置がよく見えなくても心配無用——次章の「選択」を覚えればいつでも動かせます。

### 5.3 ステップ 3：選ぶ

左の「選択／変換」ツールをクリックし、その立方体を**単クリック**（📱🤖 は指一本タップ）。周りに矢印か枠が出て「選択された」と。右パネルが点灯します。

### 5.4 ステップ 4：色を付ける

右パネルの「色」ゾーンで：
- **プリセット色**を直接クリック（例：鮮やかオレンジ）——立方体が即変化；
- もっと個性を、カスタム色の「吸い取り」を。
⚠️ **注意**：「色なし」をクリックしたり不透明度を 0.1 にすると、透明や「見えなく」なります——消えたのではなく、戻せばいいだけ。

### 5.5 ステップ 5：動かし、回す

選択したまま、矢印をドラッグして移動（青前後／赤左右／緑上下）、リングをドラッグして回転。第 4 章の三軸を体感してください。

### 5.6 ステップ 6：結果を保存

トップバーの「スクリーンショット」（または `Ctrl+P`）で PNG に。後で「書き出し」JSON でバックアップも、「取り込み」で次回続きを。

✏️ **やってみよう**：「赤い立方体の左に青い球」という小シーンを作り、スクリーンショット。体の動き（前後、左右、上下）で各オブジェクトの位置を友達に説明できますか？

## 第 6 章 保存と共有：スクリーンショット・エクスポート・バックアップ

作ったものは残して見せたいものです。この章は「保存」の四つの方法と使い分けです。

### 6.1 なぜ「こまめな保存」が良い習慣か

ページを閉じる、更新する、誤って戻る——書き出してないシーンは失われます。「一区切りごとに JSON 書き出し」を癖にしてください。何度も助かります。

💻 **PC 版は例外**：**自動保存とクラッシュ復旧**があり、異常終了後に再開すると最後の進行を復元する案内が出ます。でもこれは「安全綱」、能動的書き出しの代わりにはなりません。

### 6.2 スクリーンショット：作品を写真に（Ctrl + P）

「スクリーンショット」は現在の見え方を **PNG 画像**に保存します。
- 向く：SNS 共有、挿絵作り、他者への「プレビュー」；
- 提案：撮る前にトップバーで**軸とグリッドを隠し**、きれいな絵に；
- 出力サイズは現在のキャンバス画素。

**画像の行き先はエディションで異なります**：

| 形態 | 行き先 |
| --- | --- |
| 🖥️📱 Web | ブラウザの**ダウンロード**経由、システム「ダウンロード」フォルダへ（モバイルは「画像を保存」を促す場合あり） |
| 💻 PC | **システム保存ダイアログ**が出て、フォルダと名前を選ぶ |
| 🤖 Android | アプリ保存領域へ、さらに**システム共有**パネルで微信／フォト等へ直接送信可 |

💡 スクリーンショットは「見た目」だけを保存し、編集可能なデータではありません。後で編集したいなら下の「書き出し」を。

### 6.3 シーン書き出し：編集可能な「プロジェクト」を保存（Ctrl + S）

「書き出し」は各オブジェクトの位置・色・パラメータを記録した **JSON ファイル**を作り、次回「取り込み」でそのまま復元します。
- 向く：未完成作品、手を入れる予定の作品；
- ファイル名にはたいていタイムスタンプが付く、意味のある名前（例 `house_v1.json`）に変えて。

行き先はスクリーンショットと同じ：🖥️📱 Web はブラウザダウンロード、💻 PC はシステム保存ダイアログ、🤖 Android はアプリ保存領域へ共有可。

> ✅ **重要**：この `.json` は**エディション間共通**。スマホで書き出したプロジェクトは PC 版で取り込み続行でき、その逆も可。

### 6.4 取り込み：プロジェクトを読み戻す（Ctrl + O）

以前書き出した `.json` を選ぶとシーンが再構成されます。⚠️ 取り込みは**現在のシーンを置換**します。先に現在の作業を保存してください。

エディションごとの選び方：
- 🖥️📱 **Web**：「取り込み」をクリック、ブラウザの選択で；
- 💻 **PC**：クリックするほか、`.json` を**ウィンドウへ直接放り込み**可。メニューに「最近使った」一覧も；
- 🤖 **Android**：「取り込み」をクリック、システム選択で json を探す。

### 6.5 新規：ゼロから始める（Ctrl + N）

「新規」はシーン全体をクリアします。危険ですが「先に書き出しバックアップ」と併せれば安全。

### 6.6 🤖 Android 専用：戻るキーが「白骨化」させない

Android 版で戻るキーがアプリを終了するとき、確認が出て三択：
- **保存して終了**：現在シーンを先に書き出し、その後終了（推奨）；
- **そのまま終了**：保存せず、注意；
- **キャンセル**：残って編集継続。

💡 だから Android で誤タップしても怖くない——でもこまめな書き出しの癖はやはりお勧め。

### 6.7 しっかりしたバックアップのリズム

> 始める前に一度書き出し → 節目ごとに別名で書き出し → 取り消し／やり直しいつでも。
> （🖥️💻 マウス：`Ctrl+Z`；📱🤖 タッチ：トップバーの「取り消し」ボタン。）

✏️ **やってみよう**：第 5 章の「赤立方体＋青球」を「スクリーンショット」と「書き出し」で各一回保存し、さらに「取り込み」で戻し、内容が合うか確認。
応用：スマホとパソコン両方あるなら、**一方で書き出し、他方で取り込み**、プロジェクトファイルの跨端持ち運びを感じてみて。

# 第 2 篇 操作の基礎（選ぶ・変える・取り消す）

## 第 7 章 オブジェクトを選ぶ技術：単一選択・複数選択・囲み選択

3 次元の世界では、**「まず選び、次に操作」**が鉄則です。この章は「選ぶ」という地味なことを尽くします。

### 7.1 なぜまず選ぶのか

右パネルのパラメータも変換矢印も「現在選ばれたオブジェクト」向けです。選ばなければ、ツールは「誰を変えるか」分かりません。クラス全員に一つの賞を渡せないのと同じ——まず名前を呼ばねば。

### 7.2 単一選択：一度クリック

「選択／変換」ツールでオブジェクトを一度クリック。ハイライトしてコントロールが出て「選択された」と。
- 🖥️💻 **マウス**：**左クリック**；
- 📱🤖 **タッチ**：**指一本タップ**（置いて離す、ドラッグしない）。

### 7.3 複数選択：二つ目、三つ目を加える…

| 形態 | 複数選択のやり方 |
| --- | --- |
| 🖥️💻 Web·マウス／PC | `Shift` を押しながら他のオブジェクトをクリックで**蓄積**；既選択をクリックで**除く** |
| 📱🤖 Web·タッチ／Android | 物理 `Shift` なしだが、オブジェクトを**指一本長押し**——未選択なら加え、選択済なら除く（`Shift`クリック相当）；あるいは下部「**囲み選択**」で一片を、あるいは「**全選択**」で全部 |

💡 複数選択後、変換は「群の中心」を基準に、すべてのオブジェクトを一まとめとして動かします。

### 7.4 囲み選択：矩形をドラッグ

「一片まとめて掴む」に向きますが、二エディションの始め方が全く違い、ここが一番混乱しやすいです：

**🖥️💻 マウス（Web·マウス／PC）**
空白で**左ボタンを押したまま矩形をドラッグ**、中のオブジェクトを全部選択。いつでも可、モード切替不要。
⚠️ 囲み選択は「空白」から始めねばなりません。オブジェクトの上でドラッグを始めると、それは**そのオブジェクトの移動**になります。

**📱🤖 タッチ（Web·タッチ／Android）**
指のドラッグは既定で「視点回転」なので、まず「囲み選択」と伝える必要があります：
1. ボトムバーの「**囲み選択**」ボタンをタップ、青くなってモード入り；
2. 指一本で矩形を**ドラッグ**、囲みたいオブジェクトを包む；
3. 離すと選択完了——**囲みモードは自動で抜け**、ボタンが元の色に。
⚠️ **重要**：タッチの囲み選択は**一回限り**。もう一度囲みたいなら、**もう一度「囲み選択」をタップ**。誤タッチ防止です。

### 7.5 全選択

シーン内の全オブジェクトを一度に選択。クリアや全体変換と相性抜群。
- 🖥️💻 **マウス**：`Ctrl + A`；
- 📱🤖 **タッチ**：ボトムバーの「**全選択**」ボタン。

### 7.6 選択解除

- **四形態共通**：キャンバス空白をクリック；
- 🖥️💻 **マウス追加**：`Esc`。

### 7.7 選択ヒント：画面が「何を選んだか」を教える

この版から、選択状態が変わるたび、キャンバス上部に**軽いヒントバー**が浮かび（数秒で自動消え、操作を邪魔しない）：

| 状況 | ヒント内容 |
| --- | --- |
| 図形 1 つだけ選択 | `「立方体」を選択`（`「」` 付きでオブジェクト名） |
| テキスト 1 つだけ選択 | `「テキスト：実際の内容」を選択`（オブジェクト名＋コロン＋文本） |
| 2 つ以上選択 | `5 個のオブジェクトを選択`（現在の総数） |
| Shift で加除 | 毎クリックで現在数へ更新、例 3 → 4 → 3 |
| 全選択解除 | `選択を解除しました` |

💡 このヒントが最も役立つのは**囲み選択と Shift クリック**：一つずつ数えず、数字を見れば過不足が分かります。

### 7.8 選択状態でツールバーをタップ：自動で選択解除

オブジェクトを選んだ状態で、左パネルの次の**5 ツール**をクリックすると、エディタはまず**現在の選択を自動解除**し、そのツールへ入り、`選択モードを抜けました`とヒント：
- テキスト
- 画像
- 3D ペン
- 2D ペン
- 消しゴム

これら 5 つは皆「キャンバスに新しく描き始める」もので、古い選択を残すと邪魔になるからです。

⚠️ それ以外のツール（各 3D／2D 図形ボタン）をクリックしても**選択中は無効**——これは「パラメータを調整しようとしたのに誤って新図形を落とす」を防ぐ意図的な保護です。新図形を落とすには先に選択解除（🖥️💻 `Esc` か空白クリック；📱🤖 空白タップ）。

### 7.9 選べない？まずこれを

1. まだ「配置モード」にいないか？「選択／変換」ツールに戻って；
2. 狙う物が他の裏に隠れていないか？視点（ボトムバー）を変えて正面から；
3. 不透明度を最低 0.1 に下げて透明化していないか？元に戻して；
4. 2D の線か？消しゴムや特殊ロジックが必要な場合、通常クリックでは選べないことも。

❓ **考えてみよう**：複数選択と囲み選択、どちらが「離れた 3 つを正確に選ぶ」に向き、どちらが「一列まとめて」に向く？
✏️ **やってみよう**：図形を 5 つ置き、①単一選択 ②`Shift`で 3 つ蓄積（ヒント数字の変化を見る）③一片囲み ④`Ctrl+A` 全選択 ⑤「テキスト」ツールをクリックし自動解除を観察。

## 第 8 章 変換 3 点セット：移動・回転・スケール

「変換」は 3 次元創作で最も頻繁な動作、本質は三つ：**位置を動かす、向きを回す、大きさを変える**。

### 8.1 三つの変換とは

| 変換 | 日常の比喩 | 画面のコントロール |
| --- | --- | --- |
| 移動（translate） | カップを机の左から右へ | 3 本の色矢印 |
| 回転（rotate） | カップの口をこちらへ向ける | 円／弧ハンドル |
| スケール | カップを大きく／小さく | 立方ハンドル |

### 8.2 移動：三軸に沿ってドラッグ

選択後、色矢印が出ます（画面ラベル：Y 赤＝左右、Z 緑＝高さ、X 青＝前後）。
- **赤矢印**をドラッグ → Y（左右）に；
- **緑矢印**をドラッグ → Z（高さ）上下に；
- **青矢印**をドラッグ → X（前後）に。
💡 一つの矢印だけ掴めば、その方向だけ真っ直ぐ、斜めにならず。斜め自由に動かすには矢印間の「平面正方形」を。

### 8.3 回転：軸を中心に回す

「回転」モードに切り替えると、オブジェクトをリングが囲みます：
- リングをドラッグ → 対応軸を中心に回転。例えば「正面」を前向きから左向きにするのは Z（緑高さ軸）回り。
⚠️ **注意**：回転は「どの軸を中心に」です。語呂：緑軸（Z）回り＝その場で回る（人が回るよう）、青軸（X 前後）回り＝人がうなずくよう、赤軸（Y 左右）回り＝首を横にかしげるよう。

### 8.4 スケール：大きさを変える

「スケール」に切り替え、ハンドルをドラッグで拡大縮小。既定は**均等**（ロックは第 9 章）。

### 8.5 精密が要る？右の数値を

ドラッグは感覚、パラメータは入力。右パネルに各変換の数値枠：
- 位置：X／Y／Z の三数（画面ラベルでは前後／左右／高さ）；
- 回転：三つの角度；
- スケール：倍率。
💡 「ぴったり整列」には同じ値を入力するのが目押しより確実。

✏️ **やってみよう**：立方体を置き、まず矢印で右上へ動かし、次に右の数値枠で X, Y, Z を整数（例 2, 0, 3）にして精密な着地を見る。

## 第 9 章 変換モードと均等スケールロック

前章は動作、この章は「モードの切り替え方」と「比をロックする方法」。

### 9.1 三モードの切り替え場所

右パネル（オブジェクト選択後）に「移動／回転／スケール」の三ボタンがあり、ショートカットでも可（後半の効率篇で詳細）。切り替えるとオブジェクト上のコントロールが対応する見た目に。

### 9.2 均等スケールロックとは

スケール時に「均等スケールロック」スイッチがあります：
- **オン**：全方向へ同期拡縮、形は**歪まない**（球は球、立方体は立方体のまま）；
- **オフ**：**単軸だけ伸ばせる**、例えば球を楕円に潰したり、立方体を棒に伸ばしたり。
⚠️ **注意**：均等スケール行は「単一選択かつ均等オン」のときだけ表示。複数選択では無効（群全体の拡縮は変換コントロールで）。

### 9.3 テキストは均等スケールに対応しない

**テキストオブジェクト**を選ぶと：
- 右パネルの「均等スケール」スライダー行が**非表示**；
- 「均等スケールロック」チェックが**非表示**；
- モードボタンの「スケール」が**灰色でクリック不可**（スケールモードにいたら自動で移動へ戻る）。
理由：テキストはフォントサイズ等のパラメータからその場で生成される薄いテクスチャ板で、直接伸ばすと文字がぼやけ変形するから。**テキストサイズは右パネルの「フォントサイズ」パラメータで**——それが劣化なし。

### 9.4 いつロックを外すか

「潰したクッション」「伸ばした柱」「平たい楕円レンズ」が欲しいとき、ロックを外して単軸ドラッグ。これが「標準体」から「個性ある体」への鍵です。

❓ **考えてみよう**：なぜ「潰した球」と「標準球」は 3 次元で別の視覚言語なのか？それぞれ何の物体に向く？
✏️ **やってみよう**：球を置き、均等ロックを外し、Z（緑高さ軸）だけ 0.3 に潰して「UFO／平皿」を作り、単軸スケールを感じる。

## 第 10 章 取り消しと履歴：失敗を恐れず試せる底力

初心者最大の心理的壁は「間違えて押すのが怖い」です。この章は落ち着き薬。

### 10.1 取り消しとやり直し

- `Ctrl + Z`：一つ前へ取り消し；
- `Ctrl + Y`：やり直し。
連続で何度も戻り、やり直しでまた進めます。

### 10.2 「履歴スタック」とは

内部では**操作リスト**（ブラウザの戻る履歴のよう）を保持。重要な操作ごとに一項目を積み、取り消しは最後の一つを Pop。

⚠️ **注意**：履歴には**上限**があります。とても古い操作はリストから「押し出され」取り消し不可に——だから節目で JSON バックアップを（第 6 章）。

### 10.3 何が履歴に入り、何が入らない

- **入る**：オブジェクト追加／削除、色替え、変換、テクスチャ——「作品内容の変更」；
- **入らない**：ただ視点を回転、ズームして観察すること（これらは「見方」の変更で、作品自体の変更ではない）。
だから観察のために自由に回転ズームしても、視点変更が取り消し段に溜まる心配は無用。

### 10.4 大胆試錯の心得

> あらゆる操作は取り消し可 ＋ 節目でバックアップ ＝ 本当の「台無し」はない。

これを心に刻めば、クリックを恐れずに済みます。

✏️ **やってみよう**：5 つの異なる操作（追加、色替え、移動、スケール、一つ削除）を連続で行い、 `Ctrl+Z` を押しながら順に巻き戻し、次に `Ctrl+Y` で順に再生——「タイムマシン」を感じて。

# 第 3 篇 図形の宇宙（20 + 20 種の使い方）

## 第 11 章 3D 図形総覧（20 種をどう分類するか）

### 11.1 「3D 図形」とは

3D 図形は**体積**を持ち、光と影を受け、後ろを遮り、周囲から見られます。本ツールは立方体からトーラス結びまで 20 種の立体を備えます。

### 11.2 二十種を一望

| # | キー | 名称 | 一目でわかる | 特有パラメータ |
| --- | --- | --- | --- | --- |
| 1 | box | 立方体 | 6 面の正方形 | 長さ／幅／高さ |
| 2 | sphere | 球 | 丸く膨らむ | 半径 |
| 3 | cylinder | 円柱 | 上下円、まっすぐな筒 | 半径／高さ |
| 4 | cone | 円錐 | 先がとがり、底が円 | 底半径／高さ |
| 5 | torus | トーラス | ドーナツ | 外径／内径 |
| 6 | knot | 結び | 編んだ輪 | 半径／管太さ |
| 7 | icosa | 二十面体 | 20 面の三角形 | 辺長 |
| 8 | octa | 八面体 | 上下とがり、中ふくらむ | 辺長 |
| 9 | dodeca | 十二面体 | 12 面の五角形 | 辺長 |
| 10 | capsule | カプセル | 両端丸い柱 | 半径／円柱長 |
| 11 | pyramid | 四角錐 | 正方形底、先とがり | 底辺／高さ |
| 12 | prism | 三角柱 | 三角の柱 | 底辺／高さ |
| 13 | tube | チューブ | 湾曲した管 | スパン／アーチ高／管半径／曲線分割 |
| 14 | lathe | 旋盤立体 | 花瓶／コマ形 | 分割数／底半径／中半径／最大半径／高さ |
| 15 | tetra | 四面体 | 4 面の錐 | 底辺 |
| 16 | barrel | 樽 | 上下口径の異なる円柱 | 上半径／下半径／高さ |
| 17 | dome | 半球 | 半分の卵／ドーム | 半径 |
| 18 | helix | 開トーラス | 欠け口のある輪 | 外径／内径／主スイープ角 |
| 19 | octaPrism | 八角柱 | 8 面のまっすぐな柱 | 底辺／高さ |
| 20 | star3d | 3D 星 | 厚みのある星 | 外径／内径／尖り数／厚み |

💡 **「特有パラメータ」はどこに？** オブジェクト選択後、右パネルの「不透明度」の下にその図形専用のパラメータスライダーが出ます。変えると**形状がリアルタイム再構成**され、設定済みの色・テクスチャ・変換には影響しません。

### 11.3 三つの分類の仕方（20 の中から素早く探す）

- **身近さで**：box, sphere, cylinder, cone は実物に最も似て、初心者の第一 picks；
- **「幾何感」で**：正多面体（icosa/octa/dodeca/tetra）は「数学っぽく」、knot/helix/tube は「流れる」；
- **用途で**：建築は box/cylinder/prism/pyramid/dome、装飾は torus/star3d/heart(2D)/lightning(2D)、有機モデリングは sphere/capsule/lathe/barrel。

### 11.4 まず一つ選ぶには

どれにするか分からなければ、まず **box** で感覚を掴み、次に **sphere** で「曲面の光と影」を、最後に **torus** で「中を抜く 3D の楽しさ」を。

❓ **考えてみよう**：立方体・球・円錐のうち、どれが「最少の材料で最大容量」か？これは実は実世界の問題（容器やタンクはこれを元に設計される）。

### 12.1 2D とは

2D 図形は**厚みがなく**、紙切れのように**地面に寝て**（XY 面、Z=0）います。記号・目印・装飾に向きます。

💡 **二つの見落としやすい点**：
- **半円**の平らな辺が今は**上向き**（旧版から 180° 回転）になり、「アーチ」「日の出」が自然に；

### 12.3 「シール」思考

2D を、地面に貼ったシールだと思ってください。いつも「寝て」いて、決して立ち上がりません。利点——上視点では明確な記号絵になり、テクスチャと色を組めば床の案内線や会社ロゴの床デカール、碁盤目などが作れます。

### 12.4 隠れに注意

2D 図形は地面に寝ているので、3D 物体が押さえると隠れ、ある角度では薄い 2D が「線」に消えます。目立たせたいなら少し持ち上げ（緑 Z 軸）、または開けた場所に。

✏️ **やってみよう**：square2, heart, arrow, star を各一つ置き、「上」視点で最も明確な見た目を、次に「透視」で地面に「寝ている」様子を見る。

## 第 13 章 各 3D 図形のパラメータ詳解（上）：基本形体

> この節は最もよく使う 10 種を一つずつ。各「見た目／比喩／用途／tip」の四つで直観を築きます。

### 13.1 立方体 box
- **パラメータ**：`長さ`／`幅`／`高さ`（独立、わざわざロックを外して伸ばさずとも長立方体が作れる）。
- **見た目**：6 面の長方形からなる直角な体。
- **比喩**：宅配箱、サイコロ、レンガ。
- **用途**：壁、台、何でも「四角い」もの。
- **tip**：最も安定する「土台」図形。低い壁なら `高さ` を縮めるだけで、スケールより精密。

### 13.2 球 sphere
- **パラメータ**：`半径`。
- **見た目**：完璧な球。
- **比喩**：バスケ、惑星、泡。
- **用途**：頭、天体、装飾球。
- **tip**：球はテクスチャ／画像を最も「平ら」に広げ、アイコン球に良い。

### 13.3 円柱 cylinder
- **パラメータ**：`半径`／`高さ`（上下同口径の真円柱。上下異口径には **barrel**）。
- **見た目**：上下円、まっすぐな側面。
- **比喩**：缶、柱、蝋燭。
- **用途**：梁、管体、塔軸。
- **tip**：cylinder は「一半径」、barrel は「二半径」——役割分担を覚えて。

### 13.4 円錐 cone
- **パラメータ**：`底半径`／`高さ`。
- **見た目**：円底、先とがり。
- **比喩**：アイス、誘導標識、クリスマスツリー各層。
- **用途**：とんがり屋根、表示灯。
- **tip**：`底半径`を縮めながら数段重ねて「層塔」を。

### 13.5 トーラス torus
- **パラメータ**：`外径`／`内径`（**目に見える二つの輪そのもの**：外側の円、中央の穴。旧「管半径」は削除）。
- **見た目**：中央に穴の空いたドーナツ。
- **比喩**：フラフープ、タイヤ、指輪。
- **用途**：輪装飾、管エルボ、後光。
- **tip**：`内径`は `外径` より小さく自動制限。近づくほど輪は細く、針金輪のよう。

### 13.6 結び knot
- **パラメータ**：`半径`／`管太さ`（管太さ上限は `半径` に自動追従、約 0.4 倍で自己交差を防ぐ）。
- **見た目**：三つ編みのように編んだ輪。
- **比喩**：ロープの結び、エネルギー記号。
- **用途**：テック感装飾、ロゴ体。
- **tip**：複雑な形。単色か単純テクスチャが無難。

### 13.7 二十面体 icosa
- **パラメータ**：`辺長`（半径ではなく、**各辺の実長**を直接指定、幾何感覚的）。
- **見た目**：20 の正三角形からなる球近い多面体。
- **比喩**：サッカーボール（古典 32 面の親類）、鉱物結晶。
- **用途**：宝石、サイコロ、低ポリ風球。
- **tip**：「ローポリ」美学の代表。単色で高級に見える。

### 13.8 八面体 octa
- **パラメータ**：`辺長`。
- **見た目**：上下とがり、8 面ふくらむ。
- **比喩**：カットダイヤ、双円錐。
- **用途**：結晶、宝石、抽象彫刻。
- **tip**：回転時の光影変化が豊かで「焦点装飾」に。

### 13.9 十二面体 dodeca
- **パラメータ**：`辺長`。
- **見た目**：12 の五角形からなる球状多面体。
- **比喩**：魔法石、サイコロ（D12）。
- **用途**：神秘記号、装飾。
- **tip**：同じ辺長でも外接球半径係数が高く、icosa より「一回り大きく」見える。

### 13.10 カプセル capsule
- **パラメータ**：`半径`／`円柱長`（全高＝円柱長＋2×半径）。
- **見た目**：両端が半球の円柱。
- **比喩**：カプセル薬、トラック、ボウリングピン。
- **用途**：簡略人体胴、ホース、丸い柱。
- **tip**：純円柱より柔らかく、キャラや生物に。

✏️ **やってみよう**：box + cylinder + cone で「街灯」を：円柱を柱、box を灯具、cone を上部笠に。基本の組み合わせの力を感じて。

## 第 14 章 各 3D 図形のパラメータ詳解（下）：特殊形状

### 14.1 四角錐 pyramid
- **パラメータ**：`底辺`／`高さ`（旧「辺数」は削除——もともと**正方形**錐の意）。
- **見た目**：正方形底＋一つの尖り。
- **比喩**：エジプトのピラミッド、屋根。
- **用途**：塔、とんがり屋根建築、記念碑。
- **tip**：この版で法線を再計算、4 斜面に**明確な面の光影**が出て、旧版の「ぼやけ」が消えた。

### 14.2 三角柱 prism
- **パラメータ**：`底辺`／`高さ`。
- **見た目**：三角断面のまっすぐな柱。
- **比喩**：プリズム、路上ブロック、屋根梁。
- **用途**：三角梁、くさび、テック部品。
- **tip**：やはり法線固定で 3 面がシャープ。横に寝かせて「斜面ブロック」に。

### 14.3 チューブ tube
- **パラメータ**：`スパン`／`アーチ高`／`管半径`／`曲線分割`。
- **見た目**：持ち上がったアーチ状の丸管、両端は地面に。
- **比喩**：アーチ橋、虹、取っ手。
- **用途**：橋、アーチ、装飾リボン。
- **tip**：`スパン`は両端の水平距離、`アーチ高`は中央の高まり——両者の比で「平アーチ」か「高アーチ」かが決まる。`管半径`上限はスパン／アーチ高に応じ自動で締まる。曲線分割が大きいほど滑らか。

### 14.4 旋盤立体 lathe
- **パラメータ**：`分割数`（≥3）／`底半径`／`中半径`／`最大半径`／`高さ`。
- **見た目**：プロファイルを中心軸周りに回した体（花瓶／コマ形）。
- **比喩**：花瓶、電球、コマ、ゴブレット。
- **用途**：対称容器、器、彫刻。
- **tip**：三半径は**底・腰・最大**を制御。花瓶なら `最大半径`＞`中半径`＞`底半径`、コマなら逆。`分割数`は周方向精度、最小 3（三角錐台風に）。

### 14.5 四面体 tetra
- **パラメータ**：`底辺`。
- **見た目**：4 面の最小多面体。
- **比喩**：三角錐、結晶破片。
- **用途**：碎石、低ポリ装飾、尖り記号。
- **tip**：面が少なく硬い。ハード／テック風に。

### 14.6 樽 barrel
- **パラメータ**：`上半径`／`下半径`／`高さ`（旧の曖昧な「半径」は削除）。
- **見た目**：上下口径の異なる円柱。
- **比喩**：木樽、植木鉢、紙コップ、ロケット胴。
- **用途**：容器、機体、貯水池。
- **tip**：**最も柔軟な柱**——等半径は円柱、上小は植木鉢、上大は紙コップ、`上半径`を 0 近くまで下げれば円錐に。

### 14.7 半球 dome
- **パラメータ**：`半径`。
- **見た目**：球の半分（上半）。
- **比喩**：ゲル状天幕、天文台、鐘撞堂。
- **用途**：屋根、蓋、プラネタリウム。
- **tip**：box と組んで「屋根付き小屋」に。反転（回転）すれば「鉢」。

### 14.8 開トーラス helix
- **パラメータ**：`外径`／`内径`／`主スイープ角`（旧「管半径」削除、トーラスと同じ外径／内径の二半径に）。
- **見た目**：欠け口のある輪——トーラスの一部が切り取られた弧。
- **比喩**：C 字留め具、開いた腕輪、バネの一巻。
- **用途**：動的装飾、渦記号、エネルギー輪、留め構造。
- **tip**：`主スイープ角`は「この輪が総計何度回るか」：360°は全トーラス、270°は典型 C、180°は半輪。**この一つで「閉じる」から「開く」へ滑らかに遷移**。

### 14.9 八角柱 octaPrism
- **パラメータ**：`底辺`／`高さ`（旧「半径」は直観的な辺長へ変更）。
- **見た目**：8 面の垂直な柱。
- **比喩**：八角柱、灯台、井戸壁。
- **用途**：正多角柱、塔軸、台。
- **tip**：円柱より角があり、立方体より丸い。良い折衷。

### 14.10 3D 星 star3d
- **パラメータ**：`外径`／`内径`／`尖り数`／`厚み`。
- **見た目**：厚みを持たせて押し出した星。
- **比喩**：メダル、星ペンダント、バッジ、歯車。
- **用途**：褒賞記号、装飾体、ロゴ。
- **tip**：`尖り数`は 5 に限らず、3 にすれば三角星、内外半径を近づけて大きくすれば**歯車**に。`内径`は `外径` より小さく自動制限。

## 第 15 章 「立つ」と「寝る」：3D と 2D の本質的な違い

### 15.1 体積と面積

- **3D は体積あり**：空間を占め、影を落とし、互いを遮れる。「地面に立つ」、高さ（緑 Z 軸）を持つ；
- **2D は面積のみ**：平らに敷かれ、厚みゼロ。「地面に寝る」（Z=0）。
これを理解すれば、3D が「積み木のように積める」のに、2D は「床を敷く」しかできない理由が分かります。

### 15.2 なぜ片方は立ち、片方は寝るか

コードでは 3D は `seatOnGround` で底面を y=0（画面ラベル Z=0）へ落とし、2D は `shape2D` で XZ 面（地面）へ回転して貼り付けます。だから：
（注：先の「地面／XY 面／Z=0」は**画面インターフェースのラベル**口調、ここでの `y=0`／`XZ 面`は **Three.js 内部座標**口調——同じ地面を指すだけで命名系が異なります：Three.js 内部では Y 軸を「高さ」とし、本書 UI ラベルの緑軸 Z に対応、内部 X, Z 軸は本書 UI ラベルの X（前後）／Y（左右）に対応。）
- 立方体を置けば自然に「地面に座り」、
- ハートを置けば自然に「地面に貼り付く」。

### 15.3 混ぜる技

- 2D を「立たせたい」？赤軸（Y）周りに 90° 回転、寝たままから立った「立て札、看板」に；
- 3D を「寝かせたい」？横に倒れて「倒木／斜め板」に；
- 地面記号（方向矢印）＋立体建物が最も一般的なシーン構成。

✏️ **やってみよう**：矢印（2D）を置き、Y（赤／左右）周りに 90° 回転させ、寝た「地面矢印」から立った「方向看板」へ変わるのを見る。これが「立つ・寝る」の自在切替。

# 第 4 篇 色とマテリアル

色は作品の「雰囲気」です。この篇は「光とは何か」から 27 プリセット、カスタム色抽出、12 テクスチャ、そして画像テクスチャと不透明度へと進みます。

## 第 16 章 色入門：人間の目と光のゲーム

### 16.1 色は物体に「本来ある」ものではない

暗がりのリンゴは黒です——赤く見えるのは光が当たり「反射」して目に入るから。だから**色＝物体＋光**。本ツールは `MeshStandardMaterial`（光反応材）を用い、環境光（強度 1.0）と指向光（強度 2.6）で光影を出します。

💡 同じ色が背光面で「暗く」見えるのは色が変わったのではなく、光が変わったからです。

### 16.2 RGB：画面は三原色を混ぜる

ディスプレイは **赤(R)・緑(G)・青(B)** の光で全色を作ります。プリセット `0xff0000` は「赤最大、緑青ゼロ＝純赤」を意味。

### 16.3 HSV：人間の脳が色を選ぶ直観

RGB 以上に、人は **色相(H)・彩度(S)・明度(V)** の方が直観的です。抽出器を動かすとき、実は HSV を調整しています。
- 色相＝赤橙黄緑青藍紫と巡る環；
- 低彩度→灰色っぽく、高彩度→鮮やか；
- 低明度→暗く、高明度→明るく（白っぽくも）。

### 16.4 二つの隠れた材質パラメータ

表面には `粗さ`（rough/0.6、大きいほどマット）と `金属性`（metal/0.0、大きいほど金属っぽく）があります。現在は「マットなプラスチック」寄りの既定。色を変えてもこの二つは通常そのまま——でも存在を知っていれば「なぜ鏡反射しないか」が説明できます。

### 16.5 不透明度：光を通す

色以外に「透明か否か」。詳細は第 20 章、ここでは：不透明度 1＝不透明、0＝見えなく。

❓ **考えてみよう**：なぜ病院の壁や手術衣は「低彩度の浅い青／浅い緑」か？彩度高／低が気分にどう影響するか。
✏️ **やってみよう**：白い球を置き、視点を変えて背光面が暗くなるか。それが「光が色を作る」の生証拠。

鮮赤 `#ff4444`、橙 `#ff8800`、金黄 `#ffcc00`、鮮緑 `#44ff44`、ティール `#00cc88`、鮮青 `#4488ff`、紫 `#8844ff`、薔薇 `#ff44aa`、浅シアン `#6ee7ff`、浅紫 `#c084fc`、浅桃 `#fb7185`、翠 `#34d399`、琥珀 `#fbbf24`、空青 `#60a5fa`、桃 `#f472b6`、藤紫 `#a78bfa`、珊瑚赤 `#f87171`、青灰 `#94a3b8`。

💡 プリセットは設計者が調整した「安全パレット」、初心者がそのまま押してもたいてい悪くありません。ブランド色は第 18 章でカスタムを。

✏️ **やってみよう**：第 13 章の街灯をプリセットで着色——柱は青灰、灯具は琥珀、上部笠は珊瑚赤。パレットが個性だと感じて。

## 第 18 章 カスタム色：HEX・HSV とスクリーンカラーピッカー

### 18.1 HEX とは

HEX は `#` の後に 6 桁の 16 進数、R・G・B 各 2 桁。例 ブランド色 `#1e90ff`（ドジャー青）。色を正確に再現するには HEX 入力が最も確実。

### 18.2 抽出器の動かし方

右パネルの「抽出器」ボタンを開くと、「大きな色盤＋色相バー＋HEX/RGB 入力」の窓が出ます：
- 大きな盤をクリック／ドラッグ → **彩度＋明度**を選ぶ（左右＝濃さ、上下＝明るさ）；
- 下の**色相バー**をドラッグ → **色相**を巡る；
- 絶対精度なら HEX か R/G/B 枠へ直接入力。

💡 「同色の濃淡」を探すには**色相バーを固定**し、盤内だけ上下にドラッグ（明度だけ変える）が最も調和。

### 18.3 スクリーンカラーピッカー（吸い取り）

一部版には「画面から色を拾う」があり、吸い取りボタンを押してキャンバス任意の場所（別の物体の色や背景も）をクリックしその色を取得。実物から「色を拾う」パレット作りに最適。

### 18.4 「色なし」(NO_COLOR) とは

ソースに特殊マーカ `NO_COLOR = -1` があり、選ぶと物体に**単色を適用しない**（画像テクスチャや特殊材と組むと「下地色なし」）。

⚠️ **注意**：うっかり「色なし」をクリックすると物体が「着色なし／暗い」に見えます——壊れではなく、普通の色を選び直せば。

✏️ **やってみよう**：HEX で好きな色（例 `#ff6b6b`）を立方体へ入力、次に吸い取りで画面のどこかから色を拾い、二つを比べる。

## 第 19 章 12 種のテクスチャ：表面に物語を

単色は平板、テクスチャが表面に「中身」をくれます。本ツールには **12 種のテクスチャ** (`PATTERNS`) を内蔵：

| テクスチャ | 見た目／用途 |
| --- | --- |
| Solid | 無地、最も清潔 |
| Checker | 碁盤、テーブルクロス、床タイル |
| Stripe | 縞馬、警告、布 |
| Dot | 水玉、キャンディ |
| Gradient | 空、金属遷移 |
| Brick | 壁、建物 |
| Diagonal | 速度、テック |
| Wave | 水紋、シルク |
| Dot matrix | ピクセル、テックパネル |
| Cross | 格子布、包帯 |
| Grid | 方眼紙、製図 |
| Thread | 渦、ねじ管 |

💡 テクスチャは通常「主色＋テクスチャ色」の二層で、右パネルで別々に調整でき、無限の表面に。
⚠️ **注意**：複雑なテクスチャ（Brick、Grid 等）を低ポリ球に広げると「歪む」のは正常。きちんとさせたいなら面の多い box/cylinder が良い。

✏️ **やってみよう**：box を置き、Brick／Checker／Stripe を順に試し、表面が「壁／布／警告標識」に変わるのを感じる。

## 第 20 章（色とマテリアル篇の続き）画像テクスチャのアップロードと不透明度・ワイヤーフレーム

### 20.1 画像アップロード：写真を表面に貼る

プリセットテクスチャ以外に、**自分の画像**（PNG/JPG）を表面テクスチャにアップロード可——会社ロゴ、写真、手書きすべて。貼れば表面にその画像が「印刷」されます。
- 向く：実写入り掲示板、印刷ロゴ入りメダル、地図を敷いた地面；
- tip：画像は正方形で鮮明なほど良く、box の面に貼るのが最も明瞭。

### 20.2 不透明度

右パネルで「不透明度」を調整：
1＝完全不透明；
0.1＝ほぼ見えず；
中間＝半透明（ガラス、幽霊、水っぽさ）。
💡 「ガラス蓋」「氷」「幻影」はこれに頼る。半透明にすると後ろの物体が透けて、階層が一気に豊かになります。

### 20.3 ワイヤーフレーム

「ワイヤーフレーム」を入れると、物体は骨組み線（三角形メッシュ）だけを残し、面を塗りません。向く：
- 構造を見る（授業、模式図）；
- 「ワイヤーフレーム風」装飾を作る；
- 形が望み通りか確認。

### 20.4 組み合わせ

- テクスチャ＋半透明＝かすんだ絹；
- 画像＋ワイヤーフレーム＝インフォグラフィック風；
- 単色＋高透明＝ガラス煉瓦。

❓ **考えてみよう**：「一片の氷」を表すなら、色・不透明度・テクスチャをどう組む？「半透明のレンガ壁」はどんな効果か？
✏️ **やってみよう**：パソコンから画像を平たい box にアップロード、次に不透明度を 0.5 にして「画像が半透明に」を、最後にワイヤーフレームで骨組みを見る。

# 第 5 篇 テキストと画像

図形のほか、シーンには「言葉」と「写真」で情報を伝える必要があります。この篇は二つの「内容型」オブジェクト：テキストと画像です。

## 第 21 章 テキストを追加：シーンに話させる

### 21.1 テキストは「話す薄板」

看板、名前、ヒント、スローガン…テキストが 3D シーンに意味を与えます。テキストオブジェクトは本質的に「言葉を貼った薄い板」で、通常のオブジェクト同様に選択・移動・回転・スケール・着色できます。

### 21.2 テキスト追加の三ステップ

1. 左パネルの「ツール」から「テキスト追加」；
2. 中央地面を一度クリック、入力枠が出る（placeholder「Input text······」）；
3. 入力し **Enter** で確定、地面に降り立つ。入力枠内では **Shift + Enter** で改行（複数行）。

💡 placeholder「Input text······」は「ここに入力」を促すだけで内容ではなく、最終作品には出ません。

### 21.3 内容変更：ダブルクリック

置いた後で編集したい？テキストオブジェクトを**ダブルクリック**すれば入力枠が再び、編集して Enter。削除して作り直す必要なし。

### 21.4 テキストも立派なオブジェクト

テキストは全通常操作に対応：選択、移動（青前後／赤左右／緑上下）、回転、スケール、着色、不透明度。発光テキスト／半透明テキストも可。

✏️ **やってみよう**：「Welcome」を追加し、入口へ移動、次にダブルクリックで「Welcome in」へ変え、即編集の便利さを感じる。

---

## 第 22 章 フォント・文字サイズ・太さ・縦書き横書き

テキスト選択後、右パネルにテキスト専用コントロールが出ます。本ツールは **8 フォント**と幾つかの配置切替を備えます。

### 22.1 八フォントの選び方

| フォント | 気質／用途 |
| --- | --- |
| YaHei | モダン、明瞭、中国語既定 |
| Song | フォーマル、書籍風 |
| Kai | 筆記体、伝統、扁額 |
| Hei | 重厚、目を引く見出し |
| FangSong | 公文書、繊細 |
| Arial | 西洋モダンサンセリフ |
| Times | 西洋セリフ、フォーマル |
| Courier | 西洋等幅、コード／タイプライター風 |

💡 中国語は最初の 5 つ、純英語は後ろ 3 つで気質を変えられます。

### 22.2 フォントサイズ（既定 80）

既定サイズは **80**、右パネルで調整。大きすぎるとシーンスケールを「破壊」し、小さすぎると読めません。

⚠️ **注意**：サイズはシーン単位に対する比で、図形サイズと合わせねばならず、500 サイズのフォントを 1.2 単位の立方体と組むと文字が物体よりずっと大きくなります。

### 22.3 太さ（太字スイッチ）

ワンクリックで太字にし、見出しを際立てます。Hei／Kai では「扁額感」が良く出ます。

### 22.4 横書き／縦書き

- **横書き**：通常の一行、左から右へ；
- **縦書き**：上から下へ、中国語の扁額・書名・看板に向く。
💡 組み合わせ提案：縦書き＋Kai＋大サイズ＝伝統扁額、横書き＋Hei＋中サイズ＝モダン看板。
⚠️ **注意**：長すぎるテキストは薄板幅を超えることがあり、入力枠で **Shift + Enter** 改行するか、適宜サイズを縮めて。
✏️ **やってみよう**：縦書きの「茶館」扁額（Kai、縦書き、大サイズ、木色）を作り、フォント組みの「個性」を感じる。

## 第 23 章 画像オブジェクト：写真を 3 次元世界へ

### 23.1 画像オブジェクトの追加

左パネル「ツール」→「画像追加」→ローカル画像を選び→地面をクリック、画像が**平たいデカール**（立った写真のよう）として出ます。

### 23.2 通常オブジェクト同様に操作

選択後、移動・回転・スケール可。壁に凭れさせ、床装飾として平らに敷き、看板として持ち上げ。

### 23.3 画像は「テクスチャ」にもなる

第 20 章のように画像は任意の 3D オブジェクト表面に「貼り付け」（表面材として）可。だから同じ画像に二つの使い方：
- **独立デカールとして**：シーン内の「写真」；
- **表面テクスチャとして**：box／円柱等の面に印刷。

### 23.4 画像と 2D 図形

| | 画像オブジェクト | 2D 図形 |
| --- | --- | --- |
| 内容 | 自分の写真／ロゴ | ソフト生成の図形 |
| 着色可 | 全体テクスチャとして概ね | 単色／テクスチャ可 |
| 典型用途 | 実写写真、実ロゴ | 記号、目印、装飾 |

両者とも「薄く」、立ても寝かせも可、必要に応じ選んで。

✏️ **やってみよう**：自分の写真を「平たいデカール」として立て、同じ画像を box 面のテクスチャにして、二つの使い方を比べる。

# 第 6 篇 ペンと消しゴム

前の篇は「標準図形」、この篇は「手描き」——ペンでシーンに線を引くよう描き、消しゴムで拭います。

## 第 24 章 2D ペン：地面に線を描く

### 24.1 2D ペンとは

2D ペンは**地面（XZ 面）に平らな線**を描き、紙にペンで線を引くよう。床デカール、道、落書き、床案内に向きます。

### 24.2 使い方

1. 左パネル「ツール」で「2D ペン」；
2. 中央地面で**左ボタンを押したままドラッグ**、離すと一本完了；
3. 続けて何本も描ける。

### 24.3 Shift で直線に拘束

ドラッグ中に **Shift** を押すと線が**直線に拘束**（二点間）。「まっすぐな道」／「整った辺」に。
> 方向ロック：直線拘束に入ると、**この一本（左ボタン描画）が終わるまで**方向は最初に決まった水平／垂直／45° に固定され、途中でマウスがそれても変わらず。方向を変えるには左ボタンを離し新たな一本を。

### 24.4 ペンの四つの属性

右パネル（ペン活性時）で設定：
| 属性 | 効果 |
| --- | --- |
| 色 | 線の色 |
| 太さ | 線の幅 |
| 不透明度 | 線の濃さ |
| 最小間隔 | サンプル点間の最小距離、小さいほど滑らかで密 |

💡 最小間隔が小さいほど細い線だが頂点が増え、大きいほど疎らで角ばる。細い曲線は縮めて、写生は広げて。

### 24.5 ペンと 2D 図形

- 2D 図形は「標準形」（円・ハート…）、着色やテクスチャ替え可；
- 2D ペンは「あなたの手描き任意線」、自由だが不規則。
標準記号には図形を、気ままな落書きにはペンを。

✏️ **やってみよう**：2D ペンで地面に「∞」を描き、Shift でその中へ直線を引く——自由線と拘束線を感じる。

---

## 第 25 章 3D ペンと参照平面

### 25.1 3D ペンとは

3D ペンは空間に**立体の管**を描き、地面に貼らず「空中に浮くパイプ線」。まさに「空中に描く」。

### 25.2 参照平面：最初のクリックが「どの層に描くか」を決める

3D ペンの最初のクリックで**半透明の「参照平面」**が決まり、以後のドラッグはこの平面を基準に、線はその近くに着地します。
💡 **水平線**を描きたい？まず「上」視点に切り替え、クリックで水平参照平面を、**垂直線**なら「前／左／右」で垂直平面を。平面の向きが「描く次元」を決めます。

### 25.3 平面上に描き、Shift で直線拘束

- 参照平面上を自由にドラッグ；
- **Shift** を押しながらドラッグで直線拘束（2D ペンの Shift 拘束と同じだが空間の管に作用）。
> 方向ロック：同上、Shift で直線拘束すると**方向は一本終わるまで固定**、途中で変わらず、離して新たな一本で方向変更。

### 25.4 玉キャップ端

一本の両端に自動で**玉キャップ端**が付き、線は丸く、決して開かず、端キャップのある本物のパイプのよう。

### 25.5 用途

- リボン、連結、エネルギービームを気ままに造形；
- シーンに「動的線」（標準体より有機的）；
- 抽象美術、回路模式図。

❓ **考えてみよう**：3D ペンの「参照平面」は画家が「まず紙を張る」のと同じか？なぜ 3D にはこの「仮想の紙」が特に必要か？
✏️ **やってみよう**：「上」に切り替え、3D ペンで水平参照平面を決めて波線を、次に「前」で別の垂直線を描き、空間線の次元差を感じる。

## 第 26 章 消しゴム：全体と部分

失敗は消せねばなりません。本ツールの消しゴムは二モードで挙動が異なり、見分けてください。

### 26.1 二モードの切り替え場所

右パネルの消しゴム属性に「消し方」：全体消去／部分消去。

### 26.2 全体消去（既定）

消しゴム円をドラッグ、触れたものは**オブジェクトごと削除**（一本のペン線、一つの図形ごと）。これは「大胆な」掃除。
💡 3D 線一本や図形一つをさっと消すなら全体モード、円をかぶせて削除。

### 26.3 部分消去

「部分消去」を入れると：
- **2D 線**：消しゴム円と交差する**区間だけ**消去、残りは残る（細かい線修理）；
- **3D 線**：同様に交差する**軌跡点だけ**消去、残りは残る（2D・3D 線とも区間ごとの部分消去に対応）；
- **その他のオブジェクト**（標準 3D/2D 図形、テキスト、画像）：やはり**オブジェクトごと削除**（全体消去）。

⚠️ **注意**：部分モードは「ペン線（2D と 3D）」の区間ごと消去のみ。標準図形・テキスト・画像には全体消去のまま。「立方体の角を少し齧る」とは期待しないで。

### 26.4 消しゴムサイズ

「消しサイズ」スライダで消しゴム円の半径を調整、細工修理にも大掃除にも。小さすぎると何度も、大きすぎると隣を誤削除。

### 26.5 誤消しも復元可

消しゴムで消したオブジェクトも他操作同様に履歴に入り、`Ctrl+Z` で戻ります。だから大胆に消して。

✏️ **やってみよう**：2D ペンで長い曲線を描き、先に「部分消去」で小さな区間を拭き（残りは残る）、次に「全体消去」で別の線を円ごと消し、二モードを比べる。

# 第 7 篇 視点と観察

「別の角度から見る」だけで多くのことが明確になります。この篇は視点の観察と固定方法です。

## 第 27 章 7 つのプリセット視点：別の角度で世界を見る

### 27.1 なぜ視点を切り替えるか

人間の目は一角度しかなく、前後左右どちらが高いかを誤りがち。ワンクリック視点切替は作品の周りを歩くこと。ボトムバーに **7 つの視点ボタン**。

### 27.2 七視点を一つずつ

| 視点 | あなたは… | 見える主面（画面ラベル） |
| --- | --- | --- |
| 透視 | 普通に立って見る | 近大遠小、最も自然 |
| 上 | 真上から見下ろす | X（青前後）× Y（赤左右）面 |
| 下 | 真下から見上げる | 上と同じだが反転 |
| 前 | 真正面から水平に見る | Y（赤左右）× Z（緑高さ）面 |
| 後 | 真後ろから水平に | 前と同じだが逆 |
| 左 | 真左から水平に | X（青前後）× Z（緑高さ）面 |
| 右 | 真右から水平に | 左と同じだが逆 |

💡 画面ラベルを覚えて：**X 青＝前後、Y 赤＝左右、Z 緑＝高さ**。上視点は「前後×左右」（地面）、前視点は「左右×高さ」（立面）を見る。

### 27.3 いつどれを

- **透視**：全体観察、スクリーンショット見せ；
- **上**：精密配置、一列整列（上視点の地面が最も正確）；
- **前／左／右**：「まっすぐか」「整列しているか」確認、対称構図；
- **下／後**：稀だが「裏面／底面」が予想通りか検証。

❓ **考えてみよう**：なぜ建築家は「平面図・立面図・側面図」を描く？この七視点のうちどれがその三図面に対応するか？
✏️ **やってみよう**：図形を 3 つ置き、上・前・右を順にクリックし、同じシーンが視点でどう変わるか観察。

---

## 第 28 章 視点のロック・補助の非表示・全画面

### 28.1 現在視点をロック

トップバーで「現在視点をロック」(`lockCurrentView`) 可：ロック後、カメラは**操作に連動して自動回転しない**ので、固定角度で微調整に集中。

💡 精密整列時は先に視点をロックし、ゆっくり調整、画面が「勝手に逃げ」ない。

### 28.2 軸とグリッドを隠す

トップバーに「軸」と「グリッド面」の二スイッチ：
- 軸を隠す：3 本の文字ラベル矢印を消す；
- グリッドを隠す：地面の升目を消す。
⚠️ **注意**：スクリーンショット／見せる書き出しの前は**軸とグリッドを先に隠し**てきれいに。補助に過ぎず作品自体には影響なし。

### 28.3 全画面

| 形態 | 全画面の方法 |
| --- | --- |
| 🖥️📱 **Web** | トップバーの「全画面」ボタン、🖥️ マウス側は **F11** も可。ブラウザ全画面へ |
| 💻 **PC** | 「全画面」ボタンか **F11** でウィンドウ全画面（タイトルバーと窓ボタンを隠す） |
| 🤖 **Android** | **全画面ボタンなし**——もとから全画面アプリ |

🖥️💻 **Esc** はコントロール閉じ／選択解除のみで全画面を抜けず、全画面を抜けるには **F11** 再押し／「全画面」再クリック。

### 28.4 実用の組み合わせ

> 見せる画像を作るには：軸隠し＋グリッド隠し＋透視へ＋（🖥️📱💻 任意）全画面＋スクリーンショット。

✏️ **やってみよう**：小シーンを作り、先に軸／グリッドを隠して「きれいな画像」を、次に表示して「補助付き画像」を撮り比べ。

## 第 29 章 なぜショートカットを覚えるか：効率の複利

### 29.1 見くびられがちな事実

小さな実験：シーンに立方体を置き、右パネルの「均等スケール」スライダーをマウスで 10 往復、次にキーボード `+`／`-` を 10 回。あなたはほぼ確実に：**キーボードの方が速く、正確で、疲れない**。三つの理由：
1. **手がキーボード中心から離れない**——目はキャンバス、指は文字キー、脳は「キャンバス見→パネル探し→マウス動かし→スライダー引く」を切り替えず；
2. **固定ステップ**——矢印キー一押しで物体がちょうど「0.1 升目」、10 押しでちょうど 1 升目。スライダー 10 回ではどれだけ動いたか分からず；
3. **蓄積可、取り消し可**——キー操作は全て履歴スタックへ（第 32 章）、押し誤りは `Ctrl+Z` 一つ、スライダー引きは連続変化で取り消しが「跳ぶ」ことが多い。
💡 **一言**：マウスは「選ぶ」「描く」、キーボードは「変える」「調整する」。役割分担で倍速。

### 29.2 ショートカットにも「場面」がある

このツールのショートカットは「全体で一つ」ではなく、**現在オブジェクトが選択されているかで異なります**：

| 現在の状態 | 矢印キー／A D W S の動き |
| --- | --- |
| **何も選択されていない** | **カメラ**を動かす（シーンを回す） |
| **オブジェクト選択中** | **そのオブジェクト**を動かす（シーン内で移動／回転） |

同じ `↑` が、何も選択なしでは「カメラ前進」、選択中では「物体前進」。この区別がショートカット全体の核心、まず刻み込まねば後で混乱。

❓ **考えてみよう**：なぜ「何も選択なしならカメラ移動」が合理的な設計か？——そのときあなたはたぶん「角度を探し、全体を見る」最中で、キーボードで視点をパン／回転した方が空白ドラッグ（連続で段なし）より精密だから。

### 29.3 まず「軸の言葉」を復習

この篇の「X／Y／Z 軸に沿って」はすべて**画面ラベル**（画面に表示される軸と一致）：
- **X 軸（青）＝前後**（青≈「奥行き」）
- **Y 軸（赤）＝左右**（赤≈「左右」）
- **Z 軸（緑）＝高さ、上が正**（緑≈「高さ」）
> ⚠️ 注意：これは「画面ラベル軸」。コード内部は別の軸（X 赤、Y 緑、Z 青、Y が上）を用いますが、UI・本書・ヘルプに表示されるのは常に上のラベル。ラベル軸を覚え、内部実装に惑わされるな。
これを覚えれば、あとの各章はこれで「文」を書きます。

### 30.2 ジェスチャー操作（📱 Web·タッチ／🤖 Android）

## 第 31 章 単キー操作と Shift 組み合わせ

キーボードショートカットの核心ルール：**オブジェクトが選択されているかで異なる**。下の二表はアプリ内「設定 → ショートカット」の「単キー操作」／「Shift 組み合わせ」と**完全同一**、直接使用を。

### 31.1 単キー操作

> オブジェクト選択中：移動 0.1 升目（0.15 長さ）／回転 5°；選択なし：視点パン 0.1 升目／回転 5°。

| キー | オブジェクト選択中 | 選択なし |
| --- | --- | --- |
| `↓` / `↑` | X 軸に沿って +/− 移動 | 視点前後パン |
| `→` / `←` | Y 軸に沿って +/− 移動 | 視点左右パン |
| `PgUp` / `PgDn` | Z 軸に沿って +/− 移動 | 視点上下面パン |
| `A` / `D` | Z 軸周り CW / CCW 回転 | 視点左右回転 |
| `W` / `S` | Y 軸周り CW / CCW 回転 | 視点上下回転 |
| `E` / `Q` | X 軸周り CW / CCW 回転 | — |
| `+` / `-` | 5% 拡大／縮小 | — |
| `Esc` | 操作取り消し | コントロール閉じ |
| `F11` | 全画面／抜け | （同） |
| `Del` / `Backspace` | 選択オブジェクト削除 | — |

✏️ **やってみよう**：立方体を置く→選んで `↑` で「前へ歩く」、選択解除（空白クリック）してもう一度 `↑`→今度はカメラが前進。同じキー、二つの顔。

### 31.2 Shift 組み合わせ

> オブジェクト選択中：移動 1 升目（1.5 長さ）／回転 90°；選択なし：視点パン 1 升目／回転 90°。

| `Shift` + キー | オブジェクト選択中 | 選択なし |
| --- | --- | --- |
| `↓` / `↑`, `→` / `←`, `PgUp` / `PgDn` | 1 升目移動 | 視点 1 升目パン |
| `A` / `D`, `W` / `S`, `E` / `Q` | 90° 回転 | 視点 90° 回転 |
| `+` / `-` | ×2 拡大／×0.5 縮小 | — |
| 左シングルクリック | オブジェクト加選（ピック） | （同） |
| 左長押し（ペンツール） | ペン拘束直線モード（水平／垂直／45° 拘束、Shift 拘束と同等） | （同） |

💡 語呂：**通常キーは近づけ、Shift キーは決まる**。まず矢印で大まかに、次に `Shift`+矢印で最後の 1 升目ジャンプで即整列。回転も同様、まず `A` で 5°、次に `Shift+A` で 90° に足してまっすぐに。

## 第 32 章 スライダー／入力枠 と Ctrl 組み合わせ

### 32.1 スライダー／入力枠

カーソルがスライダーや数値入力枠にあるとき、下のキーは「その枠の数値を変える」になり、元のショートカットは**一時無効**。この表はアプリ内「設定 → ショートカット」の「スライダー／入力枠」と**完全同一**：
| キー | スライダー | 入力枠 |
| --- | --- | --- |
| `→` / `←` | 増／減 | カーソル移動 |
| `↑` / `↓` | 増／減 | 増／減 |
| `+` / `-` | — | 正／負符号入力 |
| `PgUp` / `PgDn` | 大増／大減 | 右パネル上下スクロール |

⚠️ オブジェクトショートカットを使うには、まず空白キャンバスかオブジェクトをクリックし、入力枠からフォーカスを出して（第 32.1 節）。

### 32.2 Ctrl 組み合わせ

| `Ctrl` + キー | 組み合わせ |
| --- | --- |
| `A` | 全選択 |
| `N` | 新規シーン |
| `O` | シーン取り込み |
| `S` | シーン書き出し |
| `P` | スクリーンショット／画像書き出し |
| `Z` | 取り消し |
| `Y` | やり直し |
| `C` | コピー |
| `V` | 貼り付け |
| `D` | 複製 |
| `Del` / `Backspace` | シーンクリア（`「シーンをクリアしますか？取り消し可能です」`確認が出て、確認後クリア；`Ctrl` なしの通常 `Delete`/`Backspace` は選択オブジェクトのみ削除） |

⚠️ `Ctrl + Del` は一気に全オブジェクトを消すが、**確認が出**て、クリアは**取り消し可能**（`Ctrl + Z` で復元）。それでもクリア前に `Ctrl + S` でバックアップを。

### 32.3 総合ドリル：純キーボードで「小灯台」を

この篇の流れを一つのパイプラインに：
1. パネルから**円柱**をシーンへドラッグ（これだけマウス必須、許容）；
2. 選んで `Shift + PgUp` 数回で「伸ばす」好位置へ；
3. `Ctrl + D` で一つ複製を「灯具」に、`PgUp` で柱頂へ；
4. `Shift + A` で灯具を 90° まっすぐ（必要なら）；
5. `Ctrl + A` 全選択、`Ctrl + S` 保存；
6. 「前」ボタンで視点まっすぐ、`Ctrl + P` スクリーンショットで納品。
第 1 ステップの図形配置を除けば、ほとんどマウスパネルに触れず——これが「効率」の果て、手をキーボードに育てること。

# 第 9 篇 変換コントロール篇（「話す」矢印）

> 第 32 章でキーボードでオブジェクトを動かしました、もう速い。でもキーボードは「固定ステップ」——精密な反復移動には向くが、「感覚で引っ張って別の物体にぴったり触れさせる」には向かない。
> この篇の主役は、選択オブジェクトに浮かぶ**色矢印／リング／立方体**——技術的には「変換 gizmo」。マウスで「つかんで」引っ張れます。

## 第 33 章 変換コントロール初め：3 つの「つかむ道具」

### 33.1 いつ現れるか

オブジェクトを**選択**するや否や（クリックで選択枠）、その中心に一組のハンドルが浮かびます。それが変換コントロールです。

右パネルの「変換モード」ゾーン（⇔ ↻ ⤢ の三平方ボタン）で三つの「皮」を切り替えます：
| モード | ボタン | ハンドル | 何のため |
| --- | --- | --- | --- |
| **移動** | ⇔ | 3 本の**矢印** | オブジェクトを動かす |
| **回転** | ↻ | 3 つの**リング** | 向きを回す |
| **スケール** | ⤢ | 3 つの**立方体**（角の小立方） | 拡大／縮小 |

既定は**移動**モード。切り替えは対応ボタンをクリック、切り替え時に下部に「移動／回転／スケール」のヒントが浮かびます。
💡 豆知識：変換コントロールとキーボードショートカットは**同じものへの二つの入り口**——キーボードは「精密ステップ」、コントロールは「自由ドラッグ」。第 36 章で組み合わせを詳しく。

### 33.2 最初に伝えるべき「色の罠」

⚠️ **この篇全体で最も重要な注意——まず読んで**。
シーン内の三つの**軸ラベル**は「画面ラベル色」：
- **X ＝ 青 ＝ 前後**
- **Y ＝ 赤 ＝ 左右**
- **Z ＝ 緑 ＝ 高さ**
しかし変換ハンドルの着色は **three.js コード軸の慣例**（赤＝X、緑＝Y、青＝Z）に従い、上の色と**一致しません**！だからハンドル色は次のように訳す必要があります：
| ハンドル色 | 実際のコード軸 | 対応する画面ラベル軸 | 画面上の意味 |
| --- | --- | --- | --- |
| 🔴 赤ハンドル | コード X | 画面 **Y** | **左右**移動／左右軸回り |
| 🟢 緑ハンドル | コード Y | 画面 **Z** | **高さ**（上下）移動／高さ軸回り |
| 🔵 青ハンドル | コード Z | 画面 **X** | **前後**移動／前後軸回り |
> 覚えられない？一言：**赤ハンドル＝左右、緑ハンドル＝上下、青ハンドル＝前後**（画面ラベルで読む）。表面の赤緑青に騙されて軸色を当てはめないように。
✏️ **やってみよう（検証）**：立方体を選び移動モードへ。まず**赤矢印**を引く——左右か前後か？→左右のはず。次に**青矢印**→前後？この実験で表を脳に刻めば、あとの回転／スケール軸も乱れない。

### 33.3 ハンドルを引っ張りながら視点は動かせるか

動かせます、しかも本ツールの非常に快適な設計：
- **左ドラッグ**＝オブジェクト操作；
- **右ドラッグ**＝視点回転（カメラが回る）；
- **中ドラッグ**＝視点平行移動；
- **ホイール**＝視点ズーム。
つまり片手で右ボタンを押して物体の横から角度を付け、もう片手（または同じ手でキー交替）でハンドルを引き続け——視点と変換が**喧嘩しない**。以前の「変換抜け→視点回転→再変換」の煩わしさが消えます。

## 第 34 章 移動モード：矢印でオブジェクトを「つかんで」動かす

### 34.1 三つの引っ張り方

移動モードでは、三本の軸矢印のほか、コントロールに**二つの平面正方形**（二軸が広げる面）もあり、三つの掴みがあります：
1. **単一矢印**（赤／緑／青）を掴む → その一軸だけ真っ直ぐ、最も精密、斜めにならず；
2. **平面正方形**（例 赤と緑矢印の間の面）を掴む → その二軸の平面内で自由に滑る；
3. 地面に沿って「自由に」動かしたい？対応平面へ切り替えて引く。
💡 経験：精密整列には常に**単一矢印**を掴み、平面は誤って不要な方向へ運びやすい。

### 34.2 平面の読み方（色の罠と共に）

移動モードの平面は「二本の隣接矢印が挟む三角／正方形領域」。第 33.2 節の訳し方で：
- 赤矢印（左右）＋緑矢印（上下）面 ＝ **左右 × 高さ**面（物体の「側面」）；
- 緑矢印（上下）＋青矢印（前後）面 ＝ **高さ × 前後**面（物体の「前／後面」）；
- 赤矢印（左右）＋青矢印（前後）面 ＝ **左右 × 前後**面 ＝ **地面**（物体の「立つ面」）。
✏️ **やってみよう**：物体を地面に置き、「赤＋青」平面正方形を掴んで引く——地面に沿って素直に滑り、浮きも沈みもしない？これが「地面移動」の最も安定した姿勢。

### 34.3 キーボード移動と並習

| やりたい | コントロール | キーボード（第 32 章） |
| --- | --- | --- |
| 前後 0.1 升目精密移動 | **青矢印**を掴む | `↑`/`↓` |
| 左右 0.1 升目精密移動 | **赤矢印**を掴む | `←`/`→` |
| 高さ精密上げ／下げ | **緑矢印**を掴む | `PgUp`/`PgDn` |
| 大ステップ 1 升目 | 矢印を強く引く | `Shift`+矢印 |

💡 語呂：**コントロールは「感覚」、キーボードは「精密」**。まずコントロールで約 90% まで、次に `↑`/`←`/`PgUp` で数升目微調整して升目に吸わせ。

---

## 第 35 章 回転モード：リングが「どの軸を回すか」を決める

### 35.1 三つのリング＝三軸回りの回転

回転モード（↻）へ切り替えると、物体を三つの色リングが囲み、各が「その軸を中心に回転」を表します：
| リング色 | コード軸 | 画面ラベル軸 | 感覚（第 32 章比喩を思い出す） |
| --- | --- | --- | --- |
| 🔴 赤リング | コード X | 画面 **Y**（左右軸） | **前後に宙返り**するよう |
| 🟢 緑リング | コード Y | 画面 **Z**（高さ軸） | **その場で回る**（コマのよう） |
| 🔵 青リング | コード Z | 画面 **X**（前後軸） | **左右に倒れる**（横転）よう |

⚠️ リング色と「どの軸を中心に回すか」の対応も第 33.2 節の訳し表を用います——**赤リングは左右軸、緑リングは高さ軸（最も常用、まっすぐに）、青リングは前後軸**。

### 35.2 リングを引く回転 ＝ キーボード A/D/W/S/E/Q、同じもの

第 32 章でキーボードで回転：
- `A`/`D` は**高さ軸**（画面 Z、垂直軸）周り；
- `W`/`S` は**左右軸**（画面 Y）周り；
- `E`/`Q` は**前後軸**（画面 X）周り。
対応するコントロールリング：
- キーボード `A`/`D` ↔ **緑リング**引き（高さ軸）；
- キーボード `W`/`S` ↔ **赤リング**引き（左右軸）；
- キーボード `E`/`Q` ↔ **青リング**引き（前後軸）。
✏️ **やってみよう**：「正面」を持つオブジェクトを選び、`Shift + A` で 90° まっすぐ回し、次に回転モードで**緑リング**を引く——手引きも同じ垂直軸周りで、任意の角度に止められる（キーボードは 5°/90° のみ、コントロールは途中値も可）。補完し合う。

### 35.3 自由回転と精密回転

- コントロールリング：任意角度に止められ、「ちょうど良い角度まで回す」に向く；
- キーボード `Shift`＋文字：90° だけ全体ジャンプ、「必ずまっすぐ、必ず直角」に向く；
- キーボード通常文字：5° ステップ、「数度微調整」に向く。
💡 実践：まずコントロールで大まかな角度へ→次に `Shift+A`（緑軸）でちょうど 90°/180° に足す、3D テキストや建物ファサードの「必ずまっすぐ」に最も使う。

## 第 36 章 スケールモード：立方ハンドルと「均等」スイッチ

### 36.1 立方ハンドル：一軸引っ張り、または全体膨張

スケールモード（⤢）へ切り替えると、角に小立方ハンドルが出ます。単一立方体を引く＝**その一軸だけ伸縮**（例 球を楕円に潰す、柱を細長く伸ばす）、中心立方体を引く＝全体拡縮。
| ハンドル色 | 画面ラベル軸 | 引いた効果 |
| --- | --- | --- |
| 🔴 赤立方 | 左右（Y） | 広げる／狭める |
| 🟢 緑立方 | 高さ（Z） | 高く／低く |
| 🔵 青立方 | 前後（X） | 深く／浅く |

### 36.2 「均等スケール」ロック：初心者が最もつけるべきスイッチ

右パネルの変換モードゾーン下に「均等スケール」チェック（既定オン）。オンのとき、どの立方体を引いてもオブジェクトは**全体に比例拡縮**し、歪みません——たいていまさにそれを望みます。
⚠️ オフにすると単一立方体を引き「単軸伸縮」で歪む。創造的用途（潰したクッション、伸ばした梁）はありますが、初心者は誤ってオフにし「なぜ曲がったか」となることが多い。分からなければオンのまま。

### 36.3 キーボードスケールと比較、「複数選択はスケール不可」

| やりたい | コントロール | キーボード（第 32 章） |
| --- | --- | --- |
| 全体 5% 拡大 | 中心立方を引く（均等オン） | `+` |
| 全体 5% 縮小 | 中心立方を引く | `-` |
| 倍／半分 | 中心立方を強く引く | `Shift`+`+` / `Shift`+`-` |
| 単軸潰し | 均等オフ、単一立方を引く | キーボード不可 |

⚠️ **重要な制限**：**複数オブジェクトを一度に選択**するとスケールモードは**自動無効**（ボタン灰色、スケールモードにいたら自動で移動へ戻る）。キーボード `+`/`-` も複数選択でスケール不可の理由と同じ、大きさのばらばらな数個を一緒に拡縮は不自然だから。

💡 複数選択でサイズを統一するには二つの道：① `Ctrl + A` 後、コントロール／キーボードで一つずつ、②「均等スケール」以外の手段——例えば先に良く組み、移動で配置し、スケールに頼らない。

### 36.4 変換コントロールが「させてくれない」とき

複数選択でスケール不可のほか、モードボタンが灰色でクリック不可になる場合：
- **ペン／テキスト／消しゴム**ツールモードにいるとき（これらがクリックを奪う、変換コントロールは譲る）；
- **テキスト編集中**（入力枠が出る）は一時無効、入力後復帰；
- **テキストオブジェクト**自体は均等スケール非対応、テキスト選択で均等関連コントロールを隠し、スケールモード無効化、自動で移動へ；画像とペン線は通常通りスケール可。
⚠️ 三モードボタンが灰色でクリック不可ならまず確認：まだどこかツールに留まって抜けていないか？`Esc` かトップの「選択」系ボタンでツールを抜ければ変換コントロールが生きる。

### 36.5 コントロールと数値枠：双方向同期

右の「変換」ゾーンにも対応する**数値スライダー／入力枠**（位置、回転角、スケール値）があり、コントロールと**双方向同期**：
- コントロールを引くと数値枠がリアルタイム追従；
- 数値枠へ直接精密値を入力（例 回転 `45`、スケール `2.5`）すれば即変化。
💡 「絶対精密」が要るなら（回転正確に 30°、スケール正確に 1.5×）、**直接数値枠入力**がドラッグよりずっと確実。コントロールは「感覚探し」、数値枠は「値留め」に。

---

✏️ **篇まとめ**：変換コントロールはキーボードの「自由ドラッグ版」。三つ覚えて——①移動／回転／スケールの三つの皮で矢印／リング／立方体に対応；②**赤ハンドル＝左右、緑＝上下、青＝前後**（常に画面ラベルで読み、表面の色に騙されない）；③左でオブジェクト、右／中／ホイールで視点、三者喧嘩せず。次篇は「群管理、整列、配列」で、「単体移動」から「大群を配置」へ。

# 第 10 篇 群像篇（一度に「一群」を管理）

> 前篇の終わりに「群管理、整列、配列」と約束しました。先に白状します：**このツールには独立した「グループ」ボタンも、「ワンクリック整列／配列」ボタンもありません**——より軽く柔軟な道を取ります：**複数選択＋まとめて変換＋複製配列**。
> この篇は「大群のオブジェクトをどう効率管理するか」を教えます。銀の弾丸はないが、十分な「地に足の着いた方法」のセットで、同じようにきちんと並べられます。

## 第 37 章 一度に一群を選ぶ：「選択セット」を知る

### 37.1 なぜ複数選択か

以前は「一つクリック、一つ変更」でした。でも本当の創作はたいてい一群：一列の木、一列の灯、地面の小石。100 個を一つずつ調整していては先に参ります。
解決：まずすべてを一度に「選択セット」へ選び、まとめて操作。それが複数選択の意味。

### 37.2 複数選択の三つのやり方

| 方法 | やり方 | 向く |
| --- | --- | --- |
| **全選択** | 「全選択」ボタン | シーン内の全オブジェクト |
| **加除** | `Shift` を押しながらオブジェクトをクリック：未選択なら追加、選択済なら除外 | 特定数個（「この二灯＋あの木」） |
| **囲み選択** | 空白で**押したままドラッグ**して破線矩形、中を一度に選択 | 密集した一片、一つずつ面倒 |

✏️ **やってみよう**：シーンに図形を 5 つ散らし。まず `Ctrl + A` で全部点灯→空白クリックで解除→`Shift` で 2 つクリックオフ（灰色に）→空白で矩形を引き残り 3 つを囲む。選択セットが付箋の山のように加除自由なのを感じて。
💡 囲み選択の細かい点：マウスは空白ドラッグで矩形、タッチには「空白ドラッグ」概念がないので専用「囲み選択」ボタンを作った——オンで指一本ドラッグで囲み（オン時下部に「囲み選択」ヒント）。矩形が何も当てはまらなければ「囲み選択は命中せず」と優しくヒント、黙って失敗しない。

### 37.3 選択の「境界例」

- 空白を**クリック**（ドラッグなし）＝全選択解除；
- 囲み選択中に矩形が**空っぽ**なら選択セットをクリア（「無し」へ解除と同等）；
- **テキスト編集中**や**ペン／消しゴム**ツール中は選択ロジックがツールに譲り、複数選択一時不可。

❓ **考えてみよう**：なぜ「Shift+クリック」は追加にも除外にもなるか？——選択セットは二値の「オン／オフ」ではなく**集合**だから。既存要素をクリックすれば除き、非存在をクリックすれば加える。この「トグル」ロジックはあとでファイル管理やメールでも出会う。

## 第 38 章 一群まとめて動かす：複数選択変換の「マスター支点」

### 38.1 見えない「マスター支点」

**複数**オブジェクトを選ぶと、ツールはどの特定オブジェクトにもコントロールを掛けず（掛ければ不公平）、この群の**中心**に**見えない代理点**（`multiTransformProxy`）を置きます。
あなたが見る変換コントロール（矢印／リング）は実はこの「マスター支点」に掛かっています。引くとアルゴリズムがマスター支点の移動／回転の**差分**を計算し、それを各選択オブジェクトへ**同期分配**します。
> 平たく：あなたが引くのは一つの見えない「マスタースイッチ」、選ばれたものは全部一緒に動き、相対位置を保つ。

### 38.2 複数選択でできること

| 操作 | 複数選択で可？ | 備考 |
| --- | --- | --- |
| まとめて移動（矢印／平面引き） | ✅ 可 | 群が一軸へ移動 |
| 中心回りまとめて回転（リング引き） | ✅ 可 | 群が群中心を回り、駒のターンテーブルのよう |
| まとめてスケール | ❌ 不可 | 複数選択でスケールモードボタンが灰色、自動で移動へ戻る |

✏️ **やってみよう**：散らばった 3 つを選び→回転モード→**緑リング**（高さ軸周り）を引く→「一つの手で一度に捻られる」ように群中心を回りつつ間隔を保つを見る。それが「群回転」の楽しさ。

### 38.3 なぜ複数選択でまとめてスケールできないか

⚠️ これは**意図的な制限**、バグではありません：
- 大きさ／形の異なる数個を一緒に比例拡縮すると奇妙なことが多い（大きいは巨大に、小さいはゴマに）；
- だからツールは複数選択で**スケールモードを無効化**し、「一つずつスケールするか、複製してから調整」を強います。
💡 代わり：
1. 群を「全部同じサイズ」にしたいなら、まず `Ctrl + D` で同一の列を複製、もとより同じサイズ、後は一つずつ微調整；
2. 本当に群全体をスケールしたいなら「全部選択→JSON 書き出し→値変更→取り込み」は面倒。より実用的は「仮のグループとして扱い、個別スケール＋統一オフセットで配置」。

### 38.4 複数選択＋Shift 大ステップも便利

第 32 章の `Shift` 大ステップ（1 升目／90°）は**複数選択でも可**。群を選んだ後 `Shift`＋矢印を押せば群が一昇目ずつジャンプ——配列に最適（次章）。

---

## 第 39 章 量産：コピー・複製・「配列」

繰り返すとき、2 つ目・3 つ目を手描きしてはいけません。コピー／複製でコンピュータに生ませましょう。

### 39.1 「コピーを生む」三つのやり方

| キー | 名称 | 特徴 |
| --- | --- | --- |
| `Ctrl + C` | コピー | 選択オブジェクトを**クリップボード**へ（即座には出ない） |
| `Ctrl + V` | 貼り付け | クリップボードから**取り出し**、元位置近くへ貼る |
| `Ctrl + D` | **複製** | 一段で：その場コピーし**少し自動オフセット** |

💡 **最も使うのは `Ctrl + D`**。コピー→貼り付けより一段少なく、複製コピーは自動で少しオフセットされるので即見え、すぐ再配置可——配列の標準。
✏️ **やってみよう**：図形を 1 つ置く→`Ctrl + D` で 2 つ目が少しずれて出る→新しい方を選び `→` で次の升目へ→また `Ctrl + D`→`→`…数手で一列が埋まる。マウスパネルに触れず。

### 39.2 「複製＋キーボード」で整った配列

「整列／配列」ボタンがない？大丈夫、**升目ステップ**で手動配置すれば十分整います：
1. オブジェクト選び `Ctrl + D` 複製；
2. 矢印キーで**ちょうど 1 升目**へ移動（既定ステップ 0.1 升目＝10 押し、または `Shift`+矢印で 1 押し＝1 升目）；
3. `Ctrl + D`＋矢印を繰り返し、一列が；
4. 一列後、`Ctrl + A` で全体選び、`Shift`+矢印で「群ごと」次の行へ大ステップ、さらに複製——二次元配列（方形）の完成。

💡 **円配列の技**：一つ複製→中心から一定半径へ移動→群中心周りに回転（第 38 章）→角度ごとに複製。数回で「環配列」が。これが手動の「配列」。

### 39.3 コピー貼り付けの境界

⚠️ 当たりやすい二つのヒント（ツールが小さく表示）：
- **「変換中、コピー／複製不可」**：コントロールを引いている（変換活性）とコピー／複製ボタンが一時無効。離してから押して。
- **「まずオブジェクトを選んでコピーしてください」**：何も選ばず `Ctrl + C` は先に選ぶよう促す。`Ctrl + V` でクリップボード空なら「空です」とヒント。
❓ **考えてみよう**：複製とコピー貼り付けの根本的な違いは？——複製は「その場でオフセット複製」、中間保存に頼らず；コピー貼り付けは「先にクリップボードへ格納、後で取り出し」なのでシーン A からコピー、シーン B へ貼り付けも可（このツールのクリップボードは同一ページ内のメモリ級）。これを知れば `Ctrl + V` が効かない理由が分かる——たぶんクリップボードが空。

---

## 第 40 章 保存と共有：作品を画面の外へ

せっかく作ったシーン、ページを閉じたら消える？いいえ——本ツールはファイルへ**書き出し**、**取り込み**で戻し、**スクリーンショット**で画像に。

### 40.1 三つの「保存／読込」キー

| キー | 動作 | 産物 |
| --- | --- | --- |
| `Ctrl + S` | シーン書き出し | **JSON ファイル**（シーンの完全記述） |
| `Ctrl + O` | シーン取り込み | 以前書き出した JSON を読み戻す |
| `Ctrl + P` | 画像書き出し | **PNG 画像**（現在キャンバスの写真） |

💡 流れ：**一区切り作る→`Ctrl + S` 保存→翌日 `Ctrl + O` で読み戻し続き**。JSON は「プロジェクトファイル」、PNG は「結果写真」、役割分担。

### 40.2 JSON に正確に何が蓄えられるか

書き出す JSON は画像ではなく**オブジェクト一覧**、おおよそ記録：
- 各オブジェクトの**種類／図形**（球かテキストか、長さ幅高さパラメータ）；
- 各オブジェクトの**変換**（位置、回転、スケール——どこにあり、傾いているか、大きさか）；
- 各オブジェクトの**外観**（色、テクスチャ、不透明度、テクスチャ画像）；
- シーンの**環境設定**（軸、グリッド表示等）。
⚠️ 「パラメータ」を蓄え「画素」ではないので、取り込み後も**編集継続可**——これは死んだ絵ではなく生きたプロジェクト。だから以前の操作が「履歴スタック」に入り取り消し可なのも、結局このパラメータセットを変えているから。

### 40.3 共有と協働の提案

- **同僚に効果を見せる**：PNG（`Ctrl + P`）が最速；
- **同僚に編集を続けてもらう**：JSON（`Ctrl + S`）を送り、相手は `Ctrl + O` で開き編集；
- **跨端**：JSON をクラウド／微信へ送り、別のパソコンでページを開き取り込み——シーンが付いていく。
- ⚠️ `Ctrl + Del` が**確認なしでシーン全体をクリア**するのを忘れず。クリア前に `Ctrl + S` でバックアップを。

### 40.4 手動の「整列と配列」：ボタンなしでも整う

篇頭の約束へ戻り、独立した整列／配列ボタンがないので、ここに三つの**純手動**な整い方を、学んだことを組み合わせて：
1. **升目に頼る**：既定移動ステップ 0.1 升目（＝0.15 単位）、整数押しで升目線へ正確着地。`Shift`+矢印一押し＝1 升目、「升目線へ吸う」に最適；
2. **複製に頼る**：第 39 章の複製＋固定ステップ＝等間隔配列（それが「配列」）；
3. **視点に頼る**：まず下部「前／上」で物体を標準カメラへ正しく直し、次にキーボードで単軸移動、配置の「曲がり」を避ける。

✏️ **総合練習（篇の卒業）**：「立方体＋`Ctrl + D` 複製＋`Shift`+矢印」で 5×3 の方形を並べ、`Ctrl + A` で全部選び `PgUp` で群を地面から 1 升目持ち上げ、`Ctrl + S` 保存。これで「量産＋整列配置＋結果保存」ができた。

✏️ **篇まとめ**：このツールは「グループ／整列」ボタンに頼らず、**複数選択＋代理マスター支点＋複製配列**で群を管理。覚えて——複数選択三法（全選択／Shift 加除／囲み）、複数選択は移動と回転は可だがスケール不可、複製 `Ctrl + D` は配列の救世主、JSON は生きたプロジェクトファイル。次篇は**総合実戦**：ゼロから完整な小シーン（小屋／小庭）を作り、これまで十篇の技を一つの流れに繋ぎ、「初心者から習熟へ」の最後の一マイルを体験。

## 第 41 章 プロジェクト 1：小さな家を建てる

### 41.1 まず完成品を見て、どう分解するか考える

作るのは簡単：草地に立つ屋根・扉・窓付きの小屋。
急いで図形を引っ張るな。10 秒で一つ問いを：
❓ **考えてみよう**：家を、もし「立方体・円錐・四角錐・円柱・平面」の基本図形だけで組むなら、どう分解する？
これが 3 次元創作の核心思考——**複雑な物体を単純幾何の組み合わせへ**。専門用語は「プロック分析」、平たくは「積み木」。
参考分解：

| 部分 | どの図形 | なぜ |
| --- | --- | --- |
| 壁（本体） | `box` 立方体 | 家は本質的に箱 |
| 屋根 | `pyramid` 四角錐 | 正方形底、尖り、正方形壁に合う |
| 扉 | `box` 潰した薄板 | 壁に貼る、図形を描くより楽 |
| 窓 | `box` より小さい薄板 | 同様、半透明でガラスに |
| 煙突 | `cylinder` 円柱 | 細長く、屋根から突く |
| 草地 | `square2` 正方形 | 2D が地面に寝て芝生に |

💡 **心得**：どんなモデルもまず「どんなブロックから成るか」を問う。車もロボットも思考は同じ。

### 41.2 ステップ 1：基礎を敷く（芝生）

1. 左パネルで **2D 図形**へ切り替え、`square2` **正方形**をシーン中央へ；
2. 選んで右パネルで**緑系**の色；
3. テクスチャで **Checker**——遠目に刈り込んだ芝生の模様；
4. **均等スケール**（右パネルスライダーか `Shift + +`）で家より明らかに大きく拡大。
⚠️ **罠**：2D 図形は「地面に寝た平らなシール（Z=0）」。もし「立った」なら回転コントロールで誤って回したはず、`Ctrl + Z` で戻し無理に曲げるな。
✏️ 側面練習：下部「**上**」ボタンをクリックし真上から芝生が十分か、次に「透視」へ戻る。この「視点切替で確認」の癖をこの篇以降毎ステップ勧めます。

### 41.3 ステップ 2：壁を立てる

1. **3D 図形**へ切り替え、`box` **立方体**を芝生中央へ；
2. 選んで `PgUp` で**地面にちょうど座る**まで持ち上げ（底面が地面、浮かず沈まず）；
3. 右パネルで**ベージュ／薄黄**（壁色）へ；
4. テクスチャで **Brick**——「ブロック」から「家の壁」に一変。
💡 **「地面に乗る」を見極める技**：下部「**前**」ボタンをクリックし真正面から、物体が浮くか沈むか一瞥で分かる。透視では誤りやすく、前視点は嘘をつかない。
⚠️ **罠**：多くの初心者が透視で高さを調整し「何か変」になる。前視点へ切り替えれば二秒で解決。

### 41.4 ステップ 3：屋根を被せる

1. `pyramid` **四角錐**を引く；
2. `PgUp` で壁頂の**真上**へ持ち上げ、円錐底がちょうど壁頂に乗る；
3. 左右前後が揃わない？`↑↓←→` で微調整（0.1 升目）、大きい数は `Shift`+矢印で一升目ジャンプ；
4. 色を**赤茶／濃灰**（瓦色）へ。
❓ **考えてみよう**：なぜ屋根に「四角錐」で「円錐」ではないか？——壁が正方形だから。正方形屋根を正方形壁に、辺がぴったり閉まる；円錐を正方形壁に、四隅が飛び出す。**形の一致が「見た目が合う」の鍵**。
✏️ **やってみよう**：わざと `cone` に切り替え、前と上から見て「飛び出す角」の不自然さを感じ、`Ctrl + Z` で戻す。

### 41.5 ステップ 4：扉と窓を切る

扉／窓の方法は「**潰した薄板を壁に貼る**」：
1. `box` を引き、まず**「均等スケール」をオフ**（第 36.2）にして**薄いスライス**に伸ばす；
2. 均等スケールを再オン（以後の誤変形防止）；
3. 矢印キーで壁の**表面**に貼り付け——少しだけ飛び出させる（下の罠参照）；
4. 色を**濃茶**（木扉）に。
窓も同様、より小さい薄板二枚を作り、色**薄青**、**不透明度を約 0.5** に——ガラス感が即（第 20.2）。
⚠️ **重要な罠：Z 戦い（ちらつき）**
扉板と壁が**まさに同面**だと、二つの面が同じ深さで「位置を取り合い」ちらつき交差します。バグではなく二面が「深さで争う」現象。
**解決**：矢印キーで扉を 1〜2 ステップ（0.1 升目）前方へ動かし、壁の「前」に明確に浮かせる。
💡 二つ目の窓を描き直すな——一つ選び `Ctrl + D` 複製、次に `←` か `→` で反対側へ。第 39 章の複製配列が実践で初登場。

### 41.6 ステップ 5：煙突を加え締める

1. `cylinder` を引き、均等スケールで細く、`PgUp` で屋根斜面へ持ち上げて少し突き出す；
2. 色**濃灰**；
3. もっと賑やかなら `sphere` 球を数個複製、煙突口に「煙」として積み、不透明度 0.3 に。
**最終チェックリスト**（各プロジェクトで勧め）：
| 確認項目 | 方法 |
| --- | --- |
| 浮く／沈む？ | 「前」水平視点 |
| 前後貫通？ | 「左」か「右」視点 |
| 全体配置は中央？ | 「上」真上 |
| 見栄えする？ | 「透視」で通常へ戻る |
確認後：`Ctrl + S` で JSON 保存、`Ctrl + P` で PNG スクリーンショット納品。

### 41.7 応用課題

1. **連棟住宅を作る**：家全体を選び（`Ctrl + A`）→`Ctrl + D` 複製→`Shift`+矢印で群を一升目離す→三回繰り返す。複数選択複製では相対位置がそのまま保たれる（第 38 章「マスター支点」機構）。
2. **季節を変える**：芝生テクスチャを「Dot」に、色を白へ→雪原；壁不透明度を 0.4 へ→氷の家。
3. **名札を加える**：第 21 章テキストツールで扉上に「No.1」を追加、フォント「Hei」、サイズを家と比べて縮小。
⚠️ 注意：テキスト既定サイズは **80**、家のブロックは通常 1〜2 単位——そのまま追加すると「家より巨大な文字」に。サイズを縮小（またはテキスト全体をスケール）して調和を。これが初心者が看板で最も挫ける点、慌てずサイズを変えて。

## 第 42 章 プロジェクト 2：立体文字のスローガンを作る

### 42.1 目標と着想

シーンに立つ**スローガン板**：裏板＋テキスト＋装飾、例「Welcome」「グランドオープン」や好きな一行。
⚠️ まず誤解しやすい点：本ツールのテキストは「**言葉を貼った薄板**」（第 21.1）であり、本当に厚みのある押し出し 3D 文字ではない。だから「立体感」は**裏板＋テキスト＋層状配置**の組み合わせに頼り、文字自身の厚みではない。
これを理解すれば着想は明確：
| 層 | 何 | 役割 |
| --- | --- | --- |
| 裏板 | `box` 潰した薄板 | テキストに「支え面」を |
| 主テキスト | テキストオブジェクト | 内容本体 |
| 影テキスト | テキストオブジェクト（濃く、少し後ろへオフセット） | 厚みの錯覚を作る |
| 支柱 | 二本の `cylinder` | 板を「立たせる」 |

### 42.2 ステップ 1：裏板を作る

1. `box` を引き、「均等スケール」オフで**垂直な薄板**（幅＞高さ＞厚み）に潰す；
2. 均等スケール再オン；
3. `PgUp` で目の高さまで持ち上げ（地面につかず）；
4. 色**濃い**（濃青／濃緑／木系どれも）—濃地に淡字が最も明瞭。
💡 **配色原則**：テキストと裏板は**明度差**が必須。濃地淡字、または淡地濃字、どちらかを。同明度の組（例 中灰地＋中緑字）は遠目でぼやける——デザインで最も基本だが最も見落とされやすい。

### 42.3 ステップ 2：テキストを入力

1. 左パネル「ツール」→「**テキスト追加**」；
2. シーンをクリック、入力枠（placeholder「Input text······」）；
3. スローガンを入力、`Enter` で確定；
4. 選んで右パネル調整：
   - **フォント**：モダンなら「Hei」、伝統なら「Kai」；
   - **サイズ**：既定 80、たいていブロックに合わせ**縮小**（41.7 注意参照）；
   - **太字**：スローガンにはオンを推奨、遠目で際立つ；
   - **色**：裏板と強いコントラストの淡色。
5. 矢印キーでテキストを裏板の**前面**へ、少し飛び出させ（41.5 の Z 戦い防止）。
✏️ **やってみよう**：入力後、**ダブルクリック**で内容を別の文へ変える。削除作り直し不要の便利さを（コピー推敲に便利）。

### 42.4 ステップ 3：「影テキスト」で厚みを

この章の核心の技—簡単だが目を引く：
1. 主テキストを選び `Ctrl + D` **複製**；
2. 複製を**濃く**（裏板より少し濃いか純黒）に；
3. 矢印キーで**後ろと下へ 1〜2 小ステップ**（0.1 升目で十分）動かす；
4. 主テキストを覆うなら前後関係が逆、主テキストを一ステップ前へ。
透視から見れば、後ろの濃字、前の淡字で**視覚的に「浮く」**。これはグラフィックの「ドロップシャドウ法」、3D でも同様に効く。
❓ **考えてみよう**：なぜ「後ろ＋下」オフセットが「後ろのみ」より良いか？—現実の光は通常**上**から来るから、影は自然に**下と後ろ**に落ちる。日常の光経験に合うオフセットで脳が「本物」と感じる。
💡 もっと立体的に？影テキストを**さらに 2〜3 枚**複製、各少しずつ後ろへ、色を次第に濃く—「多層押し出し」の偽厚みに。層が多いほど重いがぼやみやすく、3 層が目安。

### 42.5 ステップ 4：支柱を加え板を立たせる

1. `cylinder` 二本を引き、均等スケールで細長く；
2. `PgUp`／矢印で裏板の**両側下**へ差し込み、上端を裏板へ少し入れる（ここは**意図的な貫通**で継ぎ目を隠す）；
3. 色**濃灰／木系**。
💡 二本目を手描きし直すな—一本選び `Ctrl + D` 複製、次に `←`／`→` で反対側へ。対称なものは常に複製、手配置より正確。

### 42.6 ステップ 5：横書きと縦書き

同じ文でも配置で全く気質が変わる：
| 組み合わせ | 気質 | 向く |
| --- | --- | --- |
| 横書き＋Hei＋太字 | モダン、商業 | 店看板、イベント横断幕 |
| 縦書き＋Kai＋大サイズ | 伝統、厳か | 扁額、アカデミー、茶館 |
| 横書き＋Times＋非太字 | 西洋、フォーマル | 英看板、案内板 |
| 横書き＋Courier | テック、レトロ | テック感、タイプライター風 |
✏️ **やってみよう（比較実験）**：同じ「茶」の字で二版—横書き Hei と縦書き Kai 大サイズ＋木裏板。シーンに並べ「前」から見れば、フォントと配置自体が語り、内容同じで気質が隔たるを直観。

### 42.7 陥りやすい罠まとめ

| 現象 | 原因 | 直し方 |
| --- | --- | --- |
| 文字が法外に大きく全体を覆う | 既定 80 がブロック規模と不合 | サイズ縮小、またはテキスト全体スケール |
| 文字と裏板がちらつき交差 | 同面（Z 戦い） | 矢印で文字を 1〜2 ステップ出す |
| 遠目でぼやける | 文字／裏板の明度差不足 | 明暗コントラストを増す、または太字 |
| 文字が裏板端を超える | コピーが長すぎ | サイズ縮小、または裏板拡幅 |
| サイズ変えられない／矢印効かず | カーソルが数値入力枠に残り | まず空白キャンバスをクリック（第 32.1） |

### 42.8 応用課題

1. **両面看板**：全体（裏板＋テキスト＋影）を選び複製、`Shift + A` で 180° 回し裏へ配置、両面から読める立て札に。
2. **発光文字**：主テキストを鮮黄、裏板を深黒、その後テキストの後ろに半透明（不透明度 0.3）の淡黄薄板を「後光」に。
3. **第 41 章とリンク**：この看板を第 41 章の家の前に置き、`Ctrl + S` で一つの完成シーンに。家＋看板の完整な小シーンができた。

## 第 43 章 プロジェクト 3：ロゴ／アイコンをデザインする

### 43.1 なぜロゴが「最良の練習」か

最初の二プロジェクトは「3D 物」を作った。これは逆—グラフィックデザインに見えるが 3D 手段で実装するロゴを作る。
優れた練習だから：
- **2D 図形**のみで足りる（第 12 章の 20 種）、図形負担が低；
- 実際のデザイン課題（**整列、層、色**）を強制する；
- 製品を「上」視点でスクリーンショットすれば清潔なアイコン、そのままアバター／ロゴに。
❓ **考えてみよう**：見たことのあるロゴ（車エンブレム、校章、App アイコン）—たいてい何層から成る？—通常 3〜4 層以下：基形＋主図＋アクセント＋テキスト。**少ないほど洗練**、これがロゴ設計の鉄則。

### 43.2 前提：上視点で作業

⚠️ このプロジェクトは**「上」視点で全体**を操作してください（下部視点ボタン）。
理由：ロゴは「正面」の平面構成、2D 図形は全て地面に寝る（Z=0）。真上から見れば完成像、透視では近大遠小で当てずっぽう整列に。
💡 一般経験：**やることにその視点から見る**。床配置は上、高さは前、全体効果は透視。一つの視点で通すな。

### 43.3 ステップ 1：基形（最外郭）

1. 左パネルで **2D 図形**へ、一つを基に：
   - `circle2` 円 → 丸バッジ、最も汎用；
   - `hexagon` 六角 → テック、工業感；
   - `octagon` 八角 → 安定、アイデンティティ感；
   - `pentagon` 五角 → 盾、アカデミー感。
2. 中央に配置；
3. 均等拡大で適切なサイズ；
4. 色**濃く**（濃青／濃緑／ワイン赤どれも映える）。

### 43.4 ステップ 2：内層と主図（層を作る）

ロゴの洗練は 80% が「**同心層**」から。
1. 基形を選び `Ctrl + D` **複製**；
2. 複製を均等スケールで小さく（`-` 数押し、または `Shift + -` 半分）；
3. **重要**：`PgUp` で**少し持ち上げ**、基形よりわずかに浮かせ；
4. **淡色**（白／ベージュ／鮮金）へ。
これで「濃外輪＋淡内芯」の同心構造が。
⚠️ **避けられない罠**：2D 図形二つが共に Z=0 なら激しくちらつき交差（また Z 戦い、第 41.5）。**2D 図形を重ねるとき各層を `PgUp` で少し持ち上げ**、高さで分離。これが章で最も重要な操作規律。
💡 呪文：**層を重ねるごとに一ステップ持ち上げ**。三層なら三つの異なる高さ。
次に主図（ロゴの「主人公」）を配置：
| 表現したい | どの 2D 図形 |
| --- | --- |
| 栄誉、評価 | `star` 五尖星 |
| 愛、慈善 | `heart` ハート |
| エネルギー、速度 | `lightning` 稲妻 |
| 医療、救援 | `cross` 十字 |
| 方向、物流 | `arrow` 矢印 |
| 自然、水 | `teardrop` 涙 |
| 夜、静けさ | `crescent` 三日月 |
| テック、接続 | `hexagon` 六角 |
配置し、持ち上げ、コントラスト色へ、中央整列。
💡 tip：heart/arrow/crescent/cross/lightning は**独立した図形パラメータ**を持つ（第 12.2、例 heart の `scale`、arrow の `線幅/長さ/幅`）、右パネルで直接調整可。全体サイズだけ変えたいなら均等スケールや変換コントロールでも。

### 43.5 ステップ 3：どうやって中央に整列するか

このツールに「ワンクリック中央」ボタンはない（第 10 篇で述べた）が、ロゴは正確な整列を要する。三つの手動整列法：
1. **グリッドに頼る**：上視点で地面の升目線が物差し。各層の中心を**同じ升目交点**へ、矢印で微調整（0.1 升目）；
2. **複製に頼る**：複製コピーは**平行移動せず均等スケールのみ**なので中心がそのまま—自然に同心。最も楽な手、強推奨；
3. **数値枠に頼る**：右パネルの位置数値枠（第 36.5）へ直接入力。各層の水平位置を**同じ数値の組**にすれば絶対精密中央。
💡 **最良実践**：方法 2＋方法 3 併用。まず複製で同心を保証、最後に数値枠で数字一致を二重確認。マウス引きより百倍確実。

### 43.6 ステップ 4：文字環／下部文字を加える

1. 「テキスト追加」、ブランド名や年を；
2. サイズ**縮小**（ロゴ文字は通常小さく）；
3. フォント：モダンなら「Hei」、アカデミーなら「Times」、伝統なら「Song」；
4. **最上層**（全図形より一ステップ高く）へ持ち上げ；
5. ロゴ下部か空白中央へ。
⚠️ 本ツールのテキストは**円弧に沿う配置不可**（「リング文字」なし）。同効果には文字を一文字ずつ分割、複製して各回転—非常に面倒。初心者は**下部の横書き**を直接勧める、同等にプロ。

### 43.7 ステップ 5：画像を書き出す

1. 「**上**」をクリック、ロゴを枠内中央へ；
2. 必要なら `F11` 全画面でより大きく清潔に；
3. 邪魔を除けたい？軸とグリッドを隠す（第 28）—このステップ重要、さもなくば升目が写り込む；
4. `Ctrl + P` で PNG 書き出し；
5. `Ctrl + S` で後で色替え用の JSON 保存。
💡 **画像書き出し三点セット**：上＋補助隠し＋全画面。清潔な完成画像が要るたび。

### 43.8 配色早見（持って使え）

| スタイル | 基形 | 内層 | 主図 | 文字 |
| --- | --- | --- | --- | --- |
| ビジネス安定 | 濃青 | 白 | 濃青 | 白 |
| 自然エコ | 濃緑 | オフ白 | 緑 | オフ白 |
| 活発スポーツ | 鮮橙 | 白 | 濃灰 | 白 |
| 高級ラグジュアリ | 純黒 | 金 | 金 | 金 |
| 医療ヘルス | 白 | 薄青 | 赤十字 | 濃青 |
⚠️ 初心者が最も陥る色ミスは**色が多すぎ**。ロゴは **2〜3 色以内**に留めれば一気にプロ。層を豊かにしたいなら**同相の明暗差**（第 18.2：色相バー固定、盤内だけ上下）で、色を足すな。

### 43.9 応用課題

1. **アイコン一式を作る**：ロゴを選び三複製、主図だけ変え（星／ハート／稲妻）、他はそのまま。統一感あるアイコンセット—本物のブランド設計実践そのもの。
2. **浮き彫り感を加える**：主図を濃い複製にし、側へ少しオフセット、その下の層（第 42.4 の「影テキスト」技を図形へ）に。
3. **実体バッジを作る**：ロゴ全体の下に `cylinder` 平円柱を敷き、透視へ戻せば平たいロゴが「手に取る金属バッジ」に。

## 第 44 章 プロジェクト 4：総合シーン「我が家の小庭」

### 44.1 この章は「卒業設計」

最初の三プロジェクトは各々一技を鍛えた：ブロック組み（家）、テキスト配置（スローガン）、平面構成（ロゴ）。この章は**三つを一つのシーンへ合わせ**、さらにペン・画像・半透明と残りの技で完成作品に。
目標：家・塀・道・木・池・名札・空の雰囲気を備えた**庭付き小屋**。
⚠️ 本書で最も長い練習、いくつかに分けて、**一区切りごとに `Ctrl + S` 保存**を勧めます。「こまめ保存」の癖はどの技より価値あり。

### 44.2 制作の流れ：大を先に、小を後、固定を先に、装飾を後

プロと初心者の最大差は手速さではなく**順序**。厳守：
| 段階 | 何を | なぜこの順 |
| --- | --- | --- |
| ① 地面を敷く | 芝生を敷き庭の範囲を定義 | まず「舞台」を区切り、後の基準に |
| ② 本体を置く | 家を置く（第 41 章結果） | 最大物を先に、全体規模を決める |
| ③ ゾーンを分ける | ペンで道の向きを描く | 空き地に機能ゾーンを計画 |
| ④ 中物を加える | 木、池、塀 | 中程度の体積を埋め層を豊かに |
| ⑤ 小物を加える | 小石、花、名札 | 詳細は最後、早期判定を妨げぬ |
| ⑥ 雰囲気を調える | 色、不透明度、視点 | 統一調、仕上げて書き出し |
❓ **考えてみよう**：なぜ「詳細は最後」か？—詳細は**全体の判断を邪魔する**から。小石がそこらにあれば家の位置が正しいか見えない。まず大関係を固め、詳細は後。絵画の「全体から局部へ」、3D も同様。

### 44.3 ① 地面を敷く

1. 2D 図形で `square2` 正方形を引き、庭の地面として拡大；
2. 緑＋「Checker」パターン＝芝生；
3. 「**上**」へ切り替え、範囲が十分か—**むしろ大きく**、後で物を足すと小さければ変えにくい。
💡 最外郭に一段大きな淡色基板を敷くことを勧める（ `PgDn` で芝生より**一ステップ低く**し同面ちらつき回避）、庭の外の「開けた空間」として絵に境界感を。

### 44.4 ② 家を置く

第 41 章の結果をそのまま：
- プロジェクト保存済みなら `Ctrl + O` で取り込み；
- 未保存でも 41.2–41.6 を再建（この時はずっと速い）。
配置提案：**真正面の中央に置かぬ**。家を庭の**後ろ寄り、片側**へ、前に大きな空き地を残す—構図が自然、道や池の余白も。
💡 **構図小技**：本体を真正中に置くと堅い。少しオフセットが活き活き。写真の「三分割法」、地面升目で位置を見積もって。

### 44.5 ③ ペンで道を描く

ペンツールの典型用途（第 24）の実践：
1. 左パネル「ツール」→ **2D ペン**；
2. 色（土黄／薄灰）と線幅（太め、道のように）を設定；
3. 庭口から家の扉へ、わずかに**曲がった**線を描く；
4. 描き終わったらペンを抜ける（`Esc` か選択へ戻る）。
⚠️ **ペンの二つの規律**：
1. ペン線は描いたら「そこに固定」、図形のように細工整形不可—曲がったら `Ctrl + Z` で戻し描き直し、直そうとせず；
2. ペン線の形は**描いた時点で固定**、標準図形のよう細かく調整不可（但し線オブジェクト自体は全体スケール可）。
💡 なぜ道を「わずかに曲げる」か直線ではない？—直線は設計図風、曲線は生活風。この小さな違いでシーンが一気に「人間味」に。
✏️ **やってみよう**：まず直線の道を描き見て、`Ctrl + Z` で曲線を描き比べ。二版作って比べる方法が美学向上の最短。

### 44.6 ④ 木・池・塀を加える

**木**（二段）：
1. `cylinder` 細長く→幹、濃茶；
2. `sphere`→樹冠、緑、`PgUp` で幹頂へ；
3. 幹と樹冠を選び（`Shift` 加選、両選択）→ `Ctrl + D` で木全体を複製→他へ移動。
💡 ここで第 38 章の鍵機構：複製時に二部の相対位置が保たれ、コピーされるのは「完成した一つの木」、ばらけない。木一列は「複製＋`Shift`+矢印」の繰り返しのみ。
⚠️ 木を全て同じサイズにするな—複製後、適当に `+`／`-` で各 5% 程度の差を。自然感が一気に。規則性に少しの不規則が、シーンを本物らしく見せる秘訣。
**池**：
1. 2D 図形 `ellipse` または `circle2`、地面に寝る；
2. `PgUp` で**少し持ち上げ**（芝生と同面にせず）；
3. 薄青、パターン「**Wave**」；
4. **不透明度 0.6**—半透明の水感が（第 20.2）。
**塀**（複製配列の教科書的用途）：
1. `box` を薄い高い板に潰し→一つの柵；
2. `Ctrl + D` 複製→`Shift`+矢印で一升目移動→また `Ctrl + D`→また移動…；
3. 一列埋まったら、その列を `Shift` 選択→`Ctrl + D` で列全体複製→`Shift + A` で **90° 回転**→庭の反対側へ移動。
💡 ステップ 4 は本書十篇の集大成：**複数選択＋複製＋群全体 90° 回転**、三技同時。この後「卒業」と言える。

### 44.7 ⑤ 小物を加える

- **小石**：`sphere` か `dodeca` 十二面体を縮小、道両脇に数個散らし、色調は灰色でも**明暗差**を；
- **花**：`star` 五尖（2D）か小球、鮮色、芝生に点々と；
- **名札**：第 42 章のスローガン板を縮小版、扉に番地と共に；
- **写真壁**：「画像追加」で自身の画像を一つ（第 23）、庭の看板に。
⚠️ 詳細は**抑制**を。見栄えよくだが散らからぬ程度で止める。基準：上視点で真上から、主従が一目で分からなければ多すぎ、いくつか削除。

### 44.8 ⑥ 雰囲気を調え書き出す

**調子を統一**（質感を最も上げるステップ）：
| 望む雰囲気 | やり方 |
| --- | --- |
| 朝 | 全体やや淡く涼しく（薄青、オフ白）、不透明度やや高く |
| 夕 | 全体やや暖かく（橙、茶、金）、影面色を深く |
| 童話 | 高彩度（桃、シアン、鮮黄）、パターン「Dot」 |
| ミニマル | 黒白灰＋一つのアクセント色のみ |
💡 第 18.2 の技で統一：色相バーを固定、明度と彩度だけ変え、全体の色が自動「調和」。最も労力少なく効果大な着色法。
**書き出し流れ**（43.7 と同じ）：
1. 7 視点を全部試し、最も良い（通常「透視」でわずか下から）を；
2. 軸とグリッドを隠し（第 28）、一気に清潔に；
3. `F11` 全画面；
4. `Ctrl + P` スクリーンショット；
5. `Ctrl + S` 保存。
✏️ **最後の練習**：同じシーンを**三視点**でスクリーンショット—上（平面図）、前（立面図）、透視（効果図）。これが建築家の標準三点セット納品、あなたもできる。

### 44.9 行き詰まったときの自己チェック表

大シーンは「作るほど乱れる」に陥りやすい。詰まったらこの表で：
| 症状 | たぶん原因 | 救済 |
| --- | --- | --- |
| どんどん乱れ何をすべきか不明 | 「大を先に小を後」の順を守らず | 止めて上視点で全体を見て大物を先に |
| 面が交差ちらつく | 同面（Z 戦い） | `PgUp`/`PgDn` で層を分離 |
| 比例がおかしく某物が特に大きい | 基準がない | 既知サイズの物を「物差し」に置き他を合わせ |
| 色が散らかり安っぽい | 色種が多すぎ | 3 色以内に切り、層は明暗で |
| 狙う物が選べない | 他に遮られ | 視点変えてからクリック、または遮る物を先に退かす |
| 矢印が突然効かず物体動かず | 未選択／カーソルが入力枠 | 第 32.1 三ステップトラブル |
| 誤って全部消えた | 誤って `Ctrl + Del` クリア | `Ctrl + Z` 取り消し、次は先に保存 |

### 44.10 結びの言葉：使えるから作れるへ

あなたの歩みを振り返ると：
- 第 1 篇ではまだ「3 次元とは」と問い；
- 第 5 篇でシーンに話させるを学び；
- 第 8 篇で手がマウスを離れ；
- 第 10 篇で群をまとめて指図でき；
- 今、庭付き小屋を独りで建てた。
ツールのボタンは限られ（3D 20＋2D 20＋テクスチャ 12＋フォント 8）でも、**組み合わせは無限**。作品の高さを決めるのは知るボタンの数ではなく：
1. **分解能力**—複雑な物を単純幾何の組み合わせと見る；
2. **順序感**—大を先に小を後、固定を先に装飾を後；
3. **審美判断**—いつ止めるかを知る。
これら三つをこの篇四プロジェクトで繰り返し鍛えた。後の練習に委ねる。
💡 **次の一歩**：好きな写真（部屋、街角、玩具）を一つ、このツールで「再現」してみよ。合わなくて構わない—**合わない場所に、あなた独自の問題が生まれ、そこが進歩の始まり**。

## 第 45 章 よくある問題のトラブルシューティング

### 45.1 一般トラブル

現象 → 最もありそうな原因 → 直し方、で並べます。大半は辿れる原因があり、「バグだ」と飛躍しないで。
| # | 現象 | 最もありそうな原因 | 直し方 |
| --- | --- | --- | --- |
| 1 | 矢印／`+`/`-` が物体に効かない | 物体未選択、またはカーソルが右パネルの数値入力枠に残り | 空白キャンバスをクリック、物体選択と入力枠非フォーカスを（第 32.1） |
| 2 | 二面がちらつき交差 | 二面が同面（**Z 戦い**） | `PgUp`/`PgDn` で一面を一段持ち上げ分離（第 41.5、43.4） |
| 3 | テキストが法外に大きく全体を覆う | テキスト既定サイズ **80** がブロック規模よりずっと大 | フォントサイズ縮小、またはテキスト全体スケール（第 21、41.7、42.3） |
| 4 | フォントサイズ変えても矢印効かず | カーソルが数値入力枠に残り | 空白キャンバスをクリックし入力枠非フォーカス（第 32.1） |
| 5 | `Ctrl+C`/`Ctrl+D`/`Ctrl+V` 無反応 | 変換コントロール活性中、または物体未選択 | `Esc` で変換コントロール抜け、選択して操作（第 33、39） |
| 6 | 複数選択で `+`/`-` 拒否 | 複数選択は**均等スケールを禁止**（「NoScaleMulti」ヒント） | 複数選択を解除し一つずつスケール、または変換コントロールで引く（第 36.4） |
| 7 | テキスト選択でスケールモード無効 | **テキストは均等スケール非対応**、自動で移動へ | 「フォントサイズ」パラメータで変更（第 21）；画像とペン線は通常通りスケール可（第 24、36.4） |
| 8 | ペン／図形が曲がり直したい | ペン線は描いた時点で固定、図形のよう細工不可 | `Ctrl+Z` で戻し描き直し（第 24、44.5） |
| 9 | 中央にしたいが「中央」ボタンがない | このツールに**ワンクリック中央なし** | 三法：グリッド、複製同心、数値枠（第 43.5） |
| 10 | テキストを円弧に（リング文字）したいが不可 | このツールは**リング文字非対応** | 下部横書きを、または一文字ずつ分割して各回転（第 43.6） |
| 11 | ある 2D 図形（heart/arrow/crescent/cross/lightning）の形パラメータを調整したい | これらは各**独立形パラメータ**を持つ（heart `scale`、arrow `線幅/長さ/幅`、crescent `三日月度/厚み`、cross `腕長/幅`、lightning `振幅/幅`、第 12.2） | 右パネルの対応形パラメータで直接（第 12.2、43.4） |
| 12 | 誤ってシーン全体や重要物を消した | `Delete` 誤タップ、またはシーンクリア | 直ちに `Ctrl+Z` 取り消し、こまめな `Ctrl+S` の癖を（第 44.1） |
| 13 | JSON 取り込み「読込失敗」 | ファイル破損、または本ツール形式外 | 本ツール `Ctrl+S` の `.json` であるか確認（第 6） |
| 14 | 視点ボタンが点灯せず回転後カメラが暗い | 自由回転後「透視」ボタンが消灯（正常） | 視点ボタンをクリックし再整列（第 28） |
| 15 | 📱🤖 タッチはドラッグで視点回転のみ、囲み選択できず | タッチは**先に囲み選択モードへ** | まず下部「囲み選択」ボタン（青く）をタップしてから指一本ドラッグ、**一回で自動終了**、もう一度タップで再囲み（第 7.4） |
| 16 | 全体色を変えたのに一物体が変わらず | その物体に**独立色上書き**がある、または「色なし」 | 選んで別途色を変更（第 18） |
| 17 | 画面カラー取得が効かない | 取得ツールを先に起動せず | 色ゾーンの取得ボタンをクリックしてから拾う（第 18） |
| 18 | スクリーンショットに升目／軸が写る | 補助を隠さず | 軸とグリッドを隠してから `Ctrl+P`（第 28、43.7） |
| 19 | 複製物が「ばらけた」 | 複数選択複製前に群全体を選んでいない | `Shift` で群全体を選んでから `Ctrl+D`（第 38） |
| 20 | 回転／物体の方向が逆 | 軸混同：`A/D` は Z、`W/S` は Y、`Q/E` は X 周り | 第 47 章早見、または `Shift`+矢印で大角度試し（第 32、34） |

💡 **トラブルの第一原理**：奇妙さの 90% は三つの根因のみ——**未選択**、**カーソルが入力枠**、**二面が同面**。まずこの三つを唱え、次に表を——半分の時間が節約。

### 45.2 形態別の問題

上の大半は四形態共通。以下は特定形態のみ：
**🖥️📱 Web 版**

# 第 13 篇 付箋・多言語

ここまで「ツールの使い方」は習得。この篇は二つの「学びの供」：読みながらメモと、説明書自身の多言語対応。

## 第 49 章 読みながらメモ：説明書の中の付箋

学びながら「一節をマーク」したくなるもの。説明書は**範囲選択→付箋追加**をできます：
1. 読みながら任意のテキストを選択：
   - 🖥️💻 **マウス**：左ボタンを押したまま**ドラッグ選択**；
   - 📱🤖 **タッチ**：テキストを**長押し**で選択ハンドルを出し、両端をドラッグして範囲調整；
2. 離すと「付箋追加」ボタンが出る、クリック；
3. 選択テキストがハイライトされ**付箋リスト**に記録；
4. リスト各項目は個別に**削除**可—削除前に確認が出て誤失を防ぐ。

> 💡 付箋は「テキストに従う」：選んだ文に結びつくので、後で「当時何を考えていたか」を再読可。

## 第 50 章 付箋を画面に「浮かべる」

一々付箋リストを往復したくなければ、メモを**浮動付箋ウィンドウ**に展開可：
- 浮動付箋ウィンドウはドラッグ可能な浮きカード、キャンバス上に浮かび操作を邪魔せず；
- 読み取り専用と編集の二状態、読み取りは付箋のよう、編集はテキスト変更可；
- 不要になればウィンドウの閉じるボタン（`closeSticky`）を、画面から消えリストには残る。

### 50.1 💻 PC 専用：メモをメインウィンドウの「外」へ

PC 版はメモを本当に独立したシステムウィンドウにできます：
- **常に最前面**で全プログラムの上に浮く；
- 二画面目へドラッグ可；
- ブラウザで調べ物してもメモが見えている。
「チュートリアルを見ながら操作」に特に便利。🖥️📱🤖 他三形態のメモはアプリ画面内だけに浮き、外へは引き出せない。

### 50.2 付箋を閉じる順序（📱🤖 タッチ注意）

🤖 Android 版では**戻るキーを一度タップ**すると**まず付箋を順に閉じ**（未保存なら確認）、次に目次、次に説明書を閉じ、それからアプリ終了の確認。

> 📌 付箋は「仮のヒント」に向く：例えばパラメータ説明を脇に貼り、見ながら作る。

### 50.3 数量上限と一括管理

- **同時に浮く浮動付箋は最大 5**：超えるとシステムが**最も古いものを自動閉じ**し性能と UI を清潔に。メモ自体はリストに残り失われず。
- 付箋リストは**一括削除**対応：リストで複数チェックして一括削除（やはり確認付き）、一つずつ不要。
